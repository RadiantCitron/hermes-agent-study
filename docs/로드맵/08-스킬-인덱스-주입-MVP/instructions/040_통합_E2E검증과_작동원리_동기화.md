사실 검증 4축(동작·순서·소유자·시점)으로 **현재 코드와 대조한 사실만** 적는다. 미래형 약속은 쓰지 않고, 확인하지 못한 것은 「미확인」으로 적는다. 갱신 대상:

1. **머리**: 기준일을 갱신하고, 기준 커밋을 「이 문서가 설명하는 `src/`·`tests/`를 마지막으로 바꾼 커밋」으로 갱신한다(작동원리 README의 정의. 이 커밋 자신의 해시는 적을 수 없으므로, `git log -1 --format=%h -- src` 로 확인한 가장 최근 `src/` 변경 커밋을 적는다 — 07의 050도 같은 방식이었다). 「다시 확인하는 법」에 **13번 묶음**을 더한다: 스킬 인덱스(`render_skills_index`·`format_skills_index_section`·`SKILLS_INDEX_HEADING`/`SKILLS_INDEX_RULE`는 `prompt_builder.py`, `_resolve_skills_index_block`·`skills_index`는 `agent.py`, `--no-skills-index`는 `cli.py`, `SKILLS_INDEX_*` 상수는 `constants.py`)를 찾는 `grep` 명령들.
2. **1부 트레이드오프 표 「스킬 시스템」 행**: 「점진 공개 3단계(안내문만 헤드 고정…)」를 현재 사실로 정정한다 — 앱 기본은 안내문 + 세션 시작 때 한 번 고정한 이름·한 줄 설명 인덱스(상한 50개·설명 120자·전체 4,000자), 본문과 부속 파일은 도구로 단계적 조회. 포기/얻음/아직 없음을 맞춘다(포기: 세션 중 새 스킬이 인덱스에 즉시 반영되는 편의 — 도구는 실시간 / 얻음: 모델이 스킬의 존재를 첫 호출부터 알고, 헤드는 세션 내내 불변 / 아직 없음: 스킬 설명 속 자연어 지시를 기계적으로 거르는 장치).
3. **2부 Q11**: 제목을 현재 사실에 맞게 고치고(「…모든 스킬을 처음부터 지시문에 넣지 않고…」는 인덱스가 생겼으므로 「본문은 넣지 않고 이름·설명 인덱스만 한 번 고정하고 나머지는 점진 공개」 취지로), 1단계 설명의 「스킬 이름 목록조차 지시문에 넣지 않으므로 …캐시 100% 유지」를 정정한다. 인덱스가 **라이브러리 기본은 꺼짐·앱 기본은 켜짐**임, 세션 시작 때 한 번 고정되고 세션 중 추가된 스킬은 인덱스에 안 나오되 `skills_list` 도구는 실시간임, 설명이 지시문에 실리는 새 경로이며 정제(줄바꿈·제어문자·`<>` 제거, 3중 상한)는 구조만 지키고 자연어 지시는 못 거른다는 「솔직한 한계」를 쓴다. 인덱스가 실제 모델의 스킬 호출을 늘리는지는 **미확인**(050 이전)임을 적는다. 「근거」 줄에 새 5부 ② 항목 번호를 추가한다.
4. **3부 소프트웨어 방어선 10번 「스킬 점진 공개 격벽」** 서술과 도해 라벨: 「스킬 목록을 지시문에 넣지 않고 안내문만」을 인덱스 사실에 맞게 정정한다(본문은 여전히 도구로만, 인덱스는 정제·상한·세션 1회 고정, 자식에는 미주입).
5. **5부 ① 안전 대조표**: 「스킬 목록 조회」 행의 「지시문 미포함으로 프롬프트 캐시 보존」을 정정하고, 새 행 **「스킬 인덱스 주입」**을 추가한다 — 위험(설명 텍스트를 통한 지시문 구조 위조, 지시문 비대화, 세션 중 지시문 변동), 보장(정제·3중 상한·세션 1회 고정·라이브러리 기본 꺼짐과 `--no-skills-index`·자식 미주입), 아직 못 막는 것(설명 속 자연어 지시), 근거 번호.
6. **5부 ② 코드 정본 색인**: 항목 15(스킬 시스템)의 `SKILLS_GUIDANCE` 설명을 현재 코드에 맞게 손보고, 새 **항목 17 「스킬 인덱스 주입」**을 추가한다(위 1의 심볼과 파일 링크).
7. **5부 ③ 검증 범위와 「미확인」**: 검증 방법 문단에 로드맵 08 시점 코드를 읽었음을 더하고 (h) 항목(스킬 인덱스 E2E: 인덱스 포함 프롬프트로 도구 순환, 세션 중 고정, 압축 뒤 헤드 바이트 동일, 설명 위조 방어, 상한 초과, 자식 미주입, 켜지 않은 구성과 스킬 없는 구성의 불변, Zero Leakage)을 추가한다. 「지금은 없다」 목록에 「스킬 설명 속 자연어 지시 필터링」「세션 중 스킬 인덱스 갱신」을 더한다. 4축 표의 15행을 갱신하고 **17행 「스킬 인덱스 주입」**을 추가한다(미확인: 실제 모델이 인덱스를 보고 스킬을 더 부르는지, 스킬이 매우 많을 때 첫 조립의 지연).
8. [작동원리/README.md](../../../작동원리/README.md) 대시보드에 기준 커밋이나 개수를 적는 곳이 있으면 맞춘다(**테스트 개수는 적지 않는다** — 작동원리 README 규칙).
9. 작동원리 01편에 계획·제안·미래형 문장을 넣지 않는다(예: 「050에서 확인할 예정」 금지. 확인하지 못한 것은 「미확인」).

## 4. 검증 기준 (Done 조건)

1. 시나리오 1~8이 통과한다 (`test_agent_e2e.py`의 `test_r08_040_*`).
2. 기존 테스트가 모두 통과한다 (기준선 + 신규). `git diff <단계 시작 커밋>..HEAD -- tests/`에서 **삭제된 줄이 0**이다.
3. `git diff <단계 시작 커밋>..HEAD -- src/`가 **0줄**이다.
4. 작동원리 01편: 머리 기준 커밋이 `git log -1 --format=%h -- src`와 같다. 「다시 확인하는 법」 13번 묶음의 모든 `grep`이 결과를 낸다. 스킬 관련 서술(1부 표, Q11, 3부 10번, 5부 ①②③)에 「스킬 목록을 지시문에 넣지 않는다」 같은 낡은 서술이 남아 있지 않다(`grep -n "목록" docs/작동원리/01-*.md`로 점검). 계획·미래형 문장이 새로 들어가지 않았다.
5. 작동원리 01편의 새 서술이 4축(동작·순서·소유자·시점)으로 코드와 대조되었고, 확인하지 못한 것은 「미확인」이다.

## 5. 위험·주의

- **E2E가 아닌 기대 고정**: 시나리오 1·5·6의 기대 문자열은 모두 리터럴이다. 구현의 렌더링·정제 함수를 호출해 기대값을 만들지 않는다. 문구가 바뀌면 시험이 깨지는 것이 의도이다(030).
- **모델 행동은 시험하지 않는다**: 시나리오 1의 「`skills_list` 없이 `skill_view`로 바로」는 **가짜 대본**이 그렇게 응답한 것일 뿐이며, 실제 모델이 인덱스를 보고 그렇게 한다는 증거가 아니다. 그 관찰은 050이다. 작동원리에도 「실제 모델이 늘어난다」고 쓰지 않는다.
- **세션 고정의 경계**: 시나리오 3은 「인덱스는 첫 조립 때 한 번」을 검증한다. 에이전트는 첫 `run_conversation`에서 조립하므로 시험은 첫 턴 이후에 스킬을 추가해야 한다.
- **압축 시나리오의 크기**: 시나리오 4는 06의 7번 시험 구성(대용량 스킬 본문)을 따른다. 이 시험이 느려지면(기존 시험 수준을 넘으면) 보고한다.
- **작동원리는 결정 문서**: 사실과 다르면 즉시 최신 상태로 고친다. 낡은 서술을 남기고 새 서술을 덧붙이지 않는다(과거는 Git 이력으로).
- **이 단계의 범위 밖**: `src/` 변경, 실제 모델 관찰(050), 문구 조정, 스킬 인덱스의 추가 기능.
