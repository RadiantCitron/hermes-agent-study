## 1. 구현 내용 명세

020까지는 어느 앱 경로도 인덱스를 켜지 않는다. 이 단계는 **실제 앱 진입점(`cli.py`)이 기본으로 인덱스를 켜고, 플래그로 끌 수 있게** 한다. 위임(`--delegate`)과 달리 기본이 **켜짐**이다: 이 로드맵의 목적이 앱 사용자가 모델에게 스킬의 존재를 알려 주는 것이기 때문이다. 켠 상태에서도 스킬 폴더가 없거나 비어 있으면 프롬프트는 이전과 바이트 동일하다(020 시나리오 7·8).

1. **플래그** ([`cli.py`](../../../../src/hermes_core/cli.py)): `parser.add_argument("--no-skills-index", action="store_true", help="Disable the skills index in the system prompt (skills stay available via the skills_list/skill_view tools)")`.
2. **에이전트 생성에 전달**: 기존 `HermesAgent(model=..., llm_client=..., context_window_tokens=...)` 호출에 `skills_index=not args.no_skills_index`를 더한다. **모의 모드와 실제 모드 모두 같다**(모드마다 프롬프트가 갈라지는 분기를 만들지 않는다). `--delegate`와 함께 써도 충돌하지 않는다.
3. **배너 안내**: `args.no_skills_index`일 때만 시작 안내에 정확히 한 줄 `Skills index disabled (--no-skills-index).`을 출력한다(`Delegation enabled` 줄 근처, 모드와 무관). 기본(켜짐)에서는 아무것도 출력하지 않는다(스킬이 없을 수도 있어 「켜졌다」는 안내가 오해를 부르고, 매 실행의 소음이 된다).
4. **위임 자식**: `register_delegate_tool` 호출과 `delegate_tool.py`는 바꾸지 않는다. 자식은 `skills_index` 기본값(False)이라 인덱스가 없다.
5. **작동원리 갱신**: 없음 (040에서 일괄 반영).
6. **ROADMAP·ADR 정정**: 없음. 이 지시서 작성 때 ADR-0008 §2-5(`b4427a8`)와 ROADMAP §3·대시보드를 맞췄다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: [`test_cli_delegate.py`](../../../../tests/test_hermes_core/test_cli_delegate.py)와 같은 방식으로 `cli.OpenRouterClient`를 대본형 가짜로 바꾸고, `sys.argv`·`sys.stdin`을 지정해 `cli.main()`을 돌린다. 가짜 클라이언트는 **이 시험 파일 안에 작게 직접 정의한다**(다른 시험 모듈에서 import하지 않는다). 모의 모드 시험은 `sys.stdin`을 비터미널 가짜 입력으로 두어 자동 1턴 경로를 탄다. `HERMES_HOME`은 `tmp_path`로 격리하고, 키는 가짜 문자열을 `OPENROUTER_API_KEY`로 둔다. **기대 문자열은 리터럴로 직접 적는다**(020의 시험 상수나 렌더링 함수를 재사용하지 않는다).

공통 준비: `<HERMES_HOME>/skills/` 아래에 `release/SKILL.md`(머리말 `name: release-procedure`, `description: Team release procedure`)와 `deploy/SKILL.md`(`name: deploy-guide`, `description: Deploy steps`)를 만든다. `BLOCK`은 정확히 `"<available_skills>\n- deploy-guide: Deploy steps\n- release-procedure: Team release procedure\n</available_skills>"`.

| 1 | 실제 모드, 인자 없음, 스킬 2개, 입력 `hi` → `exit` | 클라이언트 첫 호출의 system 메시지(`call_history[0]["messages"][0]["content"]`)에 `BLOCK`이 정확히 1번 있고, 표준 출력에 `Skills index`가 **없다** |

## 5. 위험·주의

- **기본 켜짐의 파급**: 이 단계 이후 앱의 모든 실행은 스킬 폴더에 `SKILL.md`가 있으면 시스템 지시문이 달라진다. 스킬 폴더가 없거나 비어 있으면 달라지지 않으므로(020), 기존 시험과 스킬을 쓰지 않는 사용자는 영향이 없다. 영향이 있다고 느끼면 `--no-skills-index`로 끈다.
- **모의 모드에서도 켜는 이유**: 모의 모드는 오프라인 시연이며 실제 모드와 같은 에이전트 구성을 쓰는 편이 모드마다 다른 분기를 피한다. 모의 모드가 사용자의 실제 `~/.hermes/skills`를 읽는지는 `HERMES_HOME` 설정에 달려 있다(시험은 `tmp_path`로 격리). 읽기 전용이라 파일은 바뀌지 않는다(020 시나리오 12).
- **배너를 켜짐 때 출력하지 않는 이유**: 켜졌어도 스킬이 없으면 인덱스가 없어서 「켜졌다」는 안내가 사실과 어긋날 수 있다. 실제로 인덱스가 실렸는지는 세션 시스템 프롬프트(상태 DB)로 확인한다. 050 스모크는 이 방법을 쓴다.
- **끄는 스위치의 용도**: 050에서 같은 모델로 켠 경우와 끈 경우를 비교할 수 있게 한다(예: deepseek이 인덱스 없이는 스킬을 부르지 않았다는 06의 관찰을 같은 날, 같은 자료로 재확인).
- **대본형 가짜 클라이언트 정의 위치**: 다른 시험 모듈에서 import하면 그 모듈의 변경이 이 시험을 깨뜨린다. 이 파일 안에 필요한 만큼만 정의한다.
- **이 단계의 범위 밖**: 제목과 규칙 문장(030), E2E·작동원리(040), 실제 모델 관찰(050), 자식에게 인덱스 주기.
