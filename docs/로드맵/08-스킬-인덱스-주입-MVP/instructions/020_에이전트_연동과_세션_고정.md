## 1. 구현 내용 명세

이 단계는 010의 `render_skills_index`를 **에이전트의 시스템 프롬프트 조립에 연결**한다. 기본값은 **꺼짐**이라, 켜지 않은 모든 구성(기존 시험, 자식, 라이브러리 사용)은 이 단계 후에도 한 글자도 바뀌지 않는다. 실제 앱에서 켜는 일은 025다. 제목과 규칙 문장은 030이다(이 단계의 블록은 010이 만든 `<available_skills>…</available_skills>` 그대로다).

1. **`build_system_prompt` 선택 인자** ([`prompt_builder.py`](../../../../src/hermes_core/agent/prompt_builder.py)): 매개변수 목록의 **맨 끝**(`start_time` 뒤)에 `skills_index_block: Optional[str] = None`을 더한다. 값이 비어 있지 않으면 `.strip()`한 문자열을 **도구 안내문 바로 뒤, 호출자 지시(`caller_prompt`) 앞**에 하나의 조각으로 넣는다. `None`이거나 공백뿐이면 아무것도 넣지 않아 출력이 이전과 바이트 단위로 같다. 독스트링의 「계층 조립 순서」 목록에 이 조각을 도구 안내문 다음 항목으로 넣고 번호를 다시 매긴다.
2. **`HermesAgent` 키워드 인자** ([`agent.py`](../../../../src/hermes_core/agent/agent.py)): 생성자 매개변수 맨 끝(`skip_context_files` 뒤)에 `skills_index: bool = False`를 더하고 `self.skills_index`에 보관한다. 또 `self._skills_index_block: Optional[str] = None`(아직 계산하지 않음)을 둔다.
3. **인덱스 계산 `_resolve_skills_index_block(tool_names) -> str`** (같은 클래스의 비공개 메서드):
   - `self.skills_index`가 거짓이거나, `tool_names`에 `skills_list`와 `skill_view`가 **모두** 없으면 `""`을 돌려준다(`select_tools_guidance`가 스킬 안내문을 고르는 규칙과 같다). 이 경우 계산·보관을 하지 않는다.
   - 그렇지 않고 `self._skills_index_block`이 `None`이면 `render_skills_index(discover_skills(get_skills_dir()))`를 계산해 보관한다. 이미 보관돼 있으면 **다시 계산하지 않고** 보관된 값을 돌려준다. 즉 에이전트당 한 번만 스킬 폴더를 읽는다(세션 중 고정, D-02).
   - 새로 필요한 import는 `render_skills_index`(prompt_builder), `discover_skills`(`hermes_core.tools.skills_tool`), `get_skills_dir`(`constants`)뿐이다. 스킬 폴더는 만들지 않는다(`discover_skills`가 읽기 전용).
4. **`_build_system_prompt` 연결**: 기존처럼 `tool_names`를 구한 뒤 `block = self._resolve_skills_index_block(tool_names)`를 부르고, `build_system_prompt(..., skills_index_block=block or None)`로 넘긴다. 캐시 구조(`_cached_system_prompt`, `update_system_prompt`)는 그대로다. 나머지 흐름은 바꾸지 않는다.
5. **작동원리 갱신**: 없음 (040에서 일괄 반영).
6. **ROADMAP·ADR 정정**: 없음. 이 지시서 작성 때 `ADR-0008` §2-5를 「기본 꺼짐」으로 개정하고 ROADMAP·WHY·대시보드를 맞췄다(각각 `ad11d28`, `R08-PLAN` 커밋).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: `HermesAgent`를 모의 클라이언트로 직접 만든다. 네트워크 없음. **기대 문자열은 시험 안에 리터럴로 직접 적는다**(010의 정제·렌더링 함수나 상수를 import해서 기대값을 만들지 않는다 — 동어반복 방지). 시험 파일은 06 시험(`test_skills_guidance.py`)처럼 `HERMES_HOME`과 작업 폴더를 `tmp_path`로 격리한다. **시각은 고정한다**: 프롬프트 끝의 `Conversation started: …`가 분 단위라 두 에이전트의 프롬프트를 비교할 때 분 경계에서 흔들릴 수 있으므로, `hermes_core.agent.prompt_builder.datetime`을 `now()`가 고정값을 돌려주는 대체물로 `monkeypatch`한다.

공통 준비: 스킬 폴더 `<HERMES_HOME>/skills/` 아래에 `release/SKILL.md`(머리말 `name: release-procedure`, `description: Team release procedure`)와 `deploy/SKILL.md`(`name: deploy-guide`, `description: Deploy steps`)를 만든다. 아래에서 `BLOCK`은 정확히 다음 문자열이다.

2. 기존 테스트가 모두 통과한다 (기준선 + 신규). `git diff <단계 시작 커밋>..HEAD -- tests/`에서 **삭제된 줄이 0**이다.

## 5. 위험·주의

- **기존 시험과의 충돌**: `test_scenario_05_skills_list_not_injected_into_prompt`는 스킬이 있어도 프롬프트에 스킬 이름이 없다고 단언한다(ADR-0006의 구 결정). 기본을 꺼짐으로 둔 이유이며, 시나리오 2·13이 이를 지킨다. 이 시험의 이름과 기대는 바꾸지 않는다. 기본 켜짐으로 바꾸고 싶다면 그 시험을 고쳐 써야 하므로 별도 결정이 필요하다 (ADR-0008 §2-5).
- **「세션 시작」의 의미**: 에이전트는 시스템 프롬프트를 생성자가 아니라 **첫 `run_conversation`에서** 조립한다. 생성자와 첫 턴 사이에 추가된 스킬은 인덱스에 들어가고, 그 뒤에 추가된 스킬은 들어가지 않는다. 시나리오 6은 첫 조립 후의 고정을 고정한다.
- **재조립 경로**: `system_message`를 넘기면 프롬프트가 다시 조립된다. 인덱스를 매번 다시 계산하면 세션 중 스킬 변화가 새어 들어온다. 그래서 블록을 에이전트당 한 번 보관한다(시나리오 6). 구현이 보관 없이 매번 계산하면 6이 실패한다.
- **시각 고정**: 프롬프트 비교 시험(2·7·8·9)은 시각을 고정하지 않으면 분 경계에서 드물게 실패한다. 고정 없이 쓰지 않는다.
- **스킬이 많을 때의 비용**: 켠 에이전트는 첫 조립 때 모든 `SKILL.md`를 한 번 읽는다(`discover_skills`). 스킬 수가 많을 때 세션 시작 지연은 **미확인**이다.
- **비용은 헤드에 상주한다**: 인덱스는 모든 호출에 실린다(최대 4,000자). 압축·캐시 쪽 영향은 시나리오 10과 040의 E2E로 확인한다.
- **이 단계의 범위 밖**: 앱(`cli.py`)에서 켜기(025), 제목과 규칙 문장(030), E2E·작동원리(040), 실제 모델 관찰(050).
