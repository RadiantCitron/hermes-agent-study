## 1. 구현 내용 명세

이 단계는 **글을 만드는 부분만** 만든다. 에이전트에 붙이지 않는다(020). 시스템 프롬프트는 이 단계 후에도 한 글자도 바뀌지 않는다.

1. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py), 스킬 상수 묶음 아래): `SKILLS_INDEX_MAX_ENTRIES = 50`, `SKILLS_INDEX_DESC_MAX_CHARS = 120`, `SKILLS_INDEX_MAX_CHARS = 4_000`.
2. **`render_skills_index(skills, max_entries=SKILLS_INDEX_MAX_ENTRIES, desc_max_chars=SKILLS_INDEX_DESC_MAX_CHARS, max_chars=SKILLS_INDEX_MAX_CHARS) -> str`** ([`prompt_builder.py`](../../../../src/hermes_core/agent/prompt_builder.py), 정적 상수와 `build_system_prompt` 사이의 함수 구역). **순수 함수**다: 디스크·환경·시계에 접근하지 않고, 입력을 바꾸지 않는다. `tools/`를 import하지 않는다(의존 방향 유지). 입력은 `discover_skills`가 돌려주는 사전 목록(`name`, `description`, `category`, `path` 키)이며, 이 함수는 `name`과 `description`만 읽는다.
3. **항목 정제** (한 곳에 모은다. 규칙을 다른 곳에 흩뿌리지 않는다):
   1. 사전이 아닌 항목, `name`이 문자열이 아니거나 정제 뒤 비는 항목은 **건너뛴다**(예외 없음). 건너뛴 항목은 「나머지(more)」 수에 세지 않는다.
   2. `name`·`description`은 문자열이 아니면 빈 문자열로 본다(`description`만 해당. `name`은 위 1).
   3. 문자열마다 순서대로: ① `<`·`>` 제거 → ② 공백 문자(`str.isspace()`)와 유니코드 범주 `C*`(제어·서식·사용자 지정·미할당, 예: `\x00`, 제로폭 공백 `\u200b`)를 공백 하나로 바꿈 → ③ 연속 공백을 하나로 접고 앞뒤 공백 제거.
   4. `description`이 정제 뒤 `desc_max_chars`를 넘으면 `desc[: desc_max_chars - 3].rstrip() + "..."`로 자른다. `name`은 자르지 않는다(발견 단계 `discover_skills`가 이미 64자로 제한한다. 이 함수에 직접 긴 이름이 들어오면 아래 5의 전체 상한이 막는다).
   5. 줄은 `- {name}: {desc}`, 설명이 비면 `- {name}`.
4. **블록 조립과 상한**:
   - 블록은 `<available_skills>` 줄, 항목 줄들, (잘린 것이 있으면) 초과 안내 줄, `</available_skills>` 줄을 `\n`으로 이은 문자열이다. 끝에 `\n`을 붙이지 않는다. 초과 안내 줄은 정확히 `(+{N} more; use skills_list to see all)`이고 `N`은 유효한 항목 수에서 실린 수를 뺀 값이다.
   - 입력 순서를 유지한다(정렬하지 않는다. 정렬은 `discover_skills`가 이미 결정적으로 한다).
   - 유효 항목 수를 `total`, 후보 개수를 `k`라 하자. **`k = min(total, max_entries)`부터 1까지 내려오며** `k`개 항목 + `N = total - k`로 블록을 만들어 `len(블록) <= max_chars`인 **첫 블록**을 반환한다. 하나도 들어맞지 않으면(또는 `total == 0`이면) 빈 문자열 `""`을 반환한다. (초과 안내 줄이 붙으면 후보가 더 길어질 수 있으므로 앞에서부터 채우다 멈추는 방식은 쓰지 않는다 — 일부 입력에서 전부 들어가는데도 잘리게 된다.)
   - 반환값은 `""`이거나 `len <= max_chars`인 완전한 블록이다(둘 중 하나). 호출부(020)는 `""`이면 블록을 만들지 않는다.
5. **인자 검증**: `max_entries < 1`, `desc_max_chars < 4`, `max_chars < 1`이면 `ValueError`(이름에 잘못된 값이 조용히 지나가지 않게 한다).
6. **작동원리 갱신**: 없음 (040에서 일괄 반영).
7. **ROADMAP 정정**: [ROADMAP.md](../ROADMAP.md) §6-1에 상한 판정 방식(큰 개수부터 내려오기)과 「하나도 못 넣으면 빈 문자열」을 반영했다(이 지시서 작성 때 `R08-PLAN` 커밋).

## 5. 위험·주의

- **기대값 동어반복**: 시나리오의 기대 문자열은 모두 리터럴이다. 구현의 정제 코드를 시험에서 재사용하지 않는다. 길이 경계(12~15)는 `H`·`T`·초과 안내 줄 길이를 구현과 무관한 문자열 산술로 센 값(91·100·88·86·81)이다. 후보 길이는 개수 `k`에 대해 단조 증가하지 않는다(초과 안내가 사라지는 마지막 후보가 가장 짧을 수 있다).
- **초과 안내가 후보를 길게 만든다**: 시나리오 13·14가 이 경계를 고정한다. 구현이 「앞에서부터 채우다 멈추기」로 되어 있으면 13이 실패한다.
- **정제의 한계**: 이 함수는 구조(줄바꿈·태그 위조·길이)만 지킨다. 설명 속 자연어 지시는 막지 못한다 ([ADR-0008](../../../adr/0008-스킬_인덱스_주입_범위와_신뢰_경계.md) §2-4의 알려진 한계). 시험도 이를 막는다고 단언하지 않는다.
- **`name`을 자르지 않는 이유**: 발견 단계가 이미 64자로 제한한다. 이 함수에서 또 자르면 `skill_view`에 넘길 이름이 달라질 수 있어 자르지 않는다. 다만 정제(`<`·`>` 제거, 제어문자·연속 공백 접기)는 이름에도 적용되므로, 그런 문자가 든 이름은 인덱스에 보이는 이름과 도구가 받는 이름이 다를 수 있다(드문 경우이며 `skill_view`가 실패하면 `available_skills`를 돌려줘 모델이 복구할 수 있다). 긴 이름이 직접 들어오면 전체 상한이 막는다.
- **값의 확정**: 50·120·4,000은 에이전트가 정한 안이다. 이 지시서 착수(「진행해라」)를 승인으로 갈음하며, 바꾸고 싶으면 착수 전에 알린다.
- **이 단계의 범위 밖**: 에이전트·`build_system_prompt` 연동(기본 꺼짐 인자 `skills_index`)은 020, 앱(CLI)에서 켜기는 025, 제목과 규칙 문장은 030이다. 이 단계에서 시스템 프롬프트는 바뀌지 않는다.
