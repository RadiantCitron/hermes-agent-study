1. **[목표 1 — 도구 계층 의존성 역전(R7) 및 캡슐화]**: [`tools/ports.py`](../../../src/hermes_core/tools/ports.py)에 역할별 5종 프로토콜(`SessionCounterPort`, `SessionSearcherPort`, `SessionLedgerPort`, `MemoryStorePort`, `ChildRunnerPort`)을 정의하여 `tools/*` 모듈들이 구체 클래스 [`SessionDB`](../../../src/hermes_core/session_db.py)와 비공개 `_conn`에 직접 결합하지 않도록 격리.
2. **[목표 2 — 위임 도구 역방향 의존 해소 및 아키텍처 부채 0건 달성]**: [`delegate_tool.py`](../../../src/hermes_core/tools/delegate_tool.py)의 `HermesAgent`·`build_child_system_message` 직접 참조를 [`assembly.py`](../../../src/hermes_core/assembly.py)의 자식 실행기(`ChildRunnerPort`) 주입으로 역전시켜 울타리 예외 목록인 `KNOWN_DEBT` 4건을 0건(`{}`)으로 완전 청산하고, 자식 세션 생명주기 마감 안전망(`try...finally`, R-2) 확립.

### 1-4. 실제 모델 스모크를 하지 않는 이유

20번 로드맵은 도구 계층의 프로토콜 기반 의존성 역전, 위임 도구 역방향 결합 해소(`KNOWN_DEBT = {}`), 체크포인트 순수 도메인 분리, 런타임 취소 및 턴 경계의 원장-메모리 동기화 무결성 확보, 아키텍처 불변식 영구 잠금을 달성하는 내부 구조 정비다.  
[ROADMAP.md §5](ROADMAP.md)에 명시된 바와 같이 검증은 1층위(외부 의존성 및 유료 모델 호출 없는 완전 자동 시험)로 완벽하게 설계되었다. 모의 객체, `MockTransport`, 가상 터미널(`pty`)을 통해 LLM 호출 흐름과 도구 실행 간섭이 전혀 없음을 증명하였으므로, 실제 과금 토큰을 소모하는 모델 호출 스모크는 수행하지 않는다.

- **Why**: 도구 계층 모듈들이 데이터베이스 본체(`SessionDB`)와 비공개 내부 연결선(`_conn`)을 직접 다루고 있어, 도구 계층이 영속성 인프라의 구체 구현에 강결합되어 있었고 테스트 대역(Mock) 작성이 어려웠다.
- **What**:

  - `checkpoint.py`의 `_conn.execute` 3곳을 `count_child_sessions` 호출로 교체하고, `checkpoint.py`, `delegate_tool.py`, `session_search_tool.py`, `context_compressor.py`, `dispatcher.py` 5개 파일의 `SessionDB` import를 포트로 교체.

## 4. 아키텍처 성과와 작동원리 반영 목록

### 4-1. 영구적인 아키텍처 성과
1. **도구 계층 의존성 역전(DIP, R7) 및 포트 5종 확립**:
   - 도구 계층 모듈들이 비대한 `SessionDB` 대신 자신의 관심사에 맞는 좁은 프로토콜(`SessionCounterPort`, `SessionSearcherPort`, `SessionLedgerPort`, `MemoryStorePort`, `ChildRunnerPort`)만을 바라보도록 격리함.
   - 비공개 SQLite 연결선(`_conn`)의 외부 접근을 완전히 차단하고 `SessionDB.count_child_sessions` 정식 질의 API로 캡슐화함.
2. **`KNOWN_DEBT` 4건의 완전 청산(부채 0건) 및 자식 세션 생명주기 안전망(R-2)**:
   - 위임 도구의 상위 에이전트 역방향 결합을 조립 계층(`assembly.py`)의 자식 실행기 주입으로 해소하여, 레포 개설 이래 지속되던 아키텍처 예외 부채를 영구히 0건으로 청산함.
   - 자식 에이전트 실행 도중 어떤 예외가 발생하더라도 `try...finally`로 감싸 `session_db.end_session`이 무조건 실행되도록 보장함.
3. **체크포인트 순수 도메인 분리(R-4)**:
   - 909줄 비대 모듈이었던 `checkpoint.py`에서 I/O가 전혀 없는 순수 비즈니스 로직(판정, 분류, 렌더링)을 `checkpoint_domain.py`로 분리하여 단위 시험성을 극대화하고, 기존 `time.time` 패치 호환성 및 실행 순서 계약을 완벽히 유지함.
4. **런타임 취소 시 원장-메모리 Split-Brain 차단(R-1) 및 턴 경계 Fail-Safe(R-3)**:
   - 턴 도중 컨텍스트 압축 직후 `KeyboardInterrupt` 취소가 발생하더라도, 원장 정리 후 `agent.load_conversation_history()`로 대화 목록을 재동기화하여 메모리와 원장의 상태 불일치를 원천 차단함.
   - 턴 시작 경계에서 `apply_pending()`이나 `get_last_active_message_id()` 실패가 발생해도 대화창 전체가 꺼지지 않고 경고 로그 후 안전하게 지속되도록 Fail-Safe 보호막을 구축함.
5. **아키텍처 불변식 3대 잠금 자동화**:
   - `KNOWN_DEBT == {}` 영구 0건, `session_db.py` 외 `_conn` 접근 0건, 순수 도메인 모듈 4종의 인프라 무의존성을 AST 기반 단위 시험으로 영구 고정하여 미래의 회귀를 원천 방지함.

## 6. 새로 발견한 부분

1. **`time.time` 패치 호환성을 유지하는 순수 함수 분리 기법**:
   - `checkpoint.py`를 테스트하는 기존 시험들이 `unittest.mock.patch("hermes_core.tools.checkpoint.time.time")` 방식을 사용하고 있어, 순수 도메인 모듈로 단순 이전 시 모듈 격리 파괴 또는 패치 무효화의 딜레마가 발생할 수 있음을 발견.
   - 이를 해결하기 위해 I/O 조정자(`checkpoint.py`)가 자신의 네임스페이스에서 `time.time()`을 평가한 뒤 순수 도메인 함수에 `current_time` 인자로 명시 전달하는 구조를 채택함. 순수 도메인은 시간조차 외부에서 주입받는 완전한 결정론적 순수 함수가 되고, 기존 패치 테스트도 100% 무수정 통과함을 실증함.
2. **원장 기반 재동기화가 Split-Brain을 완벽히 해결하는 유일한 해법**:
   - 턴 취소 시 메모리 안의 대화 목록을 자의적으로 깎아내거나 조작하려 하면, 그 턴 안에서 요약(압축)이 일어났는지 여부에 따라 복잡한 상태 분기가 발생하여 실패하기 쉬움을 발견.
   - 영구 원장(DB)에서 `load_conversation_history()`로 활성 대화를 그대로 다시 읽어오는 방식이, 턴 도중 압축 발생 여부나 취소 시점과 무관하게 메모리와 원장의 상태를 100% 일치시키는 가장 확실한 단일 진실 공급원임을 입증함.
3. **`typing.Protocol` 기반 포트 분리의 테스트 격리 극대화**:
   - `tools/ports.py`를 통해 인터페이스를 좁게 격리하자, 테스트 코드에서 무거운 SQLite 인스턴스를 띄우지 않고도 메모리 딕셔너리 기반의 단순 테스트 대역(`FakeStore`)만으로 도구의 모든 동작을 1ms 미만의 초고속 단위 시험으로 검증할 수 있음을 확인함.

## 9. 사실 검증 4축(동작·순서·소유자·시점) 결과와 「미확인」 해소 보고

### 9-1. 사실 검증 4축 매트릭스
- **동작 (Action)**:
  - 포트 기반 도구 통신(`ports.py`), 자식 세션 생성 및 `try...finally` 마감(`delegate_tool.py`), 순수 도메인 모델 평가 및 알림 렌더링(`checkpoint_domain.py`), 턴 취소 시 원장 재동기화(`load_conversation_history`), 턴 경계 Fail-Safe(`apply_pending`).
- **순서 (Sequence)**:
  - 1. CLI 사용자 입력 접수
  - 2. 턴 시작 경계 Fail-Safe: `apply_pending()` 설정 일괄 반영 및 `get_last_active_message_id()` 번호 획득
  - 3. `agent.run_conversation()` 진입
  - 4. (필요 시 턴 도중 컨텍스트 압축 발생 및 요약 메시지 DB 저장)
  - 5. 도중 취소 발생 (`KeyboardInterrupt`)
  - 6. 원장 롤백: `deactivate_messages_after(last_active_message_id)`
  - 7. 원장-메모리 재동기화: `history = agent.load_conversation_history()` (Split-Brain 원천 차단)
  - 8. 다음 사용자 입력 대기 (일관된 상태 유지)
- **소유자 (Owner)**:
  - 도구 계약 포트: [`tools/ports.py`](../../../src/hermes_core/tools/ports.py)
  - 순수 비즈니스 규칙: [`tools/checkpoint_domain.py`](../../../src/hermes_core/tools/checkpoint_domain.py)
  - 자식 에이전트 조립 및 실행 책임: [`assembly.py`](../../../src/hermes_core/assembly.py)
  - 세션 영구 원장 및 FTS 질의: [`session_db.py`](../../../src/hermes_core/session_db.py)
  - 취소 복구 및 터미널 뷰: [`cli.py`](../../../src/hermes_core/cli.py)
- **시점 (Timing)**:
  - `startup`: 기동 시 조립 계층에서 포트 주입 및 위임 도구 단일 배선
  - `runtime`: 턴 루프 실행, 턴 도중 취소 시 원장 기반 즉시 재동기화
  - `teardown`: 자식 에이전트 종료 시 `finally` 블록에서 영구 세션 마감

### 9-2. WHY §6 「미확인」 항목 3건 전수 해소 보고
1. **[심부름 도구 기존 시험의 에이전트 패치 여부]**:
   - `test_extension_e2e.py`가 모듈 속성 `create_child_dispatcher`를 직접 패치하고 있음을 실측 확인.
   - `delegate_task`에서 모듈 속성 함수를 호출해 디스패처를 먼저 생성한 뒤 러너에 주입하도록 조치하여, 기존 시험을 단 한 줄도 수정하지 않고 100% 무수정 통과시킴 (해소 완료).
2. **[첫 턴 취소 시 `load_conversation_history()` 동작]**:
   - 세션이 시작된 직후 첫 번째 턴에서 대화가 끝나기 전에 `Ctrl+C`로 취소할 경우, 원장에 `active=1`인 메시지가 존재하지 않아 `load_conversation_history()`가 `None`을 반환함을 확인.
   - `history = agent.load_conversation_history()`를 수행하면 `history`가 정확히 `None`(대화 없음 초기 상태)으로 설정되어, 기존 CLI의 초기값 기대와 완벽하게 일치함을 검증 완료 (해소 완료).
3. **[체크포인트 내부 함수 기존 시험 import 여부]**:
   - 기존 시험(`test_checkpoint_ledger.py`) 및 외부 모듈에서 `checkpoint.py`의 심볼들을 직접 import하는지 전수 점검.
   - `checkpoint.py` 상단에서 `checkpoint_domain.py`의 모든 심볼(데이터클래스, 판정 함수, 렌더러)을 그대로 재수출하도록 구성하여 기존 시험들과의 100% 하위 호환성을 완벽히 보존함 (해소 완료).
