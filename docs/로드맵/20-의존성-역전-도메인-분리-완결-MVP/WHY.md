# [WHY] 20-의존성-역전-도메인-분리-완결-MVP — 왜 이 정도로만 하는가

> 사람의 말로, 코드 용어 없이 적는다([ROADMAP_정책 §3-2](../ROADMAP_정책.md)). 마감 때 종합보고서가 이 문서의 가정을 하나씩 대조한다.
> 근거: [ADR-0020](../../adr/0020-의존성_역전_도메인_분리_완결_MVP_범위와_결정.md), [PLAN.md](PLAN.md)

## 1. 왜 지금 이 로드맵인가

- 18번과 19번에서 프로그램의 한가운데(대화를 되풀이하는 심장부)와 제어판은 바깥의 구체적인 부품들을 직접 알지 못하게 울타리를 쳤다.
- 그러나 나머지 부분에는 아직 네 가지 구조적 빚과 실행 중 위험이 남아 있다:
  1. **아랫사람이 윗사람을 직접 불러 만드는 역방향 참조**: 일을 나눠 맡는 심부름 도구(하위 에이전트 위임)가 에이전트 전체 본체를 직접 끌어다 만들고 있다. 울타리 검사표에 「나중에 갚을 빚」 네 줄로 남아 있던 유일한 예외다. 심부름 도구가 도중 실패했을 때 열린 작업 기록을 끝까지 닫아 주는 보장도 한곳에서 관리되지 않는다.
  2. **도구들이 거대한 장부 전체를 통째로 들고 있는 결합**: 명령 승인기, 파일 되돌리기 기록기, 대화 검색 도구가 각자 필요한 한두 가지 일만 알면 되는데, 실제로는 데이터베이스 전체 본체를 직접 붙잡고 있다. 심지어 파일 되돌리기 기록기는 장부의 문을 거치지 않고 안쪽 데이터베이스 연결선을 직접 찔러 세어 보는 곳도 한 군데 남아 있다.
  3. **판단 규칙과 파일·장부 작업이 한 덩어리로 뭉친 900줄짜리 파일**: 파일을 되돌릴지 건너뛸지 따지는 순수한 규칙과 안내 문구 만들기, 그리고 실제로 파일을 읽고 쓰고 장부를 고치는 바닥 작업이 한 파일에 뒤섞여 있어 읽기도 어렵고 고치기도 조심스럽다.
  4. **대화 도중 내용을 줄인 직후 취소(`Ctrl+C`)했을 때 기억이 둘로 갈라지는 실행 중 위험**: 한 턴 안에서 대화가 길어져 요약본으로 줄여 장부에 적어 둔 직후 사람이 `Ctrl+C`로 그 턴을 취소하면, 장부에는 줄여 둔 요약본이 남는데 프로그램이 손에 들고 있는 대화 목록은 줄이기 전 옛날 대화를 그대로 들고 있게 된다. 그 상태로 다음 대화를 이어 가면 장부와 머릿속 기억이 서로 다른 말을 하는 위험이 있다. 또한 턴이 시작될 때 대기 중인 설정을 반영하다가 장부가 잠깐 막히면 대화창 전체가 꺼져 버릴 수 있다.
- 이번 20번 로드맵을 **구조 정비의 마지막 로드맵**으로 삼으려면, 이 네 가지 정적·동적 구조 결함을 모두 없애 「울타리 위반 빚 0건」과 「실행 중 취소·오류에도 흔들리지 않는 단일 기억」을 달성해야 한다. 구조가 깨끗하게 끝나야 이후 코드 품질을 다듬는 작업을 안심하고 할 수 있다.

## 2. 왜 이 정도로만 하는가 (비목표)

| 하지 않는 것 | 이유 | 언제 하나 |
|---|---|---|
| 옛날 부품 이름을 새 위치로 연결해 주는 호환 다리 없애기 | 이미 검증된 천 개가 넘는 시험들이 옛 이름을 부르고 있다. 호환 다리는 내용 없이 이름만 이어 주는 얇은 판이고 전용 시험이 지키고 있으므로, 지금 없애면 검증된 시험들을 대거 고쳐야 한다 | 기존 시험들의 이름을 별도 정리 작업에서 바꿀 때 |
| 고정 숫자·문구 모음 파일 쪼개기 | 여러 부품과 시험이 이 파일 하나에서 상수를 가져간다. 기능이나 구조적 안전과 무관한 파일 나누기는 불필요한 흔들림만 만든다 | 코드 품질 다듬기 단계에서 필요할 때만 |
| 파일 되돌리기 기록기를 도구 앞단 공통 통로(미들웨어)로 완전히 옮기기 | 지금 시험들은 「도구 인자가 올바른지 먼저 검사한 뒤에야 되돌리기 기록을 남긴다」는 순서를 엄격히 검증하고 있다. 앞단 공통 통로로 옮기면 인자 검사보다 먼저 실행되어 잘못된 호출에도 빈 기록이 남는다. 따라서 실행 순서는 지금 계약을 그대로 지키고, 안쪽의 판단 규칙과 바닥 작업만 분리한다 | 도구 앞단 통로에 「인자 검사 뒤」 자리를 새로 설계할 필요가 생길 때 |
| 새로운 외부 기능(웹 화면, 여러 하위 에이전트 동시 실행 등) 더하기 | 이번 로드맵의 목적은 기능을 더 넣는 것이 아니라 지금까지 만든 것들의 구조를 완결짓는 것이다 | 이 로드맵으로 코어 구조를 마감한 뒤 별도 응용 프로젝트에서 |

## 3. 왜 이 순서, 왜 이 단계 수인가

1. **도구 계층의 장부 약속 세우기(010)**: 먼저 도구들이 거대한 장부 본체 대신 각자 필요한 약속(포트)만 바라보게 만들고, 장부 안쪽 연결선을 직접 만지던 구멍을 막는다. 이 약속이 먼저 있어야 다음 단계에서 심부름 도구도 깨끗하게 고칠 수 있다.
2. **심부름 도구의 역방향 참조 끊기와 빚 0건 달성(020)**: 가장 중요한 1순위 구조 결함인 「아랫사람이 윗사람을 부르는 빚 4건」을 갚고, 자식 작업이 중간에 실패해도 반드시 작업 종료 기록이 남게 감싼다.
3. **파일 되돌리기의 순수 규칙 떼어내기(030)**: 가장 큰 파일(900줄)에서 파일·장부를 전혀 건드리지 않는 순수 판단 규칙과 알림 문구 조립을 별도 파일로 떼어내어 도메인 규칙과 바닥 구현을 가른다.
4. **실행 중 취소·시작 경계 복구 보강과 조립 정돈(040)**: 대화 도중 요약 후 `Ctrl+C`로 취소했을 때 장부에서 대화 목록을 다시 읽어 기억이 갈라지지 않게 고치고, 턴 시작 직전 일시적 오류가 나도 대화창이 꺼지지 않게 방어하며, 명령창의 조립과 명령어 분기를 정돈한다.
5. **구조 울타리 최종 잠금 시험(050)**: 「빚 0건」「안쪽 연결선 직접 접근 0건」「순수 규칙 파일의 외부 무의존」을 자동 시험으로 영구히 못 박는다.
6. **해설서 동기화(060)**, **마감(070)**: 바뀐 구조와 실행 중 복구 원리를 해설서에 반영하고 가정을 대조해 최종 마감한다.

## 4. 왜 이 방식을 택하고 무엇을 배척했나

- **택한 것**:
  - 도구들이 장부 전체 대신 자기 역할에 필요한 작은 약속만 보게 한다.
  - 하위 에이전트를 만들고 끝까지 닫아 주는 일은 「조립하는 곳」이 맡아 심부름 도구에 건네준다.
  - 대화 도중 취소(`Ctrl+C`)가 일어나면 장부를 정리한 직후 **장부에서 대화 목록을 다시 읽어** 손에 든 기억을 장부와 하나로 맞춘다.
  - 파일 되돌리기에서 순수 규칙을 떼어내되, 밖에서 부르는 이름과 실행 순서는 그대로 유지한다.
- **배척한 것**:
  - 심부름 도구 안에서 실행할 때만 몰래 에이전트를 불러오는 눈속임: 글자 위치만 바뀔 뿐 아랫사람이 윗사람을 아는 구조적 결함은 그대로 남는다.
  - 취소됐을 때 손에 든 대화 목록을 직접 잘라내어 맞추려는 방식: 그 턴 안에서 요약이 일어났는지 아닌지를 밖에서 따로 추적해야 해서 다시 어긋나기 쉽다. 장부가 유일한 정본이므로 장부에서 다시 읽는 것이 가장 확실하다.
  - 기존 시험을 고쳐 가며 내부 모양을 크게 흔드는 방식: 시험까지 함께 고치면 구조 변경이 기존 기능을 깨뜨렸는지 알 수 없다.

## 5. 성공 판단 기준과 검증할 가정 목록

| 번호 | 가정 |
|---|---|
| **A** | 울타리 검사표에 남아 있던 예외 빚(`KNOWN_DEBT`)이 0건이 되고, 일곱 가지 방향 규칙(R1~R7)을 어기는 파일이 하나도 없다 |
| **B** | 도구 폴더 안의 어떤 파일도 구체 장부 모듈을 직접 부르지 않고, 장부 모듈 밖의 어떤 파일도 장부의 안쪽 비공개 연결선(`_conn`)을 직접 만지지 않는다 |
| **C** | 파일 되돌리기의 순수 규칙 파일은 파일 읽기·쓰기나 장부나 통신 도구를 전혀 부르지 않고 혼자서도 시험할 수 있다 |
| **D** | 한 턴 안에서 대화가 요약본으로 줄어든 뒤 `Ctrl+C`로 취소하더라도, 같은 세션의 다음 턴에서 프로그램이 들고 있는 대화 목록과 장부의 활성 대화가 똑같다 |
| **E** | 하위 에이전트 심부름 도중 어떤 오류가 나더라도 하위 에이전트의 세션 기록은 열린 채로 남지 않고 종료 사유가 기록된다 |
| **F** | 턴이 시작될 때 대기 중인 설정을 반영하거나 장부 번호를 읽다가 일시적인 오류가 나더라도 대화창 전체가 꺼지지 않고 다음 입력을 받을 수 있다 |
| **G** | 한가운데(되풀이와 약속) 파일들은 이 로드맵 동안 한 줄도 바뀌지 않는다 |
| **H** | 에이전트와 도구들을 만드는 방법(겉모습)은 바뀌지 않고, 기존 시험 1,148개는 한 줄도 고치지 않고 모든 단계에서 통과한다 |
| **I** | 한 단계 낮은 파이썬 버전(3.12)에서도 새로 만든 약속 파일과 도메인 파일을 포함해 프로그램이 정상으로 켜진다 |

## 6. 알려진 위험과 아직 확인하지 못한 것

- 심부름 도구를 시험하는 기존 시험들이 에이전트를 직접 갈아끼우는 방식(패치)을 쓰고 있는지는 **미확인**이다. 020 지시서를 쓰기 전에 시험 파일을 열어 확인한다.
- 대화 도중 취소 뒤 장부에서 대화를 다시 읽을 때, 아직 한 번도 대화가 끝나지 않은 첫 턴 취소에서 빈 값(`None`)으로 돌아오는지 기존 취소 시험들과 부딪히지 않는지는 040 지시서를 쓰기 전에 확인한다.
- 순수 규칙 파일을 떼어낼 때 기존 시험들이 되돌리기 파일에서 직접 꺼내 쓰는 내부 함수 이름이 있는지 030 지시서를 쓰기 전에 전수 확인한다.
