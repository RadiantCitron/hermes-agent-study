## 0. 착수 전 점검 (지시서 작성 시점에 완료된 사실)

`ROADMAP.md §6-4` 및 `§9`의 탐침 체크리스트를 실제 소스 코드와 테스트로 대조한 결과는 다음과 같다.

1. **`src/hermes_core/cli.py`의 정확한 줄 번호 및 변수명 확인**:
   - **위임 도구 등록 (486~493행, 515~516행)**:
     ```python
     if not args.mock and settings.delegate:
         register_delegate_tool(
             agent.dispatcher,
             session_db=agent.session_db,
             parent_session_id=agent.session_id,
             llm_client_factory=lambda: OpenRouterClient(api_key=api_key, model=model),
         )
     ```
     및
     ```python
     if not args.mock and settings.delegate:
         print("Delegation enabled (delegate_task).")
     ```
     `not args.mock and settings.delegate` 조건이 중복 확인되고 있으며, 조립 책임이 `cli.py`에 직접 노출되어 있음. 이를 `assembly.register_delegate_if_enabled(...)` 단일 진입로로 일원화(S-4)함.
   - **슬래시 명령 분기 (568~577행)**:
     `/rollback`과 `/ctl`의 파싱·호출·`pending_notices` 누적 분기가 REPL 주 루프에 직접 노출되어 있음. 이를 `_dispatch_slash_command(...)` 도우미 함수로 추출하여 REPL 가독성을 확보(S-4)함.
   - **`panel.apply_pending()` (579행)**:
     예외 처리가 없어 감사 원장 또는 설정 저장소 오류 발생 시 REPL 전체가 비정상 종료됨. 이를 `try...except Exception as e:` 경고 로그로 감싸 Fail-Safe 보호(R-3)함.
   - **`last_active_msg_id = agent.session_db.get_last_active_message_id(agent.session_id)` (589~591행)**:
     예외 처리가 없어 DB 일시 오류 시 REPL이 비정상 종료됨. 이를 `try...except`로 보호하고 예외 시 `last_active_msg_id = 0`으로 폴백(R-3)함.
   - **`KeyboardInterrupt` 취소 복구 (606~625행)**:
     취소 시 `agent.session_db.deactivate_messages_after(agent.session_id, last_active_msg_id)`만 호출하고 메모리의 `history` 변수를 갱신하지 않음.
     만약 턴 도중 `BEFORE_LLM`에서 압축(`archive_and_compact`)이 실행된 후 다음 단계에서 취소되면 DB 원장은 압축 요약본으로 교체되었으나 메모리 `history`는 이전 상태를 유지하여 메모리와 원장의 상태가 어긋나는 **Split-Brain(R-1)**이 발생함.
     취소 직후 `history = agent.load_conversation_history()`로 원장으로부터 인메모리 대화 내역을 재동기화하여 Split-Brain을 원천 차단함.

2. **`tests/test_hermes_core/test_cli_resume.py:493-519` (시나리오 R12) 호환성 확인**:
   - 취소 복구 중 `deactivate_messages_after`가 `RuntimeError("db locked")`를 던지더라도 CLI가 죽지 않고 경고 로그(`logger.warning("deactivate_messages_after failed: %s", e)`)만 남긴 채 다음 대화 프롬프트로 복귀하는 계약이 엄격히 존재함.
   - 따라서 `history = agent.load_conversation_history()`는 `deactivate_messages_after` 성공 직후에 위치시키거나, DB 실패 시 기존 `history`를 보존하도록 `try...except` 블록 내부에 안전하게 배치해야 함.

3. **`src/hermes_core/agent/agent.py:476-483` (`load_conversation_history()`) 계약 확인**:
   - `self.session_db.get_messages_as_conversation(self.session_id)`의 활성(`active=1`) 메시지가 없으면 `None`을 반환함.
   - 활성 메시지가 1개 이상이면 `[{"role": "system", "content": sys_prompt}, *active_msgs]` 리스트를 반환함.
   - 첫 번째 턴에서 `KeyboardInterrupt`로 취소된 경우 이번 턴의 메시지가 모두 비활성화되어 활성 메시지가 0개가 되므로 `history`는 정확히 `None`으로 복구됨(시나리오 2 경계값 안전 성립).

4. **`src/hermes_core/assembly.py` 의존 방향 및 포트 규약 확인**:
   - `assembly.py`는 이미 `Settings`, `ChildRunnerPort`, `run_child_session`을 보유하고 있음.
   - `register_delegate_if_enabled`를 `assembly.py`에 추가할 때 `agent.dispatcher`에 위임 도구를 바인딩하며 `child_runner=run_child_session`을 명시적으로 주입하여 020에서 확립한 의존성 역전 계약을 완벽히 보존함.

### 1.1 `src/hermes_core/assembly.py`에 `register_delegate_if_enabled` 추가 (S-4)

1. 함수 정의 및 시그니처:
   ```python
   def register_delegate_if_enabled(
       agent: Any,
       settings: Settings,
       *,
       mock: bool,
       llm_client_factory: Callable[[], Any],
   ) -> bool:
       """설정에 따라 에이전트 디스패처에 위임 도구(delegate_task)를 등록한다 (S-4).

       Args:
           agent: HermesAgent 또는 디스패처/세션DB를 보유한 에이전트 객체
           settings: 로드된 Settings 스냅샷
           mock: 오프라인 목(Mock) 실행 여부
           llm_client_factory: 자식 에이전트용 LLM 클라이언트 팩토리

       Returns:
           bool: 위임 도구가 성공적으로 등록되었으면 True, 건너뛰었으면 False
       """
       if mock or not settings.delegate:
           return False

       from hermes_core.tools.delegate_tool import register_delegate_tool

       register_delegate_tool(
           agent.dispatcher,
           session_db=agent.session_db,
           parent_session_id=agent.session_id,
           llm_client_factory=llm_client_factory,
           child_runner=run_child_session,
       )
       return True
   ```
2. 위치: `assembly.py`의 `create_child_runner()` 아래 모듈 하단에 배치.

### 1.2 `src/hermes_core/cli.py` 슬래시 라우터 `_dispatch_slash_command` 신설 (S-4)

1. 함수 정의 및 시그니처:
   ```python
   def _dispatch_slash_command(
       tokens: list[str],
       *,
       checkpointer: Optional[Checkpointer],
       panel: ControlPanel,
       pending_notices: list[Union[RollbackResult, InterruptedTurn]],
   ) -> bool:
       """슬래시 명령(/rollback, /ctl)을 라우팅한다 (S-4).

       Args:
           tokens: 공백으로 분리된 사용자 입력 토큰 목록
           checkpointer: 파일 체크포인터 인스턴스 (없으면 None)
           panel: 제어판 인스턴스
           pending_notices: 다음 턴 모델에게 전달할 보류 알림 목록

       Returns:
           bool: 슬래시 명령을 처리했으면 True, 일반 대화 입력이면 False
       """
       if not tokens:
           return False

       cmd = tokens[0].lower()
       if cmd == "/rollback":
           rollback_res = _handle_rollback(tokens, checkpointer)
           if rollback_res is not None:
               pending_notices.append(rollback_res)
           return True

       if cmd == "/ctl":
           _handle_ctl(tokens, panel)
           return True

       return False
   ```
2. 위치: `_handle_ctl` 함수 정의 바로 아래(기존 440행 부근)에 배치.
