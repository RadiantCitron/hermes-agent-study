   - 순서: 사용자 입력 -> 턴 경계 Fail-Safe(`apply_pending`, `get_last_active_message_id`) -> `run_conversation` -> (턴중 압축) -> `KeyboardInterrupt` -> `deactivate_messages_after` -> `history = agent.load_conversation_history()` -> 다음 턴 진입.
   - 소유자: 포트(`tools/ports.py`), 도메인 규칙(`tools/checkpoint_domain.py`), 조립자(`assembly.py`), 원장(`session_db.py`), 사용자 접점(`cli.py`).
   - 시점: startup(포트 및 조립), runtime(턴 루프 및 취소 복구), teardown(세션 마감 `try...finally`).
   - WHY §6의 미확인 항목 3건 전수 해소 검증:
     1. 심부름 도구 기존 시험의 에이전트 패치 여부: `assembly.run_child_session` 주입 및 기존 4인자 호환 러너로 기존 시험 100% 무수정 통과 확인 완료.
     2. 첫 턴 취소 시 `load_conversation_history()` 동작: 원장에 `active=1` 없으면 `None` 반환하여 기존 초기값과 완전 일치 확인 완료.
     3. 체크포인트 내부 함수 기존 시험 import 여부: `checkpoint.py`에서 `checkpoint_domain.py`의 모든 심볼을 재수출하여 100% 하위 호환 보존 확인 완료.

### 1-3. 실제 모델 스모크를 하지 않는 이유 (보고서에 적는다)

20번은 전 계층 의존성 역전, 순수 도메인 분리, 런타임 예외·취소 복구 정합성, 아키텍처 불변식 잠금을 달성하는 내부 구조 정비다. [ROADMAP.md §5](../ROADMAP.md)는 검증을 1층위(실제 모델 호출 없이 전부 자동 시험)로 설계했다. 모의 객체, MockTransport, 단위 시험, 가상 터미널(`pty`) 시험을 통해 LLM 호출 흐름과 도구 실행 간섭이 없음을 완전하게 입증했으므로, 실제 유료 모델 키를 사용하는 스모크 테스트는 수행하지 않는다.

## 5. 다음 로드맵으로 넘기는 사실 (21번 계획 때 쓸 것, 이 단계에서 처리하지 않음)

21번 로드맵은 20 `Closed` 뒤 플랜 모드에서 따로 기획한다. 20번이 확립한 기반과 남긴 사실:
1. 에이전트 코어의 모든 계층에서 포트(Protocol) 기반 의존성 역전(DIP)이 확립되었고, `KNOWN_DEBT == {}`로 의존 방향 위반 부채가 완전히 0건으로 청산되었다.
2. 체크포인트 도메인이 순수 모델과 I/O 조정으로 분리되어, 향후 파일 롤백 규칙 변경이나 검증이 파일시스템이나 SQLite 연결 없이도 순수 단위 시험으로 즉시 수행될 수 있다.
3. 턴중 압축 후 취소 시 메모리-원장 Split-Brain 복구(R-1), 자식 세션 마감 보장(R-2), 턴 경계 Fail-Safe(R-3)를 통해 런타임 예외 및 취소 상황에서도 데이터 무결성이 완벽하게 보장된다.
4. 구형 호환 재수출 층(`COMPAT_REEXPORTS` 21건) 제거 및 `constants.py` 분할 등 잔여 품질 다듬기는 안정화된 기반 위에서 안전하게 진행할 수 있다.
