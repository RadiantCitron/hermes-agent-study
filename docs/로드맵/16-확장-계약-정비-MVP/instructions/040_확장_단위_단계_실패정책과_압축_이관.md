## 1. 구현 내용 명세

이 단계는 확장을 하나의 단위로 설치하게 하고, 미들웨어의 순서와 고장 규칙을 단계로 고정하며, 압축을 에이전트를 모르는 첫 확장으로 옮긴다.

### 1-1. 계약 추가 ([`extensions/contract.py`](../../../../src/hermes_core/extensions/contract.py))

- `class MiddlewarePhase(Enum)`: `GUARD = 1`, `POLICY = 2`, `TRANSACTION = 3`(값이 작을수록 바깥).
- `class FailurePolicy(Enum)`: `OPEN`, `CLOSED`. 고정 표 `PHASE_FAILURE_POLICY = {GUARD: OPEN, POLICY: CLOSED, TRANSACTION: CLOSED}`.
- `Extension`(`typing.Protocol`): `name: str`, `install(self, host: "ExtensionHost") -> None`.
- `ExtensionHost`(`Protocol`): `add_tool_middleware(phase: MiddlewarePhase, middleware: Callable) -> None`, `add_turn_hook(point: str, hook: Callable) -> None`, `emit(kind: str, **data) -> None`.
- `ExtensionRecord`(불변 데이터 클래스): `name: str`, `kind: str`(`"tool_middleware"` 또는 `"turn_hook"`), `slot: str`(단계 이름 또는 훅 지점), `failures: int`.
- `TurnScope.report_extension_error(name: str, slot: str, exc: Exception) -> None`: 생성 때 받은 콜백(`on_extension_error`, 기본 `None`)을 부른다. 콜백이 없으면 아무것도 하지 않는다.

### 1-2. 디스패처의 단계·실패 정책 ([`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py))

- `add_middleware(middleware, phase=MiddlewarePhase.POLICY, name=None)`: 이름 기본값은 `getattr(middleware, "__name__", type(middleware).__name__)`. 내부 목록에 `(phase, 등록번호, name, middleware)`로 둔다. 기존 호출 `add_middleware(mw)`는 `POLICY` 단계 = 15번 동작과 같다.
- `dispatch`는 `(phase.value, 등록번호)` 순으로 정렬한 체인을 만든다.
- 각 미들웨어를 감싸는 래퍼:
  - **CLOSED 단계**: 예외는 지금처럼 체인 밖으로 나가 `dispatch`가 `Tool '<name>' failed: …` 오류 JSON으로 바꾼다. 추가로 `call.scope`가 있으면 `report_extension_error(name, phase.name, exc)`.
  - **OPEN 단계(GUARD)**: 래퍼가 `next` 호출 여부를 기록한다. 예외가 나면 `logger.warning`, `call.scope`가 있으면 `report_extension_error`. 그다음 ① `next`를 아직 부르지 않았으면 `next(call)`을 불러 그 결과를 반환(그 미들웨어만 건너뜀) ② 이미 불렀으면 안쪽 결과를 그대로 반환(**도구를 다시 실행하지 않는다**). 안쪽 결과를 아직 받지 못한 채(안쪽이 예외) 던진 경우는 안쪽 예외를 그대로 위로 보낸다.

### 1-3. 에이전트의 확장 설치 ([`agent.py`](../../../../src/hermes_core/agent/agent.py))

- `install_extension(ext)`: 같은 `ext.name`이 이미 있으면 `ValueError`. `_ExtensionHost`(모듈 비공개 클래스, `ExtensionHost`의 세 메서드만 가짐)를 만들어 `ext.install(host)`. 호스트의 `add_tool_middleware`는 `self.dispatcher.add_middleware(mw, phase=phase, name=ext.name)`, `add_turn_hook`은 `self.hooks.register(point, hook)`(훅에도 확장 이름을 기록), `emit`은 `self._emit`.
- `extensions` 속성: `ExtensionRecord`의 튜플(설치 순서). 실패 횟수는 에이전트의 내부 카운터에서 채운다.
- 실패 보고: `TurnScope(..., on_extension_error=self._on_extension_error)`. `_on_extension_error`는 카운터 증가, `logger.warning`, `self._emit("extension_error", name=…, slot=…, error=str(exc))`. 훅 예외(`_on_hook_error`)도 그 훅이 확장에서 왔으면 같은 카운터를 올린다.
- `events.py`에 `EVENT_EXTENSION_ERROR = "extension_error"` 추가(`ConsoleEventSink`는 무시).

### 1-4. 압축을 첫 확장으로 ([`compression_hook.py`](../../../../src/hermes_core/agent/compression_hook.py))

- `CompressionConfig`(불변 데이터 클래스): `enabled: bool`, `context_window_tokens: int`, `threshold_ratio: float`, `llm_client: Any`.
- `CompressionExtension(config: Callable[[], CompressionConfig])`, `name = "compression"`, `install(host)`은 `host.add_turn_hook(BEFORE_LLM, self._before_llm)`.
- `_before_llm(ctx)`: 매 호출마다 `config()`로 현재 설정을 읽는다(시험이 생성 뒤 `agent.compression_enabled`·`agent.llm_client`를 바꾸므로). 판정에 쓰는 마지막 입력 토큰·메시지 수는 `ctx.last_input_tokens`·`ctx.last_message_count`(에이전트가 반복마다 채우는 `TurnContext`의 읽기 전용 값)에서 읽는다. 거부 기억은 `ctx.scope.session_state("compression")["rejected_at_tokens"]`. 그 밖의 판정·호출 순서·로그·`report`는 030 결과를 그대로 유지한다.
- **에이전트를 받지도, 에이전트 속성을 읽지도 쓰지도 않는다.** `compression_hook.py`에서 `agent` 이름이 사라진다.
- 에이전트: `__init__`에서 `self.install_extension(CompressionExtension(self._compression_config))`. `_compression_config()`는 현재 속성으로 `CompressionConfig`를 만든다. `self.hooks.register(BEFORE_LLM, CompressionHook(self))`는 지운다.
- 호환: `_rejected_at_tokens`를 `@property`(세션 칸 값을 돌려줌, 없으면 `None`)로 바꾼다. 기존 시험이 읽기만 하므로 쓰기(setter)는 만들지 않는다. 쓰는 시험은 작성 시점 0건이다(`grep "_rejected_at_tokens *=" tests`). 착수 때 다시 확인하고, 생겼으면 멈추고 보고한다.
- `CompressionHook` 이름은 지운다(`test_turn_hooks.py`가 import하면 멈추고 보고 — 착수 때 `grep`으로 확인).

### 1-5. 내부 구현에 기댄 기존 시험 2건 (사용자 승인 필요, 미승인)

압축에서 에이전트 역참조를 없애면 아래 두 시험이 깨진다. 둘 다 동작이 아니라 내부 구현(생성자 인자, 비공개 속성, 클래스 이름)을 검사한다. 지시서 작성 시점(2026-10-31) `grep`으로 확인했다.

| 시험 | 지금 검사하는 것 | 바꿀 안 (동작은 같게 검사) |
|---|---|---|
| `test_turn_hooks.py::test_g5_compression_max_per_run_bound` | `CompressionHook(agent)`를 만들어 직접 호출, `ctx.run_state["compression"]["attempts"] == 3` 유지 | `CompressionExtension(agent._compression_config)`의 훅을 같은 `ctx`로 직접 호출하고 같은 단언(`attempts == 3`) |
| `test_pipeline_extension.py::test_scenario_e5_session_resume_registers_compression_hook` | `agent2.hooks._hooks[BEFORE_LLM][0]`의 클래스 이름이 `"CompressionHook"` | `agent2.extensions[0].name == "compression"`이고 `slot == "before_llm"`. 이어지는 재개 대화 단언은 그대로 |

- 이 변경이 승인되지 않으면 대안은 「`CompressionHook(agent)` 호환 생성자를 남긴다」인데, 이는 없애려는 역참조를 다시 들이는 것이라 권하지 않는다.
- 승인되면 이 표대로만 바꾸고, 바꾼 사실을 단계 보고와 종합보고서에 기록한다. 15번 지시서는 고치지 않는다.
