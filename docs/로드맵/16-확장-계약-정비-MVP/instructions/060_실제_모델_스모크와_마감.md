# [구현지시서 060] 실제 모델 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [16-README.md](../README.md)  
> **선행 조건**: 050 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~I, [ADR-0016](../../../adr/0016-확장_계약_정비_MVP_범위와_결정.md) §2-9  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 및 마감 단계**다.

---

## 1. 목적

1. **가정 A (실제 모델에서의 압축)**: 계약 정비 뒤에도 낮춘 창에서 압축이 발동하고 앞선 내용을 기억하는가.
2. **화면·경고 무변화**: `[Tool Call]` 줄이 같고, 평소 실행에서 `hook_error`·`extension_error` 경고가 나오지 않는가.
3. **비용 실측**: 훅의 대화 복사·비교에 드는 시간(ADR-0016 §4 단점, ROADMAP 위험 8). 자동 시험으로 긴 대화(예: 메시지 200건)에서 `run_conversation` 한 바퀴의 소요 시간을 이 로드맵 전 커밋과 비교해 기록한다(에이전트가 수행, 키 불필요).
4. 키가 장부·로그에 저장되지 않는가.

가정 I(17번 LoopGuard를 이 계약만으로 붙일 수 있나)는 대상이 아니다. 17번 020 재작성 때 확인한다.

---

## 2. 사전 조건

1. **에이전트**: `.venv/bin/python -m pytest -n 4` 전체 통과, `git diff <050 커밋>..HEAD -- src/` 0줄.
2. **사용자 (Zero Leakage)**: 키(`OPENROUTER_API_KEY`)는 대화창에 입력하지 않고 **별도 터미널**에서 내보낸다([AGENTS.md](../../../../AGENTS.md) §3). 임시 폴더: `export H=$(mktemp -d); echo "$H"`

---

## 3. 스모크 절차 (사용자가 별도 터미널에서 실행)

레포 루트에서 `HERMES_HOME="$H" .venv/bin/python -m hermes_core.cli --context-window 4000` 실행. 실제 모드의 작업 폴더는 `<HERMES_HOME>/workspace`다.

| 단계 | 입력 | 볼 것 |
|---|---|---|
| 1 | `안녕, workspace에 a.txt를 만들고 hello라고 써줘.` | `  [Tool Call] write_file(...)` 줄이 이전과 같은 모양 |
| 2 | `고마워, 내용을 읽어서 알려줘.` | `  [Tool Call] read_file(...)`와 답 |
| 3 | `이 프로젝트의 코드명은 ORCA야. 기억해줘.` (처음 3개 메시지는 압축 때 보호되는 헤드이므로 ORCA를 앞서 말하지 않는다) | 답 |
| 4 | `workspace에 long1.txt를 만들고 1부터 300까지 한 줄에 숫자 하나씩 써줘. 그다음 읽어서 마지막 숫자만 알려줘.` 를 파일 이름만 바꿔 2~3회 | 도구 호출 줄, 압축 임계 접근 |
| 5 | `내가 말한 프로젝트 코드명이 뭐였지?` | `ORCA`를 기억 (가정 A) |
| 6 | `exit` | 정상 종료, 화면에 `hook_error`·`extension_error` 경고 없음 |

### 원장 및 키 미저장 확인 명령

```bash
sqlite3 "$H/state.db" .dump | python3 -c "import os,sys; print('key_leaked:', os.environ['OPENROUTER_API_KEY'] in sys.stdin.read())"
sqlite3 "$H/state.db" "SELECT count(*) FROM messages WHERE compacted=1"
sqlite3 "$H/state.db" "SELECT count(*) FROM llm_calls"
sqlite3 "$H/state.db" "SELECT end_reason FROM sessions"
```

실행 결과(키 값 제외)만 에이전트에게 전달한다. 실패하면 자동 재시도나 코드 수정 없이 원인을 기록하고 멈춘다.

## 4. 마감 (사용자의 종료 선언이 있을 때만)

1. 스모크 결과와 비용 실측을 대시보드 실행 기록에 적는다.
2. [ROADMAP_정책 §5](../../ROADMAP_정책.md)의 9항목으로 `결과정리및리뷰.md`를 쓴다. WHY.md 가정 A~I를 하나씩 대조한다(I는 「미확인」으로 명시하고 후속에 17번 020 재작성). 시험 변경 사실(H3, 040 §1-5의 2건)을 기록한다. **문서에 쓰는 클래스·함수 이름은 `grep`으로 실제 코드에 있는지 확인한 것만 쓴다**(15번 종합보고서의 오기 재발 방지).
3. 대시보드 전체 상태 `Closed`, 완료 일자·마감 태그·종합보고서 링크.
4. 커밋 제목: `docs(core): R16-마감 - 16번 확장 계약 정비 MVP 마감 및 종합보고서 작성`
5. 태그: `git tag roadmap-16-closed` (푸시는 별도 지시 시에만).
6. 후속 인계에 제안으로만 적는다: 17번 020 LoopGuard 재작성, 18번 제어판 로드맵, 승인·체크포인트의 단계 이관.
