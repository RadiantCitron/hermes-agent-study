## 1. 구현 내용 명세

이 단계는 모든 도구 호출(인자를 읽지 못한 호출 포함)이 미들웨어 체인을 지나게 한다. 모델이 받는 결과와 로그는 바뀌지 않는다.

### 1-1. 디스패처 ([`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py))

- `ToolCall`에 `raw_arguments: Optional[str] = None`, `parse_error: Optional[str] = None`을 더한다(010의 `scope` 뒤).
- `dispatch(self, call: ToolCall) -> str`를 추가하고, 지금 `handle_function_call` 안의 체인 구성·예외 처리·비문자열 결과 처리를 이 메서드로 옮긴다. **체인을 실행하는 메서드는 `dispatch` 하나뿐**이다.
- `handle_function_call(function_name, function_args, task_id=None)`는 `return self.dispatch(ToolCall(name=function_name, args=function_args, task_id=task_id))` 한 줄이 된다(시그니처·반환 유지).
- 가장 안쪽 `_execute(call)`: 조회(`Unknown tool`) 다음, 스키마 검증 전에 `call.parse_error`가 있으면 핸들러를 부르지 않고 `{"success": false, "error": "Invalid JSON arguments for tool '<name>': <parse_error>"}`(`ensure_ascii=False`)를 반환한다. 이 문구는 현재 `agent.py`가 만드는 문자열과 **글자까지 같아야** 한다.
  - 알 수 없는 도구 + 깨진 인자: 지금은 에이전트가 파싱 오류를 먼저 돌려준다. 순서를 지키기 위해 `_execute`에서 **`parse_error` 검사를 조회보다 먼저** 한다.

### 1-2. 에이전트 ([`agent.py`](../../../../src/hermes_core/agent/agent.py) `_execute_tool_calls`)

- 인자 파싱(`_parse_tool_arguments`)은 에이전트에 그대로 둔다. 실패하면 지금처럼 `logger.warning("Invalid JSON arguments for tool '%s': %s", …)`을 남긴다(시험 `test_agent_loop_signals.py`가 `hermes_core.agent.agent` 로거를 검사).
- 성공·실패 모두 `ToolCall(name=func_name, args=args or {}, scope=scope, raw_arguments=args_str if isinstance(args_str, str) else None, parse_error=parse_error)`를 만들어 `self.dispatcher.dispatch(call)`을 부른다. 에이전트가 직접 오류 JSON을 만드는 분기는 지운다.
- `scope`는 010에서 만든 현재 턴의 `TurnScope`.
- `tool_call` 이벤트 방출 위치와 `tool` 메시지·원장 기록 순서는 바꾸지 않는다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_dispatch_single_entry.py`(신규). 도구 `echo`(필수 `x`: integer, 호출 기록) 등록.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 미들웨어 M(진입 시 `call`을 기록)을 단 디스패처로, 인자가 `"{bad"`인 `echo` 호출이 있는 턴 실행 | M이 1회 진입, 기록된 `call.parse_error`는 비어 있지 않고 `call.raw_arguments == "{bad"`, `call.args == {}`. 핸들러 호출 0회 |
| 2 | 같은 턴의 `tool` 메시지 내용 | 이 로드맵 전 코드와 **같은 문자열**: `json.loads` 결과가 `{"success": False, "error": "Invalid JSON arguments for tool 'echo': <json 오류 메시지>"}` |
| 3 | 인자가 `"[1, 2]"`(객체 아님)인 호출 | `error`가 `"Invalid JSON arguments for tool 'echo': arguments must be a JSON object"` |
| 4 | 같은 턴에서 `caplog`(로거 `hermes_core.agent.agent`, WARNING) | 경고 1건 이상 |
| 5 | 등록되지 않은 도구 이름 + 깨진 인자 | `Invalid JSON arguments` 오류(파싱 오류가 조회보다 먼저, 이전과 같은 순서) |
| 6 | 정상 인자 호출에서 M이 기록한 `call` | `parse_error is None`, `raw_arguments == '{"x": 1}'`, `call.scope`는 그 턴의 `TurnScope`(같은 턴 두 호출에서 같은 객체) |
| 7 | 미들웨어 M이 `next`를 부르지 않고 차단 문자열 반환, 깨진 인자 호출 | 차단 문자열이 `tool` 메시지 내용이 된다(깨진 호출도 미들웨어가 막을 수 있음) |
| 8 | `handle_function_call("echo", {"x": 1})` 직접 호출 | 이전과 같은 결과, M이 받은 `call.scope is None` |
| 9 | `grep -n "_make_chain\|chain(" src/hermes_core/tools/dispatcher.py`로 체인 실행 위치 확인 | 체인 실행은 `dispatch` 안에만 있다 |
| 10 | `grep -n "Invalid JSON arguments" src/hermes_core/agent/agent.py` | 로그 문자열 1건만 남고 오류 JSON 생성은 0건 |
| 11 | 기존 시험 전체(`test_agent_loop_signals.py`, `test_agent_events.py` 시나리오 7, `test_agent_e2e.py` 포함) | 수정 없이 통과 (가정 A·B) |
