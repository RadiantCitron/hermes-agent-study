## 1. 구현 내용 명세

이 단계는 확장의 상태가 살 자리(턴 칸·세션 칸)와 결과 보고 길을 만들고, 코어가 압축을 직접 아는 곳(결과의 `compression` 조립)을 없앤다. 동작은 바뀌지 않는다.

### 1-1. 중립 계약 모듈 (`src/hermes_core/extensions/__init__.py`, `contract.py`, 신규)

- `contract.py`는 **표준 라이브러리만** import한다. `hermes_core.agent`·`hermes_core.tools`를 import하지 않는다.
- `RESERVED_RESULT_KEYS = frozenset({"final_response", "messages", "iterations", "session_id", "stopped_reason", "error"})`
- `TurnScope`(데이터 클래스):
  - 필드: `session_id: str`, `iteration: int = 0`, `stop_reason: Optional[str] = None`, `turn_slots: dict[str, dict[str, Any]]`(기본 빈 사전), `session_slots: dict[str, dict[str, Any]]`(호출자가 넘김, 기본 빈 사전), `reports: dict[str, Any]`(기본 빈 사전).
  - `request_stop(reason: str) -> None`: `stop_reason`이 `None`일 때만 기록(먼저 요청한 것이 이김).
  - `state(name: str) -> dict`: `turn_slots`에서 `name`의 사전을 만들거나 돌려줌. `name`이 빈 문자열이면 `ValueError`.
  - `session_state(name: str) -> dict`: `session_slots`에서 같은 일.
  - `report(key: str, value: Any) -> None`: `key`가 `RESERVED_RESULT_KEYS`에 있으면 `ValueError`, 아니면 `reports[key] = value`.
- 모듈 독스트링에 원본 매핑: 원본 `hermes-agent/model_tools.py`는 훅 억제 상태를 `ContextVar`(`_post_tool_call_hook_suppressed`)로 두지만, 여기서는 문맥을 인자로 전달한다.

### 1-2. `TurnContext` 연결 ([`turn_hooks.py`](../../../../src/hermes_core/agent/turn_hooks.py))

- `TurnContext`에 `scope: TurnScope` 필드를 더한다(필수 아님: 기본값은 `session_id`로 만든 새 `TurnScope`, 기존 생성 방식 호환).
- `run_state`는 `scope.turn_slots`와 **같은 사전 객체**가 되게 한다(`__post_init__`에서 연결). 기존 시험 `test_g5_…`가 `ctx.run_state["compression"]`에 직접 쓰고 읽으므로 그대로 동작해야 한다.
- `stop_reason`·`request_stop`은 `scope`에 위임한다(`TurnContext.stop_reason` 읽기는 `scope.stop_reason`, 쓰기 경로는 `request_stop` 하나).
- `iteration`은 `TurnContext`와 `scope` 양쪽이 같은 값을 갖도록 에이전트가 반복마다 둘 다 갱신한다.

### 1-3. `ToolCall` 연결 ([`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py))

- `ToolCall`에 `scope: Optional[TurnScope] = None`을 더한다(필드 순서 마지막, 기존 위치 인자 호환). `dispatcher.py`는 `hermes_core.extensions.contract`에서 `TurnScope`를 import한다.
- 디스패처 동작은 바꾸지 않는다(이 필드는 아직 아무도 읽지 않는다).

### 1-4. 에이전트 연결 ([`agent.py`](../../../../src/hermes_core/agent/agent.py))

- `HermesAgent.__init__`에 세션 칸 저장소 `self._session_slots: dict[str, dict] = {}`.
- `run_conversation` 시작에서 `scope = TurnScope(session_id=self.session_id, session_slots=self._session_slots)`를 만들고 `TurnContext(..., scope=scope)`로 넘긴다.
- 반복마다 `ctx.iteration`과 `scope.iteration`을 같은 값으로 갱신.
- `_execute_tool_calls`에 `scope`를 넘겨 `handle_function_call` 대신 `ToolCall(name, args, scope=scope)`를 만들 준비를 하되, **이 단계에서는** 기존 `handle_function_call(func_name, args)` 호출을 유지하고 `ToolCall`에 `scope`를 싣는 것은 020에서 `dispatch`와 함께 한다.
- 결과 조립: `agent.py`의 `ctx.run_state.get("compression")` 블록(현 481-486)을 지우고, 결과 사전을 만든 뒤 `result.update(scope.reports)`를 한다.
- 압축 훅([`compression_hook.py`](../../../../src/hermes_core/agent/compression_hook.py)): 지금처럼 `run_state["compression"]`에 횟수를 쌓되, 성공(`count`)이 늘어난 직후 `ctx.scope.report("compression", {"count": n, "fallback": m})`를 한다. 결과 형식은 이전과 같다.
