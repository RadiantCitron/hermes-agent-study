## 2. 시스템 개요 (동작 · 순서 · 소유자 · 시점)

### 사실 검증 4축 매핑

1. **상태 격리 (`TurnScope`)**:
   - **소유자**: 턴 루프 실행 시 `HermesAgent.run_conversation`이 생성하여 `TurnContext` 및 `ToolCall`에 주입.
   - **시점**: 각 턴 시작 시 생성되며 턴 종료 시 소멸 (단, `session_slots`는 에이전트 수명 동안 유지).
   - **동작**: `scope.state(name)`(턴 칸), `scope.session_state(name)`(세션 칸), `scope.report(key, value)`(결과 보고).
2. **도구 디스패처 단일 입구 (`ToolDispatcher.dispatch`)**:
   - **순서**: LLM의 `tool_calls` → `ToolCall` 객체 생성 → 미들웨어 체인(`GUARD` → `POLICY` → `TRANSACTION`) → `_execute`(파싱에러 검사 → 도구조회 → 스키마검증 → 핸들러실행).
   - **동작**: 파싱 에러를 포함한 모든 호출이 체인을 통과하며, 체인 내 예외는 `dispatch`가 오류 JSON으로 감싸 루프로의 누출을 원천 방지.
3. **대화 무결성 (`_replace_transcript`)**:
   - **소유자**: `HermesAgent` 단일 진입로.
   - **순서**: 새 대화의 시스템 메시지 무결성 사전 검증 → `SessionDB.archive_and_compact`(장부 선기록) → 성공 시에만 메모리 `messages[:]` 교체 및 토큰 추정 상태 무효화 → 사용량 집계 → 훅 레지스트리 비교본 동기화.
4. **확장 프로토콜 및 호스트 (`Extension`, `ExtensionHost`)**:
   - **소유자**: `HermesAgent.install_extension`.
   - **동작**: 비공개 `_ExtensionHost`를 통해 미들웨어 및 턴 훅을 등록하고, 등록 기록을 불변 `ExtensionRecord` 튜플로 노출(`agent.extensions`).

## 3. 주요 결정 (ADR-0016 D-01 ~ D-09 반영)

- **D-01 (상태 칸)**: `TurnScope`를 통한 턴 칸(`state`)과 세션 칸(`session_state`)의 물리적 격리.
- **D-02 (결과 보고)**: 예약 키(`RESERVED_RESULT_KEYS`) 충돌 방지 및 `scope.report`를 통한 명시적 결과 조립.
- **D-03 (단일 입구)**: `ToolCall(raw_arguments, parse_error)` 확장을 통한 깨진 JSON의 체인 우회 방지.
- **D-04 (미들웨어 문맥)**: 미들웨어에 대화 리스트 대신 턴 문맥(`call.scope`)만 노출.
- **D-05 (대화 무결성)**: 훅에 깊은 복사본 제공 및 변경 감지, 대화 교체 단일 진입로 `replace_transcript`.
- **D-06 (고정 단계)**: `MiddlewarePhase`(`GUARD=1`, `POLICY=2`, `TRANSACTION=3`) 고정 정렬.
- **D-07 (실패 정책)**: `GUARD`(fail-open, 도구 재실행 방지) / `POLICY`·`TRANSACTION`(fail-closed).
- **D-08 (확장 단위)**: `Extension` 단위 설치 및 `agent.extensions` 읽기 전용 조회.
- **D-09 (압축 이관)**: `CompressionExtension` 도입으로 에이전트 역참조 제거.

## 7. 새로 발견한 부분 (인사이트)

1. **GUARD 단계 fail-open의 도구 재실행 방지 장치**:
   - 미들웨어가 `next(call)`을 호출한 뒤(도구가 이미 실행된 후) 예외를 던지는 경우, 단순 fail-open을 적용하면 `next`를 다시 불러 도구가 2번 실행되는 치명적인 부작용(예: 결제 도구 이중 호출)이 생길 수 있다.
   - `called_next` 플래그와 `inner_result` 보관 기법을 통해 **도구는 반드시 1회만 실행되고 안쪽 결과가 보존**되도록 구현함으로써 다층 방어의 안전성을 한 단계 끌어올렸다.
2. **단일 입구(`dispatch`)가 주는 체인 무결성**:
   - 인자 파싱 에러를 포함한 모든 호출을 `ToolCall(parse_error=...)`로 캡슐화하여 디스패처 단일 진입로를 통과시키자, 미들웨어 체인의 감사 로그나 보안 가드가 단 1건의 호출도 놓치지 않고 일관되게 관찰할 수 있게 되었다.

1. **로드맵 17번(루프 정체 감지 MVP) 착수 및 020 LoopGuard 재작성**:
