## 1. 마감 개요

- **목표 달성**:
  1. **단일 종료 지점 정합**: 세션이 `exit` 정상 종료, 입력 프롬프트 `Ctrl+C`(`user_interrupt`), `Ctrl+D`(`eof`), 처리 중 미처리 예외(`error`) 중 어떤 경로로 끝나더라도 장부 `sessions.end_reason`에 사유를 단일 지점(`cli.py` `main`의 `finally`)에서 일관되게 남김.
  2. **처리 중 Ctrl+C 턴 취소**: AI가 응답 생성 또는 도구 실행 중 `Ctrl+C`(`KeyboardInterrupt`)를 누를 때 프로세스가 죽지 않고 해당 턴만 취소되어 프롬프트(`User >`)로 복귀하며, 대화 맥락과 세션 장부를 온전히 유지함.
  3. **취소 턴 맥락 격리 및 변경 사실 알림 주입**: 도구 호출 짝(Pair) 깨짐 방지를 위해 취소된 턴은 AI 대화 이력(`messages`)에서 제외하되, 취소 전 파일 도구로 이미 변경되었거나 변경 중단된 파일 내역을 `collect_interrupted_turn`으로 추출하여 사람의 다음 메시지 앞 알림(`[Interruption notice - ...]`)으로 결합 전달함.
  4. **12번 한계 2·4 정리**:
     - **한계 4**: 롤백 실행 도중 DB 예외가 발생해도 기복원 항목을 보존하고 잔여 항목을 `skipped`로 묶어 부분 결과(`RollbackResult.error`)를 반환하며 재시도 가능 상태로 원장을 보호함.
     - **한계 2**: 롤백 알림이나 취소 알림이 모델에 전달되기 전 세션이 종료되는 경우 `finally`에서 화면 안내(`CLI_UNSENT_NOTICE_ON_EXIT`)를 표출함.

## 3. 단계별 구현 및 검증 요약

### 010: 세션 종료 단일 지점과 `end_reason` 어휘
- **무엇을**: `constants.py`에 종료 사유 4종(`user_exit`, `user_interrupt`, `eof`, `error`) 정의, `cli.py`에 `_close_session` 헬퍼 함수 구현 및 `main()`의 `finally:` 블록에서 단일 호출 배선.
- **왜**: 세션이 종료되는 여러 분기(`exit`, 단축키, 예외 등)마다 분산 호출하던 구조를 일원화하여, 어떤 경로로 끝나든 누락 없이 SQLite 원장 `sessions.end_reason`을 보장하기 위함.
- **결과**: `test_cli_interrupt.py` 시나리오 1~9 통과 (커밋 `926c01a`).

### 020: 처리 중 Ctrl+C 턴 취소
- **무엇을**: `cli.py`의 `with hold_typeahead():` 블록을 `try/except KeyboardInterrupt:`로 감싸 취소 안내 출력 후 프롬프트 복귀, `pending_notices` 사본 되돌리기(`delivered`) 구현.
- **왜**: 처리 도중 사용자가 `Ctrl+C`를 눌렀을 때 세션 전체가 종료되어 대화 맥락을 잃는 문제를 방지하고, 직전 턴에 결합되었던 보류 알림이 대화 이력 제외로 유실되는 것을 방지하기 위함.
- **결과**: 시나리오 1~9 추가 및 `test_cli_input_pty.py` 14번 갱신 통과 (커밋 `ce1f4a6`).

### 030: 취소 알림 글과 CLI 배선, `pending` 틈 시험 고정
- **무엇을**: `InterruptedItem`·`InterruptedTurn` 데이터 구조 정의, `collect_interrupted_turn`, `format_interrupt_notice`, `format_pending_notices` 순수 함수 구현, CLI `pending_notices` 통합 배선.
- **왜**: 취소된 턴에서 파일 도구가 실제로 바꾼 파일 내역을 모델에게 정확히 알려 환각 및 상태 불일치(자가 치유 함정)를 방지하기 위함.
- **결과**: 단위 U1~U12, CLI C1~C11 신규 23개 시험 통과 (커밋 `8f3064d`).

### 040: 12번 한계 정리 (부분 롤백 결과, 미전송 알림 화면 안내)
- **무엇을**: `RollbackResult.error` 필드 추가, `execute_rollback` 루프 예외 포착 및 잔여 항목 skipped 처리, `_handle_rollback` 중단 안내, `main`의 `finally`에서 미전송 알림 화면 출력(`CLI_UNSENT_NOTICE_ON_EXIT`).
- **왜**: 롤백 실행 중 DB 오류 발생 시에도 복원된 결과를 보존하고 알림을 생성하며, 알림 미전송 상태로 종료될 때 사용자에게 명확한 화면 피드백을 주기 위함.
- **결과**: 단위 E1~E5, CLI F1~F7 신규 12개 시험 통과 (커밋 `1d7618e`).

### 050: 통합 검증과 작동원리 동기화
- **무엇을**: 실제 `OpenRouterClient` + `MockTransport` 대본 기반 통합 E2E 테스트(`test_cli_interrupt_e2e.py`, G1~G6) 작성, 작동원리 01편(Q12 신설, 4축 검증 동기화) 및 WHY/PLAN 문서 갱신.
- **왜**: 취소 알림이 실린 요청이 실제 HTTP 계층과 원장 `llm_calls`에 완전하게 보존됨을 실증하고, 취소된 호출의 원장 기록 방식(요청 보존, 상태코드 NULL)을 규명하기 위함.
- **결과**: E2E 시험 3건 통과, 전체 867건 회귀 테스트 통과 (커밋 `749d44c`).

## 4. 미흡한 부분 및 알려진 한계

1. **터미널 하위 프로세스 강제 정리 미구현**:
   - 터미널 도구 실행 도중 `Ctrl+C`가 발생해도 파이썬의 표준 `subprocess.run`은 인터럽트를 수신하지만 백그라운드로 도는 자식 프로세스 트리를 강제로 `kill`하지는 않음.
2. **취소된 질문 재입력 필요**:
   - 취소된 턴은 도구 짝 어긋남을 막기 위해 통째로 대화에서 제외되므로, 사용자가 입력했던 원래 질문 텍스트는 모델이 다시 볼 수 없으며 사람이 재입력해야 함.
3. **복원 0건 롤백 중단 시 모델 알림 부재**:
   - 롤백의 첫 번째 항목에서 원장 갱신이 실패하여 `rolled_back_count == 0`인 경우 모델 알림은 만들어지지 않음(화면 중단 안내만 표시).
4. **배너 구간 종료 시 사유 공백**:
   - 초기 배너 출력 및 대화 루프 진입 전 예외나 즉시 종료 시 세션 레코드가 생성되기 전이거나 기본 사유가 기록되지 않을 수 있음.

## 5. 새로 발견한 사실 (인사이트)

1. **`finally` 블록의 불변 기록 가치**:
   - `llm_client.py`의 `finally`는 호출 도중 `KeyboardInterrupt`가 발생하더라도 `record_llm_call`을 호출하므로, 취소된 호출도 `request_json` 전문이 남고 `status_code`와 `error_kind`는 `NULL`로 기록되는 정확한 실패 증거가 남음을 실측으로 확인.
2. **보류 알림 목록의 원자적 되돌리기**:
   - 턴 처리 시작 시 보류 알림을 비우는 기존 방식에서는 턴이 취소되었을 때 알림이 영구 유실될 수 있으므로, 복사본(`delivered`)을 유지하다가 취소 예외 포착 시 리스트 선두에 원자적으로 복원하는 메커니즘이 필수적임을 발견.

## 6. 후속 과제 후보

1. **터미널 프로세스 그룹 시그널 격리 및 강제 종료**: 터미널 명령 실행 시 프로세스 그룹(`preexec_fn=os.setsid`)을 지정하여 `Ctrl+C` 취소 시 자식 프로세스 트리를 깨끗하게 정리.
