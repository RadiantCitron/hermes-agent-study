## 1. 구현 내용 명세

010~040은 가짜 클라이언트로 「모델이 받은 글」을 확인했다. 이 단계는 남은 것을 확인하고, 바뀐 동작을 작동원리 문서에 반영한다.

1. **실제 클라이언트 경로**: 실제 `OpenRouterClient`가 취소 알림이 붙은 메시지를 HTTP 요청으로 직렬화하는지, 그 요청이 원장 `llm_calls.request_json`에 그대로(열쇠는 가린 채) 남는지.
2. **취소된 모델 호출의 원장 기록**: 모델을 부르는 도중 `KeyboardInterrupt`가 일어난 호출이 `llm_calls`에 남는지.
3. **압축과의 공존**: 취소 알림이 든 사람 메시지가 압축을 거쳐도 이전 요약으로 오인되지 않는지, 오래된 알림은 요약으로 대체될 수 있다는 것.

### 1-1. 코드 대조로 확정한 사항

- 취소된 호출의 기록: `OpenRouterClient.chat_completion`의 `finally`가 예외 종류와 무관하게 `_invoke_on_call(record)`를 부른다(`llm_client.py:239-252`). `KeyboardInterrupt`도 `finally`를 지나므로 취소된 호출은 **요청 본문은 있고, 응답·상태 코드·오류 종류는 비어 있는** `llm_calls` 행으로 남는다고 읽힌다. 시나리오 G2가 이를 확인한다(010~030 지시서와 020의 「남지 않을 수 있다(미확인)」는 이 읽기로 대체된다. 020 지시서는 같은 커밋에서 정정했다).
- `httpx.MockTransport`의 handler가 `KeyboardInterrupt`를 던지면 `httpx`는 `httpx.TimeoutException`·`TransportError`로만 감싸고(`llm_client.py:231-238`) `BaseException`은 그대로 통과시킨다. 따라서 handler에서 취소를 재현할 수 있다.
- `OpenRouterClient`는 `transport` 인자를 받는다. 12의 030 시험이 쓴 방식을 따른다: `cli.OpenRouterClient`를 「실제 클래스에 `MockTransport`를 넣어 만드는 함수」로 바꿔 끼운다.

### 1-2. 시험 파일

- **새 파일** `tests/test_hermes_core/test_cli_interrupt_e2e.py`. 헬퍼(MockTransport handler, 입력 가로채기)는 12의 `test_cli_rollback_notice_e2e.py`와 같은 모양으로 이 파일 안에 둔다(다른 시험 파일에서 가져오지 않는다). handler는 요청 본문을 목록에 모으고, 대본 항목이 `BaseException` 인스턴스면 그것을 던지고, 아니면 JSON 응답을 돌려준다.
- 새 pty 시험은 만들지 않는다(D-11).

### 1-3. 발견 수정 슬롯 (src 변경이 허용되는 유일한 범위)

시나리오가 결함을 드러내면 아래 순서로 처리한다.
1. 실패하는 시험을 먼저 확인한다.
2. 원인이 이 로드맵의 변경(010~040) 안에 있을 때만 그 파일(`tools/checkpoint.py`, `cli.py`, `constants.py`)을 고친다.
3. 수정마다 대시보드에 `F1`, `F2`…로 기록한다.

원인이 `agent/`·압축·`llm_client.py`·`session_db.py`처럼 이 로드맵 밖에 있으면 **고치지 않고 멈춰 보고한다.**

## 2. 문서 동기화 (문서작업)

### 2-1. 작동원리 01편 ([01-헤르메스코어-작동원리.md](../../../작동원리/01-헤르메스코어-작동원리.md))

작성 규칙은 [작동원리 README](../../../작동원리/README.md)의 「설명의 기준」「이름의 3층」을 따른다(개념·이유 중심, 고유 이름은 첫 등장에 한마디, 구현 귀띔은 문단 끝, Why는 더 되물을 수 없는 곳까지, 이유가 없으면 없다고, 시험 개수는 적지 않음).

1. **Q1 6번** 끝의 「Ctrl+C는 그 동안에도 그대로 프로그램을 멈춥니다」를, 일하는 동안의 Ctrl+C가 그 요청만 취소한다는 내용으로 고친다(새 Q12로 연결).
2. **Q1 「지금은 없는 것 / 한계」**에서 「입력을 기다리는 중 Ctrl+C나 Ctrl+D로 나가면 장부만 닫히고 「왜 끝났는지」는 적히지 않습니다」를 지우고, 입력 칸에서의 종료 사유 기록은 Q12가 설명한다고 한다. Q1 4번의 「exit」 문장은 사실 그대로 둔다.
3. **새 Q12** 「일하는 도중 Ctrl+C로 멈추거나 대화를 끝내면 무슨 일이 일어나나요?」를 Q11 뒤에 추가한다. 담을 내용:
   - 끝난 이유가 어떤 길로 끝나든 한 곳에서 장부에 적히는 것: 길(`exit`, 입력 칸의 Ctrl+C, Ctrl+D, 그 밖의 오류)과 적히는 이유 4가지의 표. 이미 적힌 이유는 덮지 않는다. 왜 한 곳인가(끝나는 길이 늘 때 빠뜨리지 않으려고).
   - 일하는 도중 Ctrl+C: 그 요청만 취소되고 대화는 이어진다. 취소된 요청은 AI가 보는 대화에서 빠지고(도구 호출과 결과의 짝이 깨지지 않게), 장부에는 일어난 일이 그대로 남는다. 왜 대화에서 빼나(짝이 어긋난 대화는 다음 호출이 거부될 수 있음), 왜 장부는 지우지 않나(일어난 일의 증거). 모델을 부르던 도중의 취소도 장부에 요청까지는 남는다(G2).
   - 취소 알림: 그 요청이 파일 도구로 바꿨을 수 있으면, 사람의 다음 말 앞에 「취소됐고 이 파일들이 바뀌었을 수 있다, 이어서 하지 말고 다시 읽어라」를 붙인다. 왜 알리나(대화에서 빼면 AI는 이미 바뀐 파일을 모른다, Q11의 되돌림 알림과 같은 이유). 롤백 알림과 같은 방식·같은 줄에 순서대로 합친다. 쓰는 중에 끊기면 「바뀌었는지 모름」으로 표시한다.
   - 12번 한계 두 건의 처리: 되돌리는 도중 오류가 나도 거기까지의 결과로 알림이 간다, 알림이 가기 전에 끝나면 화면에 알린다.
   - 지금은 없는 것 / 한계: 터미널 명령으로 바뀐 것은 알리지 못함, 취소된 요청의 내용은 AI가 다시 보지 못함, 안내를 찍는 순간의 연타·되돌리기 실행 중 Ctrl+C·강제 종료는 다루지 않음, 첫 항목에서 중단된 롤백은 알림 없음, 입력 칸 앞(배너 구간) 오류는 이유가 비어 남음, 취소된 요청 도중 압축이 일어나면 다음 말에서 한 번 더 압축될 수 있음. 실제 모델이 알림을 따르는지는 060에서 관찰(060 결과는 마감 때 반영).
   - 구현 귀띔: 종료 이유는 `cli.py`의 `_close_session`과 `main`의 `finally`, 취소는 `main`의 `KeyboardInterrupt` 처리, 알림은 `tools/checkpoint.py`의 `collect_interrupted_turn`·`format_interrupt_notice`·`format_pending_notices`, 부분 롤백은 `execute_rollback`·`RollbackResult.error`.
4. **Q11 「지금은 없는 것 / 한계」**를 고친다.
   - 「되돌린 뒤 아무 말 없이 세션을 끝내면 모델에게 알림이 가지 않습니다」 → 가지 않지만 화면에 알린다는 내용 추가.
   - 「되돌리기 실행 도중 예외가 발생하면 알림이 생성되지 않습니다」 → 부분 결과로 알림이 가고, 복원이 0건이면 알림이 없으며, 실행 도중 Ctrl+C는 다루지 않는다는 내용.
   - 「12번 로드맵 040 스모크에서 관찰할 예정입니다」는 낡은 문장이다. 12의 [결과정리및리뷰](../../12-롤백-모델알림-MVP/결과정리및리뷰.md)에 기록된 관찰 결과(1개 모델, 쓰기 도구 호출 0회)로 바꾸고, 모델 1종뿐이라는 한계를 적는다.
5. **3부** 「이상이 생기면」 표에 행을 추가한다: 일하는 도중 Ctrl+C / 입력 칸에서 Ctrl+C·Ctrl+D / 되돌리는 도중 오류.
6. **4부**에 배척한 방식 1개를 추가한다: 「취소된 요청을 AI의 대화에 남기고 짝이 어긋난 부분만 정리하기」(택했다면: 정리 코드가 늘고 짝이 어긋난 대화를 거부당할 수 있음 / 포기한 것: 취소된 요청의 글을 AI가 다시 보는 것).
7. **5부 ①**: 새 행 「일하는 도중 멈추기·대화 끝내기」를 추가하고(안에서 일어나는 일 / 지금은 없는 것 / 근거 Q12·5부 ② 번호), 「잘못 고친 파일 되돌리기」 행의 「종료 시 알림 미전송」을 「종료 시 알림 전달 없음(화면 안내)」로 바꾼다.
8. **5부 ②**: 1번(CLI)에 `_close_session`, `pending_notices`, `KeyboardInterrupt` 취소를 추가하고, 19번에 `InterruptedTurn`·`collect_interrupted_turn`·`format_interrupt_notice`·`format_pending_notices`·`RollbackResult.error`를 추가하며, 18번(시험)에 `test_cli_interrupt.py`·`test_cli_interrupt_e2e.py`를 추가한다.
9. **5부 ③**: Q12 행을 추가한다(동작·순서·소유자·시점·미확인). Q1·Q11 행의 미확인에서 낡은 항목(「실행 중 Ctrl+C는 미확인」 등)을 정리한다. 미확인 후보: 실제 모델이 취소 알림을 따르는지, 터미널 자식 프로세스 정리, 취소된 요청 도중 압축 시의 실측.
10. **머리 기준 커밋**: 이 단계 직전에 `src`·`tests`를 마지막으로 바꾼 커밋(`git log -1 --format=%h -- src tests/test_hermes_core`)으로 옮기고, 옮긴 이유를 ③ 검증 문단에 적는다. 작동원리 문서에는 시험 개수를 적지 않는다(RULE-002).

## 4. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_cli_interrupt_e2e.py`. 공통 진행: 실제 `OpenRouterClient` + `MockTransport` 대본. 입력은 `go` → `read it` → `exit`. 대본(HTTP 응답/예외 순서): ① `notes.txt`를 `write_file`로 만드는 도구 호출 응답 → ② 도구 결과를 받은 두 번째 요청에서 handler가 `KeyboardInterrupt`를 던짐 → ③ `read it`에 대한 최종 응답 `Read it done`. 따라서 handler가 받는 요청은 3개(`go`, `go`의 도구 결과 뒤, `read it`)이고 두 번째에서 취소된다.

| # | 입력 | 기대 결과 |
|---|---|---|
| G1 | 공통 진행 | 세 번째 HTTP 요청 본문(JSON)의 `messages` 마지막 user `content`가 `[Interruption notice - added by the CLI, not typed by the user]`로 시작하고, `  changed: notes.txt`를 포함하며, `\n\nread it`으로 끝난다. 그 본문의 어느 메시지 `content`에도 `go`는 없다(취소된 요청이 대화에서 빠짐, 가정 B). `cli.main()`은 예외 없이 끝난다 |

| G4 | 공통 진행 | 원장 `messages`의 user 행은 `go`와 (알림+`read it`) 두 개뿐이고(알림이 별도 행으로 생기지 않음), 취소된 요청의 assistant(도구 호출)·tool 행은 **지워지지 않고 남아 있다** |
