## 1. 구현 내용 명세

세션이 끝나는 길이 여러 개인데 종료 사유는 `exit` 한 곳에서만 적는다. 이 단계는 `main` 하나의 `finally`를 종료 사유 기록의 **단일 지점**으로 만든다. 처리 중 `Ctrl+C`의 동작은 바꾸지 않는다(020).

### 1-1. 종료 사유 상수 ([`constants.py`](../../../../src/hermes_core/constants.py))

세션 종료 사유 상수 4종을 추가한다. 값은 아래 문자열 그대로다.

| 상수 | 값 | 쓰는 곳 |
|---|---|---|
| `SESSION_END_USER_EXIT` | `"user_exit"` | `exit`·`quit` (기존 값 유지) |
| `SESSION_END_USER_INTERRUPT` | `"user_interrupt"` | 프롬프트에서 `Ctrl+C` |
| `SESSION_END_EOF` | `"eof"` | 프롬프트에서 `Ctrl+D`(EOF) |
| `SESSION_END_ERROR` | `"error"` | 그 밖의 예외로 종료 |

- mock 단발 실행의 `"completed"`와 위임 자식(`delegate_tool.py`)의 사유 문자열은 **건드리지 않는다**.

### 1-2. 단일 기록 함수 `_close_session` ([`cli.py`](../../../../src/hermes_core/cli.py))

모듈 수준 private 함수를 하나 둔다.

```python
def _close_session(session_db: SessionDB, session_id: str, end_reason: str) -> None:
    """세션에 종료 사유를 한 번만 남긴다. 이미 끝난 세션은 건드리지 않는다."""
```

- `session_db.get_session(session_id)`로 조회해 `end_reason`이 **이미 있으면** 아무것도 하지 않는다(덮어쓰기 방지, ADR §2-2). 세션 행이 없으면(`None`) 기록하지 않는다.
- 비어 있으면 `session_db.end_session(session_id, end_reason)`을 부른다.
- DB 오류(`Exception`)가 나도 밖으로 던지지 않고 `logger.warning`으로 남긴다. 이 함수는 `finally`에서 불리므로, 던지면 원래 예외를 가리고 뒤따르는 `session_db.close()`를 건너뛰게 한다. 이를 위해 `cli.py`에 `import logging`과 모듈 `logger`를 추가한다.
- **`SessionDB.end_session`의 동작은 바꾸지 않는다.** 위임 자식 세션도 쓰는 공용 메서드라서, 덮어쓰기 방지를 거기에 넣으면 자식 경로까지 영향이 간다(위험 7). 기존에 사유를 직접 적는 곳은 `cli.py`와 `delegate_tool.py`뿐임을 `grep -rn "end_session" src`로 착수 전에 확인한다.

### 1-3. `main` 연결 ([`cli.py`](../../../../src/hermes_core/cli.py))

- 대화 루프의 `try:` 직전에 `session_end_reason = SESSION_END_ERROR`로 둔다. 「깨끗한 종료 경로가 덮어쓰지 않으면 오류로 끝난 것」이라는 기본값이다.
- 프롬프트 읽기의 `except (EOFError, KeyboardInterrupt)`를 둘로 나눈다. 안내 출력(`"\nExiting session..."`)과 `break`는 그대로 두고 사유만 다르게 둔다: `KeyboardInterrupt` → `SESSION_END_USER_INTERRUPT`, `EOFError` → `SESSION_END_EOF`.
- `exit`/`quit` 분기: `agent.session_db.end_session(..., "user_exit")` 호출을 **지우고** `session_end_reason = SESSION_END_USER_EXIT`만 둔다. `"Session saved and closed. Goodbye!"` 출력과 `break`는 그대로다.
- 기존 `finally: agent.session_db.close()`를 아래 순서로 바꾼다.
  ```python
  finally:
      _close_session(agent.session_db, agent.session_id, session_end_reason)
      agent.session_db.close()
  ```
- 처리 중(`run_conversation`) 발생한 예외는 지금처럼 밖으로 전파된다. 기본값 때문에 `error`가 기록된다. 처리 중 `KeyboardInterrupt`도 이 단계에서는 같은 길로 가서 `error`로 기록되며, 020이 이를 「턴 취소」로 바꾼다. 이 단계의 시험은 처리 중 `KeyboardInterrupt`를 다루지 않는다.
- mock 단발 실행(`args.mock and not sys.stdin.isatty()`) 경로는 `try` 앞에서 끝나므로 손대지 않는다.

### 1-4. 알려진 한계 (이 단계에서 고치지 않음)

- 세션 생성(`HermesAgent` 생성)부터 대화 루프의 `try:` 사이(배너 출력 등)에서 예외가 나면 사유가 비어 남는다. 이 구간은 출력과 설정뿐이라 실패 가능성이 낮고, `try`를 위로 옮기면 diff가 커져서 이번에는 두지 않는다. 마감 보고의 「미흡한 부분」에 적는다.
- `SIGTERM`·`SIGKILL`은 다루지 않는다(비목표).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_cli_interrupt.py`(신규). 기존 `test_cli_multiline_hint.py`의 방식을 따른다: `hermes_home` 픽스처, `cli.OpenRouterClient`를 가짜로 바꾸고, `cli.read_user_input`을 대본 함수로 바꾸어 `cli.main()`을 부른다. 종료 사유는 `SessionDB(hermes_home / "state.db")`로 열어 `SELECT end_reason, ended_at FROM sessions`로 확인한다. **기대값은 상수가 아니라 문자열 리터럴로 단언한다**(상수와 구현이 함께 틀려도 통과하는 것을 막는다).

| # | 입력 (대본) | 기대 결과 |
|---|---|---|
| 1 | `exit` | `end_reason == "user_exit"`, `ended_at`은 비어 있지 않다. 출력에 `Session saved and closed. Goodbye!` |
| 2 | 입력 읽기가 `KeyboardInterrupt` | `end_reason == "user_interrupt"`, `ended_at`이 있다. 출력에 `Exiting session...`. 예외가 밖으로 나오지 않는다 |
| 3 | 입력 읽기가 `EOFError` | `end_reason == "eof"`, `ended_at`이 있다. 출력에 `Exiting session...`. 예외가 밖으로 나오지 않는다 |
| 4 | `hello` 입력, 그 처리(`HermesAgent.run_conversation`)가 `RuntimeError("boom")` | `RuntimeError`가 `cli.main()` 밖으로 전파된다. `end_reason == "error"`, `ended_at`이 있다. `SessionDB.close`가 정확히 1회 불렸다 |
| 5 | `_close_session`을 직접 호출: 이미 `end_session(id, "custom")`로 끝난 세션에 사유 `"user_exit"` | `end_reason == "custom"` 그대로이고 `ended_at`도 처음 값 그대로다(덮어쓰지 않음) |
| 6 | `_close_session`을 직접 호출: 아직 안 끝난 세션, 사유 `"user_exit"` | `end_reason == "user_exit"`, `ended_at`이 있다 |
| 7 | `_close_session`을 직접 호출: 존재하지 않는 세션 ID | 예외 없이 돌아오고, 어떤 세션 행도 새로 생기지 않는다 |
| 8 | `SessionDB.end_session`이 `RuntimeError`를 내도록 바꾸고 `exit` | `cli.main()`이 예외 없이 끝난다. 출력에 `Session saved and closed. Goodbye!`. 로그에 경고(`caplog`)가 남는다. `SessionDB.close`가 정확히 1회 불렸다 |
| 9 | `--mock`, 표준입력이 터미널 아님(단발 실행) | `end_reason == "completed"`(기존 동작 유지) |

시나리오 4·8의 `close` 호출 횟수는 `SessionDB.close`를 원래 함수를 부르면서 횟수를 세는 래퍼로 바꿔 확인한다. 시나리오 5~7은 임시 폴더의 `SessionDB`에 `create_session`으로 세션을 만들어 직접 호출한다(`main`을 거치지 않는 결정적 시험).
