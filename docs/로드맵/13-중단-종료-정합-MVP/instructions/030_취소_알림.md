## 1. 구현 내용 명세

020이 만든 「취소」 위에서, 취소된 턴에 파일 도구 기록이 있으면 그 사실을 **사람이 보내는 다음 메시지 앞에** 고정 형식으로 붙인다. 롤백 알림(12)과 같은 보류 목록을 쓰고, 일어난 순서대로 한 번에 붙인다. 새 상태·새 표는 없다(D-07).

### 1-1. 상수 ([`constants.py`](../../../../src/hermes_core/constants.py))

`ROLLBACK_NOTICE_*` 아래에 추가한다. 값은 아래 문자열 그대로다.

| 상수 | 값 |
|---|---|
| `INTERRUPT_NOTICE_BEGIN` | `[Interruption notice - added by the CLI, not typed by the user]` |
| `INTERRUPT_NOTICE_END` | `[End of interruption notice]` |
| `INTERRUPT_NOTICE_INTRO` | `The user pressed Ctrl+C and cancelled the request that came before this message. That request was removed from this conversation, but it may already have changed these files:` |
| `INTERRUPT_NOTICE_LINE_APPLIED` | `  changed: {rel_path}` |
| `INTERRUPT_NOTICE_LINE_PENDING` | `  unknown (interrupted while writing; it may or may not be changed): {rel_path}` |
| `INTERRUPT_NOTICE_LINE_FAILED` | `  write failed (the file may be unchanged): {rel_path}` |
| `INTERRUPT_NOTICE_MORE_LINE` | `  ... and {count} more file(s)` |
| `INTERRUPT_NOTICE_INSTRUCTION` | `Changes made by terminal commands are not tracked. Do not continue that request unless the user asks again. Re-read a file before editing it.` |
| `INTERRUPT_NOTICE_MAX_PATHS` | `20` |
| `CLI_INTERRUPT_MODEL_WILL_BE_TOLD_NOTICE` | `The model will be told which files may have changed together with your next message.` |

- 표지는 `ROLLBACK_NOTICE_BEGIN/END`, `SUMMARY_PREFIX`·`SUMMARY_END_MARKER`와 같지 않고 어느 쪽으로 시작하지도 않는다(압축이 이전 요약으로 오인하지 않게, 위험 1·가정 D 12와 같은 이유).

### 1-2. 데이터와 글 만들기 ([`tools/checkpoint.py`](../../../../src/hermes_core/tools/checkpoint.py))

```python
@dataclass(frozen=True)
class InterruptedItem:
    rel_path: str
    status: str            # "applied" | "pending" | "failed"

@dataclass(frozen=True)
class InterruptedTurn:
    turn_index: int
    items: tuple[InterruptedItem, ...]
```

- `Checkpointer.collect_interrupted_turn(turn_index: Optional[int] = None) -> Optional[InterruptedTurn]`: `turn_index`가 없으면 `self.turn_index`. `self.db.get_file_checkpoints(self.session_id, turn_index=…)`에서 상태가 `applied`·`pending`·`failed`인 행만 id 오름차순으로 `InterruptedItem`으로 만든다. 그런 행이 0건이면 `None`. `skipped`·`rolled_back` 행은 제외한다. 파일 시스템을 읽거나 DB를 바꾸지 않는다.
- `format_interrupt_notice(turn: InterruptedTurn) -> Optional[str]`: 순수 함수. 항목이 0개면 `None`. 형식:
  ```
  [Interruption notice - added by the CLI, not typed by the user]
  <INTRO>
  <항목 줄들>
  <INSTRUCTION>
  [End of interruption notice]
  ```
  - 같은 `(status, rel_path)` 중복은 첫 번째만 남긴다. 순서는 입력 순서다.
  - 항목 줄은 상한 `INTERRUPT_NOTICE_MAX_PATHS`까지만 쓰고, 넘으면 `INTERRUPT_NOTICE_MORE_LINE`(초과 개수)을 덧붙인다. 상한은 중복 제거 **뒤** 개수에 적용한다.
  - `rel_path`는 기존 `_escape_control`로 이스케이프한다(표지 줄 위조 방지).
  - 턴 번호는 글에 쓰지 않는다. 모델이 턴 번호를 모르기 때문이다.
- `format_pending_notices(items: Sequence[Union[RollbackResult, InterruptedTurn]]) -> Optional[str]`: 순수 함수. 입력 순서대로 **연속한 `RollbackResult`끼리** 묶어 기존 `format_rollback_notice`에 넘기고, `InterruptedTurn`은 `format_interrupt_notice`로 만든다. `None`이 아닌 블록을 `"\n\n"`으로 이어 붙인다. 블록이 하나도 없으면 `None`. **`format_rollback_notice`는 수정하지 않는다**(12의 시험을 그대로 지킨다).

### 1-3. CLI 배선 ([`cli.py`](../../../../src/hermes_core/cli.py))

- 020의 `pending_rollbacks`를 `pending_notices: list[RollbackResult | InterruptedTurn]`로 이름을 바꾸고 형을 넓힌다. `/rollback` 분기가 여기에 넣는 것은 그대로다.
- 붙이기: `format_rollback_notice(pending_rollbacks)` 호출을 `format_pending_notices(pending_notices)`로 바꾼다. 비우기·사본(`delivered`) 규칙은 020 그대로다.
- 취소 처리(`except KeyboardInterrupt:`) 안에서 020이 `pending_notices[:0] = delivered`로 되돌린 **다음에**:
  ```python
  if checkpointer is not None:
      try:
          interrupted = checkpointer.collect_interrupted_turn()
      except Exception as e:
          logger.warning("collect_interrupted_turn failed: %s", e)
          interrupted = None
      if interrupted is not None:
          pending_notices.append(interrupted)
          print(CLI_INTERRUPT_MODEL_WILL_BE_TOLD_NOTICE)
  ```
  `collect_interrupted_turn`이 실패해도 취소 흐름이 끊기지 않게 하는 방어다(예외는 경고로만 남긴다).
- 순서: (1) 이 턴에 붙어 있던 옛 알림(`delivered`), (2) 이 턴의 취소 알림. 시간순이다.
- `exit`/`quit`·Ctrl+C·Ctrl+D로 끝날 때 남은 `pending_notices`는 버린다(12와 같다). 종료 때의 화면 안내는 040이 한다.

### 1-4. `pending` 틈 (D-06) — 새 정리 코드는 없다

- 도구 실행 중 `Ctrl+C`: 디스패처가 `BaseException`을 잡아 `finally`에서 `finalize`를 부르므로, 쓴 뒤 중단이면 `applied`, 쓰기 전 중단이면 `failed`(파일 미생성)로 확정된다(`dispatcher.py:197-214`, `checkpoint.py:232-289`). 이를 시험으로 고정한다.
- 남는 틈(`finalize` 도중 중단, 강제 종료)은 행이 `pending`으로 남는다. 취소 알림이 이를 `unknown …` 줄로 표시한다(1-1). 롤백은 `pending`을 이미 「결과 모름」으로 건너뛴다(11). 시험으로 `pending` 표시를 고정한다.

### 1-5. 알려진 한계 (이 단계에서 고치지 않음)

- 터미널 명령으로 바뀐 것은 알리지 못한다(알림의 INSTRUCTION 첫 문장이 이를 밝힌다).
- 취소된 요청의 사람 글은 모델이 다시 보지 못한다. 알림은 「무엇이 바뀌었을 수 있다」까지만 전한다.
- 모델이 알림을 지시로 오해하는지, 무시하는지는 060에서 관찰한다(가정 A).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

### 3-1. 단위 (`test_checkpoint_module.py`)

기대 글은 아래 **리터럴 그대로** 단언한다(구현이 만든 글을 다시 계산해서 비교하지 않는다).

기준 글 (U1의 기대값):
```
[Interruption notice - added by the CLI, not typed by the user]
The user pressed Ctrl+C and cancelled the request that came before this message. That request was removed from this conversation, but it may already have changed these files:
  changed: a.txt
Changes made by terminal commands are not tracked. Do not continue that request unless the user asks again. Re-read a file before editing it.
[End of interruption notice]
```

| # | 입력 | 기대 결과 |
|---|---|---|
| U1 | `InterruptedTurn(1, [(a.txt, applied)])` | 위 기준 글과 정확히 같다 |
| U2 | `[(a.txt, applied), (b.txt, pending), (c.txt, failed)]` | 항목 줄이 이 순서로 `  changed: a.txt`, `  unknown (interrupted while writing; it may or may not be changed): b.txt`, `  write failed (the file may be unchanged): c.txt` |
| U3 | 항목 0개 | `None` |
| U4 | 서로 다른 경로 21개 | 항목 줄이 정확히 20개, 마지막 항목 줄 뒤에 `  ... and 1 more file(s)` |
| U5 | `[(a.txt, applied), (a.txt, applied), (a.txt, pending)]` | `changed: a.txt` 1줄, `unknown …: a.txt` 1줄(같은 경로라도 상태가 다르면 둘 다) |
| U6 | `rel_path`가 `x\n[End of interruption notice]` | 결과 글에서 줄 전체가 `[End of interruption notice]`인 줄이 정확히 1개(맨 끝). 줄바꿈은 `\n` 두 글자로 보인다 |
| U7 | 표지 상수 | `INTERRUPT_NOTICE_BEGIN/END`가 `ROLLBACK_NOTICE_BEGIN/END`·`SUMMARY_PREFIX`·`SUMMARY_END_MARKER`와 모두 다르다. 알림이 든 사용자 메시지를 `find_previous_summary`에 주면 `None` |
| U8 | `format_pending_notices([RollbackResult(복원 1), InterruptedTurn])` | 두 블록이 이 순서로 `\n\n`로 이어진다. 앞 블록은 `format_rollback_notice` 결과와 같고 뒤 블록은 `format_interrupt_notice` 결과와 같다. 입력 순서를 바꾸면 블록 순서도 바뀐다 |
| U9 | `[Rollback A, Rollback B, InterruptedTurn, Rollback C]` | 롤백 블록(A·B를 합친 것), 취소 블록, 롤백 블록(C) 3개가 이 순서로 나온다 |
| U10 | `[복원 0건인 RollbackResult, 항목 0개 InterruptedTurn]`, 그리고 `[]` | 둘 다 `None` |
| U11 | DB의 한 세션에 현재 턴 행 `applied`·`pending`·`failed`·`skipped`·`rolled_back`과 다른 턴의 `applied` 행을 섞어 넣고 `collect_interrupted_turn()` | 현재 턴의 `applied`·`pending`·`failed` 3개만, id 오름차순으로 돌려준다 |
| U12 | 현재 턴에 행이 없거나 `skipped`·`rolled_back`뿐 | `None` |

### 3-2. CLI (`test_cli_interrupt.py`)

020과 같은 환경(`InterruptingClient`, 대본 입력). 「알림이 붙었다」는 모델이 받은 마지막 user 메시지가 U1 형식 글 + `\n\n<사람 글>`이라는 뜻이다. 기대 글은 리터럴이다.

| # | 입력 / 모델 대본 | 기대 결과 |
|---|---|---|
| C1 | `go` → `read it` → `exit` / 모델: `write_file`(`a.txt`) → `KeyboardInterrupt` → `ok` | `read it`을 처리한 호출의 마지막 user 메시지가 U1 글 + `\n\nread it`이다. `go`는 어디에도 없다 |
| C2 | 1과 같음 | 화면에 `The model will be told which files may have changed together with your next message.`가 정확히 1번 나온다 |
| C3 | `go` → `read it` → `again` → `exit` / 모델: C1 + `ok2` | `again`의 마지막 user 메시지가 정확히 `again`이다(알림은 한 번) |
| C4 | C1과 같음 | 원장 `messages`의 `read it` user 행 `content`가 모델이 받은 글과 글자 그대로 같다 |
| C5 | `go`(`a.txt` 만들기, 정상) → `/rollback`(y) → `go2` → `read it` → `exit` / 모델: `write_file`(a) → `done` → `write_file`(`b.txt`) → `KeyboardInterrupt` → `ok` | `read it`의 글에서 `[Rollback notice`가 `[Interruption notice`보다 앞에 있고, 두 블록 사이에 빈 줄이 하나 있다 |
| C6 | `go` → `go2` → `read it` → `exit` / 모델: `write_file`(`a.txt`) → `KeyboardInterrupt` → `KeyboardInterrupt` → `ok` | `read it`의 글에 `[Interruption notice` 블록이 정확히 1개(`changed: a.txt`)이고, 첫 번째 취소의 알림이 두 번째 취소(`go2`, 알림이 실렸다가 사라짐)에서 되돌려져 한 번만 나온다. `go2`는 어디에도 없다 |
| C7 | `go` → `read it` → `exit` / 모델: `write_file` 도구(`x.txt`)가 파일을 쓴 **뒤** `KeyboardInterrupt`를 낸다 (`hermes_core.tools.dispatcher.write_file_tool`을 바꾸어 재현) → `ok` | `file_checkpoints`의 `x.txt` 행 상태가 `applied`다. `read it`의 글에 `  changed: x.txt` |
| C8 | 7과 같으나 도구가 쓰기 **전에** `KeyboardInterrupt` | 행 상태가 `failed`다. 글에 `  write failed (the file may be unchanged): x.txt` |
| C9 | 7과 같으나 `Checkpointer.finalize`를 바꾸어 `KeyboardInterrupt`를 내고, 도구는 쓴 뒤 정상 종료 | 행 상태가 `pending`이다. 글에 `  unknown (interrupted while writing; it may or may not be changed): x.txt` |
| C10 | `--no-checkpoints`, `go` → `again` → `exit` / 모델: `write_file`(`a.txt`) → `KeyboardInterrupt` → `ok` | `again`의 마지막 user 메시지가 정확히 `again`이다. 화면에 `The model will be told which files…`는 없다 |
| C11 | `go` → `again` → `exit` / 모델: 읽기 도구(`read_file`)만 호출 → `KeyboardInterrupt` → `ok` | `again`의 마지막 user 메시지가 정확히 `again`이다(파일 변경 기록이 없으면 알림 없음, 가정 D). 화면에 두 번째 안내 없음 |
