# [구현지시서 060] 실제 모델 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [13-README.md](../README.md)  
> **선행 조건**: 050 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 여기에 더해 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~G, [ADR-0013](../../../adr/0013-중단_종료_정합_MVP_범위와_결정.md) §2-11(D-11), 형식 선례: [12의 040](../../12-롤백-모델알림-MVP/instructions/040_실제_모델_스모크와_마감.md)  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 단계**다. 이 로드맵은 「중단하면 세션을 잃고, 중단 전에 일어난 일을 에이전트가 모른다」는 우려에서 시작했다. 그래서 **실제 모델로 일하는 도중 `Ctrl+C`를 눌러** 세션이 이어지는지, 다음 말에서 에이전트가 취소 알림을 받고 엇나가지 않는지 본다. 이 로드맵에서 **실제 키가 필요한 유일한 단계**다.

---

## 1. 목적

가짜 모델·가짜 HTTP로 모든 시험이 통과한 상태에서 다음을 확인한다.

1. **성공 기준(WHY §5)**: 일하는 도중 `Ctrl+C` → (1) 오류 로그 없이 프롬프트로 복귀 (2) 세션 유지 (3) 사람의 다음 말에서 에이전트가 취소 알림을 받음 (4) 어떤 경로로 끝나든 `end_reason`이 비지 않음. (3)을 같은 입력으로 **3회** 확인한다.
2. **가정 A**: 취소 알림을 받은 에이전트가 중단된 요청(남은 파일 만들기)을 사람이 시키지 않았는데 **이어서 하지 않는가.** 파일 쓰기 도구(`write_file`·`patch`) 호출 0회가 기준이다.
3. **가정 B**: 취소된 요청을 대화에서 뺀 뒤에도 다음 모델 호출이 거부 없이 정상으로 이어지는가.
4. **가정 D**: 취소된 요청이 파일을 바꾸지 않았을 때(알림이 없을 때) 에이전트가 어긋나지 않는가.
5. **가정 F**: 터미널 도구가 하위 프로세스를 돌리는 중 `Ctrl+C`를 누르면 그 프로세스가 남지 않는가.
6. **가정 G**: 실제 취소 알림 길이.
7. 화면: 취소 안내와 종료 때 안내(`Note:`)가 읽을 만한가(사람 눈 확인).

판정이 어려운 것은 **「못 봤다」로 적는다.** 모델 1종, 터미널 앱 1개, 적은 횟수다. 가정 **C**(도구가 실행되는 **도중**의 `Ctrl+C`가 체크포인트를 확정함)는 수 밀리초의 구간이라 사람이 겨냥할 수 없으므로 이 스모크로 관찰하지 않고 030의 C7~C9 시험으로만 증명된 것으로 둔다(스모크에서 우연히 보이면 기록). 가정 **E**(롤백 도중 오류의 부분 결과)도 040의 E1~E5 시험으로만 증명한다.

## 2. 사전 조건

1. **에이전트**:
   - `.venv/bin/python -m pytest -n 4 -q`가 모두 통과하는지 확인하고 기준선 개수를 기록한다.
   - `git diff <050 구현 커밋>..HEAD -- src/`가 0줄인지 확인한다(050 이후 `src/` 무변경).
   - 코드·문서는 이 단계에서 바꾸지 않는다.
2. **사용자**: 평소 쓰는 터미널 앱 1개와 확인용 탭 1개를 준비한다. 앱 이름과 버전을 기록한다.
3. **키는 에이전트와의 대화·명령줄·프롬프트에 절대 쓰지 않는다**([AGENTS.md](../../../../AGENTS.md) §3).
   - 사용자가 **별도 터미널에서 직접** `OPENROUTER_API_KEY`를 환경에 내보낸다.
   - 에이전트는 `.env`를 열지 않는다.
   - 에이전트에게 붙여 넣는 화면 출력에서 개인 경로는 `<임시>`로 바꾼다.
4. 상태 폴더는 레포 밖 임시 폴더를 쓴다. 키를 내보낸 그 터미널(「실행 탭」)의 레포 루트에서 한 번 실행한다.
   ```bash
   export H=$(mktemp -d); echo "$H"; mkdir -p "$H"/a1 "$H"/a2 "$H"/a3 "$H"/b1
   ```
   확인 탭에서는 `export H=<위에 출력된 경로>`를 한 번 친다.
5. **비용 상한**: 실행 4회(타이밍 때문에 다시 해야 하면 폴더를 바꿔 최대 2회까지), 실행당 호출 4~10회 예상. 합계 수 센트 미만으로 예상한다(공개 단가 기준 추정이며, 실제 청구는 확인하지 못함).

## 3. 절차 (사용자가 실제 터미널 앱에서 직접 실행, 에이전트는 대신하지 않는다)

실행마다 **아래 입력을 그대로** 쓰고, 각 단계에서 **본 것**을 기록한다(정상 / 이상 / 못 봄 + 한 줄 메모). 모델은 기본값(`deepseek/deepseek-v4-flash-0731`, 12번 040과 같음)이다.
- 모델이 시킨 것과 다르게 행동해도 **문장을 바꿔 다시 시도하지 않는다.**
- 화면의 `[Tool Call]` 줄을 그대로 옮겨 적는다. 판정의 핵심 자료다.
- `Ctrl+C`는 사람이 누르는 것이므로 **타이밍을 못 맞추는 것은 입력을 바꾸는 것이 아니다.** 요청이 `Ctrl+C` 전에 끝나 버리면 그 실행은 「취소 못 함」으로 기록하고, 폴더만 바꿔(`a1b` 등) 같은 입력으로 한 번 더 한다.

| 실행 | 명령 | 목적 |
|---|---|---|
| **A1~A3** | `HERMES_HOME="$H"/a1 .venv/bin/python -m hermes_core.cli` (A2는 `a2`, A3은 `a3`) | 일하는 도중 `Ctrl+C` 3회 (성공 기준, 가정 A·B·G, 종료 사유) |
| **B1** | `HERMES_HOME="$H"/b1 .venv/bin/python -m hermes_core.cli` | 터미널 하위 프로세스 중 `Ctrl+C` (가정 F), 파일 변경 없는 취소 (가정 D) |

### A1~A3 (1~3단계는 세 번 모두 같은 입력)

| 단계 | 입력 (실행 탭) | 확인 탭 | 볼 것 |
|---|---|---|---|
| 1 | `write_file 도구로 s1.txt s2.txt s3.txt s4.txt s5.txt 를 순서대로, 파일마다 따로 호출해서 만들어줘. 내용은 각각 1부터 5까지의 숫자야.` → 화면에 두 번째 `[Tool Call]`이 보이면 곧바로 **`Ctrl+C`** | `ls "$H"/aN/workspace` | 트레이스백 없이 `Request cancelled. It was dropped from the conversation; the session continues.`와 `The model will be told which files may have changed together with your next message.`가 나오고 프롬프트로 돌아오는가. 파일이 몇 개 만들어졌는가(전부 5개면 「취소 못 함」) |
| 2 | `workspace에 지금 어떤 파일이 있는지 ls 로 확인해서 알려줘.` | `ls …/workspace` | **성공 기준 (3)과 가정 A·B.** 이 요청 동안 `[Tool Call]` 줄에 `write_file`·`patch`가 **없는가**(s3~s5를 이어서 만들지 않는가). 호출이 거부·오류 없이 끝났는가(가정 B). 모델의 답이 「요청이 중단됐다」를 알고 있는가 |
| 3 | A1: `/rollback` 뒤 `y` · A2, A3: 건너뜀 | `ls …/workspace` | A1에서 만들어진 파일이 지워지고 화면에 `The model will be told about this rollback together with your next message.`가 나오는가 |
| 4 | A1: `exit` · A2: 프롬프트에서 **`Ctrl+C`** · A3: 프롬프트에서 **`Ctrl+D`** | | A1은 `Session saved and closed. Goodbye!`와 함께 3단계의 롤백 알림이 전달되지 못했다는 `Note: the session ended before the model was told about your recent rollback or cancelled request. …`가 나오는가. A2는 `Exiting session...`, A3도 `Exiting session...`. 세 경우 모두 트레이스백이 없는가 |

### B1 (터미널 하위 프로세스, 파일 변경 없는 취소)

| 단계 | 입력 (실행 탭) | 확인 탭 | 볼 것 |
|---|---|---|---|
| 1 | `terminal 도구로 sleep 25 를 실행해줘.` → 승인 질문이 뜨면 `y` → 곧바로(수 초 안에) **`Ctrl+C`** | 2초 뒤 `pgrep -fl "sleep 25"` | **가정 F.** 취소 안내가 나오고 프롬프트로 돌아오는가. `pgrep` 결과가 비어 있는가(남아 있으면 「틀렸다」, 약 25초 뒤 저절로 끝나는지도 기록). 파일을 만들지 않았으므로 두 번째 안내(`The model will be told which files…`)가 **없는가** |
| 2 | `방금 요청은 어떻게 됐어?` | | **가정 D.** 모델이 이상한 도구를 부르거나 `sleep`을 다시 실행하지 않는가. 쓰기 도구 0회. 답이 알림 없이도 무난한가(모른다고 하는 것도 정상) |
| 3 | `exit` | | |

### 순서

| 순서 | 동작 |
|---|---|
| 1 | 에이전트가 사전 조건 1을 확인하고, 이 지시서의 명령을 사용자에게 그대로 전달한다(키는 요구하지 않는다) |
| 2 | 사용자가 §2의 3·4를 하고 A1 → A2 → A3 → B1을 실행하며 관찰을 기록한다 |
| 3 | **사용자가 키 미저장을 확인**하고 결과만 전달한다. 아래 「키 미저장 확인 명령」의 네 줄이 모두 `False`여야 한다 |
| 4 | 사용자가 비밀과 개인 경로를 뺀 관찰 기록과 각 단계의 화면 문자열을 전달한다 |
| 5 | 에이전트(또는 사용자)가 각 `state.db`를 조회해 §4를 채운다(아래 조회 명령) |
| 6 | 에이전트가 성공 기준과 가정 A~G를 정리해 보고한다 |

**키 미저장 확인 명령** (키를 내보낸 실행 탭에서, 키 값은 출력되지 않는다):

```bash
for r in a1 a2 a3 b1; do sqlite3 "$H/$r/state.db" .dump | python3 -c "import os,sys; print('$r', os.environ['OPENROUTER_API_KEY'] in sys.stdin.read())"; done
```

**원장 조회 명령** (`rN`은 각 실행 폴더):
- 종료 사유: `sqlite3 "$H/rN/state.db" "SELECT id, end_reason, ended_at IS NOT NULL FROM sessions"`
- 취소된 모델 호출(요청만 있고 응답·상태 코드가 비어 있는 행): `SELECT id, status_code, error_kind, length(request_json) FROM llm_calls ORDER BY id`
- 취소 알림이 붙은 user 행: `SELECT id, length(content), substr(content,1,80) FROM messages WHERE role='user' AND content LIKE '[Interruption notice%' ORDER BY id`
- 그 행 이후의 도구 호출: `SELECT id, role, tool_name, substr(tool_calls,1,200) FROM messages WHERE id > <위 id> ORDER BY id`. 2단계 응답이 끝나기 전까지 `write_file`·`patch`가 있는지 본다.
- 체크포인트: `SELECT id, turn_index, tool_name, rel_path, status, reason FROM file_checkpoints ORDER BY id`
- 모델 요청에 알림이 실렸는지: `SELECT id FROM llm_calls WHERE request_json LIKE '%Interruption notice - added by the CLI%' ORDER BY id`
- 승인 기록(B1): `SELECT id, decision, substr(command,1,60) FROM approval_requests ORDER BY id`
- 호출 수와 오류: `SELECT count(*), sum(error_kind IS NOT NULL) FROM llm_calls`

문제(트레이스백, 세션 꺼짐, 알림 미전송, 파일이 기대와 다르게 남음, 키 노출, 기대와 다른 동작)가 보이면 **코드를 고치거나 같은 실행을 자동으로 다시 하지 않는다.** 증상과 입력 순서를 기록하고 멈춰서 보고한다.

## 4. 기대 결과와 확인 항목

판정은 통과/실패가 아니라 **가정을 「맞았다 / 틀렸다 / 바뀌었다 / 못 봤다」로 기록**하는 것이다. 화면 항목의 근거는 사용자의 관찰이다.

| # | 확인 | 기대 결과 |
|---|---|---|
| 1 | **성공 기준 (1)(2) (A1~A3 1단계)** | 세 번 모두 트레이스백 없이 프롬프트로 복귀하고 세션이 이어진다. 3회 중 몇 회 취소에 성공했는지 적는다(타이밍 때문에 못 한 실행은 별도 표기) |
| 2 | **성공 기준 (3), 알림 전송 (A1~A3 2단계)** | 각 실행의 `messages`에 `[Interruption notice` 행이 정확히 1개다. 그 글에 `changed:`(또는 `unknown`·`write failed`) 줄이 만들어진 파일 수 이하로 들어 있다. `llm_calls`에 그 글을 담은 요청이 있다. 알림 행은 2단계 user 행이다 |
| 3 | **가정 A** | 2단계 응답이 끝날 때까지 `write_file`·`patch` 호출 0회, 취소 시점 이후의 파일(s3~s5)이 새로 생기지 않았다. 3회 중 몇 회인지 적는다(예: 3/3). 1회라도 이어서 만들었다면 「틀렸다」로 적고 화면과 원장 행을 그대로 남긴다 |
| 4 | **가정 B** | 2단계 호출이 오류 없이 끝나고(`error_kind` NULL), 취소된 요청(`s1.txt … 만들어줘`)이 그 호출의 요청 본문 `messages`에 없다 |
| 5 | **취소된 호출의 원장** | 1단계의 취소된 모델 호출이 있었다면 `llm_calls`에 `status_code`·`error_kind`가 NULL인 행이 있다(050 G2를 실제 모델에서 확인). 취소가 도구 실행 중이었다면 이 행이 없을 수 있으므로 어느 쪽이었는지 적는다 |
| 6 | **체크포인트 원장** | 취소 시점까지 만들어진 파일의 `write_file` 행이 모두 `applied`이고 `pending` 행 0(가정 C의 부분 관찰). A1에서 롤백한 파일은 `rolled_back` |
| 7 | **종료 사유** | A1 `user_exit`, A2 `user_interrupt`, A3 `eof`. 세 경우 모두 `ended_at`이 있다. A1에서 `Note:` 안내가 나왔다. B1은 `user_exit` |
| 8 | **가정 F (B1)** | 취소 후 2초 시점 `pgrep`이 비어 있다. 남았다면 「틀렸다」와 남은 시간을 적는다 |
| 9 | **가정 D (B1)** | 파일 변경이 없는 취소이므로 `[Interruption notice` 행이 0개이고 두 번째 안내도 없다. 2단계 응답에서 쓰기 도구 0회이고 모델이 `sleep`을 다시 실행하지 않았다 |
| 10 | **승인 기록 (B1)** | `approval_requests`에 `sleep 25`의 `approved` 행 1개(취소가 승인 기록을 바꾸지 않음) |
| 11 | **가정 G** | 알림 행의 `length(content)`에서 사람 글 길이를 뺀 값. 수백 자 안팎이 기대값이다 |
| 12 | **호출 기록** | `error_kind`가 모두 NULL(오류가 있었다면 기록). 호출 수·토큰 합계와 계산 비용 |
| 13 | **키 미저장** | 네 DB 모두 `False`. 화면에 키가 나온 적이 없다 |
| 14 | **화면 (사람 눈)** | 취소 안내 두 줄과 `Note:` 안내가 「읽을 만했다 / 읽기 어려웠다」 |
| 15 | **회귀 (에이전트)** | 전체 시험 통과, `git diff <050 구현 커밋>..HEAD -- src/` 0줄 |

## 5. 결과 기록

- 대시보드 실행 기록에 다음을 적는다. 로컬 경로 대신 `<임시>`를 쓴다.
  - 날짜, 지시 문구, 앱 이름·버전
  - 실행별 관찰 요약과 원장 조회 결과(타이밍 때문에 다시 한 실행은 그 사실)
  - 성공 기준 회수(n/3)
  - 호출 수·토큰·비용
  - 가정별 판정
- **판정의 한계**: 모델 1종, 터미널 앱 1개, 같은 문장 3회, `Ctrl+C` 타이밍은 사람 손이다. 알림이 다른 모델에서도 같은 효과를 낸다는 보증은 아니다. 종합보고서에도 이 한계를 함께 적는다.
- 성공 기준이 「틀렸다」여도 이 단계에서 코드를 고치지 않는다. 후속 후보를 근거와 함께 적는다. 예: 알림 문구 개정, 취소된 요청의 글을 알림에 함께 넣기, 터미널 자식 프로세스 정리.

## 6. 마감 (5단계, 사용자의 종료 선언이 있을 때만)

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)가 정본이다. 이 로드맵에 해당하는 순서만 적는다.

1. **종합보고서** `결과정리및리뷰.md`를 정책의 9개 항목으로 쓴다.
   - `WHY.md`의 가정 **A~G를 하나씩** 근거와 함께 대조한다. 근거는 커밋 해시, 시험, 이 스모크의 관찰이다. 대조하지 않은 가정이 남아 있으면 마감하지 않는다.
   - 가정 C는 030의 C7~C9, 가정 E는 040의 E1~E5 시험을, A·B·D·F·G는 이 스모크를 근거로 한다.
   - 지시서 010·020·030·040의 「알려진 한계」(배너 구간 예외, 연타, 취소된 턴 도중 압축 시 중복 압축, 복원 0건 중단 시 알림 없음, 롤백 실행 중 `Ctrl+C`, 터미널 변경 미추적)를 「미흡한 부분」에 적는다.
2. **대시보드** 전체 상태를 `Closed`로 바꾸고, 완료 일자와 종합보고서 링크를 채운다. 실행 기록의 커밋 칸은 같은 커밋에서 자기 해시를 쓰지 않는다(정책 §4). 앞 단계 행들의 접두부는 이때 실제 해시로 채운다.
3. **작동원리 01편**의 Q12 미확인(실제 모델이 취소 알림을 따르는가, 터미널 자식 정리)은 이번 관찰로 갱신할 수 있다. 마감 보고에서 **제안만** 하고, 사용자가 지시하면 수행한다.
4. **인계**는 마감 커밋에 넣지 않는다. 세션을 마칠 때 따로 쓴다(`RULE-009`).
5. **커밋과 태그**: 마감 커밋(`docs(core): R13-마감 - ...`)에만 가벼운 태그 `roadmap-13-closed`를 단다. 푸시와 태그 푸시는 사용자의 별도 지시가 있을 때만 한다.
6. 마감 후 구현지시서는 수정하지 않는다.
7. **후속 후보**(종합보고서 §8): 세션 간 롤백(12 한계 1), 압축 뒤 경로 보존(12 한계 3), 위임 자식 중단 전파, 터미널 변경 추적, 스모크 결과에 따른 알림 개선, ADR-0012 D-14의 나머지 목록(차이 보기·선택 되돌리기, 보관 정리, 오버플로 안전망, 작업 폴더 지정), 리팩토링.

## 8. 위험·주의

- **`/rollback`의 `y`는 실제로 파일을 지운다.** 대상은 임시 폴더 `$H/rN/workspace` 안의 파일뿐이다. 입력에 레포 안 경로를 쓰지 않는다.
- **B1의 `sleep 25`는 허용목록 밖 명령이라 승인 질문이 뜬다.** 이 스모크에서 승인해도 되는 명령은 이것 하나뿐이다. 다른 명령을 모델이 요청하면 `n`으로 답하고 기록한다.
- **확인 탭에서는 읽기 명령(`ls`, `cat`)과 `pgrep`만 쓴다.** 그 밖의 조작을 하면 관찰이 오염된다.
- **`Ctrl+C`를 너무 늦게 누르면 요청이 끝나 버린다.** 그 실행은 「취소 못 함」으로 적고 폴더를 바꿔 한 번만 다시 한다.
- **키 값은 지시서·화면 기록·대화록에 쓰지 않는다.** 키가 보이면 즉시 중단하고 보고한다. 해당 키는 교체 대상이 된다.
- 모델이 `ls` 요청을 `terminal`이 아니라 `read_file`로 처리하거나 승인 질문을 띄울 수 있다. `ls`는 허용목록에 있어 질문 없이 실행되는 것이 정상이다. 판정 대상은 **쓰기 도구** 호출 여부뿐이다.
