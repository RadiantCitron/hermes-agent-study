## 1. 구현 내용 명세

### 1-1. 한계 4: `execute_rollback`이 예외에도 부분 결과를 돌려준다 ([`tools/checkpoint.py`](../../../../src/hermes_core/tools/checkpoint.py))

**코드로 확인한 현재 모양**: 파일 하나를 복원하는 데서 나는 오류(읽기·쓰기·삭제·경로 검사)는 이미 항목별로 잡아 `skipped`로 기록한다(`checkpoint.py:530-600`). 밖으로 새는 것은 그 밖의 예외, 예를 들어 복원은 끝났는데 원장 갱신(`update_file_checkpoint(…, rolled_back)`)이 DB 오류로 실패하는 경우다. 그러면 `execute_rollback`이 통째로 예외를 던져 결과 객체가 없고, 이미 복원된 파일이 있어도 알림이 가지 않는다.

- `RollbackResult`에 필드 `error: Optional[str] = None`을 **맨 뒤에** 추가한다(기본값이 있어 기존 생성 코드와 시험은 그대로 동작한다).
- `execute_rollback`의 `for item in plan.items:` 루프 **전체를** `try: … except Exception as e:`로 감싼다. 루프 본문은 들여쓰기 한 단계 외에 바꾸지 않는다(`git diff -w`로 확인).
- `except` 안: 이미 처리된 항목은 `item_results`에 담겨 있다. 처리 중이던 항목의 위치는 `len(item_results)`다(각 항목은 끝에서 정확히 하나의 결과를 추가한다). 거기서부터 남은 항목 전부를 `action="skipped"`, `status=CHECKPOINT_STATUS_SKIPPED`로 `item_results`에 덧붙이고 `skipped_count`를 올린다.
  - 처리 중이던 첫 항목의 `reason`: `CHECKPOINT_ROLLBACK_ABORTED_HERE_REASON.format(error=str(e))` (복원 여부를 알 수 없음)
  - 그 뒤 항목의 `reason`: `CHECKPOINT_ROLLBACK_NOT_REACHED_REASON` (건드리지 않음)
  - **이 항목들의 원장(DB) 행은 갱신하지 않는다.** 처리 못 한 항목의 행은 `applied`로 남아 다음 `/rollback`이 다시 시도할 수 있다. 이미 DB가 실패한 마당에 또 쓰지 않는다.
- 그런 다음 평소처럼 `RollbackResult(…, error=str(e))`를 돌려준다. 성공 경로는 `error=None`이다.
- `KeyboardInterrupt`는 잡지 않는다(`Exception`만). 롤백 **실행 도중** `Ctrl+C`는 이 단계의 범위가 아니다(1-4).

### 1-2. 한계 4: 화면 안내 ([`cli.py`](../../../../src/hermes_core/cli.py) `_handle_rollback`)

- `result.error`가 있으면 결과 출력(`CLI_ROLLBACK_RESULT_SUMMARY`) 뒤에 `CLI_ROLLBACK_ABORTED_NOTICE.format(reason=result.error)`를 출력한다.
- 반환은 그대로 `result`다. 알림은 `format_rollback_notice`가 복원된 항목과 건너뛴 항목(위 두 사유)을 담아 다음 메시지 앞에 붙인다. 복원이 0건이면 지금처럼 알림은 없다(1-4).

### 1-3. 한계 2: 알림이 가기 전에 끝날 때 화면 안내 ([`cli.py`](../../../../src/hermes_core/cli.py) `main`)

**근거(ADR §2-9)**: 되돌린 사실은 `file_checkpoints`에 이미 남아 있고, 세션 이어받기가 없어 끝난 세션의 모델은 다시 쓰이지 않는다. 원장을 더 늘리지 않고 화면에만 알린다.

- `pending_notices`의 정의를 대화 루프 `try:` **앞**으로 옮긴다(`finally`에서 쓰기 위해, 예외로 일찍 끝나도 이름이 있도록).
- `finally`에서 `_close_session(...)` **앞에** 아래를 둔다.
  ```python
  if format_pending_notices(pending_notices) is not None:
      print(CLI_UNSENT_NOTICE_ON_EXIT)
  ```
  보낼 알림이 실제로 만들어질 때만 안내한다(복원 0건인 롤백 결과나 취소·미실행은 안내하지 않는다). 종료 경로(`exit`·`Ctrl+C`·`Ctrl+D`·예외)와 무관하게 한 곳에서 처리한다.
- 출력 순서: `exit`이면 `Session saved and closed. Goodbye!` 뒤에 나온다. 순서는 시험하지 않는다.

### 1-4. 상수 ([`constants.py`](../../../../src/hermes_core/constants.py))

| 상수 | 값 |
|---|---|
| `CHECKPOINT_ROLLBACK_ABORTED_HERE_REASON` | `롤백 중 오류로 중단됨, 파일이 복원됐는지 알 수 없음 ({error})` |
| `CHECKPOINT_ROLLBACK_NOT_REACHED_REASON` | `앞선 항목의 오류로 롤백이 중단되어 처리되지 않음` |
| `CLI_ROLLBACK_ABORTED_NOTICE` | `Rollback stopped early because of an error ({reason}). Items not processed stay as they were; run /rollback again to retry them.` |
| `CLI_UNSENT_NOTICE_ON_EXIT` | `Note: the session ended before the model was told about your recent rollback or cancelled request. The file changes themselves stay recorded in the checkpoint ledger.` |

사유 문구는 한국어다. 기존 건너뜀 사유(`복원 직전 충돌(외부 변경 감지)` 등)가 한국어로 원장과 알림에 들어가는 선례를 따른다.

### 1-5. 알려진 한계 (이 단계에서 고치지 않음)

- **복원이 0건인 채 중단**(예: 첫 항목의 원장 갱신이 실패): `rolled_back_count == 0`이라 알림이 만들어지지 않는다. 그 항목의 파일이 실제로 복원됐어도 모델은 모른다. DB가 첫 쓰기부터 실패하는 극히 드문 경우라 두지 않는다.
- **처리 중이던 항목의 알림 문구**: 알림 줄 머리말이 「skipped (your change is still in this file)」라서, 복원됐을 수도 있는 항목에는 맞지 않는다. 뒤에 붙는 사유(`… 알 수 없음`)와 알림 끝의 「고치기 전에 다시 읽어라」로 보완된다. 12번 알림 형식은 수정하지 않는다.
- **롤백 실행 도중 `Ctrl+C`**: `execute_rollback`이 끝나기 전에 `KeyboardInterrupt`가 오면 지금처럼 밖으로 나가 `error`로 기록된다. 질문 단계의 `Ctrl+C`는 이미 취소 처리된다. 실행 구간은 파일 몇 개를 쓰는 짧은 구간이라 이번에는 다루지 않는다.
- 한계 2는 안내일 뿐이다. 모델에게 알림을 전달하는 것은 아니다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

기대 글은 리터럴로 단언한다.

### 3-1. 단위

공통 준비: `Checkpointer`를 쓰는 임시 작업 폴더에서 한 턴 동안 `a.txt`, `b.txt`, `c.txt`를 `write_file`로 새로 만든다(세 행 모두 `applied`). `plan_rollback()`으로 계획을 얻는다. 역순 복원이므로 처리 순서는 `c.txt` → `b.txt` → `a.txt`다. 「두 번째 갱신 실패」는 `SessionDB.update_file_checkpoint`를 바꾸어 `status`가 `rolled_back`인 호출의 **두 번째**에서 `RuntimeError("disk full")`를 내게 하는 것이다(첫 번째 호출은 원래대로).

| # | 상황 | 기대 결과 |
|---|---|---|
| E1 | 위 준비 + 두 번째 갱신 실패 → `execute_rollback(plan)` | 예외 없이 돌아온다. `items`는 3개이고 순서는 `c.txt`(deleted, `rolled_back`) → `b.txt`(skipped) → `a.txt`(skipped). `rolled_back_count == 1`, `skipped_count == 2`, `error == "disk full"`. `b.txt`의 `reason == "롤백 중 오류로 중단됨, 파일이 복원됐는지 알 수 없음 (disk full)"`, `a.txt`의 `reason == "앞선 항목의 오류로 롤백이 중단되어 처리되지 않음"`. 디스크에는 `c.txt`가 없고 `b.txt`도 없다(삭제는 갱신 전에 일어남), `a.txt`는 남아 있다 |
| E2 | E1 직후 원장 행 | `c.txt` 행 `rolled_back`, `b.txt`·`a.txt` 행은 여전히 `applied`다(실패 뒤 원장을 더 쓰지 않음) |
| E3 | 첫 번째 갱신부터 실패 | 모든 항목이 `skipped`이고 `rolled_back_count == 0`, `error == "disk full"`. 첫 항목은 「…알 수 없음 (disk full)」, 나머지는 「…처리되지 않음」 |
| E4 | 오류 없는 정상 롤백 | `error is None`. 나머지 필드는 변경 전과 같다(`rolled_back_count == 3`, `skipped_count == 0`) |
| E5 | E1의 결과를 `format_rollback_notice`에 넣음 | 글에 `  deleted: c.txt` 줄과, `  skipped (your change is still in this file): b.txt - 롤백 중 오류로 중단됨, 파일이 복원됐는지 알 수 없음 (disk full)` 줄과, `  skipped (your change is still in this file): a.txt - 앞선 항목의 오류로 롤백이 중단되어 처리되지 않음` 줄이 이 순서로 들어 있다 |

### 3-2. CLI (`test_cli_interrupt.py`)

020·030과 같은 환경. 「부분 롤백」 재현은 E1과 같은 방식(`SessionDB.update_file_checkpoint`를 바꿔 두 번째 `rolled_back` 갱신에서 `RuntimeError("disk full")`)이다.

| # | 입력 / 모델 대본 | 기대 결과 |
|---|---|---|
| F1 | `go` → `/rollback`(y) → `read it` → `exit` / 모델: 세 파일을 만드는 `write_file` 3회 → `done` → `ok`. 두 번째 롤백 갱신 실패 | 화면에 `Rollback stopped early because of an error (disk full). Items not processed stay as they were; run /rollback again to retry them.`가 1번 나온다. `read it`의 마지막 user 메시지가 `[Rollback notice`로 시작하고 `  deleted: c.txt`와 E5의 두 `skipped` 줄을 포함하며 `\n\nread it`으로 끝난다(한계 4 해결) |
| F2 | 정상 롤백(`go` → `/rollback`(y) → `exit`) | 화면에 `stopped early`가 없다 |
| F3 | `go`(`a.txt` 만들기) → `/rollback`(y) → `exit` | 화면에 `Note: the session ended before the model was told about your recent rollback or cancelled request. The file changes themselves stay recorded in the checkpoint ledger.`가 정확히 1번 나온다. `end_reason == "user_exit"`, 롤백 이후 모델 호출은 늘지 않았다. `file_checkpoints`의 행은 `rolled_back` |
| F4 | `go` → `/rollback`(n, 취소) → `exit` | 위 `Note:`가 없다 |
| F5 | `go` → `/rollback`(y) → (프롬프트에서 `KeyboardInterrupt`) | `Note:`가 1번 나오고 `end_reason == "user_interrupt"`다 |
| F6 | `go` → `exit` / 모델: `write_file`(`a.txt`) → `KeyboardInterrupt`(취소) | 취소 알림이 보내지기 전에 종료하므로 `Note:`가 1번 나온다 |
| F7 | `go`(`a.txt` 만들기) → 사람이 `a.txt`를 직접 고침 → `/rollback`(y, 전부 건너뜀) → `exit` | 복원이 0건이라 알림이 만들어지지 않으므로 `Note:`가 없다 |
