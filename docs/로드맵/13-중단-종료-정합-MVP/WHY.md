## 1. 왜 지금 이 로드맵인가

12번까지로 에이전트는 파일을 고치고, 사람은 그것을 되돌리고, 에이전트는 되돌린 사실을 안다. 그런데 **일이 정상적으로 끝나지 않을 때**는 아직 아무것도 정리되어 있지 않다.

> 긴 요청을 보내 놓고 마음이 바뀌어 `Ctrl+C`를 눌렀다. 화면에는 오류 로그가 길게 찍히고 프로그램이 꺼진다. 그 사이 에이전트가 이미 파일 두 개를 고쳐 놓았는데, 다시 켜면 에이전트는 그 일을 전혀 모른다.

세 가지가 비어 있다.

- **끝난 이유가 비어 있다.** 세션이 `exit`로 끝나면 이유가 적히지만, `Ctrl+C`나 `Ctrl+D`나 오류로 끝나면 비어 있다. 나중에 기록을 보고 「이 세션은 왜 끝났나」를 알 수 없다.
- **중단하면 세션을 잃는다.** 처리 중에 `Ctrl+C`를 누르면 그 요청만 취소되는 게 아니라 프로그램이 꺼진다. 쌓아 둔 대화가 모두 사라진다.
- **취소한 요청의 흔적을 에이전트가 모른다.** 12번에서 본 함정과 같다. 에이전트가 모르는 사이 사람 쪽에서 상황이 달라졌고, 에이전트는 옛 기억으로 계속 일한다.

사람이 묻는 질문은 이렇다.

- *"중간에 멈췄을 때 내 세션은 무사한가?"*
- *"멈추기 전에 이미 고쳐진 파일이 있으면 에이전트가 알고 있나?"*
- *"이 세션이 왜 끝났는지 기록에서 알 수 있나?"*

지금은 셋 모두 「아니다」다. 이 로드맵은 **「어떻게 끝나든 끝난 이유가 남고, 중간에 멈춰도 세션이 살아 있고, 멈추기 전에 일어난 일을 에이전트가 다음 말에서 알게 한다」** 하나만 만든다. 12번을 마감하며 이웃 과제로 남긴 두 가지(알림 전에 끝내기, 되돌리는 도중 오류)도 같은 뿌리라 함께 닫는다.

## 2. 왜 이 정도로만 하는가

이 로드맵이 **일부러 하지 않는 것**과 그 이유다.

| 하지 않는 것 | 이유 | 언제 하는가 |
|---|---|---|
| 다른 날 켠 세션에서 지난 세션을 되돌리기 | 지금은 세션마다 되돌릴 기록이 그 실행 안에서만 이어진다. 이어받으려면 저장 방식이 바뀐다. 중단·종료 문제와 다른 크기의 일이다 | 세션 이어받기가 필요해질 때 |
| 대화가 아주 길어져 요약된 뒤에도 알림 속 파일 이름 보존하기 | 알림은 바로 다음 요청에서 효과를 내면 된다. 오래 지키려면 요약 규칙을 건드려야 한다 | 요약 뒤에 에이전트가 다시 어긋나는 일이 관찰될 때 |
| 위임한 하위 에이전트까지 중단 전파하기 | 하위 에이전트는 한 번 일하고 요약만 돌려주는 구조다. 도중에 멈추는 설계가 없다(07번에서 뺐다) | 병렬·백그라운드 위임이 생길 때 |
| 프로그램이 강제로 죽는 경우(전원, 강제 종료 신호)까지 정리하기 | 강제로 죽으면 프로그램은 아무것도 할 수 없다. 이 경우를 코드로 막는다는 약속은 거짓이 된다. 남은 흔적을 다음 번 되돌리기가 이미 「결과 모름」으로 안전하게 건너뛴다 | 바꾸지 않는다 |
| 터미널 명령으로 바뀐 일까지 알리기 | 터미널 명령의 결과는 어디에도 기록해 두지 않는다(11번 결정). 추측해서 알리면 틀린 정보가 된다 | 터미널 변경 기록이 생길 때 |
| 알림 전에 끝낸 경우를 위해 기록을 더 늘리기 | 되돌린 사실은 이미 장부에 있고, 끝난 세션은 다시 이어지지 않아 에이전트가 읽을 일이 없다. 아무도 읽지 않는 기록을 만들지 않는다 | 해당 없음 |
| 실제 터미널 창을 띄우는 새 시험 | `Ctrl+C`의 의미는 프로그램 안에서 일어나는 일이라 가짜 상황으로 재현할 수 있다(계획 015의 기준) | 해당 없음 |

**한마디로**: 어떻게 끝나든 이유를 적고, 중간에 멈춰도 세션을 지키고, 멈추기 전에 일어난 일을 다음 말에 함께 전한다. 죽는 순간까지 책임지겠다고 하지는 않는다.

## 3. 왜 이 순서, 왜 이 단계 수인가

| 순서 | 하는 일 | 왜 이 자리인가 |
|---|---|---|
| 010 | 끝난 이유를 한 곳에서 적기 | 다른 단계가 「어떻게 끝났는가」를 이 자리에 기대므로 먼저 둔다. 가장 작고 되돌리기 쉽다 |
| 020 | 처리 중 `Ctrl+C`를 그 요청만 취소로 바꾸기 | 알림을 만들려면 먼저 「취소된 요청」이 안전하게 만들어져야 한다. 트레이스백으로 꺼지는 지금 상태에서는 그 뒤를 이을 수 없다 |
| 030 | 취소된 요청을 다음 말에서 알리기 | 020이 만든 취소 상태를 쓴다. 12번의 알림 방식을 그대로 가져다 쓴다 |
| 040 | 12번 한계 두 건 닫기 | 둘 다 「알림이 안 가는 경우」다. 030에서 알림 모음이 한 군데로 모인 뒤에 다루면 같은 틀 위에서 끝난다 |
| 050 | 통합 확인과 작동원리 갱신 | 작동원리 01편에 지금 동작(중단 시 꺼짐)이 적혀 있다. 동작이 바뀌면 문서도 같이 바뀌어야 한다 |
| 060 | 실제 모델로 돌려 보기와 마감 | 이 로드맵은 「중단 뒤 에이전트가 어긋난다」는 우려에서 시작했다. 실제 모델로 해 봐야 끝났다고 말할 수 있다 |

## 4. 왜 이 방식을 택하고 무엇을 배척했나

| 선택 | 배척한 대안 | 이유 |
|---|---|---|
| 처리 중 `Ctrl+C`는 그 요청만 취소하고 세션은 유지 | 지금처럼 프로그램을 끈다 | 긴 대화를 통째로 잃는다 |
| 취소된 요청은 에이전트의 대화에서 뺀다 | 대화에 남기고 짝이 어긋난 부분만 정리한다 | 짝이 어긋난 대화는 다음 호출이 거부당할 수 있다. 정리 코드와 시험이 커진다 |
| 뺀 대신 다음 말에서 알려 준다 | 알리지 않고 뺀다 | 이미 바뀐 파일을 에이전트가 모른 채 이어간다. 12번에서 관찰한 함정과 같다 |
| 끝난 이유는 한 곳에서 적는다 | 끝나는 길마다 따로 적는다 | 길이 늘 때마다 빠뜨릴 수 있다. 한 곳이면 빈칸이 생기지 않는다 |
| 기록 장부는 지우지 않는다 | 취소된 요청의 기록을 지운다 | 장부는 일어난 일의 증거다 |
| 새 상태·새 표를 만들지 않는다 | 「중단됨」 같은 새 상태를 만든다 | 이미 있는 틀로 충분하다. 구조를 바꾸면 되돌릴 때 더 위험해진다 |

## 5. 성공 판단 기준과 검증할 가정

**성공 기준**: 에이전트가 파일을 고치는 도중 사람이 `Ctrl+C`를 누르면 (1) 오류 로그 없이 프롬프트로 돌아오고 (2) 세션이 계속되며 (3) 사람이 다음에 말할 때 에이전트가 「직전 요청이 중단되었고 이 파일들이 이미 바뀌었을 수 있다」는 알림을 받고 (4) 어떤 경로로 끝나든 세션 기록에 끝난 이유가 남는다. 실제 모델로 (3)을 3번 확인한다.

| 번호 | 가정 | 틀렸다면 |
|---|---|---|
| **A** | 취소 알림을 받으면 에이전트가 중단된 요청을 제멋대로 이어서 하지 않는다. (**미확인**: 모델 1종) | 알림 문구를 바꾼다. 그래도 안 되면 후속 후보로 올린다 |
| **B** | 취소된 요청을 에이전트의 대화에서 빼도 다음 호출이 정상으로 이어진다(짝이 깨지지 않는다) | 대화에서 빼는 방식을 재검토한다 |
| **C** | 도구 실행 중 `Ctrl+C`로도 변경 기록이 이미 확정되어 있어서 알림에 정확한 파일 목록을 쓸 수 있다 | 확정되지 않은 칸은 「결과 모름」으로 알린다 |
| **D** | 취소된 요청에서 파일을 바꾼 도구가 없으면 알림이 없어도 에이전트가 어긋나지 않는다 | 파일 변경이 없어도 한 줄을 붙이는 쪽으로 바꾼다 |
| **E** | 되돌리는 도중 오류가 나도 부분 결과만으로 에이전트가 올바른 상태를 안다 | 오류 항목을 더 자세히 알린다 |
| **F** | 터미널 도구 실행 중 `Ctrl+C`에서 하위 프로세스가 남지 않는다 (**미확인**) | 정리 방법을 후속 후보로 올린다 |
| **G** | 취소 알림의 길이(경로 수 상한)가 실제 사용에서 문맥을 크게 쓰지 않는다 | 상한을 줄인다 |

## 6. 알려진 위험과 아직 확인하지 못한 것

- **취소된 요청의 내용은 에이전트가 다시 보지 못한다.** 사람이 다시 말해야 한다. 알림은 「무엇이 바뀌었을 수 있다」까지만 전한다.
- **터미널 명령의 영향은 알리지 못한다.** 기록이 없기 때문이다.
- **강제 종료는 다루지 않는다.** 이 경우 끝난 이유가 비고 변경 기록이 「결과 모름」으로 남는다.
- 취소된 요청 도중 대화 요약(압축)이 이미 일어난 경우의 기록 차이, 진행 중이던 모델 호출의 기록 방식, 다른 모델의 반응은 **미확인**이다. 실제로 돌려 보는 모델은 1종이다.
