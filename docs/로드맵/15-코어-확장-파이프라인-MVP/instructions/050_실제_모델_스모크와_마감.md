# [구현지시서 050] 실제 모델 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [15-README.md](../README.md)  
> **선행 조건**: 040 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~G, [ADR-0015](../../../adr/0015-코어_확장_파이프라인_MVP_범위와_결정.md) §2-8  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 및 마감 단계**다. 실제 모델과 터미널에서 이관된 압축과 화면 출력이 이전과 같게 동작하는지 확인한다.

---

## 1. 목적

가짜 모델·가짜 HTTP로 모든 자동화 시험이 통과한 상태에서 실제 모델(`deepseek/deepseek-v4-flash-0731`)로 다음을 확인한다.

1. **가정 A (실제 모델에서의 압축)**: 낮춘 창에서 압축이 발동하고(`compacted=1` 행과 요약 호출 행), 압축 뒤에도 대화가 이어지는가. 압축 시점·방식이 이관 전(05번 스모크 기록)과 같은 성격인가.
2. **화면 동일성**: 도구를 쓸 때 `  [Tool Call] name(args)` 줄이 이전과 같은 모양으로 나오는가.
3. **가정 C·E**: 확장 장치를 하나도 달지 않은 평소 실행에서 오류나 경고(`hook_error` 포함)가 나오지 않는가.
4. 키가 장부·로그에 저장되지 않는가.

가정 G(16번 `LoopGuard` 소비 가능성)는 이 스모크의 대상이 아니다. 16 개정 때 확인한다.

---

## 2. 사전 조건

1. **에이전트**:
   - `.venv/bin/python -m pytest -n 4` 전체 통과 확인.
   - `git diff <040 구현 커밋>..HEAD -- src/`가 0줄인지 확인.
2. **사용자 (Zero Leakage 준수)**:
   - 키(`OPENROUTER_API_KEY`)는 대화창에 절대 입력하지 않고 **별도 터미널**에서 내보낸다([AGENTS.md](../../../../AGENTS.md) §3).
   - 임시 폴더 준비: `export H=$(mktemp -d); echo "$H"`

---

## 3. 스모크 절차 (사용자가 별도 터미널에서 실행)

레포 루트에서 `HERMES_HOME="$H" .venv/bin/python -m hermes_core.cli --context-window 4000` 를 실행한다(05번 스모크와 같은 낮춘 창, 임계값 2,000토큰).

> 실제 모드의 작업 폴더는 `<HERMES_HOME>/workspace`이므로 파일은 그 안에서 만든다(05번 스모크와 같은 절차). 레포의 `docs/`는 읽을 수 없다.

| 단계 | 입력 | 볼 것 |
|---|---|---|
| 1 | `안녕, workspace에 a.txt를 만들고 hello라고 써줘.` | `  [Tool Call] write_file(...)` 줄이 이전과 같은 모양으로 나오는가 |
| 2 | `고마워, 내용을 읽어서 알려줘.` | `  [Tool Call] read_file(...)` 줄과 답이 오는가 |
| 3 | `이 프로젝트의 코드명은 ORCA야. 기억해줘.` (**처음 3개 메시지는 압축 때 보호되는 헤드이므로 ORCA를 앞서 말하지 않는다**) | 답이 오는가 |
| 4 | `workspace에 long1.txt를 만들고 1부터 300까지 한 줄에 숫자 하나씩 써줘. 그다음 읽어서 마지막 숫자만 알려줘.` 를 파일 이름만 바꿔(`long2.txt`, `long3.txt`) 2~3회 | 도구 호출 줄이 나오고, 입력이 쌓여 압축 임계에 접근하는가 |
| 5 | `내가 말한 프로젝트 코드명이 뭐였지?` | 압축이 발동했더라도 `ORCA`를 기억하고 답하는가 (**가정 A**) |
| 6 | `exit` | 정상 종료되는가 |

### 원장 및 키 미저장 확인 명령

```bash
# 1. 키 미저장 확인 (출력: key_leaked: False 여야 함)
sqlite3 "$H/state.db" .dump | python3 -c "import os,sys; print('key_leaked:', os.environ['OPENROUTER_API_KEY'] in sys.stdin.read())"

# 2. 압축 발동 확인 (compacted=1 행이 1건 이상)
sqlite3 "$H/state.db" "SELECT count(*) FROM messages WHERE compacted=1"

# 3. 요약 호출 행 확인 (도구 없는 호출이 1건 이상)
sqlite3 "$H/state.db" "SELECT count(*) FROM llm_calls"

# 4. 종료 사유 확인
sqlite3 "$H/state.db" "SELECT end_reason FROM sessions"
```

실행 결과(키 값 제외)만 에이전트에게 전달한다.

## 4. 마감 (사용자의 종료 선언이 있을 때만)

1. 스모크 결과를 대시보드 실행 기록에 적는다. 키 값은 적지 않는다.
2. [ROADMAP_정책 §5](../../ROADMAP_정책.md)의 9항목을 담아 `결과정리및리뷰.md`를 상세히 쓴다. WHY.md 가정 A~G를 하나씩 「이뤘다 / 못 이뤘다 / 바뀌었다」로 대조하고, 대조하지 않은 가정이 있으면 마감하지 않는다(가정 G는 「미확인」으로 명시하고 후속 인계에 16번 개정을 적는다).
3. 대시보드 전체 상태를 `Closed`로 바꾸고 완료 일자·마감 태그·종합보고서 링크를 기록한다.
4. 커밋 제목: `docs(core): R15-마감 - 15번 코어 확장 파이프라인 MVP 마감 및 종합보고서 작성`
5. 태그: `git tag roadmap-15-closed` (푸시는 별도 지시 시에만).
6. 후속 인계에 다음을 제안으로 적는다(실행하지 않음): 16번 020 지시서의 훅·미들웨어 소비자 개정과 선행 조건 문구(「14 Closed」→「15 Closed」) 갱신, 승인·체크포인트 래핑의 미들웨어 이관.
