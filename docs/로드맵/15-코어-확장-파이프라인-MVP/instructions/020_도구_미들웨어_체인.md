## 1. 구현 내용 명세

이 단계는 [`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py)의 `ToolDispatcher.handle_function_call`을 **미들웨어 체인**으로 만든다. 미들웨어를 하나도 등록하지 않으면 동작이 지금과 같다.

### 1-1. 호출 값과 미들웨어 형태

```python
@dataclass(frozen=True)
class ToolCall:
    name: str
    args: dict[str, Any]
    task_id: Optional[str] = None

ToolMiddleware = Callable[[ToolCall, Callable[[ToolCall], str]], str]
```

- 미들웨어는 `mw(call, next) -> str`이다. `next(call)`을 부르면 안쪽으로 넘어가고, 부르지 않으면 그 미들웨어의 반환값이 결과가 된다(차단). 인자를 바꾸려면 `dataclasses.replace(call, args=...)`로 새 `ToolCall`을 `next`에 넘긴다.

### 1-2. 디스패처 변경

- `ToolDispatcher.__init__`에 미들웨어 목록을 둔다. `add_middleware(mw)`는 목록 **끝에 추가**한다. 먼저 등록한 것이 바깥이다.
- `handle_function_call(function_name, function_args, task_id=None)`의 **시그니처와 반환형은 그대로**다. 안에서 `ToolCall`을 만들어 체인을 실행한다.
- 체인의 가장 안쪽 `_execute(call)`은 현재 코드의 조회(`Unknown tool`) → `_validate_arguments` → 핸들러 실행(`TypeError`·일반 예외 → 기존 오류 JSON)을 **그대로** 옮긴 것이다. 조회도 체인 안쪽이므로 미들웨어는 알 수 없는 도구 호출도 본다.
- 체인 전체를 `try/except Exception`으로 감싸, 미들웨어가 던진 예외는 `{"success": false, "error": "Tool '<name>' failed: <사유>"}`(기존 `ensure_ascii=False` JSON)로 바꾼다.
- 체인의 최종 결과가 `str`이 아니면 `{"success": false, "error": "Tool '<name>' middleware returned a non-string result."}`로 바꾼다. (중간 미들웨어가 `str`이 아닌 값을 `next`에서 받는 경우는 바깥 미들웨어의 책임이다. 최종값만 검사한다.)
- `get_tools_schema`, `register_tool`, `create_default_dispatcher`, `create_child_dispatcher`는 바꾸지 않는다. 자식 디스패처는 미들웨어 없이 만들어진다.

### 1-3. 단일 진입로 확인

`src/hermes_core`에서 `_handlers`를 직접 읽는 곳이 `dispatcher.py`의 `register_tool`과 `_execute` 두 곳뿐임을 검색으로 확인한다([코딩규약 §3-6](../../../코딩규약.md) 도구 실행 단일 진입로 유지).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_dispatcher_middleware.py`(신규). 도구 `echo`(필수 인자 `x`: integer, 호출 횟수를 기록하는 핸들러)를 등록한 `ToolDispatcher`를 쓴다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 미들웨어 없이 `handle_function_call("echo", {"x": 1})`, 알 수 없는 도구 호출, 인자 누락 호출 | 이전과 같은 결과/오류 JSON이다. 기존 `test_dispatcher.py` 전체가 수정 없이 통과한다 (가정 C) |
| 2 | 미들웨어 A, B를 이 순서로 등록하고 호출(각자 진입/복귀를 기록 목록에 추가) | 기록이 `["A:in", "B:in", "tool", "B:out", "A:out"]`이다. 결과는 핸들러 반환값 그대로다 |
| 3 | 미들웨어 하나가 `next`를 부르지 않고 `'{"success": false, "error": "blocked"}'`를 반환 | 핸들러 호출 횟수가 0이고 결과가 그 문자열이다 |
| 4 | 미들웨어가 `replace(call, args={"x": 2})`로 인자를 바꿔 `next` 호출 | 핸들러가 `x=2`를 받는다 |
| 5 | 미들웨어가 스키마에 어긋나는 인자(`{"x": "문자"}`)로 바꿔 `next` 호출 | 핸들러는 호출되지 않고 `Invalid arguments for tool 'echo'` 오류 JSON이다 (검증은 미들웨어 뒤 가장 안쪽에서 수행됨) |
| 6 | 미들웨어가 `ValueError("boom")`을 던짐 | 예외가 밖으로 나오지 않고, 결과 JSON이 `success == false`이며 `error`에 `Tool 'echo' failed`와 `boom`이 들어 있다 |
| 7 | 미들웨어가 `None`을, 다른 경우 `dict`를 반환 | 각각 `middleware returned a non-string result` 오류 JSON이다 |
| 8 | 미들웨어가 `next` 결과 문자열 뒤를 가공해 반환 | 최종 결과가 가공된 문자열이다 |
| 9 | 등록되지 않은 도구 이름으로 호출, 미들웨어 A가 있음 | A가 먼저 진입(`A:in`)하고 안쪽에서 `Unknown tool` 오류 JSON을 받는다 |
| 10 | `handle_function_call("echo", {"x": 1}, task_id="t1")`, 미들웨어가 `call.task_id`를 기록 | 기록값이 `"t1"`이다 |
| 11 | 부모 디스패처에만 미들웨어를 등록한 뒤 `create_child_dispatcher()`로 만든 자식에서 도구 호출 | 부모 미들웨어는 호출되지 않는다 |
| 12 | 미들웨어를 단 디스패처로 `HermesAgent`가 도구 호출 1건 턴을 실행 | 미들웨어가 정확히 1회 진입하고 `tool` 메시지가 정상 기록된다 |
| 13 | `grep -n "_handlers" src/hermes_core -r` | `dispatcher.py`의 `__init__`·`register_tool`·`_execute`에서만 나타난다 |
