## 1. 구현 내용 명세

이 단계는 에이전트 루프 안에 섞여 있는 화면 출력(`print`) 한 곳을 이벤트로 바꾼다. 출력 문자열은 이전과 **글자까지 같아야** 한다.

### 1-1. 이벤트 모듈 신설 (`src/hermes_core/agent/events.py`)

```python
EVENT_TOOL_CALL = "tool_call"

@dataclass(frozen=True)
class AgentEvent:
    kind: str
    data: Mapping[str, Any] = field(default_factory=dict)

EventSink = Callable[[AgentEvent], None]

class ConsoleEventSink:
    def __call__(self, event: AgentEvent) -> None: ...
```

- `ConsoleEventSink`는 `kind == EVENT_TOOL_CALL`일 때만 `print(f"  [Tool Call] {data['name']}({data['arguments']})")`를 한다(현재 `agent.py`의 f-string과 같은 형태). 모르는 종류는 아무것도 하지 않는다.
- 모듈 독스트링에 원본 매핑을 적는다: 원본 `hermes-agent/run_agent.py`의 `tool_progress_callback`(기준 커밋 `6134939882`의 `_execute_tool_calls`에서 호출)에 대응하며, 콜백 인자를 이벤트 하나로 모은 점이 다르다.

### 1-2. 에이전트 연결 ([`agent.py`](../../../../src/hermes_core/agent/agent.py))

- `HermesAgent.__init__`에 **기존 인자 뒤에** `event_sink: Optional[EventSink] = None`을 추가한다(위치 인자 호환).
- 해석 규칙: `event_sink`가 주어지면 그것을 쓰고, 없고 `quiet_mode=False`면 `ConsoleEventSink()`, 없고 `quiet_mode=True`면 sink 없음(`None`). 결과를 `self.event_sink`에 둔다.
- `_emit(self, kind, **data)`를 추가한다: sink가 없으면 아무것도 하지 않고, 있으면 `AgentEvent(kind, data)`를 넘긴다. sink가 `Exception`을 던지면 삼키고 `logger.warning`만 남긴다(`KeyboardInterrupt` 등 `BaseException`은 삼키지 않는다 — 중단 처리를 막지 않기 위함).
- `_execute_tool_calls`의 `if not self.quiet_mode: print(...)`를 `self._emit(EVENT_TOOL_CALL, name=func_name, arguments=args_str)`로 바꾼다. 방출 위치는 지금 `print`가 있는 자리(인자를 읽기 전, 도구 실행 직전)를 그대로 쓴다.
- 그 밖의 줄은 바꾸지 않는다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_agent_events.py`(신규). `MockLLMClient`, 임시 `SessionDB`, 도구 `echo`(인자 `x`를 받아 JSON 성공 반환)를 등록한 `ToolDispatcher`를 쓴다. 도구 호출 응답은 `tool_calls=[{"id": "c1", "function": {"name": "echo", "arguments": "{\"x\": 1}"}}]` 다음에 텍스트 응답이다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 기본값(`quiet_mode=False`, `event_sink` 없음)으로 위 도구 호출 1건을 포함한 턴을 `capsys`로 실행 | 표준출력이 정확히 `  [Tool Call] echo({"x": 1})\n`이다 (이전과 같은 문자열) |
| 2 | `quiet_mode=True`, `event_sink` 없음으로 같은 턴 실행 | 표준출력이 빈 문자열이다 |
| 3 | `quiet_mode=True`, `event_sink=events.append`로 같은 턴 실행 | `events == [AgentEvent("tool_call", {"name": "echo", "arguments": "{\"x\": 1}"})]` (명시한 sink는 `quiet_mode`와 관계없이 받는다) |
| 4 | 같은 응답에 도구 호출 2건(`echo` 두 번, id `c1`·`c2`)을 담고 `event_sink=events.append` | 이벤트가 호출 순서대로 2건이다 |
| 5 | `event_sink`가 항상 `RuntimeError`를 던지는 함수일 때 도구 호출 1건 턴 실행 | `run_conversation`이 예외 없이 끝나 `stopped_reason == "completed"`이고, `messages`에 `tool` 메시지가 있으며, DB 원장에도 `tool` 행이 있다. `caplog`에 경고가 남는다 |
| 6 | 도구 호출 없이 텍스트만 답하는 턴, 기본값 | 표준출력이 빈 문자열이다 (이벤트 없음) |
| 7 | 인자가 JSON이 아닌 도구 호출(`"arguments": "{bad"`) 턴, `event_sink=events.append` | 이벤트가 방출되며 `arguments == "{bad"`이고, `tool` 메시지는 기존대로 `Invalid JSON arguments` 오류를 담는다 (방출이 인자 파싱보다 먼저임을 고정) |
| 8 | `ConsoleEventSink()(AgentEvent("other", {}))` 호출 | 아무것도 출력하지 않고 예외도 없다 |
| 9 | 기존 시험 전체(`pytest -m "not pty"`) | 수정 없이 통과한다 (가정 C) |
