## 1. 구현 내용 명세

이 단계는 **소스코드를 한 줄도 바꾸지 않는다**. 세 확장 장치(미들웨어·훅·이벤트 sink)만으로 새 기능을 붙일 수 있음을 시험으로 확인하고(가정 B), 바뀐 구조를 문서에 반영한다.

### 1-1. 확장 예시 시험 (`tests/test_hermes_core/test_pipeline_extension.py`, 신규)

시험 파일 안에서 **도구 예산 기능**을 세 장치로만 붙인다. 이 기능은 시험용이며 `src/`에 두지 않는다.

- 미들웨어 `budget_middleware`: 도구별 호출 횟수를 세어 한도(`LIMIT = 2`)를 넘는 호출은 `next`를 부르지 않고 `{"success": false, "error": "budget exceeded"}`를 반환한다.
- 훅 `budget_stop_hook`(`AFTER_TOOL_CALLS`): 이번 반복에 차단이 있었다면 `ctx.request_stop("budget")`을 한다.
- sink `events.append`: 방출된 이벤트를 수집한다.
- 붙이는 방법은 `dispatcher.add_middleware(...)`, `agent.hooks.register(...)`, `HermesAgent(event_sink=...)` 세 가지뿐이다.

### 1-2. 실제 클라이언트 경로 통합 시험

실제 `OpenRouterClient`+`MockTransport`(기존 E2E 시험 `test_agent_e2e.py`의 구성을 참고)로 압축이 일어나는 세션에 위 확장을 함께 붙여, 이관된 압축과 세 장치가 같이 돌아도 원장과 대화가 일치함을 확인한다.

### 1-3. 문서 동기화

[작동원리 README](../../../작동원리/README.md)의 규칙(쉬운 말, Why, 구현 귀띔, 이름의 3층)을 따라 다음을 갱신한다.

- [03-코어구조-메인루프-확장방식.md](../../../작동원리/03-코어구조-메인루프-확장방식.md): 머리의 기준 커밋·「다시 확인하는 법」, 1부 「흔한 방식과 이 프로그램의 선택」 표의 「기능 붙이기」 행(고리를 만들지 않는다 → 세 장치로 개정, ADR-0015로 대체됨을 명시), Q1(부품 지도에 events·turn_hooks·compression_hook), Q2(한 바퀴 순서), Q3(압축이 한 바퀴 안에서 훅으로 이관되어 무겁던 곳이 풀렸음; 줄 수는 적지 않고 확인 명령으로 대체), Q4(붙는 자리 표에 미들웨어·훅·이벤트 자리 추가), 그림과 5부 ②·③.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_pipeline_extension.py`(신규). 도구 `echo`를 등록한 디스패처, 한 응답에 `echo` 호출 3건을 담은 Mock 응답 다음 텍스트 응답을 쓴다.

| # | 입력 | 기대 결과 |
|---|---|---|
| E1 | 도구 예산 기능(미들웨어+훅+sink)을 붙이고 위 입력 실행 | 첫 2건은 정상 실행, 3번째 `tool` 메시지는 `budget exceeded` 오류 JSON, `stopped_reason == "budget"`, `iterations == 1`이다. 수집된 이벤트에 `tool_call`이 3건 있다 (가정 B) |
| E2 | 기능을 붙이지 않은 대조 에이전트에 같은 입력 | 3건 모두 정상 실행, `stopped_reason == "completed"`다 (미등록 시 변화 없음, 가정 C) |
| E3 | E1 직후 장부 | `get_messages_as_conversation(session_id)`가 메모리 `messages[1:]`와 같다 (assistant `tool_calls` 하나에 대응하는 `tool` 행 3건이 모두 있음) |
| E4 | 실제 `OpenRouterClient`+`MockTransport`, 작은 `context_window_tokens`로 압축이 1회 일어나는 대화 + 위 확장 | `result["compression"]["count"] >= 1`이고, 압축 뒤에도 E3 불변식이 성립하며, 확장(미들웨어·훅·sink)이 압축과 충돌 없이 동작한다 (가정 A·B) |
| E5 | `HermesAgent(..., resume=True)`로 재개한 에이전트 | `agent.hooks`에 압축 훅이 등록되어 있고(`BEFORE_LLM` 첫 훅), 재개 뒤 대화에서 압축이 정상 동작한다 |
| E6 | 이 단계의 변경 | `git diff <030 커밋>..HEAD -- src/`가 0줄이다 (`src/` 무수정) |
| E7 | 문서 링크·정합 | 갱신한 문서의 상대 링크가 모두 존재하고, 작동원리 03편에 「고리를 만들지 않는다」는 서술이 남아 있지 않으며, 03편이 설명하는 파일·함수 이름이 실제 코드와 일치한다 (`grep`으로 대조) |
