## 1. 목표와 결과 (가정 A~G 대조)

[WHY.md](WHY.md)에서 수립한 7개 핵심 가정(A~G)을 코드 구현, 단위 시험, pty 통합 회귀 시험, 실제 터미널 앱(WezTerm 20240203-110809-5046fc22, `TERM=xterm-256color`, 기본 `-iutf8`) 수동 스모크 2종(R1 새 경로, R3 폴백; R2·R4는 생략)의 결과와 1:1로 대조했습니다. 스모크는 `--mock` 실행이며 근거는 사용자가 붙여 준 화면 출력과 상태 DB(복사본을 읽기 전용으로 조회)입니다. 화면 모양에 대한 사용자 진술은 기억이 불확실한 곳이 있어 약한 증거로 표시했습니다.

| 가정 | 내용 | 판정 | 대조 결과 및 근거 |
|---|---|---|---|
| **가정 A** | 새 입력 방식에서 한글을 치고 백스페이스로 지워도 프로그램이 꺼지지 않는다 | **맞았다** | **WezTerm R1**: 이 터미널은 기본이 `-iutf8`(원래 결함 조건)인데도 `한글ab` → Backspace 2번 → `테스트`가 DB에 `한글테스트`로, `가다` 사이 삽입이 `가나다`로 저장되었고 꺼지지 않았다(지운 글자는 기록에 없음). 지울 때의 화면 잔상은 사용자가 기억하지 못하며 「문제 없었던 것 같다」는 약한 진술뿐이다. pty 통합 회귀 시험 1번(대조군이 같은 조건에서 비정상 종료) vs 2번(새 경로 생존)이 자동 근거. R2(`stty -iutf8`)는 터미널이 이미 `-iutf8`라 생략. |
| **가정 B** | 입력 읽기 중 잘못된 바이트가 와도 프로그램이 오류로 꺼지지 않고 안내 후 다시 읽으며, 대화 기록과 저장소는 바뀌지 않는다 | **맞았다** | **WezTerm R3(폴백, `-iutf8`)**: 한글 입력 후 Backspace로 깨진 줄에서 `Input could not be decoded as UTF-8; please type it again.`가 1번 나오고 프로그램이 계속 동작했다. 그 줄은 DB `messages`에 없다(R3 user 메시지에 해당 입력 없음). pty 시험 9가 자동 근거. R4는 R3과 조건이 같아 생략. 재시도 상한 5회(`CLI_INPUT_DECODE_MAX_RETRIES`)는 시험(010 시나리오 8)으로 확인. |
| **가정 C** | 터미널이 아닌 입력의 동작은 이전과 같고, 기존 시험이 한 줄도 바뀌지 않고 통과한다 | **맞았다** | `is_interactive_terminal()`(stdin/stdout 모두 tty)에 의해 비터미널 환경은 기존 `input()` 폴백 경로를 타며, 기존 567건의 단위/통합/E2E 테스트 코드를 단 1줄도 수정하지 않고 100% 통과(`test_agent_e2e.py` diff 0줄). |
| **가정 D** | Enter는 전송, Ctrl+J는 줄바꿈이고, Ctrl+C와 Ctrl+D는 지금과 같은 종료 경로를 탄다 | **대체로 맞았다 (일부 미확인)** | **R1**: Enter 전송, Ctrl+J로 `첫째 줄\n둘째 줄`이 한 메시지로 저장되고 둘째 줄이 같은 칸에 맞춰 들여쓰기되어 보였다(화면 출력). Ctrl+C는 R1·R3 모두 `Exiting session...` 후 셸 프롬프트가 돌아왔다. **미확인**: 실제 앱에서 Ctrl+D는 실행하지 않았고(pty 시험 6이 근거), 종료 뒤 셸의 에코·커서·`stty -a` 복원은 사용자가 기억하지 못한다(프롬프트가 돌아온 것만 화면으로 확인). |
| **가정 E** | 여러 줄을 붙여넣으면 한 번의 입력으로 들어간다 (기존 방식의 줄 단위 분리 전송 실재 여부 확인) | **맞았다** | **R1 턴 5 vs R3**: 새 경로는 3줄 붙여넣기가 DB에 한 메시지(`붙여넣기 줄1\n붙여넣기 줄2\n붙여넣기 줄3`, 23자)로 저장되었다. 폴백(R3)은 줄마다 별개 메시지로 전송되었고(`줄1`, `줄2`), 줄바꿈 없이 끝난 마지막 줄은 다음 입력에 이어 붙었다(`줄3붙여넣기 줄1`). 사용자는 이상하게 느껴 3번 붙여넣었으며 DB에 그 결과가 남았다. 문제는 실재했고 새 경로가 해소했다. |
| **가정 F** | 사용자가 겪은 `User >` 사라짐이 사라진다 | **못 이뤘다 (원인 미상, 재현 안 됨)** | R1(새 경로)과 R3(폴백, 예전 방식) 모두에서 `User >`가 사라지는 현상이 **재현되지 않았다**(붙여 준 화면 출력 전 턴에서 유지됨. 창 크기 조절 중 관찰은 사용자가 기억하지 못함). 예전 방식에서도 재현되지 않았으므로 이 로드맵이 그 증상을 없앴다고 주장할 근거가 없다. WHY 가정 F의 지침대로 「원인 미상」으로 기록하고 구조는 되돌리지 않는다. 미확인 가설: 폴백에서 붙여넣기가 쪼개질 때 빈 `User >`가 줄줄이 찍히는 모양을 「지워진다」로 느꼈을 가능성(재현·검증하지 않음). |
| **가정 G** | 새 입력 부품 하나를 추가해도 설치와 실행에 문제가 없다. 입력 외의 부분에는 변경이 없다 | **맞았다** | `pyproject.toml`에 `prompt_toolkit>=3.0.52,<4` 추가 후 안정 설치. `src/hermes_core/agent/`, `tools/`, `session_db.py` 등 코어 비즈니스 로직 수정 라인 0줄(`git diff` 0줄). 미설치 환경에서도 지연 import 및 안전 폴백 완비. |

## 2. 단계별 상세 (Why 중심)

### 010: 입력 함수 분리, `input()` 폴백, 디코드 예외 안전망, 프롬프트 분리
- **무엇을**: `src/hermes_core/cli_input.py` 모듈 신설, `read_user_input(prompt)` 구현, `UnicodeDecodeError` 포착 시 안내 후 재시도 루프(상한 5회), `constants.py`에 프롬프트 및 안내 상수 추가, `cli.py`에서 `input(` 호출 제거.
- **왜**: 에이전트와 대화하는 유일한 관문인 사용자 입력 수신 로직이 CLI 메인 루프에 흩어져 있으면 안 되며, 터미널 환경이든 파이프 환경이든 한글 조합/백스페이스로 인한 `UnicodeDecodeError`로 전체 프로세스가 죽는 치명적 결함을 새 의존성 없이 즉시 막아야 했습니다.
- **결과**: 비터미널/기본 환경에서 프로세스 Crash를 방지하는 최후의 안전망 구축. 단위 시험 12개 통과, 회귀 578건 통과.

### 020: `prompt_toolkit` 경로 (Enter 전송, Ctrl+J 줄바꿈, 붙여넣기, 의존성)
- **무엇을**: `pyproject.toml`에 `prompt_toolkit` 의존성 추가, `cli_input.py`에 `is_interactive_terminal`(stdin/stdout 모두 tty 검사) 및 `read_with_prompt_toolkit` 구현. Enter 전송 및 Ctrl+J 줄바꿈 키바인딩 명시, 지연(lazy) import 및 미설치 시 프로세스당 1회 알림 후 `input()` 폴백 연동.
- **왜**: 표준 `input()` 및 단순 readline 모듈로는 한글 폭 계산, 백스페이스 잔상, 브래킷 붙여넣기(bracketed paste) 다중 행 단일 처리, 멀티라인 편집을 해결할 수 없습니다. 따라서 터미널 제어에 검증된 라이브러리를 도입하되, 파이프나 자동 테스트 환경을 방해하지 않도록 철저히 대화형 터미널에서만 조건부 발동하도록 격벽을 세웠습니다.
- **결과**: `prompt_toolkit` 3.0.53 설치 및 파이프/터미널 분기 로직 완성. 단위 시험 17개 통과, 회귀 597건 통과.

### 030: 배너 안내와 CLI 통합 검증
- **무엇을**: `constants.py`에 `CLI_MULTILINE_HINT`("Enter to send, Ctrl+J for a new line.") 추가, `cli_input.py`에 `multiline_input_available()` 순수 판정 함수 구현(`find_spec` 기반 라이브러리 미임포트 보장), `cli.py` 시작 배너에 조건부 힌트 출력.
- **왜**: 새 키바인딩(Ctrl+J)을 사용자에게 알리지 않으면 사용자는 다중 행 입력을 쓸 수 없습니다. 단, 파이프나 미설치 환경에서는 거짓 안내가 나가면 안 되므로, 실제 터미널이고 라이브러리가 존재할 때만 힌트가 출력되도록 안전하게 조립했습니다.
- **결과**: CLI 시작 시 상황에 맞는 힌트 출력 완성. 단위 시험 10개 통과, 회귀 606건 통과.

### 040: 통합 검증 (pty 회귀 시험) 및 작동원리 동기화
- **무엇을**: `tests/test_hermes_core/test_cli_input_pty.py` 신설(11종 pty 시험), 가상 터미널(IUTF8 끔) 환경에서 과거 결함 재현(Crash) 및 새 경로의 정상 생존 검증, [작동원리 01편](../../작동원리/01-헤르메스코어-작동원리.md) 동기화(Q13 신설, 12번 방어선 신설, 색인 18번 갱신).
- **왜**: 실제 터미널과 유사한 pty 환경을 통해 CI 수준에서 한글 디코드 예외 및 브래킷 붙여넣기 동작을 자동화된 회귀 시험으로 영구 보장하고, 변경된 입력 아키텍처의 Why와 트레이드오프를 시스템 정본 문서에 투명하게 사실화해야 했습니다.
- **결과**: 3회 연속 pty 시험 전수 통과, 전체 회귀 617건 통과.

### 050: 실제 터미널 앱(WezTerm) 수동 스모크 및 마감
- **무엇을**: 사용자 별도 터미널에서 WezTerm(`-iutf8`) 수동 스모크 중 R1(새 경로)과 R3(폴백) 두 번 실행, 상태 DB 복사본 읽기 전용 대조, 가정 A~G 대조 및 결과 정리. R2·R4는 터미널이 이미 `-iutf8`라 생략(지시서 대비 변경).
- **왜**: pty 시험으로는 확인할 수 없는 실제 GUI 터미널 앱의 한글 폰트 폭, 줄바꿈 화면 들여쓰기, 커서 위치 요청(CPR) 경고 여부, `User >` 프롬프트 잔상, 셸 에코 복귀 상태를 사용자의 눈으로 직접 검증해야 했습니다.
- **결과**: R1 user 메시지 8건이 입력과 일치(기대한 6건 + 반복 2건), R3은 폴백의 붙여넣기 분리·디코드 안내 동작을 확인했다. 화면 잔상·`User >` 사라짐·종료 후 터미널 상태는 사용자 기억이 불확실해 약한 증거다.

## 4. 아키텍처 성과와 작동원리 반영 목록

### 시스템 영구 사실
1. **단일 입력 관문 (`cli_input.py`)**: 사용자 입력을 수신하고 전처리하는 단일 진입로를 구축하여, 차기 10번 로드맵(승인 흐름)에서도 동일한 안전망(디코드 예외 방어, 터미널/폴백 분기)을 그대로 재사용할 수 있습니다.
2. **12번 방어선: CLI 입력 격벽**:
   - **터미널 조건 격벽**: stdin과 stdout이 모두 실제 터미널(tty)일 때만 `prompt_toolkit`을 가동하며, 파이프/리다이렉션 환경은 `input()`으로 자동 격리합니다.
   - **디코드 예외 격벽**: UTF-8 디코드 실패 시 프로그램을 죽이지 않고 해당 줄만 버린 뒤 안내 후 재입력을 유도합니다.
   - **미설치 격벽**: `prompt_toolkit`이 없는 환경이라도 프로세스당 1회 알림 후 기본 `input()`으로 폴백하여 프로그램 실행 자체가 막히지 않습니다.
   - **지연 로딩**: `find_spec`을 활용하여 힌트 판정 시에는 라이브러리를 임포트하지 않고, 실제 입력 수신 직전에만 지연 임포트합니다.

## 5. 미흡한 부분 및 한계

1. **테스트 환경의 한계 (WezTerm 1개 앱 관찰)**:
   - 이번 050 수동 스모크는 macOS WezTerm 앱 1곳에서 2번(R1, R3)만 수행되었습니다. Terminal.app, iTerm2, Alacritty, Windows Terminal 등 다른 에뮬레이터나 특정 폰트 환경에서의 한글 폭 처리는 관찰하지 못했습니다. 또한 Ctrl+D의 실제 앱 실행과 종료 뒤 셸 상태 복원은 확인하지 못했고, 화면 잔상 등은 사용자의 기억에 의존합니다.
2. **`User >` 사라짐의 정확한 트리거 미확인**:
   - R1(새 경로)과 R3(폴백) 모두에서 사라짐이 재현되지 않았습니다. 과거에 왜 발생했는지(조작 순서, 셸 상태, 터미널 폭 변화 등) 특정하지 못했고, 이 로드맵이 해소했다고 말할 수 없습니다. (WHY 가정 F에 따라 「원인 미상, 재현 안 됨」으로 기록).
3. **이월된 기능 (의도된 제외)**:
   - 위/아래 방향키를 통한 이전 입력 히스토리 탐색, 자동 완성, 실시간 마크다운 스트리밍 출력 등은 로드맵 범위(입력 안정화)에 따라 제외되었으며 후속 과제로 남아 있습니다.

## 6. 새로 발견한 부분 및 인사이트

1. **붙여넣기 동작의 극적 차이 실증 (가정 E)**:
   - 기획 당시 「가설」로만 두었던 여러 줄 붙여넣기 문제가 R1과 R3의 비교로 실체가 확인되었습니다. 기존 `input()` 방식(R3)에서는 3줄 붙여넣기가 줄마다 별개 메시지로 전송되었고, 줄바꿈 없이 끝난 마지막 줄은 다음 입력에 이어 붙었습니다(`줄3붙여넣기 줄1`). `prompt_toolkit` 경로(R1)에서는 3줄이 한 메시지로 저장되었습니다.
2. **WezTerm의 완벽한 CPR 응답**:
   - 040 가상 터미널(pty) 실험 당시에는 터미널이 커서 위치 요청(`ESC[6n`)에 응답하지 않아 경고 문구가 나왔으나, 실제 앱(WezTerm)의 R1 화면에는 경고가 나오지 않았습니다. pty 경고는 시험 환경 탓이라는 추정과 일치하지만 앱 1개·1회 관찰입니다.
3. **기본 터미널의 `-iutf8` 상태 관찰**:
   - 사용자의 실제 WezTerm 터미널 기본 상태가 `iutf8`이 꺼진(`-iutf8`) 상태, 곧 1단계에서 재현한 결함 조건 그대로였습니다. 새 경로(R1)는 이 조건에서 꺼지지 않았고 DB 대조가 일치했습니다. 화면 깨짐 여부는 사용자가 기억하지 못합니다.
4. **종료 경로의 세션 종료 사유 비어 있음 (09 범위 밖, 기존 동작)**:
   - Ctrl+C·Ctrl+D로 끝낸 세션은 `sessions.end_reason`이 `NULL`입니다(R1, R3 DB 확인). `exit`로 끝낼 때만 `user_exit`가 기록됩니다. 09에서 바꾼 부분이 아니며 후속 정리 후보입니다.
5. **폴백 경로의 `^R` 입력**:
   - 폴백에서 Ctrl+R은 `^R`이 글자 그대로 찍히고 빈 입력으로 처리되었습니다(화면 출력). 예전 방식의 줄 편집 한계를 보여 주는 관찰입니다.

## 7. 트러블슈팅과 교훈

- **010 단계의 줄 버림 범위 차이 발견**:
  - 디코드 오류 발생 시 터미널 입력은 오류가 난 줄 1개만 버려지지만, 파이프나 `TextIOWrapper` 같은 버퍼링 스트림에서는 같은 청크에 속한 정상 줄까지 함께 버려질 수 있다는 사실을 실험으로 확인했습니다. 이에 따라 ADR과 WHY 문서를 조기에 정정하고 보장 범위를 「데이터 보존」이 아닌 「프로세스가 꺼지지 않는다」로 정직하게 한정함으로써 탁상공론식 설계를 피했습니다.
- **030 단계의 기동 범위 축소**:
  - 010에서 `cli.py`가 이미 `read_user_input`을 호출하도록 구조를 잡았기 때문에 020 완료 시점에 실제 터미널 연동이 끝났음을 확인했습니다. 이에 따라 030 단계를 억지로 부풀리지 않고 배너 힌트 안내와 CLI 수준 통합 검증으로 축소 정정하여 불필요한 코드 조작을 방지했습니다.

## 8. 후속 인계 사항

1. **차기 로드맵 순서**:
   - **합의된 순서**: **10번 승인 흐름 MVP** → **11번 체크포인트·롤백 MVP**.
   - 10번 로드맵에서는 허용목록 밖의 위험 터미널 명령을 실행하기 전, 이번 09번에서 안정화된 `read_user_input()` 관문을 통해 사람에게 명시적 승인을 요청하고 그 결과를 SQLite DB에 선기록하는 흐름을 구축합니다.
2. **이월된 입력/출력 과제**:
   - 방향키 위/아래 입력 히스토리 탐색 (`history`), 터미널 크기 리사이즈 실시간 대응, 실시간 마크다운 스트리밍 출력 등은 향후 CLI 고도화 과제로 다룹니다.
3. **작동원리 문서 갱신 제안**:
   - 작동원리 01편 ③의 「미확인」 줄에 적힌 실제 터미널 앱 화면 검증 항목을 이번 WezTerm 스모크 결과로 사실화 갱신할 수 있습니다 (사용자 지시 시 수행).

|---|---|---|---|

| 〃 | 브래킷 여러 줄 붙여넣기 | **확인** | R1 DB에 3줄이 한 메시지(23자). 폴백(R3)은 줄마다 별개 메시지 + 마지막 줄 이어붙음 |
| 〃 | 디코드 예외 안전망 | **확인** | R3에서 안내 1번, 프로세스 지속, 해당 줄은 DB에 없음 |
