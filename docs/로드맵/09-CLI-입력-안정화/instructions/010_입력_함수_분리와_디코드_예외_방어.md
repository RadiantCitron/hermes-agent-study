## 1. 구현 내용 명세

입력을 읽는 일을 한 함수로 모으고, `input()`이 `UnicodeDecodeError`를 내도 프로그램이 꺼지지 않게 한다. **새 라이브러리는 쓰지 않는다**(020). 터미널에서 눈에 보이는 동작(프롬프트 모양, 종료 키)은 그대로다.

1. **새 모듈** `src/hermes_core/cli_input.py`: 함수 `read_user_input(prompt: str = CLI_USER_PROMPT) -> str`.
   - `input(prompt)`의 결과를 가공 없이 돌려준다(`strip` 등은 하지 않는다. 그건 REPL이 계속 한다).
   - `EOFError`와 `KeyboardInterrupt`는 잡지 않고 그대로 올린다(기존 종료 경로 유지, 가정 D의 기반).
   - `UnicodeDecodeError`가 나면 `CLI_INPUT_DECODE_NOTICE`를 한 줄 출력하고 같은 프롬프트로 다시 읽는다.
   - 연속 실패가 `CLI_INPUT_DECODE_MAX_RETRIES`번에 이르면 `EOFError`를 올린다(끝없이 실패하는 입력원이 무한 루프를 만들지 못하게 하고, REPL의 기존 종료 경로 `Exiting session...`을 타게 한다). 성공하면 연속 횟수는 새로 센다.
2. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py), CLI 입력 절 신설):
   - `CLI_USER_PROMPT = "User > "`
   - `CLI_INPUT_DECODE_NOTICE = "Input could not be decoded as UTF-8; please type it again."`
   - `CLI_INPUT_DECODE_MAX_RETRIES = 5`
3. **REPL 연동** ([`cli.py`](../../../../src/hermes_core/cli.py)): `user_input = input("\nUser > ").strip()`를 `print()` 후 `read_user_input().strip()`으로 바꾼다. 빈 줄은 프롬프트 밖의 별도 출력이다(ADR-0009 §2-7). 화면에 나가는 문자열은 이전과 같다(`\nUser > `). 그 이후(빈 입력 건너뛰기, `exit`/`quit`, `run_conversation`, 오류 출력)는 바꾸지 않는다.
4. **알려진 한계(코드 실험으로 확인, 시험에 고정)**: 터미널은 한 줄씩 읽히므로 오류가 난 줄 하나만 버려진다. 파이프나 `io.TextIOWrapper`처럼 한 덩어리로 읽는 입력원은 오류가 나면 같은 덩어리의 정상 줄도 함께 버려지고 그다음은 입력 끝이다. 이 단계의 보장은 「꺼지지 않는다」이다.
5. **작동원리 갱신**: 없음 (040에서 일괄 반영). ROADMAP·ADR 정정: 없음 (이 지시서 작성 때 ADR-0009 §2-5와 WHY·ROADMAP을 `c85beb6`로 맞췄다).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험은 `tests/test_hermes_core/test_cli_input.py`에 둔다. 가짜 입력원은 `readline()`이 차례로 줄 또는 예외를 내주는 작은 클래스를 시험 파일 안에 정의한다(`UnicodeDecodeError`를 줄 단위로 흉내 내는 터미널 모양). 파이프 모양은 `io.TextIOWrapper(io.BytesIO(...), encoding="utf-8")`를 쓴다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 입력원 `"hello\n"` | `read_user_input()` == `"hello"` |
| 2 | 입력원 `"  내 이름은 철수야  \n"` | 공백과 한글 그대로 `"  내 이름은 철수야  "` (가공 없음) |
| 3 | 입력원 `"x\n"`, 출력 캡처 | 출력이 정확히 `"User > "` (빈 줄은 함수가 내지 않음) |
| 4 | 입력원 `""` (끝) | `EOFError`가 그대로 올라옴 |
| 5 | `input`이 `KeyboardInterrupt`를 냄 | `KeyboardInterrupt`가 그대로 올라옴 |
| 6 | 터미널 모양 `[디코드 오류, "ok\n"]` | 반환 `"ok"`, 안내 문구가 출력에 정확히 1번, 프롬프트 `User > `가 2번 |
| 7 | 파이프 모양 바이트 `b"first\n\xed\x95\nsecond\n"` | `UnicodeDecodeError`가 밖으로 나오지 않고, 안내 1번 뒤 `EOFError`로 끝남 (`first`·`second`는 같은 덩어리라 함께 사라짐: 알려진 한계) |
| 8 | 항상 디코드 오류만 내는 입력원 | 안내가 정확히 `CLI_INPUT_DECODE_MAX_RETRIES`번 출력된 뒤 `EOFError`, 무한히 돌지 않음 |
| 9 | `[오류, 오류, "ok\n", 오류, "again\n"]` 두 번 호출 | 첫 호출 `"ok"`, 둘째 호출 `"again"` (성공하면 연속 횟수가 새로 시작) |
| 10 | `cli.main()` 실제 모드(키 환경변수 + `OpenRouterClient`를 가짜로 교체, 기존 `test_cli.py` 방식), 입력원 `[디코드 오류, "exit\n"]` | 프로그램이 정상 종료, 출력에 안내 문구 1번과 `Session saved and closed. Goodbye!`, 세션 종료 사유 `user_exit`, 대화 메시지 0건 (오류 입력이 기록에 들어가지 않음) |
| 11 | `cli.main()` 실제 모드(위와 같은 방식), 입력원 `StringIO("exit\n")` | 출력에 `"\nUser > "`가 그대로 포함됨 (화면 문자열 보존) |
| 12 | 기존 시험 전체 | 한 줄도 바꾸지 않고 통과 |

## 5. 위험·주의

- **「그 줄만 버린다」는 터미널에서만 맞다**(시나리오 6 vs 7). 문서나 안내 문구에 줄 단위 보장을 쓰지 않는다.
- **`--mock`으로는 REPL에 들어가지 않는다**: `--mock`이고 stdin이 터미널이 아니면 `cli.py`가 1턴 자동 실행 후 끝낸다(`args.mock and not sys.stdin.isatty()` 분기). 그래서 REPL을 거치는 시나리오 10·11은 기존 시험처럼 실제 모드와 가짜 클라이언트를 쓴다. 가짜 입력원 클래스에는 `isatty()`(거짓)도 둔다.
- **시험이 구현의 거울이 되지 않게**: 시나리오 7·8의 기대(꺼지지 않음, 무한 루프 없음)는 요구에서 나왔다. 구현 중 결과가 다르면 시나리오를 바꾸지 말고 멈춰서 보고한다.
- **안내 문구 출력 위치**: `print()`로 표준 출력에 낸다. 020에서 `prompt_toolkit` 경로가 같은 문구를 쓸 때 출력 방식이 충돌하는지는 020에서 확인한다(**미확인**).
- **재시도 상한 5**는 에이전트가 정한 안이다. 해당 단계 착수(「진행해라」) 시 승인으로 갈음한다.
- 실제 터미널(pty) 시험은 040에서 한다. 이 단계의 터미널 모양은 가짜 입력원이다.
