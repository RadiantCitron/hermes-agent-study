## 1. 구현 내용 명세

**계획과 달라진 점(코드 대조 결과)**: 대시보드의 030은 「CLI 연동」을 포함했지만, [`cli.py`](../../../../src/hermes_core/cli.py)는 010에서 이미 `read_user_input()`을 부르고 있고 020에서 그 함수가 터미널일 때 `prompt_toolkit`을 쓰게 됐다. 그래서 **연동 코드는 이미 끝났다.** 030에 남은 일은 (가) 줄바꿈 키 안내 한 줄과 (나) 앱 수준 통합 검증이다. 대시보드의 단계명도 이에 맞춰 고친다.

1. **안내 가능 판정** `multiline_input_available() -> bool` ([`cli_input.py`](../../../../src/hermes_core/cli_input.py)): `is_interactive_terminal()`이 참이고 `prompt_toolkit`이 설치되어 있으면(`importlib.util.find_spec("prompt_toolkit")`가 `None`이 아니면) `True`. 라이브러리를 실제로 import하지는 않는다(020의 지연 import 원칙 유지). 터미널이 아니거나 미설치면 `False`다 — 줄바꿈 키가 실제로 동작하지 않는 환경에서 거짓 안내를 내지 않기 위해서다.
2. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py), CLI 입력 절): `CLI_MULTILINE_HINT = "Enter to send, Ctrl+J for a new line."`
3. **배너** ([`cli.py`](../../../../src/hermes_core/cli.py)): `from hermes_core.cli_input import multiline_input_available, read_user_input`. 시작 배너에서 `Type 'exit' or 'quit' to terminate.` 줄 **바로 다음**, 닫는 `=` 줄 **앞**에 `multiline_input_available()`이 참일 때만 `CLI_MULTILINE_HINT`를 한 줄 출력한다. 모의·실제 모드, `--delegate`, `--no-skills-index` 여부와 무관하게 같은 규칙이다. 그 밖의 배너 줄과 REPL 흐름은 바꾸지 않는다.
4. **바꾸지 않는 것**: REPL 루프(`strip`, 빈 입력 건너뛰기, `exit`/`quit`, 종료 경로), 단발 실행 분기(`--mock`이고 stdin이 tty가 아닐 때), `agent/`·`tools/`·`session_db.py`. 여러 줄 입력은 줄바꿈이 든 문자열 하나로 `run_conversation`에 그대로 전달된다(`strip`은 양 끝 공백만 제거).
5. **알려진 한계**: 안내문이 실제 터미널 앱에서 의도대로 보이는지, Ctrl+J가 그 터미널에서 줄바꿈으로 동작하는지는 **미확인**이다(050에서 사용자가 확인). `prompt_toolkit`이 설치돼 있어도 터미널 초기화 같은 실행 중 오류가 나면 안내와 실제 동작이 어긋날 수 있다(역시 미확인).
6. **작동원리 갱신**: 없음(040에서 일괄). ROADMAP §6-3의 「앱 연동」 서술(REPL 연동은 010에서 완료됨)은 040의 문서 동기화 때 정정한다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험은 새 파일 `tests/test_hermes_core/test_cli_multiline_hint.py`에 둔다. `cli.main()` 시험은 010 시나리오 10·11과 같은 방식(키 환경변수, `OpenRouterClient`를 가짜로 교체, 임시 `HERMES_HOME`)으로 실제 모드를 쓴다. 터미널 상황은 `cli.multiline_input_available`과 `cli.read_user_input`을 대체해 만들고, 대체 입력함수는 미리 정한 값이나 예외를 차례로 내준다. 기대값은 ADR-0009 §2-4와 위 명세에서 나왔다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `multiline_input_available`을 `True`로 대체, 입력 `["exit"]`로 `cli.main()` | 출력에 `CLI_MULTILINE_HINT`가 정확히 1번, `Type 'exit' or 'quit' to terminate.` 줄 바로 다음 줄이고 그 다음 줄은 `=`로만 된 닫는 줄, 마지막에 `Session saved and closed. Goodbye!` |
| 2 | 대체 없이(비터미널 `StringIO("exit\n")`) `cli.main()` | 출력에 `CLI_MULTILINE_HINT`가 없고, 배너의 나머지 줄(`Hermes Core CLI Started`, `REAL mode`, `Working directory`, `Type 'exit' or 'quit' to terminate.`)은 그대로 있음 |
| 3 | `multiline_input_available`을 `True`로 대체하고 `--no-skills-index`로 실행 / 실제 모드 `--delegate`로 실행 | 두 경우 모두 힌트 정확히 1번 (다른 플래그와 독립), 각 플래그의 기존 배너 줄(`Skills index disabled…`, `Delegation enabled…`)도 그대로 |
| 4 | `multiline_input_available()` 단위: ⓐ tty 판정 참 + 라이브러리 설치됨 ⓑ tty 판정 참 + `sys.modules["prompt_toolkit"] = None`(미설치 모사) ⓒ tty 판정 거짓 | ⓐ `True` ⓑ `False` ⓒ `False` |
| 5 | `multiline_input_available()` 호출 전후 `"prompt_toolkit" in sys.modules` (새 프로세스에서) | 호출해도 `False`가 유지됨(판정이 라이브러리를 import하지 않음) |
| 6 | 입력 대체 `["첫째 줄\n둘째 줄", "exit"]`로 `cli.main()` (가짜 클라이언트가 고정 응답) | 상태 DB에 저장된 user 메시지 내용이 정확히 `"첫째 줄\n둘째 줄"`(줄바꿈 보존), 세션 종료 사유 `user_exit` |
| 7 | 입력 대체 `["  \n  ", "exit"]` (공백·줄바꿈만) | 모델 호출 0회(빈 입력으로 건너뜀), 대화 메시지 0건, 종료 사유 `user_exit` |
| 8 | 입력 대체가 `KeyboardInterrupt`를 낸 뒤(= 터미널의 Ctrl+C) | 출력에 `Exiting session...`, 프로그램이 오류 없이 끝나고 DB가 닫힘 |
| 9 | 입력 대체가 `EOFError`를 냄 (= 터미널의 빈 줄 Ctrl+D) | 8과 같은 결과 |
| 10 | 기존 시험 전체(010·020 시나리오 포함, `test_cli.py`·`test_cli_delegate.py`·`test_cli_skills_index.py` 포함) | 한 줄도 바꾸지 않고 통과 |

## 5. 위험·주의

- **거짓 안내 방지**: 힌트는 터미널이고 라이브러리가 있을 때만 나온다. 판정이 `find_spec`이므로 「설치는 됐으나 실행 중 실패」는 걸러내지 못한다(**미확인**, 050).
- **배너 문자열 의존**: 힌트 위치(`Type 'exit'` 다음 줄)를 시험 1이 고정한다. 구현 결과가 다르면 시나리오를 바꾸지 말고 멈춰서 보고한다.
- **시험이 실제 터미널을 흉내 내지 않음**: 시나리오 1·3·6~9는 입력 함수를 대체한 앱 수준 시험이다. 실제 키 입력의 반환값은 020 시험이, 가상 터미널(pty) 전체 경로는 040이, 화면은 050이 맡는다.
- **단발 실행 분기**: `--mock`이고 stdin이 tty가 아닐 때는 REPL에 들어가지 않으며, 이때 `multiline_input_available()`은 거짓이라 힌트가 나오지 않는다(시나리오 2와 같은 이유). 별도 시험은 두지 않는다.
- **힌트 문구**(`Enter to send, Ctrl+J for a new line.`)는 에이전트가 정한 안이다. 해당 단계 착수(「진행해라」) 시 승인으로 갈음하며, 바꾸고 싶으면 착수 전에 알린다.
- **계획 변경 기록**: 030 범위가 줄어든 사실은 [WHY.md](../WHY.md) 끝 변경 기록과 [ROADMAP.md](../ROADMAP.md) §6-3에 아직 반영하지 않았다. 해당 문서 수정은 사용자의 지시 또는 040의 동기화 단계에서 한다.
