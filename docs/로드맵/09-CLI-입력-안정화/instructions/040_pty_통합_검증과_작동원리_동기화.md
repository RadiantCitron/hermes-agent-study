## 1. 구현 내용 명세

이 단계는 **`src/`를 바꾸지 않는다.** 1단계 검토에서 재현한 결함(IUTF8를 끈 터미널에서 한글을 치고 백스페이스를 누르면 `input()`이 `UnicodeDecodeError`로 죽음)이 실제 프로그램 프로세스에서 더는 일어나지 않는지, 가상 터미널(pty)로 확인하는 회귀 시험을 추가한다. 이어서 작동원리 01편과 로드맵 문서를 사실에 맞춘다.

### A. pty 회귀 시험 (코드 작업: 시험 파일만)

1. **새 시험 파일** `tests/test_hermes_core/test_cli_input_pty.py`. 표준 라이브러리 `pty`·`termios`·`select`·`subprocess`만 쓴다(새 의존성 없음). 유닉스 계열이 아니면(`pty`/`termios` import 불가) 모듈 전체를 건너뛴다.
2. **시험용 보조 도구**(같은 파일 안):
   - `pty.openpty()`로 만든 슬레이브 터미널의 `termios` 플래그에서 `IUTF8`를 **끈다**(재현 조건). 자식 프로세스의 stdin·stdout·stderr를 모두 이 슬레이브에 연결하고 `start_new_session=True`로 띄운다.
   - 자식은 `sys.executable -c "<런처>"`로 실행한다. 런처는 `sys.argv = ["hermes-core", "--mock"]`로 설정하고 `runpy.run_module("hermes_core.cli", run_name="__main__")`를 부른다(`--mock`이고 stdin이 터미널이면 REPL에 들어간다: 코드로 확인함). 환경: `PYTHONPATH=<레포>/src`, `HERMES_HOME=<임시 폴더>`, `TERM=xterm-256color`, `PYTHONUTF8=1`, 작업 폴더 `<임시 폴더>`. 네트워크·실제 키는 쓰지 않는다.
   - **폴백 변형**: 런처 앞에 `sys.modules["prompt_toolkit"] = None`을 넣어 라이브러리 미설치를 모사한다.
   - `wait_for(표지, 제한시간)`: 마스터 쪽에서 출력을 읽어 모으며 표지 문자열이 나올 때까지 기다린다. 제한시간(기본 15초)을 넘으면 그때까지 모인 출력 끝부분을 메시지로 실패한다. 키는 **프롬프트(`User >`)가 나온 뒤에만** 보낸다(고정 `sleep`에만 기대지 않는다).
   - 종료 시(정상·실패 모두) 자식이 살아 있으면 강제로 끝내고 파일 기술자를 닫는다.
   - 대화 확인은 종료 후 `HERMES_HOME/state.db`를 `sqlite3`로 직접 읽는다: `SELECT content FROM messages WHERE role='user' ORDER BY id`.
3. **관찰된 사실 (지시서 작성 때 임시 폴더에서 같은 방식으로 실험한 결과, 시나리오의 근거가 아닌 참고)**:
   - `prompt_toolkit` 경로는 한글 입력 후 백스페이스를 받고도 `exit` 입력으로 종료 코드 0, 배너에 힌트가 나온다.
   - 폴백 경로는 같은 입력에서 오류 줄 하나가 버려지고 안내가 나온 뒤 프로세스가 살아 있으며, 이어서 `exit`를 보내면 종료 코드 0이다. 버려진 줄에 함께 입력한 `exit`는 소비된다.
   - 순수 `input()` 한 줄짜리 스크립트는 같은 조건에서 종료 코드 1로 죽었다(오류 메시지 본문은 확인하지 못함).
   - 가상 터미널이 커서 위치 요청(CPR, `ESC[6n`)에 응답하지 않으면 `prompt_toolkit`이 `WARNING: your terminal doesn't support cursor position requests (CPR).` 한 줄을 출력한다. **이 경고는 시험 환경 때문에 나오는 것으로 추정**하며 실제 터미널 앱에서도 나오는지는 **미확인**이다(050에서 확인). 시험은 이 경고의 유무를 검사하지 않는다.
4. **알려진 한계**: pty는 실제 터미널 앱(Terminal.app, iTerm2)이 아니다. 화면 모양, 한글 폭, `User >` 사라짐(가정 F)은 확인하지 못하며 050에서 사용자가 본다. 시험은 「프로세스가 꺼지지 않고, 입력이 원하는 문자열로 앱에 도달한다」까지만 보장한다.

## 5. 위험·주의

- **시간 의존(불안정) 시험**: pty 시험은 프로세스 기동·화면 갱신 시간에 흔들린다. 표지 기반 대기와 제한시간으로 막고, 키 전송 전에 반드시 `User >`를 기다린다. 붙여넣기(시나리오 4)는 `prompt_toolkit`이 raw 모드에 들어간 뒤여야 감싸기 표지를 해석하므로, 프롬프트를 확인한 뒤에 보낸다.
- **mock 모드의 응답 시간**: 임의 입력(`ok` 등)에 대한 mock 응답이 도구를 부르는 등 추가 동작을 하는지는 지시서 작성 때 확인하지 않았다(**미확인**). 시험은 다음 `User >`가 나올 때까지 기다리므로 동작이 늘어도 성립해야 한다. 멈추면 보고한다.
- **헛돌지 않는 시험**: 시나리오 1(대조군)이 결함 재현의 전제다. 플랫폼이나 터미널 설정이 달라 재현되지 않으면 이후 시나리오의 의미가 약해지므로 알리고 멈춘다.
- **IUTF8 플래그**: 이 환경(macOS, Python 3.14.8)에서는 `termios.IUTF8`가 있다. 다른 플랫폼에서의 동작은 **미확인**이다.
- **자식 프로세스 정리**: 시험이 실패해도 자식이 남지 않게 한다. 임시 폴더 밖에는 아무것도 쓰지 않는다(`HERMES_HOME`·작업 폴더 모두 임시).
- **문서 정정의 범위**: ROADMAP·WHY 정정은 이 지시서 6항에 적은 것만 한다. 그 밖의 문서(ADR 등)는 건드리지 않고, 필요해 보이면 제안으로 보고한다.
- **작동원리 서술은 시험으로 확인한 사실만**: 특히 시나리오 10(폴백 여러 줄)은 현재 동작의 기록이지 바람직한 동작이 아니다. 실제 터미널 앱, 한글 폭, `User >` 사라짐, CPR 경고의 실재는 「미확인」으로 남긴다(050).
- **기준 커밋의 한계**: 이 단계의 커밋은 `tests/test_hermes_core`를 바꾸므로 커밋 뒤 `git log -1 -- src tests/test_hermes_core`는 이 단계 자신을 가리킨다. 문서에는 직전 값 `fc7617a`를 적고(선례 `8a3c020`), 한계를 ③에 한 줄 밝힌다.
