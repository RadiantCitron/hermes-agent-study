# [구현지시서 050] 실제 터미널 앱 수동 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [09-README.md](../README.md)  
> **선행 조건**: 040 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 추가로 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 가정 A~G, [ADR-0009](../../../adr/0009-CLI_입력_안정화_범위와_prompt_toolkit_도입.md) §1(미확인 목록)·§4, 형식 선례: [08의 050](../../08-스킬-인덱스-주입-MVP/instructions/050_실제키_스모크와_마감.md)  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 단계**다. 이 단계의 핵심은 pty로 볼 수 없던 것(실제 터미널 앱의 화면, 한글 폭, `User >` 사라짐, 붙여넣기, 터미널 상태 복원)을 **사용자가 직접 눈으로** 확인하는 것이다. 지시서는 절차와 기대 결과만 정하고, 결과는 대시보드와 종합보고서에 기록한다.

---

## 1. 목적

가짜 입력과 가상 터미널(pty)로 모든 시험이 통과한 상태에서, 실제 터미널 앱에서 다음을 확인한다. **실제 모델 키는 필요 없다**(`--mock`).

1. **가정 A**: 한글을 치고 백스페이스로 지워도 꺼지지 않고, 화면이 깨지지 않는가(IUTF8 평소 상태와 끈 상태 모두).
2. **가정 B**: 라이브러리가 없는 폴백 경로에서도 잘못된 바이트로 꺼지지 않는가(IUTF8 끈 상태).
3. **가정 D**: Enter 전송, Ctrl+J 줄바꿈(화면에 어떻게 보이는지 포함), Ctrl+C·Ctrl+D 종료가 실제 앱에서 의도대로 동작하고, 종료 뒤 터미널 상태(에코·커서)가 정상으로 돌아오는가.
4. **가정 E**: 여러 줄 붙여넣기가 새 경로에서는 한 입력이 되는가, 폴백(예전 방식과 같은 `input()`)에서는 줄마다 따로 전송되는가(**지금까지 실험하지 않은 문제의 실재 여부**).
5. **가정 F**: 사용자가 겪은 `User >` 사라짐이 새 경로에서 사라졌는가, 폴백에서는 재현되는가. **재현되지 않으면 「원인 미상」으로 기록하고 구조를 되돌리지 않는다**(WHY 가정 F).
6. **가정 C·G**: 터미널이 아닌 입력과 입력 외의 부분이 이전과 같다(자동 시험의 재확인).
7. 미설치 폴백 안내와 `prompt_toolkit` 경고(CPR)가 실제 터미널 앱에서도 나오는지(040에서 pty에서는 경고가 나왔고 실제 앱은 **미확인**).

## 2. 사전 조건

1. **에이전트**: `.venv/bin/python -m pytest -q`가 모두 통과함을 확인하고 기준선(040 마감 시 617건)을 기록한다. 가짜 자료는 필요 없다. 코드·문서는 이 단계에서 바꾸지 않는다.
2. **사용자**: 평소 쓰는 터미널 앱 **1개 이상**(예: Terminal.app, iTerm2)을 준비한다. 앱이 여러 개면 앱마다 R1을 한 번씩 한다(R2~R4는 평소 앱 1개로 충분).
3. **키는 쓰지 않는다.** `--mock` 실행이라 네트워크·API 키가 필요 없다. 그래도 **화면 출력을 에이전트에게 붙여 넣을 때 개인 경로(홈 폴더 이름)는 `<임시>`로 바꾼다.**
4. 상태 폴더는 레포 밖 임시 폴더를 쓴다. 사용자가 레포 루트에서 한 번 실행한다:
   ```bash
   export H=$(mktemp -d); echo "$H"; mkdir -p "$H"/r1 "$H"/r2 "$H"/r3 "$H"/r4
   echo "TERM_PROGRAM=$TERM_PROGRAM TERM=$TERM"; stty -a | tr ' ' '\n' | grep -i iutf8
   ```
   출력(`iutf8` 또는 `-iutf8`)과 터미널 앱 이름·버전을 기록해 에이전트에게 알린다.
5. 붙여넣기용 3줄 텍스트(텍스트 편집기에 써 두고 복사한다. 터미널에 직접 쓰지 않는다):
   ```
   붙여넣기 줄1
   붙여넣기 줄2
   붙여넣기 줄3
   ```

## 3. 절차 (사용자가 실제 터미널 앱에서 직접 실행, 에이전트는 대신하지 않는다)

각 실행은 레포 루트에서 한다. 실행마다 아래 「입력 순서」를 **그대로** 따르고, 각 단계에서 화면에서 **본 것**을 기록한다(정상 / 이상 / 재현 안 됨 + 한 줄 메모).

| 실행 | 명령 | 조건 |
|---|---|---|
| **R1** | `HERMES_HOME="$H"/r1 .venv/bin/python -m hermes_core.cli --mock` | 기본 경로(`prompt_toolkit`), 터미널 기본 설정 |
| **R2** | `stty -iutf8` 입력 후 `HERMES_HOME="$H"/r2 .venv/bin/python -m hermes_core.cli --mock` (실행 후 `stty iutf8`로 되돌리거나 탭을 닫는다) | 기본 경로, **IUTF8 끈 터미널**(원래 결함 조건) |
| **R3** | `HERMES_HOME="$H"/r3 .venv/bin/python -c "import sys; sys.modules['prompt_toolkit']=None; sys.argv=['hermes-core','--mock']; import runpy; runpy.run_module('hermes_core.cli', run_name='__main__')"` | **폴백 경로**(라이브러리 미설치 모사 = 예전 `input()` 방식), 기본 설정 |
| **R4** | `stty -iutf8` 후 R3과 같은 명령에서 `r3`를 `r4`로 | 폴백 경로, IUTF8 끈 터미널 |

### R1 입력 순서 (기대 DB 메시지는 §4 참조)

| 턴 | 입력 | 보아야 할 것 |
|---|---|---|
| 시작 | (배너) | 힌트 `Enter to send, Ctrl+J for a new line.` 한 줄이 있는가, `WARNING: your terminal doesn't support cursor position requests (CPR).` 경고가 나오는가, `User >`가 보이는가 |
| 1 | `안녕하세요` Enter | 입력한 글자가 깨지지 않고 보이는가, 응답 뒤 다음 `User >`가 정상인가 |
| 2 | `한글ab` → Backspace 2번 → `테스트` → Enter | 지울 때 글자 잔상·커서 어긋남이 있는가 (`한글테스트`가 되어야 함) |
| 3 | `가다` → 왼쪽 방향키 1번 → `나` → Enter | 중간 삽입이 되는가 (`가나다`) |
| 4 | `첫째 줄` → **Ctrl+J** → `둘째 줄` → Enter | Ctrl+J 뒤 줄이 어떻게 보이는가(들여쓰기·표시), Enter에서 전송되는가 |
| 5 | 붙여넣기용 3줄을 **복사해 붙여넣기**(전송 키는 누르지 않음) → 화면 확인 → Enter | 붙여넣는 순간 줄마다 전송되지 않고 한 입력 안에 3줄로 보이는가 |
| 6 | `가`를 터미널 폭의 1.5배 이상(보통 80~120번) 입력 → Enter | 줄이 넘어갈 때 화면·커서가 어긋나는가 |
| 7 | 반복 | 1~2턴을 더 반복하며 `User >` 표시가 사라지거나 지워지는 순간이 있는지 본다. 입력 중에 창 크기를 한 번 바꿔 본다 |
| 끝 | `x` 입력 → **Ctrl+C** | `Exiting session...`이 나오고 셸로 돌아오는가. 돌아온 셸에서 글자가 보이게 입력되는지(에코), 커서가 보이는지, `stty -a`가 시작 전과 같은지 |

### R2 입력 순서 (`stty -iutf8` 상태)

| 턴 | 입력 | 보아야 할 것 |
|---|---|---|
| 1 | `한` → Backspace → `ok` → Enter | 꺼지지 않는가, 안내 문구(`could not be decoded`)가 **나오지 않는가** (`ok`가 되어야 함) |
| 2 | `한글ab` → Backspace → Enter | 꺼지지 않는가 (`한글a`) |
| 끝 | 빈 프롬프트에서 **Ctrl+D** | `Exiting session...`, 셸 상태 정상 복귀 |

### R3 입력 순서 (폴백, 기본 설정)

| 턴 | 입력 | 보아야 할 것 |
|---|---|---|
| 시작 | (배너) | `prompt_toolkit is not installed; falling back to basic input (no multi-line editing).`가 1번 나오는가, 힌트는 없는가 |
| 1 | 붙여넣기용 3줄을 복사해 붙여넣기(마지막 줄 뒤 줄바꿈 포함) | 줄마다 따로 전송되어 응답이 3번 나오는가, 아니면 다른 모양인가 (**현재 방식의 붙여넣기 동작 관찰**, 가정 E 대조) |
| 2 | `안녕하세요` → Backspace 몇 번 → 다시 입력 → Enter | `User >` 표시가 사라지거나 지워지는가, 한글 편집이 어긋나는가 (**가정 F 대조: 예전 방식에서 재현되는가**) |
| 끝 | `x` → Ctrl+C | `Exiting session...` |

### R4 입력 순서 (폴백, `stty -iutf8`)

| 턴 | 입력 | 보아야 할 것 |
|---|---|---|
| 1 | `한` → Backspace → Enter | 꺼지지 않고 안내 `Input could not be decoded as UTF-8; please type it again.`가 나오는가 |
| 2 | `ok` → Enter | 이어서 정상 동작하는가 |
| 끝 | Ctrl+D | `Exiting session...` |

### 순서

| 순서 | 동작 |
|---|---|
| 1 | 에이전트가 사전 조건 1을 확인하고 이 지시서의 명령을 사용자에게 그대로 전달 |
| 2 | 사용자가 §2의 4·5를 하고, R1 → R2 → R3 → R4를 별도 터미널에서 실행하며 관찰을 기록 (앱이 여러 개면 R1만 앱마다 반복) |
| 3 | 사용자가 비밀·개인 경로를 뺀 관찰 기록과 필요하면 화면 문자열을 에이전트에게 전달. **스크린샷은 선택**이며, 보낸다면 개인 정보가 없는지 사용자가 확인 |
| 4 | 에이전트가 각 실행의 `state.db`를 **읽기 전용**으로 조회해 §4 확인 항목 7을 채움 (`sqlite3`로 `SELECT role, content FROM messages`) |
| 5 | 에이전트가 가정 A~G를 「맞았다 / 틀렸다 / 바뀌었다」로 정리해 보고 |

문제(꺼짐, 화면 깨짐, 예상과 다른 동작)가 보이면 **코드를 고치거나 같은 실행을 자동으로 다시 하지 않는다.** 증상과 입력 순서를 기록하고 멈춰서 보고한다. 재현 시도는 사용자의 새 지시가 있을 때만 한다.

## 4. 기대 결과와 확인 항목

판정은 통과/실패가 아니라 **가정을 「맞았다 / 틀렸다 / 바뀌었다」로 기록**하는 것이다. 화면 관련 항목은 사용자의 관찰이 근거이고, 에이전트는 이를 사실처럼 부풀리지 않는다.

| # | 확인 | 기대 결과 |
|---|---|---|
| 1 | **가정 A: 한글+백스페이스** | R1 턴 2와 R2 턴 1·2에서 프로그램이 꺼지지 않고, 지운 만큼만 지워진다. 화면 잔상·커서 어긋남이 있으면 어느 앱·어느 단계인지 기록 |
| 2 | **가정 B: 폴백 예외** | R4 턴 1에서 꺼지지 않고 안내가 1번 나온다. R2 턴 1에서는 안내가 나오지 않는다 |
| 3 | **가정 D: 키** | Enter 전송, Ctrl+J 줄바꿈(R1 턴 4), Ctrl+C·Ctrl+D 종료(R1 끝, R2 끝, R3 끝, R4 끝), 종료 뒤 셸의 에코·커서·`stty -a`가 시작 전과 같다. Ctrl+J 줄의 표시 모양을 글로 적는다 |
| 4 | **가정 E: 붙여넣기** | R1 턴 5에서 3줄이 한 입력으로 들어가 Enter 전에는 전송되지 않는다. R3 턴 1에서 폴백이 어떻게 동작했는지(줄마다 전송 여부) 있는 그대로 기록. 두 결과를 나란히 적는다. **폴백에서도 문제가 없었다면 「현재 문제가 실재하지 않았음」으로 기록** |
| 5 | **가정 F: `User >` 사라짐** | R1에서 사라지지 않는다. R3 턴 2(폴백)에서 재현되는지 기록. R1에서 사라지면 「틀렸다 — 원인 미상, 후속 조사」, R3에서도 재현되지 않으면 「원인 미상(재현 안 됨)」으로 적고 둘 다 구조를 되돌리지 않는다 |
| 6 | **시작 화면과 경고** | R1 배너에 힌트가 1줄 있다. R3 배너에 미설치 안내가 1번 있고 힌트는 없다. CPR 경고가 R1에 나오는지 기록(나오면 사용자 앱에서의 추가 후속 후보) |
| 7 | **입력이 앱에 닿은 모양 (에이전트가 DB로 확인)** | `r1`의 user 메시지가 순서대로 `["안녕하세요", "한글테스트", "가나다", "첫째 줄\n둘째 줄", "붙여넣기 줄1\n붙여넣기 줄2\n붙여넣기 줄3", "가"×(입력한 횟수)]`. `r2`는 `["ok", "한글a"]`. `r3`는 관찰 기록(붙여넣기가 줄마다 전송됐다면 `붙여넣기 줄1`·`줄2`·`줄3`이 각각 별개 메시지). `r4`는 `["ok"]` (오류 줄은 기록에 없음). 기대와 다르면 어느 턴인지 기록 |
| 8 | **가정 C·G 재확인 (에이전트)** | 전체 회귀 테스트 통과, `git diff dc622f3..HEAD -- src/`가 0줄(050은 `src/` 무변경). 비터미널 입력은 040 시나리오 11이 이미 고정 |
| 9 | 비밀·개인정보 | 기록에 키·홈 경로가 없다. `.hermes`·실제 상태 폴더를 쓰지 않았다(`HERMES_HOME`은 임시) |

## 5. 결과 기록

- 대시보드 실행 기록에 날짜, 지시 문구, 앱 이름·버전, `iutf8` 상태, 실행별(R1~R4) 관찰 요약, 가정별 판정을 적는다. 로컬 경로 대신 `<임시>`를 쓴다.
- 확인 항목 1~6의 관찰은 **사용자가 본 대로** 종합보고서의 「목표와 결과」·「새로 발견한 부분」에 옮긴다. 관찰이 기대와 달라도 코드를 이 단계에서 고치지 않고 후속 제안만 근거와 함께 적는다.
- **판정의 한계**: 터미널 앱 1~2개, 실행별 1회, 사용자의 눈이 근거다. 다른 앱·다른 폰트·다른 로케일에서는 달라질 수 있다. 사용자가 겪은 `User >` 사라짐의 정확한 조작을 재현했는지는 사용자의 기억에 달려 있다. 이 한계를 종합보고서에 함께 적는다. 비용은 0이다(모의 모드).

## 6. 마감 (5단계, 사용자의 종료 선언이 있을 때만)

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)가 정본이다. 이 로드맵에 해당하는 순서만 적는다.

1. **종합보고서** `결과정리및리뷰.md`를 정책의 9개 항목으로 상세히 쓴다. `WHY.md`의 가정 **A~G를 하나씩** 「이뤘다 / 못 이뤘다 / 바뀌었다」로 근거(커밋 해시, 시험, 이 스모크의 사용자 관찰)와 함께 대조한다. 대조하지 않은 가정이 있으면 마감하지 않는다. 030 범위 축소, 미설치 폴백 결정(WHY 변경 기록)은 「바뀌었다」로 기록한다.
2. **대시보드** `README.md`의 전체 상태를 `Closed`로, 완료 일자와 종합보고서 링크를 채우고 050 행·실행 기록을 갱신한다. 실행 기록의 커밋 칸은 같은 커밋에서 자기 해시를 쓰지 않는다(정책 §4).
3. **`docs/인계.md`** 를 갱신한다(상태가 바뀌는 작업의 완료 보고). 인계의 「다음 로드맵 순서」(10 승인 흐름 → 11 체크포인트)를 이어받는다.
4. **작동원리 01편**의 Q13·③ 「미확인」(실제 터미널 앱의 화면·한글 폭·`User >` 사라짐·CPR 경고)을 이번 관찰로 갱신할 수 있다. 이 갱신은 마감 보고에서 **제안만** 하고, 사용자가 지시하면 수행한다.
5. **커밋과 태그**: 스모크 결과 기록과 마감이 같은 지시면 하나의 마감 커밋(`docs(core): R09-마감 - ...`), 스모크 기록이 먼저면 `R09-050` 기록 커밋 뒤 마감 커밋을 따로 만든다. 변경 파일을 경로로 지정해 스테이징한다. **마감 커밋에만** 가벼운 태그 `roadmap-09-closed`를 단다. 푸시와 태그 푸시는 하지 않으며 사용자의 별도 지시가 있을 때만 한다.
6. 마감 후 구현지시서(`instructions/`)는 수정하지 않는다.
7. **후속 인계**: 종합보고서 §8에 다음 로드맵 후보를 적는다. 합의된 순서는 10 승인 흐름 MVP다. 스모크에서 `User >` 사라짐이 남았거나 CPR 경고가 실제 앱에서 나오면 입력·출력 후속 조사를 후보에 올린다. 입력 히스토리(방향키 위/아래)·출력 안정화는 이월 항목으로 적는다.

## 8. 위험·주의

- **`stty -iutf8`는 해당 터미널 탭의 설정을 바꾼다.** R2·R4 뒤 `stty iutf8`로 되돌리거나 그 탭을 닫는다. 이미 `-iutf8`였다면(2-4의 출력) 되돌릴 값은 원래 상태다.
- **R1의 `User >` 사라짐은 조작 순서가 중요할 수 있다.** 사용자가 기억하는 조작(어떤 키·어떤 순서)이 있으면 R1·R3에서 그대로 시도하고 기록한다. 기억이 없으면 「원인 미상」이 정직한 답이다.
- **R3은 라이브러리를 지우지 않고 `sys.modules`로 미설치를 모사한다.** 실제 미설치 환경과 다를 수 있지만 코드 경로는 같다(040 시나리오 8·9·10과 같은 방식).
- **붙여넣기 동작은 터미널 앱 설정(붙여넣기 감싸기 지원)에 따라 다를 수 있다.** 앱 이름·버전을 반드시 적는다.
- **판정은 사용자의 눈**이다. 에이전트는 관찰 기록을 인용하며, 보지 않은 것을 확인했다고 쓰지 않는다.
- 이 단계에서 문제를 발견하면 **구조를 되돌리거나 땜질하지 않는다.** 근본 원인을 기록하고 후속 로드맵 후보로 올린다(AGENTS.md §1-4).
