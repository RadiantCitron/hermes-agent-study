## 1. 구현 내용 명세

1. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py)):
   - `WORKSPACE_DIR_NAME = "workspace"`
   - `PROTECTED_NAME_PREFIXES = (".env",)`, `PROTECTED_NAME_EXACT = (".git",)` (비교는 `casefold()`)
   - `get_default_workspace() -> Path`: `get_hermes_home() / WORKSPACE_DIR_NAME`을 만들고(`mkdir(parents=True, exist_ok=True)`) `resolve()`해서 반환한다.
2. **보호 이름 판정 함수** ([`path_guard.py`](../../../../src/hermes_core/tools/path_guard.py)): `is_protected_path(value: str, workspace: Path) -> bool`
   - 두 가지 이름 목록의 구성요소를 모두 검사한다: ① `PurePath(value).parts` (`.`·`..` 제외) ② 풀린 경로(`(workspace / value).resolve()`)에서 작업 폴더를 뺀 상대 경로의 `parts`. 풀 수 없는 경로(`OSError`, `ValueError`, `RuntimeError`)는 거짓이 아니라 **참**(보수적)으로 본다. 작업 폴더 밖이라 상대 경로를 만들 수 없을 때는 ①만 검사한다.
   - 어떤 구성요소든 `PROTECTED_NAME_PREFIXES`로 시작하거나 `PROTECTED_NAME_EXACT`와 같으면 참.
3. **`check_path`에 보호 판정 추가**: 제어문자·작업 폴더 밖 검사 **다음**에 `is_protected_path`가 참이면 `(None, f"Path '{path}' refers to a protected file or folder (.env*, .git).")`. 읽기·쓰기 모두 이 함수를 거치므로 양쪽에 적용된다.
4. **상태 폴더 쓰기 금지 규칙 예외** (`check_write_path`의 4번 검사): `workspace`가 `get_hermes_home().resolve()`의 **안쪽**(같지 않음, `is_relative_to`이고 `!=`)이면 이 규칙을 건너뛴다. 같거나 바깥이면 기존대로 적용한다. 건너뛰어도 기억 파일·`state.db`는 `check_path`가 작업 폴더 밖으로 거부한다.
5. **터미널 인자 검사에 같은 판정 사용** ([`terminal_tool.py`](../../../../src/hermes_core/tools/terminal_tool.py)): 각 인자의 `path_values`에 대해 `is_inside`가 거짓이면 기존 오류, 그 다음 `is_protected_path`가 참이면 `f"Path '{arg}' refers to a protected file or folder (.env*, .git)."`로 실행 없이 거부한다. 같은 판정 함수를 공유해 두 도구의 기준이 갈라지지 않게 한다.
6. **의도한 한계**: 검색어처럼 경로가 아닌 인자(`grep .env file`의 `.env`)도 보호 이름이면 거부된다. 보수적 판정이다.
7. **작동원리 갱신** (01편): 2부 Q9(공용 경로 판정)에 보호 이름 규칙을, Q8(쓰기 금지)에 작업 폴더가 상태 폴더 안일 때의 예외를 영구 사실로 반영한다. 「미확인」은 그대로 둔다. 로드맵 서사는 쓰지 않는다. `기준 커밋` 값은 건드리지 않는다.
