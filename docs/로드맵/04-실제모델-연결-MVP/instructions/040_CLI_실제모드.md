## 1. 구현 내용 명세

1. **`--model` 기본값**: `argparse`의 `--model` 기본값을 `None`으로 한다. 실제 모드에서 `None`이면 `DEFAULT_REAL_MODEL`을 쓴다. `--mock`에서는 모델명을 넘기지 않아(`None`) 세션 모델이 `"mock"`으로 기록된다(030).
2. **`--mock` 없이 실행**([`cli.py`](../../../../src/hermes_core/cli.py)):
   1. 환경변수 `OPENROUTER_API_KEY_ENV`(`OPENROUTER_API_KEY`)를 읽는다. 없거나 공백뿐이면 **에이전트·세션 DB를 만들기 전에** 안내(`OPENROUTER_API_KEY`가 없다는 것과 `--mock` 사용법을 모두 언급)를 표준 오류로 출력하고 종료 코드 2.
   2. 있으면 `HERMES_HOME`이 지정돼 있을 경우 `get_hermes_home()`의 절대경로로 환경변수를 **고정**한다(이후 폴더 이동으로 상대경로가 어긋나지 않게).
   3. `get_default_workspace()`로 작업 폴더를 정하고 `os.chdir`로 이동한다.
   4. `OpenRouterClient(api_key, model)`을 만들고 `HermesAgent(model=model, llm_client=client)`로 에이전트를 만든다.
   5. 시작 안내에 실제 모드임, 모델, 작업 폴더를 표시한다. **키는 어떤 출력에도 나타나지 않는다.**
3. **`llm_error` 처리**: 대화 중 `result["stopped_reason"] == "llm_error"`이면 `Model call failed (<kind>): <message>`를 출력하고 REPL을 계속한다(프로그램을 끝내지 않음).
4. **기존 `--mock` 동작은 그대로**다(단발 1턴 자동 실행, 안내 문구 포함).
5. **기존 시험 3건의 환경 고정**: [`test_cli.py`](../../../../tests/test_hermes_core/test_cli.py)의 「키 없이 `--mock` 없이 실행」 시나리오 1~3에 `monkeypatch.delenv("OPENROUTER_API_KEY", raising=False)`를 **명시적으로 추가**한다(`conftest.py`가 이미 지우지만 의미를 분명히 하기 위한 것). 시나리오의 기대 결과는 바꾸지 않는다. 이것이 이 로드맵에서 기존 시험을 고치는 유일한 곳이다.
6. **작동원리 갱신** (01편): 영구 사실로 반영한다 — 실제 모드의 작업 폴더 격리와 레포 지시문이 제공자에게 전송되지 않는 이유(Q8·Q9 관련), 모델 호출 기록(`llm_calls`)과 호출 실패 처리(Q3), 가짜/실제 모델 세션 구분(3부 방어선), 「지금은 없는 것」에서 「실제 모델 연결」 문장을 사실에 맞게 수정, 5부 코드 정본 색인에 `llm_client.py` 추가. 테스트 개수는 문서에 적지 않는다([작동원리 README](../../../작동원리/README.md)). 로드맵 서사는 쓰지 않는다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

실제 모드 시험은 `hermes_core.cli.OpenRouterClient`를 가짜 클래스로 교체(`monkeypatch`)해 **네트워크 없이** 돌린다. 현재 폴더는 `monkeypatch.chdir`로 복원 가능하게 한다. 입력은 표준 입력을 가짜로 고정(`exit`).

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `--mock` (기존 시나리오 4·5) | 기존과 같이 정상 종료, `Mock` 안내 포함. 세션 `model == "mock"`, `mode == "mock"` |
| 2 | `--mock` 없이, 키 환경변수 없음 (기존 1~3) | 종료 코드 2, 출력에 `OPENROUTER_API_KEY`와 `--mock` 포함, `state.db`가 만들어지지 않음 |
| 3 | `--mock` 없이, 키 환경변수가 `""`와 `"   "` | 각각 종료 코드 2 (에이전트 미생성) |
| 4 | `--mock` 없이, 키 있음(가짜 값), 가짜 클라이언트, 입력 `exit` | 종료 코드 0. `os.getcwd() == <HERMES_HOME>/workspace`(해당 폴더가 만들어짐) |
| 5 | 4번의 세션 | `model == DEFAULT_REAL_MODEL`, `mode == "real"` |
| 6 | `--model a/b` + 4번 조건 | 세션 `model == "a/b"`, 가짜 클라이언트가 `a/b`로 만들어짐 |
| 7 | 4번의 `capsys` 출력(표준 출력·오류 전체) | 키 값 문자열이 없음. 모델명과 작업 폴더가 표시됨 |
| 8 | 가짜 클라이언트가 `LLMError("rate_limited")`를 내고 입력이 `hi`, `exit` | 종료 코드 0, 출력에 `Model call failed (rate_limited)`, REPL이 끊기지 않고 `exit`까지 처리 |
| 9 | 원래 현재 폴더의 `AGENTS.md`에 고유 표식 문자열 `MARKER`를 두고 4번 실행 | 에이전트의 시스템 지시문에 `MARKER`가 없음 (작업 폴더로 이동했으므로 레포 지시문이 전송되지 않음) |
| 10 | `HERMES_HOME`이 **상대경로**(`rel_home`)일 때 4번 실행 | 실행 후에도 `get_hermes_home()`이 시작 때의 절대경로와 같고, 세션 DB가 그 폴더에 있음 |
| 11 | 기존 코어 테스트 | `test_cli.py` 시나리오 1~3의 환경 고정 외에는 **수정 없이** 통과 |

## 4. 검증 기준 (Done 조건)

1. 시나리오 1~10이 통과하고 기존 테스트(11)가 통과한다.
2. `git diff <단계 시작 커밋>..HEAD -- tests/`에서 삭제된 줄은 `test_cli.py`의 위 5번 범위(환경 고정) 외에 없다.
3. 시험 전체가 실제 네트워크에 접속하지 않는다 (`conftest.py`의 차단이 작동. 위반 시 시험이 실패한다).
4. `grep -rn "os.environ\|getenv" src/hermes_core/cli.py`의 결과가 키 변수 읽기와 `HERMES_HOME` 고정 외에 없다. `.env` 파일을 여는 코드가 없다(`grep -rn "\.env" src/hermes_core`에서 보호 이름 상수 외에 열기 동작이 없음).
5. 작동원리 01편이 사실과 맞고, 기준 커밋이 갱신되어 있다 (테스트 개수는 문서에 없다).
