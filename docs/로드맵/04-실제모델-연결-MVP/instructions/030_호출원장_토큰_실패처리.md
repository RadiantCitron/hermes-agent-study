## 1. 구현 내용 명세

1. **스키마 v3** ([`session_db.py`](../../../../src/hermes_core/session_db.py)):
   - `SCHEMA_VERSION = 3`. `SCHEMA_SQL`에 `CREATE TABLE IF NOT EXISTS llm_calls`를 추가한다: `id INTEGER PRIMARY KEY AUTOINCREMENT`, `session_id TEXT NOT NULL REFERENCES sessions(id)`, `created_at REAL NOT NULL`, `model TEXT`, `request_json TEXT`, `response_json TEXT`, `status_code INTEGER`, `input_tokens INTEGER`, `output_tokens INTEGER`, `latency_ms INTEGER`, `error_kind TEXT`, `error_message TEXT`. 인덱스 `idx_llm_calls_session(session_id)`.
   - `sessions`에 `mode TEXT` 열을 추가한다(새 DB는 `CREATE TABLE`에, 기존 DB는 `ALTER TABLE ... ADD COLUMN`, 이미 있으면 무시). 버전 3 미만이면 마이그레이션 후 `schema_version`을 3으로 올린다. 기존 행은 보존한다.
   - `create_session(..., mode: Optional[str] = None)`: `mode`를 저장한다.
   - `record_llm_call(session_id, model, request, response, status_code, input_tokens, output_tokens, latency_ms, error_kind, error_message)`: 요청·응답은 사전이면 `json.dumps(..., ensure_ascii=False)`로 저장하고 `None`이면 NULL.
   - `get_llm_calls(session_id) -> list[dict]`: `id` 오름차순.
2. **에이전트** ([`agent.py`](../../../../src/hermes_core/agent/agent.py)):
   - `HermesAgent(model: Optional[str] = None, ...)`: 효과 모델명은 `model`이 주어지면 그 값, 없으면 `MockLLMClient`면 `"mock"`, 그 밖은 `getattr(llm_client, "model", "unknown")`. `mode`는 `MockLLMClient`이면 `"mock"`, 그 밖은 `"real"`. 둘 다 `create_session`에 기록한다.
   - 클라이언트가 `set_call_recorder`를 가지고 있으면 호출한다: 기록 함수는 `self.session_db.record_llm_call(session_id=self.session_id, **record)`.
   - 모델 호출을 `try`로 감싼다: `LLMError`(import: `hermes_core.llm_client`)를 잡으면 경고 로그(키 없는 메시지만), `stopped_reason = "llm_error"`, `final_response = ""`로 루프를 끝낸다. 결과 사전에 `"error": {"kind": ..., "message": ...}`를 **추가**한다(실패일 때만. 기존 항목 이름·의미는 그대로).
   - 응답에 `usage`가 있으면(`getattr(resp, "usage", None)`) `update_token_counts`로 누적한다. 없으면(가짜 모델) 아무것도 하지 않는다.
3. **작동원리 갱신**: 없음 (연결은 040에서 완료되므로 그때 영구 사실을 한꺼번에 반영한다).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험용 가짜 클라이언트 `FakeReal`: `model="x/y"`, `chat_completion`이 미리 넣어 둔 `LLMResponse`(또는 `LLMError`)를 순서대로 돌려주고, `set_call_recorder(fn)`을 가지며 호출마다 `fn(record)`를 부른다. DB는 `:memory:`.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `FakeReal`이 `usage` 입력 100·출력 20인 정상 응답 1회 | 세션의 `input_tokens==100`, `output_tokens==20` |
| 2 | 도구 호출 응답(usage 50/5) 후 최종 응답(usage 70/9) | 누적 `120/14` |
| 3 | `MockLLMClient` 응답(usage 없음) | 토큰 0, 오류 없음, `stopped_reason == "completed"`, 결과 사전의 기존 4개 키와 값이 이전과 동일 |
| 4 | `FakeReal`이 첫 호출에서 `LLMError("rate_limited", ...)` | `run_conversation`이 **예외 없이** 반환, `stopped_reason == "llm_error"`, `error["kind"] == "rate_limited"`, `final_response == ""`, `iterations == 1` |
| 5 | 4번의 원장 | `user` 메시지 1건만 있고 assistant 메시지가 없음 |
| 6 | 도구 호출 후 두 번째 호출이 `LLMError("timeout")` | `stopped_reason == "llm_error"`, 원장에 user·assistant(tool_calls)·tool 메시지가 모두 있고 도구 메시지의 `tool_call_id`가 assistant의 호출 id와 같음 |
| 7 | `FakeReal`이 호출 기록을 콜백으로 전달(성공 1·실패 1) | `get_llm_calls(session_id)`가 2행, 오름차순, 성공 행 `error_kind None`·토큰 기록, 실패 행 `error_kind "rate_limited"` |
| 8 | 기록된 `request_json`·`response_json`·`error_message` | JSON으로 파싱되고, `Authorization`이라는 키가 없음 |
| 9 | 다른 세션의 호출 | `get_llm_calls`가 세션별로 분리됨 |
| 10 | `MockLLMClient`로 만든 에이전트 | 세션 `model == "mock"`, `mode == "mock"`, `llm_calls` 0행 |
| 11 | `FakeReal`(model `"x/y"`)로 만든 에이전트 | 세션 `model == "x/y"`, `mode == "real"` |
| 12 | `HermesAgent(model="foo", llm_client=MockLLMClient())` | 세션 `model == "foo"` (명시한 값 우선), `mode == "mock"` |
| 13 | 스키마 v2 DB(파일, `llm_calls` 없음, `sessions`에 `mode` 없음, 세션 1건·메시지 2건)를 `SessionDB(path)`로 열기 | 오류 없이 열림, `schema_version == 3`, `llm_calls` 표가 생김, 기존 세션·메시지 조회 결과가 그대로 |
| 14 | 새 DB | `schema_version == 3`, `sessions.mode`와 `llm_calls`가 모두 있음 |
| 15 | 응답 객체가 `usage`는 있고 `tool_calls`·`content`가 모두 비어 있음(제공자 이상 응답) | 기존 동작과 같이 종료(빈 최종 응답), 예외 없음 |
| 16 | 기존 코어 테스트(020까지 포함) | **수정 없이** 통과 |
