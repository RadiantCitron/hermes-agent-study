## 1. 목표와 결과

### 1-1. 목표 달성 요약
본 로드맵의 목표는 **실제 모델(OpenRouter `deepseek/deepseek-v4-flash-0731`)로 「모델 → 도구 호출 → 결과 → 응답」이 한 번 돌아가는 최소 탈것(MVP)**을 완성하는 것이었다.
연결 전에 환경변수 키 유출 및 깃 설정 손상 구멍을 먼저 닫고, 모든 모델 입출력을 원장에 영구 보존하며, 가짜 통신과 실제 키 스모크를 거쳐 검증을 완료했다.
**목표는 100% 완전히 달성(이뤘다)되었다.**

## 2. 단계별 상세 (Why 중심)

### 010. 작업 폴더 격리와 비밀 파일(`.env*`·`.git`) 보호
- **무엇을**: `.hermes/workspace`를 기본 작업 폴더로 정의하고, 파일 경로 및 터미널 인자에서 `.env*` 접두어와 `.git` 정확 일치 구성요소를 공용 함수 [`is_protected_path`](../../../src/hermes_core/tools/path_guard.py)로 차단했다. 작업 폴더가 상태 폴더 내부(`workspace != home`)일 때의 쓰기 예외를 승인했다.
- **왜**: 연료(실제 모델)를 붙이기 전에 가장 치명적인 구멍(API 키 파일 유출 및 깃 설정 변조)부터 닫아야 했다. 03번에서 쓰기 도구보다 쓰기 금지 정책을 먼저 만든 것과 같은 철학이다.
- **달라진 점**: 이전에는 레포 루트 전체가 작업 폴더였으나, 이제는 `.hermes/workspace` 안으로 격리되었으며, 실수로든 모델의 악의로든 비밀 파일에 절대 접근할 수 없다.

### 020. OpenRouter 클라이언트
- **무엇을**: `httpx` 기반의 [`OpenRouterClient`](../../../src/hermes_core/llm_client.py)를 구현했다. 단일 POST 요청, 타임아웃 60초, 출력 토큰 상한 4,096자, 오류 본문 500자 상한, 키 마스킹(`***`), 호출 기록 콜백(`on_call`)을 갖추었다. 테스트 환경 격리를 위해 [`tests/test_hermes_core/conftest.py`](../../../tests/test_hermes_core/conftest.py)에서 실제 네트워크 통신을 원천 차단했다.
- **왜**: 외부 라이브러리(LangChain 등)에 의존하지 않고 순수 HTTP 통신 계층을 직접 통제하여 통신 실패를 투명하게 관찰하고, 키가 예외 메시지나 로그에 찍히는 것을 원천 차단하기 위함이다.
- **달라진 점**: 정해진 대본만 읽던 가짜 에이전트에서 실제 OpenRouter 엔드포인트와 통신할 수 있는 실체 통신 계층이 생겼다.

### 030. 호출 원장·토큰 집계·모델/모드 기록·호출 실패 처리
- **무엇을**: SQLite 데이터베이스 스키마를 `v3`로 마이그레이션하여 [`llm_calls`](../../../src/hermes_core/session_db.py) 원장 테이블을 신설하고 `sessions.mode` 열을 추가했다. `HermesAgent` 루프에서 매 모델 호출 직전 `record_llm_call`을 수행하고, `LLMError` 발생 시 `stopped_reason = "llm_error"`로 안전 종료되게 했다.
- **왜**: 모델이 무슨 요청을 받고 무엇을 답했는지 모르는 시스템은 디버깅이 불가능한 블랙박스다. 또한 네트워크 실패나 토큰 한도 초과 시 에이전트가 예외로 튕겨나가지 않고 정직하게 실패를 기록해야 안전하다.
- **달라진 점**: 모든 입출력, 상태 코드, 레이턴시, 토큰이 SQLite 원장에 비행기록장치(블랙박스)처럼 선기록된다.

### 040. CLI 실제 모드 연동 및 작동원리 동기화
- **무엇을**: [`cli.py`](../../../src/hermes_core/cli.py)에 `--model` 옵션을 연동하고, `--mock`이 없을 때 환경변수 `OPENROUTER_API_KEY`를 사전 검사하여 부재 시 종료 코드 2로 안전 종료하게 했다. 실행 시 자동으로 작업 폴더(`.hermes/workspace`)로 이동하고, REPL에서 `LLMError`를 잡아 대화 루프를 복구하도록 했다. [작동원리 01편](../../작동원리/01-헤르메스코어-작동원리.md)에 실제 모드 안전 사실을 반영했다.
- **왜**: 사용자가 실제 모드를 켤 때 키가 없으면 에이전트를 아예 띄우지 않는 것이 fail-closed 원칙에 맞고, 대화 도중 한 번 통신이 실패해도 전체 CLI 프로세스가 꺼지지 않고 대화를 이어갈 수 있어야 한다.
- **달라진 점**: 사용자가 터미널에서 `python -m hermes_core.cli`를 실행하여 실제 모델과 자연스럽게 대화할 수 있는 완결된 CLI가 완성되었다.

### 050. 통합 E2E 검증
- **무엇을**: 모의 HTTP 전송 계층(`SequentialMockTransport`)을 만들어 실제 클라이언트(`OpenRouterClient`)와 코어 루프 전체가 연결된 상태에서 도구 순환, `tool_call_id` 정합성, 키 미저장, 비밀 보호 거부, 토큰 집계 일치를 검증하는 13개 통합 시나리오를 작성했다.
- **왜**: 실제 키를 써서 돈을 쓰기 전에, 가짜 통신으로 시스템 전체 부품이 하나로 맞물려 돌아가는지 100% 증명해야 했다.
- **달라진 점**: 단일 유닛 단위 검증을 넘어, 실제 네트워크 전송 직전까지의 전체 파이프라인 무결성이 증명되었다.

### 060. 실제 키 스모크 1회 (마지막 관문)
- **무엇을**: 사용자가 별도 터미널에서 실제 `OPENROUTER_API_KEY`를 주입하고, `workspace에 hello.txt를 만들고 내용에 hi라고 써줘. 그다음 그 파일을 읽어서 내용을 알려줘.`라는 복합 지시를 1회 실행했다.
- **왜**: 실제 모델의 JSON 출력 형태(가정 C)와 실제 API 키 유출 방지는 오직 단 한 번의 실제 실행으로만 증명할 수 있었다.
- **달라진 점**: `.hermes/workspace/hello.txt`(`hi`)가 정상 생성 및 판독되었고, 6회 호출 200 OK 완료, DB 덤프에서 키 미저장(`False`)이 확인되어 실전 운용 가능함이 최종 증명되었다.

## 4. 아키텍처 성과와 작동원리 반영 목록

### 4-1. 시스템의 영구 사실이 된 것
1. **작업 폴더 격리와 상태 폴더 쓰기 예외 규칙**: 작업 폴더(`.hermes/workspace`) 안에서는 파일 쓰기/패치가 자유로우나, 작업 폴더 바깥의 상태 폴더(`.hermes/state.db` 등) 및 레포 파일은 절대 건드릴 수 없다 ([ADR-0004](../../adr/0004-실제_모델_연결_MVP_범위와_안전_정책.md)).
2. **보호 파일 공용 차단 (`is_protected_path`)**: `.env*` 접두어와 `.git` 구성요소는 파일 도구(`read_file`, `write_file`, `patch`)와 터미널 도구(`terminal`) 양쪽에서 공용 함수를 통해 똑같이 거부된다.
3. **호출 원장 선기록 (`llm_calls`)**: 모든 LLM 호출은 도구 실행 전에 요청 및 응답 본문, 토큰, 레이턴시, 오류 여부가 SQLite 원장에 먼저 기록된다.
4. **통신 실패 단일 변환 (`LLMError`)**: 타임아웃, 네트워크 단절, HTTP 오류, 응답 본문 초과 등 외부 통신의 불안전성은 내부 표준 예외 `LLMError`로 정규화되어 루프의 `stopped_reason = "llm_error"`로 격리된다.
5. **Zero Leakage 원칙**: 키는 파일로 저장되지 않고 오직 메모리 상의 환경변수로만 전달되며, DB 저장 및 에러 메시지 출력 시 `***`로 안전하게 마스킹된다.

### 4-2. 작동원리 문서 ([docs/작동원리/01-헤르메스코어-작동원리.md](../../작동원리/01-헤르메스코어-작동원리.md)) 반영 내역
- **Q3 (도구 단일 통로와 에러 방어)**: 모델 호출 실패 시의 `LLMError` 처리 및 REPL 대화 지속 흐름 명시.
- **Q8 (작업 폴더 격리와 레포 지시문 비전송)**: 실제 모드 실행 시 `.hermes/workspace` 자동 격리 및 레포 루트 파일 접근 차단 원리 반영.
- **Q9 (보호 이름 공용 판정)**: `.env*` 및 `.git`의 파일/터미널 공용 차단 사실 반영.
- **3부 대화 원장 다이어그램**: `llm_calls` 테이블과 `on_call` 선기록 흐름 추가.

## 5. 미흡한 부분 (한계와 알려진 구멍)

1. **레포 코드 직접 수정 불가 (의도된 제약)**:
   - 현재 작업 폴더가 `.hermes/workspace`로 엄격히 한정되어 있어, 에이전트가 `hermes-agent-study` 본 레포의 코드를 직접 수정하거나 읽지 못한다. MVP 안전을 위한 의도된 선택이었으나, 향후 작업 폴더를 유연하게 지정하는 기능이 필요하다.
2. **작업 폴더 내 파일 개수/디스크 용량 상한 부재**:
   - 단일 파일 쓰기 10만 자 상한은 있으나, 반복 루프를 통해 수천 개의 파일을 생성하여 디스크를 채우는 행위는 방어하지 못한다 (03번 로드맵부터 이어진 한계).
3. **단일 모델 및 단일 제공자 한정**:
   - 현재는 OpenRouter API 및 `deepseek/deepseek-v4-flash-0731` 모델만 기본 지원하며, 다른 제공자(Anthropic, OpenAI 직접 연결, Ollama 등)를 위한 어댑터 계층은 마련되지 않았다.
4. **스트리밍 미지원**:
   - 응답을 한 번에 통째로 수신하므로, 모델이 긴 답변을 생성할 때 사용자가 터미널에서 실시간 출력을 보지 못하고 수 초간 대기해야 한다.
5. **자동 재시도 부재**:
   - 네트워크 일시 순단이나 일시적 503 에러 발생 시 즉시 `llm_error`로 루프가 멈춘다. 프로덕션 수준의 지수 백오프 재시도는 아직 없다.

## 6. 새로 발견한 부분

1. **DeepSeek V4 Flash 모델의 높은 도구 호출 정확도**:
   - `deepseek/deepseek-v4-flash-0731` 모델이 복합 프롬프트(`파일 만들고 hi 쓰고 -> 읽어서 알려줘`)를 받았을 때, 임의의 텍스트를 지어내지 않고 정확히 `write_file` 도구 호출 -> 결과 확인 -> `read_file` 도구 호출 -> 최종 자연어 응답의 순서를 완벽히 지켰다.
2. **도구 인자 직렬화 형태의 호환성 확인 (가정 C)**:
   - 오픈소스 모델 중 일부는 `tool_calls.function.arguments`를 JSON 객체로 직접 보내거나 이스케이프가 깨지는 경우가 있으나, 본 모델은 OpenAI 호환 표준 JSON 문자열을 정확히 전송했다.
3. **토큰 소모량의 체감**:
   - 도구 1사이클(2회 실행)을 도는 동안 시스템 프롬프트 및 이전 턴 대화가 누적되면서 매 호출마다 약 1,300~1,600개의 입력 토큰이 전송되어 6회 호출 총합 9,150 토큰이 소비되었다. 대화가 길어질 경우 문맥 압축이나 가지치기(트렁케이션)가 필수적임을 체감했다.

## 7. 트러블슈팅과 교훈

1. **테스트 환경의 오염 차단 (`conftest.py`)**:
   - 개발자 머신의 환경변수에 실제 `OPENROUTER_API_KEY`가 들어있을 때, 단위 테스트가 실수로 실제 API를 찌르고 비용이 발생할 위험이 있었다. `conftest.py` 세션 픽스처에서 환경변수를 무조건 지우고, `httpx.HTTPTransport` 호출 시 즉시 실패하도록 모킹 장치를 걸어 시험의 결정론적 안전성을 확보했다.
2. **CLI 환경변수 검사 순서**:
   - `--mock` 플래그가 지정된 경우에는 키 검사를 건너뛰어야 하고, 실제 모드일 때만 키 검사를 해야 한다. `cli.py`에서 에이전트 생성 전에 인자를 먼저 파싱하고 키 유무를 검사한 뒤 에이전트를 초기화하는 fail-closed 구조를 확립했다.
3. **SQLite 덤프를 통한 완벽한 Zero Leakage 검증**:
   - 코드로만 "키를 저장하지 않는다"고 믿는 대신, 사용자가 별도 터미널에서 `sqlite3 .dump`와 파이썬 스크립트로 실제 키 포함 여부를 검사(`False`)하는 독립 검증 절차를 도입하여 무결성을 확실히 증명했다.

## 9. 사실 검증 4축 결과와 「미확인」

| 축 (Dimension) | 확인 내용 | 검증 결과 |
|---|---|:---:|
| **동작 (Action)** | 파일 쓰기/읽기 도구 호출, OpenRouter HTTP 통신, SQLite 선기록, 키 마스킹, 실패 격리 | **검증 완료** (테스트 279건 및 실제 스모크) |
| **순서 (Order)** | 작업 폴더 이동 → 키 검사 → 모델 요청 전 `llm_calls` 선기록 → 도구 디스패치 → 결과 메시지 추가 → 후속 호출 | **검증 완료** (E2E 테스트 및 원장 로그 대조) |
| **소유자 (Owner)** | `OpenRouterClient`(통신/오류), `HermesAgent`(루프 제어), `SessionDB`(원장), `PathGuard`(경로/보호 판정) | **검증 완료** (모듈별 책임 격리) |
| **시점 (Timing)** | 키 검사는 프로세스 시작 시점, 원장 기록은 모델 요청 직전/직후, 세션 갱신은 루프 종료 시점 | **검증 완료** |

### 「미확인」 사항
- **OpenRouter 실제 결제 금액**: 단가 기반 계산으로 1센트 미만임을 확인했으나, 사용자의 OpenRouter 대시보드 실 청구액 숫자는 에이전트가 직접 보지 못했다.
- **장시간 네트워크 단절 시 OS별 소켓 동작**: 60초 타임아웃은 테스트했으나 운영체제 수준의 하위 TCP 소켓 끊김 예외의 다양성은 전부 확인하지 못했다.
