## 1. 목표와 결과

### 1-1. 목표 달성 요약
본 로드맵의 목표는 에이전트의 실제 코딩 워크플로에서 가장 시급했던 두 가지 결핍을 해소하는 것이었다:
1. **[축 1 — 가장 급선무] 안전한 코드 탐색 도구 (`search_files`)**:
   - `read_file`, `write_file`, `patch`에 이어 **`search_files`** 전용 도구를 신설하여 터미널 `find`/`grep` 승인 요청 없이 **`Search(찾기) → Read(읽기) → Edit(고치기)` 3박자 자율 완주**를 확립.
   - `.env*`, `.git`, `.hermes`, 심볼릭 링크, 바이너리 원천 제외 및 3중 상한선(최대 50건 검색 결과, 일치 줄당 최대 200자, 최대 5,000개 파일 순회 스캔)을 통해 Zero Leakage 및 컨텍스트 무결성을 보장.
2. **[축 2 — 루프 제어] 루프 정체 감지·자가 교정 (`LoopGuard`)**:
   - 16번 로드맵의 `Extension` 및 `GUARD` 단계 미들웨어를 활용하여, 동일 도구 및 정규화 인자의 연속 반복 호출을 감지하는 내장 확장 `LoopGuardExtension` 신설.
   - **1차 개입 ($K=3$)**: 도구 실행 결과에 자가 교정 경고(`_loop_warning`, `attach_loop_warning`)를 주입하여 모델 스스로 파라미터 수정이나 `search_files` 등으로 우회하도록 유도(Nudge).
   - **2차 개입 ($M=5$)**: 실제 도구 실행을 생략(우회)하되 장부에는 차단 에러 `role="tool"` 메시지를 빠짐없이 기록하여 1:1 도구 쌍 불변식을 맞추고 `stopped_reason = "stuck_loop"`로 루프 즉시 종료.
   - CLI가 빈 응답 대신 친절한 정체 안내(`CLI_STUCK_LOOP_NOTICE`)를 출력하고, `--resume` 세션 재개 시에도 장부 무결성을 유지.

010단계(탐색 도구), 020단계(루프 정체 감지기), 030단계(E2E 통합 검증 및 작동원리 01·02·03편 동기화), 040단계(마감) 전 과정을 성공적으로 완수하였다.

**목표는 100% 완전히 달성되었다.**

## 4. 아키텍처 성과와 작동원리 반영 목록

1. **`Search → Read → Edit` 자율 3박자의 완성**:
   - `search_files`가 추가됨으로써 에이전트는 코드베이스 내 키워드 탐색부터 파일 읽기, 정밀 수정까지 사람의 개입 없이 완전히 닫힌 루프(Closed-loop)로 작업할 수 있게 되었다.
2. **비밀값 및 상태 격리 경계의 공용화 (`path_guard.py`)**:
   - 기존 파일 도구들과 검색 도구가 제각기 경로 검사를 수행하지 않고, `is_hermes_home_path`를 통해 `.hermes` 상태 저장소를 단일 진입로에서 공통 격리하도록 정비하였다.
3. **16번 확장 계약의 완벽한 실증 (`LoopGuardExtension`)**:
   - 에이전트 루프 메인 본문(`agent.py`)을 단 1줄(`install_extension`)만 수정하고도, GUARD 단계 미들웨어와 `TurnScope` 턴 칸을 활용하여 정교한 루프 정체 감지 및 조기 차단을 완벽히 구현하였다.
4. **작동원리 문서 반영**:
   - [`01-헤르메스코어-작동원리.md`](../../작동원리/01-헤르메스코어-작동원리.md): 루프 종료 4대 사유(`stuck_loop` 포함), `LoopGuardExtension` 짝 맞춤 원리, `search_files` 안내서 반영.
   - [`02-지침주입-도구호출-작동원리.md`](../../작동원리/02-지침주입-도구호출-작동원리.md): `LoopGuard` 루프 정체 조기 차단 원리, `is_hermes_home_path` 공용 판정 설명, 기본 도구 9종 반영.
   - [`03-코어구조-메인루프-확장방식.md`](../../작동원리/03-코어구조-메인루프-확장방식.md): `Search → Read → Edit` 3박자 완성, 3중 과부하 상한선 및 안전 제외 정책, 확장 설치 목록 갱신.

## 5. 미흡한 부분 및 알려진 한계

1. **교차 도구 왕복 루프 미감지**:
   - 현재 `LoopGuard`는 단일 도구의 연속 동일 호출(A → A → A)만 감지한다. 도구 A와 도구 B를 번갈아 호출하는 핑퐁 루프(A → B → A → B)는 감지하지 않으며, 기존의 `max_iterations=50` 상한에 의해 차단된다.
2. **에이전트 간 디스패처 공유 시 이벤트 싱크 단일성**:
   - 확장은 에이전트에 설치되지만 미들웨어는 디스패처에 등록된다. 하나의 디스패처를 복수의 에이전트가 공유할 경우, 감지 이벤트가 먼저 생성된 에이전트의 이벤트 싱크로만 방출되는 한계가 존재한다(18번 단일 제어판에서 다룰 예정).
3. **임계값 동적 변경 인터페이스 미제공**:
   - 경고(3회) 및 차단(5회) 임계값이 `constants.py` 상수로 고정되어 있으며, 실행 중 동적으로 조정할 수 있는 설정 API나 CLI 플래그가 아직 제공되지 않는다(18번 제어판 후보).

## 6. 새로 발견한 부분 (인사이트)

1. **도구 쌍(Tool Pair) 불변식이 에이전트 생명선이다**:
   - 5회 정체 차단 시 도구 실행을 건너뛰더라도, 장부에 `role="tool"` 에러 메시지를 남기지 않고 즉시 반환하면 LLM API 제공자(Anthropic, OpenAI 등)는 직전 어시스턴트의 `tool_calls`와 짝이 맞지 않는 요청을 받아 다음 턴이나 세션 재개(`--resume`)에서 HTTP 400 에러를 뿜는다. 차단 시에도 반드시 더미/에러 도구 응답을 장부에 선기록해야 함을 확인했다.
2. **미들웨어 예외 전파 시 안쪽 예외의 격리 필요성**:
   - `dispatcher.py`의 미들웨어 래퍼에서 안쪽(POLICY 등)이 던진 예외를 바깥쪽(GUARD) 래퍼가 다시 잡아서 GUARD 실패로 중복 리포트하는 현상이 있었다. `if inner_exc is not None and mw_exc is inner_exc: raise` 처리를 통해 미들웨어 계층 간 단순 전파 예외와 자체 발생 에러를 엄격히 분리해야 함을 배웠다.

## 7. 트러블슈팅과 교훈

1. **기존 도구 수 단정 테스트들의 연쇄 실패**:
   - `search_files`가 추가되면서 기본 도구 수가 8종에서 9종(자식은 6종에서 7종)으로 증가하여, 기존 7개 시험 파일의 `len(tools) == 8` 단정이 실패했다. 새 도구 추가 시 기존 시험들이 '고정된 숫자'를 단정하고 있는지 사전 점검해야 함을 재확인했다.
2. **JSON 인자 직렬화 지문 정규화의 중요성**:
   - 모델은 `{"path": "a", "old": "b"}`와 `{"old": "b", "path": "a"}`처럼 키 순서를 바꾸거나 공백을 임의로 넣어 호출하는 경우가 흔하다. `json.dumps(args, sort_keys=True)`를 통한 표준 정규화 지문 생성이 루프 감지의 핵심 성공 요인이었다.

1. **18번 로드맵 (단일 제어판 및 통합 환경 설정 MVP)**:
