# [WHY] 14-세션-재개-원장-정합-MVP — 왜 이 로드맵을, 왜 이 정도로만 하는가

## 1. 왜 지금 이 로드맵인가

13번까지로 한 번 켠 세션 안에서는 대화가 길어져도 요약되고, 파일을 고쳐도 되돌릴 수 있고, 도중에 `Ctrl+C`로 멈춰도 세션이 살아남는다. 그런데 **프로그램을 껐다가 다시 켜는 순간** 지금까지의 모든 기록은 죽은 글자가 된다.

> 에이전트와 한참 동안 파일을 고치며 이야기하다가 실수로 터미널 창을 닫았거나 잠깐 나갔다 왔다. 다시 켜면 에이전트는 방금까지 무슨 이야기를 했는지 전혀 모르고, 직전에 에이전트가 잘못 고친 파일도 되돌릴(`/rollback`) 수 없다. 장부에는 모든 대화와 파일 변경 전 모습이 고스란히 적혀 있는데도, 에이전트는 장부를 한 번도 다시 읽지 않고 매번 백지에서 시작한다.

더 큰 문제는 **장부를 다시 읽으려고 할 때 드러나는 어긋남**이다.

- **취소된 요청이 장부에서는 살아 있다.** 13번에서 처리 도중 `Ctrl+C`를 누르면 에이전트가 기억하는 대화에서는 그 요청이 빠지지만, 장부에는 그 요청과 도중에 끊긴 도구 호출이 「현재 대화」라는 표시를 단 채 그대로 남아 있다. 장부를 그대로 읽어 대화를 이어가면, 대답이 없는 도구 호출 때문에 다음 모델 호출이 깨지거나 취소했던 일을 에이전트가 다시 보게 된다.
- **되돌리기가 세션 경계를 넘지 못한다.** 12번에서 남긴 첫 번째 한계다. 세션을 다시 열어도 몇 번째 요청까지 갔었는지 이어받지 못해서, 지난번에 고친 파일을 되돌릴 수 없다.

이 로드맵은 새로운 도구를 더하는 것이 아니라, **「장부에 적힌 현재 대화와 에이전트가 기억하는 대화를 언제나 똑같이 맞추고, 껐다 켜도 지난 세션을 그대로 이어받아 대화와 되돌리기를 계속할 수 있게 한다」**는 에이전트의 가장 기본적인 뼈대를 완성한다.

## 2. 왜 이 정도로만 하는가

이 로드맵이 **일부러 하지 않는 것**과 그 이유다.

| 하지 않는 것 | 이유 | 언제 하는가 |
|---|---|---|
| 대화의 중간 지점으로 돌아가 새 줄기로 갈라지기 (분기) | 마지막 상태부터 이어 달리는 것과 과거의 한 지점에서 새 가지를 치는 것은 복잡도가 완전히 다르다. 가지를 치면 그 뒤의 파일 변경 기록도 어디까지 유효한지 따로 따져야 한다 | 분기 기능이 꼭 필요해질 때 |
| 화면에 세션 목록을 띄우고 화살표로 고르는 창 | 가장 최근 세션을 바로 잇거나 세션 번호 앞자리만 적어 잇는 것으로도 충분하다. 선택 창을 만들려면 화면 그리기 코드가 커진다 | 세션이 많아져 고르기 불편해질 때 |
| 위임받은 하위 에이전트의 세션을 따로 이어받기 | 하위 에이전트는 본래 에이전트가 시킨 한 가지 일만 끝내고 요약을 돌려주는 일회용 일꾼이다. 사람이 직접 대화를 이어갈 대상이 아니다 | 해당 없음 |
| 끝나기 직전 미처 전하지 못한 알림까지 다음 세션으로 넘기기 | 되돌리기나 취소를 한 뒤 아무 말도 안 하고 끈 경우에는 이미 끌 때 화면에 안내가 나간다. 이를 다음 실행까지 넘기려면 장부에 새 칸을 만들어야 하는데, 얻는 이득에 비해 장부가 복잡해진다 | 실제로 문제가 될 때 |
| 장부의 표 구조 바꾸기 | 지금 있는 칸(현재 대화 표시, 끝난 이유, 파일 변경 기록)만으로도 필요한 모든 것을 표현할 수 있다 | 해당 없음 |
| 실제 터미널 창을 띄우는 새 시험 | 세션 이어받기와 장부 대조는 프로그램 안의 동작이라 가짜 입력과 가짜 통신으로 정확히 검증할 수 있다(계획 015 기준) | 해당 없음 |

**한마디로**: 장부의 현재 대화와 에이전트의 기억을 일치시키고, 가장 최근(또는 지정한) 세션을 다시 열어 대화와 되돌리기를 그대로 이어간다. 가지를 치거나 화려한 선택 창을 만들지는 않는다.

## 3. 왜 이 순서, 왜 이 단계 수인가

| 순서 | 하는 일 | 왜 이 자리인가 |
|---|---|---|
| 010 | 장부에서 취소된 요청을 내리고 이어받을 세션을 찾는 기능 만들기 | 장부가 깨끗해야 읽어들일 수 있다. 다른 부품을 건드리지 않고 장부 자체의 규칙부터 단단히 세운다 |
| 020 | 에이전트와 되돌리기 장치가 장부를 읽어 예전 상태를 복원하게 만들기 | 010이 만든 장부 기능을 써서 에이전트(처음 지시문과 대화 목록)와 되돌리기 장치(요청 번호와 사용량)가 예전 상태로 돌아오는 부품을 만든다 |
| 030 | 명령줄(`--resume`)과 취소 시점 연결하기 | 010·020의 부품을 실제 프로그램의 시작(`--resume`)과 취소(`Ctrl+C`) 자리에 연결한다 |
| 040 | 통합 확인과 작동원리 문서 갱신 | 첫 세션에서 파일을 고치고 취소하고 끝낸 뒤, 두 번째 세션으로 이어받아 되돌리고 대화하는 전 과정을 한 번에 시험하고 작동원리 문서를 고친다 |
| 050 | 실제 모델로 돌려 보기와 마감 | 실제로 터미널에서 껐다 켜도 에이전트가 이전 대화를 기억하고 되돌리기 알림을 잘 따르는지 눈으로 확인하고 마감한다 |

## 4. 왜 이 방식을 택하고 무엇을 배척했나

| 선택 | 배척한 대안 | 이유 |
|---|---|---|
| 취소된 요청의 기록은 지우지 않고 「현재 대화 아님」으로만 표시한다 | 장부에서 아예 지운다 | 장부는 일어난 모든 일의 증거다. 지우지 않고 표시만 내리면 증거도 남고 이어받을 때 섞이지도 않는다 |
| 같은 세션 번호를 다시 열어 이어 쓴다 | 새 세션 번호를 만들고 예전 기록을 복사한다 | 번호가 바뀌면 예전 세션에 묶여 있던 파일 변경 기록과 끊어져서 지난번 변경을 되돌릴 수 없다 |
| 처음 세션을 켰을 때 만든 기본 지시문을 그대로 다시 쓴다 | 이어받을 때마다 기본 지시문을 새로 조립한다 | 그사이 메모장이나 설정이 바뀌어 지시문 앞부분이 달라지면 모델의 기억 캐시가 깨진다 |
| `--resume` 한 단어로 가장 최근 세션을 바로 잇는다 | 매번 긴 세션 번호를 다 치게 한다 | 사람이 가장 자주 하는 일은 「방금 닫은 세션 다시 열기」다. 번호를 몰라도 바로 열려야 편하다 |

## 5. 성공 판단 기준과 검증할 가정

**성공 기준**: (1) 처리 중 `Ctrl+C`로 요청을 취소하면 장부에서도 그 요청의 메시지들이 현재 대화에서 빠져 에이전트가 기억하는 대화와 장부의 현재 대화가 일치하고, (2) 세션을 끝낸 뒤 `--resume`으로 다시 켜면 이전 대화 맥락을 그대로 기억해 대화가 이어지며, (3) 다시 켠 세션에서 `/rollback`을 치면 지난 실행에서 고쳤던 파일이 되돌려지고 에이전트에게 알림이 전달된다.

| 번호 | 가정 | 틀렸다면 |
|---|---|---|
| **A** | 처리 중 `Ctrl+C`로 취소했을 때 장부의 현재 대화(`active=1`) 목록이 에이전트 메모리의 대화(`history`)와 글자 그대로 일치한다 | 취소 시 장부를 내리는 기준점을 고친다 |
| **B** | 취소된 요청 도중에 대화 요약(압축)이 이미 일어났더라도, 취소 후 장부에 요약본은 남고 그 뒤의 미완성 메시지만 빠진다 | 요약이 일어난 뒤의 취소 기준점을 따로 잡는다 |
| **C** | `--resume`으로 다시 켠 세션에서 에이전트가 처음 세션의 기본 지시문과 대화 내용을 그대로 이어받아 앞선 대화를 기억한다 | 대화 복원이나 지시문 캐시 복원 경로를 점검한다 |
| **D** | 다시 켠 세션에서 `/rollback`을 실행하면 지난번 실행에서 바꾼 파일이 바이트 단위로 복원되고, 다음 말에서 에이전트가 되돌림 알림을 받아 다시 고치지 않는다 | 체크포인터 복원 규칙을 점검한다 |
| **E** | 다시 켠 세션에서 새 요청으로 파일을 고치면 요청 번호(`turn_index`)가 지난번 번호 뒤로 이어져 옛 기록을 덮어쓰지 않는다 | 번호 복원 계산을 고친다 |
| **F** | 다시 켠 세션이 끝날 때(`exit`·`Ctrl+C`·`Ctrl+D`·오류) 이번 실행의 끝난 이유가 장부에 새로 기록된다 | 세션을 다시 열 때 이전 종료 표시를 비우는 부분을 점검한다 |

## 6. 알려진 위험과 아직 확인하지 못한 것

- **취소된 요청 도중 요약이 일어난 경우의 메모리·장부 미세 차이**: 한 세션 안에서 요약 직후 취소하면 에이전트 메모리는 요약 전이고 장부는 요약 후(취소분 제외)가 된다. 그 세션을 끄지 않고 계속 쓰면 다음 요청에서 한 번 더 요약될 수 있고, 껐다 다시 켜면 장부의 요약본으로 깔끔하게 이어진다.
- **끝나기 직전 전하지 못한 알림**: 되돌리기나 취소를 한 뒤 아무 말도 하지 않고 끄면 화면에 안내가 나가며, 다시 켰을 때 그 알림이 자동으로 붙지는 않는다.
- 실제 모델이 다시 켠 세션에서도 지난번 실행의 되돌리기 알림을 똑같이 잘 따르는지는 **미확인**이다(050에서 확인).
