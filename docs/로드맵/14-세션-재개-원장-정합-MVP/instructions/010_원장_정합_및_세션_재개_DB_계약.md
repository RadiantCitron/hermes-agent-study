## 1. 구현 내용 명세

이 단계는 [`session_db.py`](../../../../src/hermes_core/session_db.py)에 취소된 턴의 원장 활성 메시지 비활성화 및 세션 재개에 필요한 4개의 DB 계약 메서드를 추가한다. 스키마(v6)와 기존 메서드는 한 줄도 바꾸지 않는다.

### 1-1. 마지막 활성 메시지 ID 조회 (`get_last_active_message_id`)

`SessionDB`의 메시지 원장 구역(`get_messages_as_conversation` 바로 아래)에 추가한다.

```python
def get_last_active_message_id(self, session_id: str) -> int:
    """해당 세션에서 현재 active=1인 메시지의 최대 id를 반환한다. 활성 행이 없으면 0."""
```

- SQL: `SELECT COALESCE(MAX(id), 0) FROM messages WHERE session_id = ? AND active = 1`
- 반환값은 항상 `int` (`>= 0`).

### 1-2. 기준 ID 이후 활성 메시지 비활성화 (`deactivate_messages_after`)

취소된 턴에서 기록된 미완성 메시지들을 원장에서 삭제하지 않고 `active = 0`으로 내린다. 단, 취소된 턴 도중에 컨텍스트 압축(`archive_and_compact`)이 이미 일어났다면 압축본(요약 행 + 복사본 `is_copy = 1` 행)은 지워지지 않도록 보호한다(위험 1, 가정 B).

`constants.py`에서 `SUMMARY_PREFIX`, `SUMMARY_END_MARKER`를 추가로 import하여 사용한다.

```python
def deactivate_messages_after(self, session_id: str, after_id: int) -> int:
    """after_id(단, 해당 턴 도중 압축이 일어났다면 압축본 마지막 행 id) 이후의 active=1 메시지를 active=0으로 내리고 변경된 행 수를 반환한다."""
```

- `after_id`가 `int`가 아니거나(또는 `bool`이거나) `0`보다 작으면 `ValueError("after_id must be a non-negative integer")`를 발생시킨다.
- **압축 보호 기준점 계산 (`effective_after_id`)**:
  - 해당 세션에서 현재 `active = 1`이면서 압축(`archive_and_compact`)이 삽입한 행, 즉 `is_copy = 1`이거나 독립 요약 행(`role IN ('user', 'assistant') AND content LIKE ? AND content LIKE ?`, `f"{SUMMARY_PREFIX}%"`, `f"%{SUMMARY_END_MARKER}"`)인 행들의 `COALESCE(MAX(id), 0)`을 조회해 `compaction_max_id`로 둔다.
  - `effective_after_id = max(after_id, compaction_max_id)`
- **비활성화 갱신**:
  - `UPDATE messages SET active = 0 WHERE session_id = ? AND active = 1 AND id > ?` (`(session_id, effective_after_id)`)
  - `self._conn.commit()`
  - `cursor.rowcount` 반환 (`int`).
- `sessions.message_count`·`tool_call_count`는 원장 누적 통계이므로 감산하지 않는다. `compacted` 컬럼은 건드리지 않는다(`0` 유지).

### 1-3. 세션 재개방 (`reopen_session`)

`SessionDB`의 세션 수명주기 구역(`end_session` 바로 아래)에 추가한다.

```python
def reopen_session(self, session_id: str) -> bool:
    """세션을 재개할 수 있도록 ended_at과 end_reason을 NULL로 비운다. 존재하는 세션이면 True, 없으면 False."""
```

- SQL: `UPDATE sessions SET ended_at = NULL, end_reason = NULL WHERE id = ?`
- `self._conn.commit()`
- 이미 `ended_at`·`end_reason`이 `NULL`인 열린 세션에 대해서도 해당 `id`의 세션 행이 존재하면 SQLite `UPDATE`의 `rowcount`가 `1`이므로 `True`를 반환하고, 존재하지 않는 `session_id`면 `0`이므로 `False`를 반환한다.

### 1-4. 재개 가능 세션 탐색 (`find_resumable_session`)

`get_session` 바로 아래에 추가한다.

```python
def find_resumable_session(self, target: Optional[str] = None) -> list[dict[str, Any]]:
    """재개 가능한 최상위 CLI 세션(source='cli' AND parent_session_id IS NULL)을 최신순으로 조회한다.

    - target이 None이거나 공백 제거 후 소문자가 'latest'이면 가장 최근 세션 최대 1건을 리스트로 반환.
    - 그 외 문자열이면 공백 제거 후 id 접두사(prefix)로 매칭되는 모든 세션을 최신순(started_at DESC, rowid DESC) 리스트로 반환.
    - 공백만 있는 문자열이면 빈 리스트([]) 반환.
    """
```

- 대상 필터는 항상 `source = 'cli' AND parent_session_id IS NULL`이다(위임 자식 `source='subagent'`나 부모가 있는 세션은 제외, 위험 3).
- `target is None` 또는 `(isinstance(target, str) and target.strip().lower() == "latest")`:
  - `SELECT * FROM sessions WHERE source = 'cli' AND parent_session_id IS NULL ORDER BY started_at DESC, rowid DESC LIMIT 1`
  - 결과를 `[dict(row) for row in cursor.fetchall()]`로 반환.
- 그 외 `isinstance(target, str)`:
  - `prefix = target.strip()`
  - `if not prefix: return []`
  - SQL `LIKE` 와일드카드 이스케이프(위험 2):
    ```python
    escaped = prefix.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_")
    ```
  - `SELECT * FROM sessions WHERE source = 'cli' AND parent_session_id IS NULL AND id LIKE ? ESCAPE '\\' ORDER BY started_at DESC, rowid DESC` (`(f"{escaped}%",)`).
  - 결과를 `[dict(row) for row in cursor.fetchall()]`로 반환.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 새 세션 생성 직후(메시지 0건) `get_last_active_message_id(sid)` | `0`을 반환한다 |
| 2 | 메시지 3건(`m1`, `m2`, `m3`) 추가 후 `get_last_active_message_id(sid)` | `m3`의 `id`를 반환한다. 다른 세션에 메시지를 추가해도 `sid`의 반환값은 바뀌지 않는다 |
| 3 | 턴 1(`user`·`assistant`, 마지막 `id = m2`) 완료 후, 턴 2에서 `user`(`m3`)·`assistant(tool_calls)`(`m4`)·`tool`(`m5`)이 기록된 상태에서 `deactivate_messages_after(sid, m2)` 호출 | 반환값은 `3`이다. `get_messages_as_conversation(sid)`는 턴 1의 2건만 반환하고, `get_messages(sid)`는 5건 모두를 반환하되 `m3`·`m4`·`m5`는 `active == 0`, `compacted == 0`이다 (가정 A, 무삭제 보존) |

| 5 | 턴 2 이후 추가된 메시지가 없을 때 `deactivate_messages_after(sid, m2)` 호출 (멱등성) | 반환값은 `0`이고 기존 `m1`·`m2`는 그대로 `active == 1`이다 |
| 6 | **압축 후 취소 보호 (가정 B)**: 턴 1 메시지들(`m1`~`m4`, `last_id = m4`) 뒤, 턴 2 도중 `archive_and_compact`가 실행되어 요약 행(`s1`)과 꼬리 복사본(`c1`, `c2`)이 삽입되고, 이어서 같은 턴 2에서 미완성 `assistant`(`u1`)·`tool`(`u2`)이 추가된 뒤 `deactivate_messages_after(sid, m4)` 호출 | 요약 행(`s1`)과 꼬리 복사본(`c1`, `c2`)은 `active == 1`로 온전히 보존되고, 압축 이후에 추가된 미완성 행(`u1`, `u2`) 2건만 `active == 0`이 된다. 반환값은 `2`이다 |
| 7 | `deactivate_messages_after(sid, -1)` 또는 `deactivate_messages_after(sid, True)` 호출 | `ValueError`가 발생한다 |
| 8 | `end_session(sid, "user_exit")`로 닫힌 세션에 `reopen_session(sid)` 호출 | `True`를 반환하고, `get_session(sid)`의 `ended_at`과 `end_reason`이 모두 `None`이다. 존재하지 않는 ID로 부르면 `False`를 반환한다 (가정 F) |
| 9 | CLI 세션 2개(`s_old`, `s_new`)와 위임 자식 세션 1개(`s_sub`, `source="subagent"`, `parent_session_id="s_new"`로 가장 늦게 생성)가 있을 때 `find_resumable_session(None)` 및 `find_resumable_session("latest")` 호출 | 둘 다 `[s_new]` 1건만 반환한다(위임 자식 `s_sub`는 제외됨) |
| 10 | 세션 ID가 `"abc11111-0000"`, `"abc22222-0000"`, `"def33333-0000"`인 CLI 세션 3개에서 `find_resumable_session("abc1")` / `find_resumable_session("abc")` / `find_resumable_session("xyz")` 호출 | `"abc1"`은 1건(`"abc11111-0000"`), `"abc"`는 최신순 2건, `"xyz"`는 `[]`를 반환한다 |
| 11 | 위 10번 상태에서 `find_resumable_session("%")`, `find_resumable_session("_")`, `find_resumable_session("   ")` 호출 | 와일드카드가 리터럴로 이스케이프되고 공백은 거부되어 셋 모두 `[]`를 반환한다 (위험 2) |
