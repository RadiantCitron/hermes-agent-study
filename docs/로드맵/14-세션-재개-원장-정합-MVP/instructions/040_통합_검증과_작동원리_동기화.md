## 2. 문서 동기화 (문서작업)

작성 규칙은 [작동원리 README](../../../작동원리/README.md)의 「설명의 기준」「이름의 3층」을 따른다(쉬운 개념·설계·이유 + 문단 끝 파일·함수 귀띔, 테스트 개수 미기재).

### 2-1. 작동원리 01편 ([01-헤르메스코어-작동원리.md](../../../작동원리/01-헤르메스코어-작동원리.md))

1. **Q11 「지금은 없는 것 / 한계」**:
   - 「되돌리기는 같은 세션 안에서만 됩니다. 세션을 끝내고 새 세션을 열면 이전 세션의 변경은 되돌릴 수 없습니다」를 지우고, `--resume`으로 지난 세션을 다시 열면 지난번 실행에서 바꾼 파일도 `/rollback`으로 되돌릴 수 있다는 내용으로 고친다(Q13으로 연결).
2. **Q12**:
   - 취소된 요청을 대화에서 뺄 때 장부(`messages`)에서도 그 요청의 미완성 메시지들을 지우지 않고 「현재 대화 아님(`active=0`)」으로 내려, 나중에 세션을 다시 열어도 취소된 요청이나 끊긴 도구 호출이 딸려 나오지 않는다는 설명과 구현 귀띔(`session_db.py`의 `get_last_active_message_id`·`deactivate_messages_after`)을 보탠다.
3. **새 Q13** 「프로그램을 껐다가 다시 켜서 지난 대화를 이어가려면 어떻게 되나요? (`--resume`)」를 Q12 뒤에 추가한다. 담을 내용:
   - 왜 필요한가: 장부에 다 적어 두고도 매번 새 세션만 열면 껐다 켰을 때 기억상실이 되고 지난번에 바꾼 파일도 되돌릴 수 없다.
   - 안에서 일어나는 일(순서): ① `--resume`(가장 최근 CLI 세션) 또는 `--resume <앞자리>`로 이어받을 세션을 찾고(하위 에이전트 세션은 제외), ② 닫혀 있던 세션의 끝난 표시(`ended_at`·`end_reason`)를 비워 다시 열고(`reopen_session`), ③ 되돌리기 장치가 장부에서 마지막 요청 번호(`turn_index`)와 쓴 용량을 복원하고(`restore_from_db`), ④ 에이전트가 처음 세션의 기본 지시문 스냅샷(`system_prompt`)과 현재 대화(`active=1`) 메시지들을 읽어 기억을 복원한다(`load_conversation_history`).
   - 왜 새 세션 번호를 만들지 않고 같은 번호를 다시 여나: 번호가 바뀌면 지난번 파일 변경 기록과 끊어져 되돌리기를 할 수 없다. 왜 기본 지시문을 새로 조립하지 않나: 앞부분이 달라지면 모델의 프롬프트 캐시가 깨진다.
   - 지금은 없는 것 / 한계: 대화 중간 지점에서 새 가지 치기(분기), 화면 목록 선택 창, 하위 에이전트 세션 단독 재개, 끝나기 직전 미전송 알림의 다음 실행 승계는 없다.
   - 구현 귀띔: `session_db.py`의 `find_resumable_session`·`reopen_session`, `tools/checkpoint.py`의 `Checkpointer.restore_from_db`, `agent/agent.py`의 `HermesAgent(resume=True)`·`load_conversation_history`, `cli.py`의 `--resume` 처리.
4. **3부·4부·5부 ①·②·③**에 Q13과 새로 추가된 함수·시험 파일(`test_session_resume.py`, `test_cli_resume.py`, `test_cli_resume_e2e.py`)을 반영하고, 머리 기준 커밋을 최신 `src`·`tests` 커밋으로 갱신한다.

### 2-2. 작동원리 04편 ([04-기억-작동원리.md](../../../작동원리/04-기억-작동원리.md))

| # | 입력 | 기대 결과 |
