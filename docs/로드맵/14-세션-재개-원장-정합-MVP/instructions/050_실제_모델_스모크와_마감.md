# [구현지시서 050] 실제 모델 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [14-README.md](../README.md)  
> **선행 조건**: 040 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~F, [ADR-0014](../../../adr/0014-세션_재개_원장_정합_MVP_범위와_결정.md) §2-7  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 및 마감 단계**다. 실제 모델과 터미널에서 세션을 끝낸 뒤 `--resume`으로 다시 열어 이전 대화 기억과 지난 세션 파일 변경의 `/rollback`이 실제로 작동하는지 확인한다.

---

## 1. 목적

가짜 모델·가짜 HTTP로 모든 자동화 시험이 통과한 상태에서 실제 모델(`deepseek/deepseek-v4-flash-0731`)로 다음을 확인한다.

1. **성공 기준 (1)·가정 A**: 처리 중 `Ctrl+C`로 취소된 턴의 메시지가 DB에서 `active=0`으로 내려가고 다음 재개 세션에 섞이지 않는가.
2. **성공 기준 (2)·가정 C**: 세션을 `exit`로 끝낸 뒤 `--resume`으로 다시 열었을 때 에이전트가 첫 세션에서 만든 파일과 대화 내용을 기억하는가.
3. **성공 기준 (3)·가정 D·E**: 다시 켠 세션에서 `/rollback`을 실행하면 첫 세션에서 바꾼 파일이 복원되고, 다음 발화에서 에이전트가 되돌림 알림을 받아 다시 고치지 않는가(쓰기 도구 호출 0회). 이어서 새 파일을 만들면 `turn_index`가 뒤로 이어지는가.
4. **가정 F**: 다시 켠 세션이 끝날 때 종료 사유가 정상 기록되는가.

가정 **B**(취소된 턴 도중 압축이 일어난 경우의 보호)는 정확한 토큰 경계 타이밍이 필요해 수동 스모크로 겨냥하지 않고 010 시나리오 6 및 040 시나리오 E2로 증명된 것으로 둔다.

## 3. 스모크 절차 (사용자가 별도 터미널에서 실행)

### 실행 1: 첫 세션 (`HERMES_HOME="$H"/s1 .venv/bin/python -m hermes_core.cli`)

| 단계 | 입력 | 볼 것 |
|---|---|---|
| 1 | `write_file 도구로 memo.txt 파일을 만들고 내용은 alpha 로 적어줘.` | `memo.txt`가 만들어지고 에이전트가 답하는가 |
| 2 | `patch 도구로 memo.txt 의 alpha 를 BETA 로 바꿔줘.` | `memo.txt`가 `BETA`로 바뀌는가 |
| 3 | `write_file 도구로 c1.txt c2.txt c3.txt 를 하나씩 순서대로 만들어줘.` → 첫 번째 `[Tool Call]` 직후 **`Ctrl+C`** | 취소 안내가 뜨고 프롬프트로 돌아오는가 |
| 4 | `exit` | `Note:` 안내와 함께 `Session saved and closed. Goodbye!`로 끝나는가 |

### 실행 2: 세션 재개 (`HERMES_HOME="$H"/s1 .venv/bin/python -m hermes_core.cli --resume`)

| 단계 | 입력 | 볼 것 |
|---|---|---|
| 1 | 시작 배너 확인 | `♻️  Resumed session ... (4 active messages, last turn: 3).` 배너가 뜨고 실행 1과 같은 세션 ID 앞 8자리인가 |
| 2 | `/rollback` → `y` (실행 1의 취소된 턴 3에서 만들어진 파일 되돌리기) → 한 번 더 `/rollback` → `y` (실행 1의 턴 2 `BETA` 패치 되돌리기) | 두 번의 `/rollback`이 각각 Turn 3(`c1.txt` 삭제)과 Turn 2(`memo.txt`를 `alpha`로 복원)를 되돌리는가 (**가정 D**) |
| 3 | `우리가 처음에 만든 파일 이름이 뭐였고, 지금 그 파일 안에 뭐라고 적혀 있는지 read_file 로 읽어서 알려줘.` | 에이전트가 첫 세션의 `memo.txt`를 기억해 `read_file`로 읽고 `alpha`라고 답하며, **`write_file`·`patch`를 호출하지 않는가(0회)** (**가정 C·D**) |
| 4 | `exit` | 정상 종료되는가 (**가정 F**) |

### 원장 및 키 미저장 확인 명령

```bash
# 1. 키 미저장 확인 (출력: False 여야 함)
sqlite3 "$H/s1/state.db" .dump | python3 -c "import os,sys; print('key_leaked:', os.environ['OPENROUTER_API_KEY'] in sys.stdin.read())"

# 2. 세션 행 확인 (1개여야 하며 end_reason == 'user_exit')
sqlite3 "$H/s1/state.db" "SELECT count(*), end_reason, ended_at IS NOT NULL FROM sessions"

# 3. 메시지 active 상태 확인 (취소된 턴 3의 행들은 active=0, 나머지는 active=1)
sqlite3 "$H/s1/state.db" "SELECT id, role, active, substr(content,1,40) FROM messages ORDER BY id"

# 4. 체크포인트 상태 확인
sqlite3 "$H/s1/state.db" "SELECT id, turn_index, tool_name, rel_path, status FROM file_checkpoints ORDER BY id"
```

## 5. 인수 테스트 시나리오 (입력 → 기대 결과)

| # | 입력 | 기대 결과 | 가정 |
|---|---|---|---|
| 1 | 실행 1 취소 후 종료 | 취소된 턴의 메시지들이 `messages` 표에 `active = 0`으로 기록됨 | A |

| 6 | 에이전트 회귀 확인 | 전체 자동화 테스트 통과, `src/` 추가 변경 0줄 | — |
