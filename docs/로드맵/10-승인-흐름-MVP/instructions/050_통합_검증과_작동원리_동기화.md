## 1. 구현 내용 명세

이 단계는 **`src/`를 바꾸지 않는다.** 010~040이 각자의 단위 시험으로 증명한 것을, 끝에서 끝까지 이어 붙였을 때도 성립하는지 두 방식으로 확인한다.

- **A. 대본형 가짜 모델 E2E**: 진짜 `HermesAgent` 루프 + 진짜 `SessionDB` + 진짜 `Approver` + 진짜 `terminal` 실행에, 모델만 대본형으로 갈아 끼운다. 「승인 질문 → 원장 → 실행 → 도구 메시지 → 다음 모델 호출」이 한 흐름으로 맞물리는지 본다. 단위 시험이 보지 못하는 **층 사이의 순서와 짝**(원장 행 순서 = 질문 순서, 도구 메시지의 `tool_call_id` 짝, 질문 순간의 DB 상태)이 대상이다.
- **B. 가상 터미널(pty) 승인 프롬프트**: 040의 시험은 `read_user_input`을 가짜로 바꿔 돌렸으므로, 실제 `prompt_toolkit`/`input()` 경로에서 도구 실행 도중 질문이 뜨고 `y`/`n`/Enter/`Ctrl+C`/`Ctrl+D`가 전달되는지(WHY 가정 G)는 아직 증명되지 않았다. 09의 pty 시험 방식(IUTF8를 끈 가상 터미널)을 재사용해 **프로세스 수준**에서 확인한다.
- **C. 문서 동기화**: 010~040 동안 미뤄 둔 작동원리 01·02·03편, ROADMAP·WHY의 서술을 사실에 맞춘다. (010·020·030·040 지시서가 모두 「050에서 일괄 반영」으로 미뤘다.)

실제 터미널 앱(Terminal.app, iTerm2)에서의 화면 모양과 출력 섞임, 실제 모델의 행동(가정 H)은 이 단계가 확인하지 못한다. 060에서 사람이 본다.

### 1-2. 시험 파일

1. **`tests/test_hermes_core/test_agent_e2e.py` 끝에 추가만 한다**(삭제 0줄). 구분 주석 `# 로드맵 10: 구현지시서 050 통합 E2E 검증 시나리오 (시나리오 1 ~ 12)`, 시험 이름 `test_r10_050_scenario_NN_...`, 픽스처 `r10_e2e_env`. 기존 파일 머리의 import에 없는 이름은 기존 관례(`test_agent_e2e.py:700` 부근)처럼 그 구간 앞에서 import한다.
   - 픽스처: 임시 `HERMES_HOME`, 작업 폴더 `HERMES_HOME/workspace`(`monkeypatch.chdir`), `OPENROUTER_API_KEY`를 가짜 값(`FAKE-NOT-A-REAL-KEY-0003`, `sk-or-` 꼴 **아님**)으로 설정, 파일 `SessionDB`, `MemoryStore`, `session_id` 미리 생성. 에이전트 조립 도우미 `build(ask, is_interactive=lambda: True, approver=True)`는 위 1-1의 조립을 한다.
   - `py(코드)` 도우미: `shlex.join([sys.executable, "-c", 코드])`. 모델 응답 도우미: 도구 호출 하나를 가진 응답(`id`가 응답마다 다름) 큐 넣기.
2. **`tests/test_hermes_core/test_cli_approval_pty.py` 신규.** 표준 라이브러리 `pty`·`termios`·`select`·`subprocess`·`sqlite3`만 쓴다. `pty`/`termios`/`termios.IUTF8`가 없으면 모듈 전체를 건너뛴다(09와 같은 방식).
   - 보조 도구 `ApprovalPtySession(argv_json, extra_args=(), fallback=False)`: IUTF8를 끈 pty, 자식은 `sys.executable -c <런처>`. 런처 = ① (`fallback`이면 `sys.modules["prompt_toolkit"] = None`) ② `hermes_core.llm_client.OpenRouterClient`를 1-1의 대본형 클래스로 교체 ③ `sys.argv = ["hermes-core", *extra_args]` ④ `runpy.run_module("hermes_core.cli", run_name="__main__")`. 환경: `PYTHONPATH=<레포>/src`, `HERMES_HOME=<임시>`, `OPENROUTER_API_KEY=FAKE-NOT-A-REAL-KEY-0003`, `TERM=xterm-256color`, `R10_PTY_ARGV_JSON=<argv JSON>`, 작업 폴더 `<임시>`.
   - `wait_for(표지, 제한시간=15초)`·`read_available`·`write`·`close`·DB 읽기(`get_approval_rows()`, `get_tool_results()`)는 09 보조 도구와 같은 규칙: **표지가 나온 뒤에만 키를 보내고**, 고정 `sleep`에 기대지 않으며, 실패해도 자식을 정리한다.
   - 질문이 뜨는 명령은 `py("open('marker.txt','w').write('x'); print('ran')")`(작업 폴더 `HERMES_HOME/workspace`에 `marker.txt`).
   - **통과 조건에 화면 모양은 넣지 않는다.** 출력 섞임·줄 위치·색은 060의 사람 관찰이다.

### 1-3. 알려진 한계 (시험하지 않고 문서에 남긴다)

- pty는 실제 터미널 앱이 아니다. `prompt_toolkit`이 가상 터미널에서 커서 위치 요청(CPR) 경고를 낼 수 있다(09에서 관찰, 실제 앱에서도 나오는지는 **미확인**). 시험은 경고의 유무를 검사하지 않는다.
- E2E의 모델은 대본이다. 실제 모델이 허용목록 밖 명령을 요청하는지, 거부 뒤 우회하는지(가정 H)는 060에서만 본다.
- 승인된 프로그램이 인자에 쓰이지 않은 경로(스크립트 안의 `.env` 읽기 등)를 여는 것, 모델 키 외 비밀 환경변수, 승인된 실행 중 `Ctrl+C`, 타임아웃 부재는 030·ADR에 적은 한계 그대로이며 이 단계에서 증명하지 않는다.

## 6. 위험·주의

- **시간 의존(불안정) 시험**: pty 시험은 기동·화면 갱신 시간에 흔들린다. 표지 기반 대기와 제한시간으로 막고, 질문 표지가 나온 **뒤에만** 답을 보낸다. 질문이 뜨기 전에 보낸 키는 `User >` 입력으로 새어 들어가 시험이 거짓 통과할 수 있다.
- **시험 쪽 DB 읽기**: 앱이 질문을 기다리는 동안 시험이 같은 `state.db`를 읽는다(시나리오 13). 읽기 전용으로 짧게 열고 닫는다. 이 읽기가 앱을 막는다면(잠김) 시나리오를 바꾸지 말고 멈춰서 보고한다.
- **가정 G가 깨질 수 있다.** pty에서 질문이 뜨지 않거나 `Ctrl+C`가 REPL을 죽이면 그것은 시험이 아니라 **발견**이다. `src/`를 임의로 고치지 않고 멈춰서 보고한다(AGENTS.md §2: 버그로 보이는 것은 먼저 보고).
- **런처 방식의 가정**: 시나리오 13~21은 「`runpy`가 새로 실행한 `cli`가 이미 바뀐 `hermes_core.llm_client.OpenRouterClient`를 가져온다」에 기댄다(1-1, 사전 점검 ④). 어긋나면 시나리오가 아니라 런처 설계를 보고한다.
- **헛돌지 않는 시험**: 시나리오 19(`--no-approval`)와 20(비터미널)이 「대본형 모델이 정말 허용목록 밖 명령을 요청한다」는 대조군이다(요청이 없었다면 `tool_success=False`가 나올 수 없다).
- **`marker.txt` 위치**: 실제 모드는 작업 폴더를 `HERMES_HOME/workspace`로 옮긴다. 시험은 이 폴더 안만 본다. 레포·홈에는 아무것도 쓰지 않는다(모든 경로 임시).
- **자식 프로세스 정리**: 실패해도 자식이 남지 않게 한다.
- **문서 정정의 범위**: 2항에 적은 문서만 고친다. ADR·로드맵 정책·다른 로드맵·작동원리 README는 건드리지 않고, 필요해 보이면 제안으로 보고한다. 구현지시서(010~040)는 불변이므로 고치지 않는다.
- **작동원리 서술은 시험으로 확인한 사실만**: pty 수준의 증거는 「가상 터미널에서 확인」으로 쓰고, 실제 터미널 앱·실제 모델 행동은 「미확인(060)」으로 남긴다. E2E의 모델은 대본이라는 한계를 ③에 밝힌다.
- **기준 커밋의 한계**: 이 단계의 커밋은 `tests/test_hermes_core`를 바꾸므로 커밋 뒤 `git log -1 -- src tests/test_hermes_core`는 이 단계 자신을 가리킨다. 문서에는 직전 값 `b4c9cac`를 적고(선례 `fc7617a`), 한계를 ③에 한 줄 밝힌다.
- **미확인**: 실제 터미널 앱에서의 질문 표시와 출력 섞임(060), 실제 모델의 요청·우회 행동(060), 승인된 프로그램의 옵션별 위험.
