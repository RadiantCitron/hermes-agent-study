## 1. 구현 내용 명세

020이 만든 승인기를 **터미널 도구에 연결**한다. 이 단계가 끝나면 승인기를 넘겨 만든 디스패처의 `terminal`은 허용목록 밖 명령을 사람에게 묻고, 승인된 것만 실행한다. 승인기를 넘기지 않은 모든 구성(`create_default_dispatcher()` 기본값, `create_child_dispatcher()`, 지금까지의 모든 호출처)은 **이전과 한 글자도 다르지 않게** 거부한다. **CLI·`HermesAgent`·`delegate_tool`은 바꾸지 않는다**(CLI 연결은 040). 이 단계의 시험은 실제 터미널 없이 가짜 `ask`로 돈다.

### 1-1. 코드 대조로 확정한 사항

| 열린 항목 (ROADMAP §6-3, ADR §2-10) | 확정 | 근거 (코드 대조) |
|---|---|---|
| 승인기를 에이전트까지 잇는 방식 | **`HermesAgent`에 인자를 더하지 않는다.** CLI(040)가 `session_id`(uuid)를 **먼저** 만들고 `SessionDB`·`MemoryStore`·승인기·디스패처를 만든 뒤 `HermesAgent(session_id=…, session_db=…, memory_store=…, dispatcher=…)`로 넘긴다. 네 인자 모두 이미 있다 | `agent.py:119-139`(인자), `agent.py:140`(`session_id or uuid4()`), `agent.py:163`(`dispatcher or create_default_dispatcher`), `agent.py:193`(세션 행은 `__init__` 안에서 생성) |
| 승인기가 세션 ID를 미리 알 수 있는가 | 알 수 있다. `Approver`는 생성 때 `session_id`를 저장만 하고 DB는 `request()`에서 처음 만진다(020). `request()`는 에이전트 생성(=세션 행 생성) 뒤에 호출되므로 외래키가 성립한다 | `approval.py` `Approver.__init__`·`request`, `agent.py:193-200` |
| 허용목록 안 명령의 실행 환경 | **실행 경로를 하나로 합친다.** 허용목록 안·승인된 명령 모두 키 환경변수 이름 목록을 뺀 환경(`env`)으로 실행한다 | 아래 1-4 |
| 허용목록 밖 명령의 `args[0]`도 보호 판정을 받는가 | **받는다.** 프로그램 경로 자리(`.git/hooks/x`, `.env`)도 승인과 무관하게 막는다 | 아래 1-3 |
| 인자 이름 | `approver` (`terminal_tool`과 `create_default_dispatcher` 모두) | ADR §2-10 「이름은 030에서 확정」 |

### 1-2. `create_default_dispatcher` ([`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py))

- 시그니처 끝에 `approver: Optional[Approver] = None`을 **추가**한다(기존 인자·순서 불변). `Approver`는 `hermes_core.tools.approval`에서 가져온다(순환 없음: `approval.py`는 `constants`와 `session_db`만 쓴다).
- `terminal` 등록을 핸들러 클로저로 바꾼다: `lambda **kwargs: terminal_tool(approver=approver, **kwargs)` (함수 한 개로 정의, 다른 도구 핸들러 `_memory_handler`·`_search_handler`와 같은 모양). 스키마는 `TERMINAL_SCHEMA` 그대로다. 모델이 보는 스키마·`properties`(`command`·`timeout`)는 불변이고, 모델이 `approver`를 인자로 보내면 기존 검증이 `unexpected argument 'approver'`로 막는다(인자 위조 불가).
- `include`에 `terminal`이 없으면 `approver`는 쓰이지 않는다(오류 아님, 등록할 터미널이 없을 뿐).
- `ToolDispatcher` 클래스, `register_tool`, `handle_function_call`, `create_child_dispatcher`는 **한 줄도 바꾸지 않는다.** 이미 등록된 `terminal`을 나중에 덮어쓰는 방식은 쓰지 않는다(ADR 대안 H). 자식은 `approver`를 넘기지 않으므로 자식의 거부는 인자 기본값 `None`으로 보장된다.

### 1-3. `terminal_tool` ([`terminal_tool.py`](../../../../src/hermes_core/tools/terminal_tool.py))

시그니처 끝에 `approver: Optional[Approver] = None`을 추가한다(`command`·`timeout`·`workspace` 불변). 판정 순서는 다음과 같고 **이 순서가 계약이다**:

1. 빈 명령 → 시간 범위 → `shlex.split`: **기존 그대로, 승인보다 앞.** 여기서 실패하면 묻지도 기록하지도 않는다.
2. `args[0]`이 허용목록 안: **기존 경로 그대로**(작업 폴더 이탈 검사 → 보호 판정 → 실행). 승인기가 있어도 묻지 않고 원장에 남기지 않는다. 이 경로의 검사 루프(현재 86-92행)는 수정하지 않는다.
3. `args[0]`이 허용목록 밖이고 `approver is None`: **기존 거부 문구 그대로**(`Command '…' is not allowed. Allowed: …`).
4. 허용목록 밖이고 `approver`가 있음 — **보호 파일 바닥**: `args[0]`과 `args[1:]`의 각 `path_values` 중 하나라도 `is_protected_path(value, base)`이면 `Path '…' refers to a protected file or folder (.env*, .git).`(허용목록 안 경로와 같은 문구)로 거부한다. 묻지 않고 원장에 남기지 않는다(010 확정: 사전 차단은 승인 요청이 아님). 승인해도 풀리지 않는 바닥이므로 **승인 질문보다 앞**이다.
5. **판정**: `outcome = approver.request(args)`. `request`가 예외를 내면(선기록·갱신 실패, 020 시나리오 15·16) **잡지 않고 올린다** → 디스패처가 `Tool 'terminal' failed: …`로 감싸고 명령은 실행되지 않는다. `outcome.approved`가 거짓이면 `_failure(outcome.message)`로 거부한다(실행 없음).
6. **실행**: 승인이면 `args`를 실행한다. 승인된 명령은 **작업 폴더 이탈 검사만 건너뛴다**(사람이 `argv`를 보고 판단. ADR §2-6). `shell=False`·`cwd=작업 폴더`·`stdin=DEVNULL`·시간 상한·출력 10,000자 절단은 허용목록 안 명령과 같다. 결과 JSON의 모양도 같다(승인 여부 필드를 더하지 않는다).

도구 결과로 모델에게 가는 거부 문구는 020 `ApprovalOutcome.message`를 그대로 쓴다(우회 재시도 금지 문구 포함).

### 1-4. 실행 경로 하나 + 키 환경변수 차단

- 현재 94-131행의 `subprocess.run` 블록(실행·절단·예외 처리)을 모듈 내부 함수 `_execute(args, base, timeout) -> str`로 **옮긴다**(동작 불변). 허용목록 안 경로(2번)와 승인 경로(6번)가 이 함수 하나를 부른다. 두 갈래로 복사하지 않는다.
- `_execute`는 `subprocess.run(..., env=_child_env())`를 쓴다. `_child_env()`는 호출 시점의 `os.environ` 사본에서 `TERMINAL_STRIPPED_ENV_NAMES`의 이름을 뺀 `dict`를 돌려준다(부모 `os.environ`은 건드리지 않는다. 이름이 없으면 그대로).
- 허용목록 안 명령에도 같은 환경을 쓰는 이유: 현재 허용목록 8개는 셸 없이 환경변수를 출력할 수 없어 새는 길이 없다. 그러나 실행 경로가 둘로 갈라져 한쪽만 키를 막는 구조는 목록이 바뀔 때 조용히 구멍이 된다. 허용목록 안 명령의 실제 동작은 바뀌지 않는다(키 환경변수를 읽는 허용 프로그램이 없음). 기존 시험 중 `subprocess.run`을 가짜로 바꾼 것은 모두 `*args, **kwargs`를 받아 `env` 인자에 영향받지 않는다(착수 전 점검 ④).

### 1-5. 상수 ([`constants.py`](../../../../src/hermes_core/constants.py), 승인 흐름 절 뒤에 추가만)

| 이름 | 값 |
|---|---|
| `TERMINAL_STRIPPED_ENV_NAMES` | `(OPENROUTER_API_KEY_ENV,)` (같은 파일의 기존 상수 `OPENROUTER_API_KEY_ENV = "OPENROUTER_API_KEY"` 재사용. 이 상수가 승인 흐름 절보다 앞에 정의돼 있으므로 순서 문제 없음) |

문구 상수는 새로 만들지 않는다(거부 문구는 020 상수, 보호 파일 문구는 기존 터미널 문구).

### 1-6. 알려진 한계 (시험하지 않고 문서에 남긴다)

- **프로그램이 인자 밖 경로로 비밀을 읽는 경우**는 막지 못한다: `python -c "open('.env').read()"`처럼 코드 문자열 안의 경로는 `path_values`가 경로로 보지 못한다. 승인 화면의 `argv`를 사람이 읽는 것이 방어선이다(ROADMAP 위험 12, **미확인** 아닌 알려진 한계). 시험은 막는다고 주장하지 않는다.
- 키 환경변수 외 비밀 환경변수는 넘어간다(ADR §4).
- 승인된 명령 실행 중 `Ctrl+C`(`KeyboardInterrupt`)는 기존 허용목록 경로와 마찬가지로 `subprocess.run` 밖으로 나가며 이 단계에서 다루지 않는다(040·060에서 관찰, **미확인**).

### 1-7. 작동원리·ROADMAP 갱신

작동원리는 050에서 일괄 반영한다. ROADMAP §2-1·§6-3의 「확정할 이름·방식」은 이 단계 마감 때 대시보드 실행 기록에 확정 내용을 남기고, ROADMAP 본문 정정은 050에서 한다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험은 `tests/test_hermes_core/test_terminal_approval.py`에 둔다. 공통 준비: 작업 폴더는 `tmp_path`의 하위 폴더(테스트가 `monkeypatch.chdir`로 이동하거나 `workspace=`로 지정), 실제 `SessionDB(tmp_path / "state.db")`에 `create_session`으로 세션 생성, 승인기는 020과 같이 **가짜 `ask`**(준비된 답을 순서대로 돌려주거나 예외를 냄)·`is_interactive=lambda: True`(또는 `False`)·`say`는 문자열을 모으는 함수. 「실행」은 `terminal_module.subprocess.run`을 호출 횟수를 세는 가짜로 바꿔 판정한다(기존 터미널 시험과 같은 방식). 허용목록 밖 프로그램은 어디서나 쓰이는 **현재 파이썬**(`sys.executable`)으로 하고 명령 문자열은 `shlex.join([sys.executable, "-c", 코드])`로 만든다(`py(코드)`라 부른다). 키 시험의 가짜 키 값은 `sk-or-` 꼴이 **아닌** 문자열(예: `FAKE-NOT-A-REAL-KEY-0001`)로 쓴다(비밀값 검사 규칙 때문). 기대값은 ADR-0010 §2-3~2-6·§2-10, ROADMAP §2-4·§4와 위 명세에서 나왔고 구현 결과를 보고 쓰지 않았다. 「행」은 `get_approval_requests(session_id)`로 읽은 원장 행이다.

## 5. 위험·주의

- **이 단계부터 허용목록 밖 명령이 실제로 실행될 수 있다.** 단, 승인기를 넘긴 디스패처에서만이고 이 단계에서는 아무 앱도 승인기를 넘기지 않는다(040 전까지 사용자 경로는 이전과 같다). 시나리오 1·2·19가 이 전제를 잡는다.
- **보호 판정은 질문 앞**: 시나리오 11~13은 「묻지 않고, 기록하지 않고, 실행하지 않는다」 세 가지를 모두 단언한다. 순서가 바뀌면 보호 파일이 승인 프롬프트까지 올라간다(WHY 가정 D).
- **`args[0]` 보호 판정은 지시서가 더한 보수적 확장**: ADR은 「인자」라고만 썼다. 프로그램 경로 자리에 `.git/hooks/…`·`.env`가 오는 경우를 승인 화면에서 사람이 놓치기 쉽다는 같은 이유로 같은 바닥에 넣었다. 정당한 프로그램 경로(`python`, `./venv/bin/python`)는 영향받지 않는다. 의도와 다르면 착수 전에 알린다.
- **실행 경로 통합은 동작 변경이 아니다**: 기존 시험이 이를 지켜 준다(시나리오 24). 시험이 `env`를 받지 못하는 가짜를 쓰고 있으면 사전 점검 ④에서 멈춘다.
- **승인기는 요청을 센다**: 승인기 하나는 세션 하나에 속한다는 전제는 040(CLI가 세션마다 승인기 하나를 만든다)에서 지켜진다. 이 단계는 승인기의 수명을 정하지 않는다.
- **기록이 어긋나면 실행하지 않는다**: 시나리오 21. 020의 「예외를 그대로 올린다」 계약을 터미널 도구가 잡지 않아야 성립한다. `terminal_tool` 안에 `try/except`로 감싸지 않는다.
- **문서 한계**: 1-6의 인자 밖 경로·타 비밀 환경변수·`Ctrl+C`는 이 단계가 해결하지 않는다. 마감 보고에서 그대로 한계로 대조한다.
- **실제 터미널 동작은 미확인**: 이 단계의 시험은 가짜 `ask`만 쓴다. 가정 G는 050(pty)·060(사람)에서 본다.
