## 1. 구현 내용 명세

030까지는 승인기를 넘기는 앱이 없어서 사용자 경로가 이전과 같았다. 이 단계는 **CLI가 승인기를 만들어 연결한다.** stdin·stdout이 모두 터미널이면 기본으로 켜지고 `--no-approval`로 끈다. 승인 질문은 09의 `read_user_input`을 재사용한다. **`HermesAgent`·`agent/`·`delegate_tool`·`cli_input.py`·`tools/`는 바꾸지 않는다**(바꾸는 파일은 `cli.py`와 `constants.py` 한 줄 묶음). 이 단계의 시험은 가짜 입력으로 도는 단위 시험이며, 실제 터미널(pty) 시험은 050, 사람이 하는 확인은 060이다.

### 1-2. 인자와 조립 ([`cli.py`](../../../../src/hermes_core/cli.py))

1. **새 인자** `--no-approval` (`store_true`). 도움말: `Disable command approval (commands outside the allowed list are denied, as before)`. `--mock`·`--delegate`·`--no-skills-index`와 함께 쓸 수 있다(충돌 없음).
2. **켜짐 판정**: `approval_enabled = not args.no_approval and is_interactive_terminal()`. `is_interactive_terminal`은 `cli_input`에서 가져와 `cli` 모듈 이름으로 쓴다(시험이 `cli.is_interactive_terminal`을 대체한다).
3. **조립** (현재 `HermesAgent(...)` 호출을 아래로 바꾼다. 다른 인자 `model`·`llm_client`·`context_window_tokens`·`skills_index`는 그대로):
   ```text
   session_id    = str(uuid.uuid4())
   session_db    = SessionDB()
   memory_store  = MemoryStore()
   approver      = Approver(session_db=session_db, session_id=session_id,
                            ask=<read_user_input 호출 람다>, is_interactive=is_interactive_terminal) if approval_enabled else None
   dispatcher    = create_default_dispatcher(memory_store=memory_store, session_db=session_db, approver=approver)
   agent         = HermesAgent(model=…, llm_client=…, context_window_tokens=…, skills_index=…,
                               session_id=session_id, session_db=session_db,
                               memory_store=memory_store, dispatcher=dispatcher)
   ```
   `Approver`·`create_default_dispatcher`·`MemoryStore`·`SessionDB`는 각 모듈에서 가져온다(`hermes_core.tools.approval`, `hermes_core.tools.dispatcher`, `hermes_core.tools.memory_tool`, `hermes_core.session_db`). 위임 도구 등록(`register_delegate_tool`)·모의 1턴·REPL·`finally: agent.session_db.close()`는 **한 줄도 바꾸지 않는다**(`close`는 같은 `session_db` 객체를 닫는다).
4. **배너**: 승인이 켜졌으면 `CLI_APPROVAL_ENABLED_NOTICE`를 한 줄, `--no-approval`이 주어졌으면 `CLI_APPROVAL_DISABLED_NOTICE`를 한 줄 출력한다(`--no-skills-index`와 같은 방식: 플래그가 주어졌을 때만 「꺼짐」 안내). 터미널이 아니라서 꺼진 경우(플래그 없음)는 줄을 출력하지 않는다(`CLI_MULTILINE_HINT`가 비터미널에서 출력되지 않는 것과 같은 방식). `--no-approval`이 주어지면 터미널 여부와 상관없이 꺼짐 안내만 나오고 켜짐 안내는 나오지 않는다.

### 1-3. 상수 ([`constants.py`](../../../../src/hermes_core/constants.py) CLI 입력 절 끝에 추가만)

| 이름 | 값 |
|---|---|
| `CLI_APPROVAL_ENABLED_NOTICE` | `"Command approval enabled: commands outside the allowed list ask for your y/N (disable with --no-approval)."` |
| `CLI_APPROVAL_DISABLED_NOTICE` | `"Command approval disabled (--no-approval)."` |

문구는 ROADMAP §6-5가 에이전트가 정한 안이라고 밝힌 값이며 착수(「진행해라」) 시 승인으로 갈음한다.

### 1-4. 한계 (시험하지 않고 문서에 남긴다)

- **`prompt_toolkit` 경로에서 도구 실행 도중 프롬프트가 정상으로 뜨는지**(WHY 가정 G)는 이 단계의 가짜 입력 시험으로 증명되지 않는다. 050(pty)·060(사람)에서 본다(**미확인**).
- 승인 질문과 에이전트 출력(`quiet_mode`가 아닌 부모의 도구 로그 등)이 섞여 보이는 정도는 060에서 관찰한다(**미확인**).
- 승인 질문 중 `Ctrl+C`는 질문만 취소하고 에이전트 루프를 중단하지 않는다(1-1). 의도된 동작이며, 사용자 불편은 060에서 관찰한다.
- 타임아웃이 없어 자리를 비우면 REPL이 멈춘다(ADR §4, 의도된 한계).

### 1-5. 작동원리·ROADMAP 갱신

없음(050에서 일괄 반영).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험은 `tests/test_hermes_core/test_cli_approval.py`에 둔다. 공통 준비는 기존 CLI 시험(`test_cli_skills_index.py`·`test_cli_delegate.py`)의 방식을 따른다: `HERMES_HOME`을 임시 폴더로, `OPENROUTER_API_KEY`를 가짜 값(`sk-or-` 꼴이 **아닌** 문자열. 예: `FAKE-NOT-A-REAL-KEY-0002`)으로 `monkeypatch.setenv`, `cli.OpenRouterClient`를 대본형 가짜 클라이언트로 대체, `monkeypatch.setattr("sys.argv", […])`로 인자 지정, 작업 폴더가 바뀌므로 먼저 `monkeypatch.chdir(tmp_path)`로 복원 지점을 만든다. **터미널 여부**는 `cli.is_interactive_terminal`을 `lambda: True/False`로 대체해 정한다. **입력**은 `cli.read_user_input`을 대체한 가짜로 한다: 호출마다 받은 `prompt`를 기록하고, `prompt == APPROVAL_PROMPT`이면 준비된 승인 답 목록에서(없으면 시험 실패), 아니면 준비된 사용자 입력 목록(마지막은 `"exit"`)에서 순서대로 돌려준다(예외 값은 raise). 대본형 모델은 첫 응답에서 `terminal` 도구로 허용목록 밖 명령 `shlex.join([sys.executable, "-c", 코드])`(`py(코드)`)을 요청하고 도구 결과를 본 다음 최종 답을 한다. 「원장 행」은 `cli.main()` 종료 뒤 `HERMES_HOME`의 상태 DB를 새로 열어 `get_approval_requests`(세션은 `sessions` 표에서 읽음)로 확인한다. 기대값은 ADR-0010 §2-3~2-5·§2-10, ROADMAP §2-4·§6-4와 위 명세에서 나왔고 구현 결과를 보고 쓰지 않았다.

## 5. 위험·주의

- **사용자 경로가 처음으로 바뀌는 단계다.** 터미널에서 CLI를 실행하면 기본으로 승인이 켜진다. 허용목록 밖 명령이 전부 거부되던 동작이 「묻는다」로 바뀐다. 시나리오 12·13이 꺼진 구성의 불변을, 시나리오 17이 기존 시험의 불변을 잡는다.
- **조립 경로를 하나로 둔다**: 켜짐·꺼짐 둘 다 같은 조립 코드를 지나므로 「승인을 끈 경로」가 별도 분기로 썩지 않는다. 대신 `HermesAgent`가 안에서 만들던 `SessionDB()`·`MemoryStore()`를 CLI가 만든다. 기본 생성자 호출이라 같은 객체 구성이다(사전 점검 ④가 기존 시험과의 충돌을 확인한다).
- **`HERMES_HOME` 고정 순서**: 조립은 실제 모드의 `HERMES_HOME` 절대경로 고정·작업 폴더 이동 뒤에 와야 한다. 앞에 두면 `SessionDB()`가 다른 경로를 열 수 있다.
- **배너 위치는 기존 시험이 정한다**: `Type 'exit'…` 바로 다음 줄이 다중 행 안내여야 하므로 새 줄은 그 앞에 둔다(시나리오 1이 순서를 확인).
- **비터미널은 켜지 않는다**: 시나리오 3·13. 승인기를 만들어 거부시키는 방식(대안)은 택하지 않았다(1-1). `Approver`의 `is_interactive` 검사는 이중 방어로 남는다.
- **취소는 거부다**: 시나리오 9. `Ctrl+C`가 REPL 전체를 죽이거나 승인으로 읽히면 안 된다(위험 7). 구현 중 결과가 다르면 시나리오를 바꾸지 말고 멈춰서 보고한다.
- **키는 대화·명령줄에 쓰지 않는다**: 시나리오 11의 키는 가짜 값이며 실제 키가 필요한 단계는 060뿐이다.
- **미확인**: 실제 터미널(`prompt_toolkit`)에서의 질문 동작과 출력 섞임(1-4). 이 단계 시험은 가짜 입력만 쓰므로 가정 G를 검증하지 못한다.
