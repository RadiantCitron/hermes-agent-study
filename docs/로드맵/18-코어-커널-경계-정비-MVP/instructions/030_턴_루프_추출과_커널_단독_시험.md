## 1. 구현 내용 명세

`run_conversation`의 반복 본문과 그 도우미(`_execute_tool_calls`·`_replace_transcript`·`_parse_tool_arguments`)를 `kernel/`로 **옮긴다**. 기록 순서, 정지 확인 시점, 로그 문구, 결과 사전의 키와 값은 하나도 바꾸지 않는다. `HermesAgent`는 시스템 프롬프트 준비와 부품 넘기기만 하는 겉면(파사드)이 된다.

### 1-1. `kernel/ports.py` (신규) — 바깥 부품의 모양

| 이름 | 내용 |
|---|---|
| `LLMError` | `llm_client.py`의 `LLMError` 클래스 **본문 그대로**(`kind`·`message` 속성, `__repr__`, `__str__`) 이동 |
| `LLMReply` (`Protocol`) | 속성 `content: Optional[str]`, `tool_calls: Optional[list[dict[str, Any]]]`. `usage`는 포트에 넣지 않는다(지금 루프가 `getattr(resp, "usage", None)`로 읽고 `MockLLMResponse`에는 `usage`가 없기 때문) |
| `LLMPort` (`Protocol`, `runtime_checkable`) | `chat_completion(self, messages: list[dict[str, Any]], tools: Optional[list[dict[str, Any]]] = None) -> LLMReply` |
| `TranscriptStore` (`Protocol`, `runtime_checkable`) | `append_message(self, session_id, role, content=None, tool_name=None, tool_calls=None, tool_call_id=None, ...)`, `archive_and_compact(self, session_id, new_messages, summary_index=None)`, `update_token_counts(self, session_id, input_tokens=0, output_tokens=0)`. 매개변수 이름은 [`SessionDB`](../../../../src/hermes_core/session_db.py)와 같게 쓴다 |
| `ToolExecutor` (`Protocol`, `runtime_checkable`) | `get_tools_schema(self) -> list[dict[str, Any]]`, `dispatch(self, call: ToolCall) -> str` |

- 어댑터(`SessionDB`·`ToolDispatcher`·`MockLLMClient`·`OpenRouterClient`)는 상속하지 않는다. 메서드 모양만 맞으면 된다(ROADMAP §2-4). 어댑터 클래스를 새로 만들지 않는다(D-09).
- import는 표준 라이브러리와 `hermes_core.kernel.tool_call`뿐이다.

### 1-2. `kernel/transcript.py` (신규) — 대화 규칙 한 곳

| 함수 | 동작 |
|---|---|
| `parse_tool_arguments(raw)` | `agent._parse_tool_arguments`의 본문 그대로 이동(이름만 밑줄 제거). `agent.py`에 옛 이름을 남기지 않는다(소비자 0건, §0-2) |
| `first_message_unchanged(before, after) -> bool` | 둘 다 비었으면 `True`, 하나만 비었으면 `False`, 아니면 두 목록 첫 원소의 `get("role")`과 `get("content")`가 모두 같을 때 `True` |
| `assistant_message(content, tool_calls) -> dict` | `{"role": "assistant"}`에 `content`가 참이면 `"content"`, `tool_calls`가 참이면 `"tool_calls"`를 더한 사전(지금 루프의 조립과 같다) |
| `tool_result_message(call_id, content) -> dict` | `{"role": "tool", "tool_call_id": call_id, "content": content}` |

- 「시스템 메시지는 바뀌면 안 된다」 판정은 `first_message_unchanged` 하나가 맡는다(ADR D-06·D-09, PLAN §2-2 #9). 부르는 곳은 두 곳이다:
  - 커널 대화 교체(§1-3 `_replace_transcript`): `not first_message_unchanged(messages, new_messages)`이면 `ValueError("system message modified by replace_transcript")`. 빈 목록 검사 두 개는 그 앞에 지금 순서대로 둔다.
  - [`kernel/turn_hooks.py`](../../../../src/hermes_core/kernel/turn_hooks.py) `HookRegistry.run`: 변조가 감지되면 `has_comp_sys and not first_message_unchanged(comparison, ctx.messages)`일 때 `system message modified by hook`, 아니면 `transcript modified outside replace_transcript`. 오류 문구·`on_error` 호출 방식·나머지 줄은 바꾸지 않는다. `turn_hooks.py`의 변경은 이 판정 부분과 import 한 줄뿐이다.
- 사용량 해석은 **합치지 않는다**. 지금 루프는 `usage`의 `input_tokens`·`output_tokens`만 보고, 대화 교체는 `prompt_tokens`·`completion_tokens`도 받는다. 합치면 동작이 바뀌므로 각자 자리에 그대로 옮긴다(§5 관찰).

### 1-3. `kernel/loop.py` (신규) — 턴 루프

```python
@dataclass
class TokenEstimate:
    """압축이 쓰는 직전 입력 토큰 수와 그때의 메시지 수. 세션 동안 파사드가 소유하고 커널이 제자리에서 고친다."""
    input_tokens: Optional[int] = None
    message_count: Optional[int] = None

def run_turn(
    *,
    messages: list[dict[str, Any]],      # 시스템 메시지(또는 이어받은 대화)까지 담긴 목록. 커널이 제자리에서 늘린다
    user_message: str,
    llm: LLMPort,
    tools: ToolExecutor,
    store: TranscriptStore,
    hooks: HookRegistry,
    scope: TurnScope,                    # session_id는 scope.session_id를 쓴다
    estimate: TokenEstimate,
    max_iterations: int,
    event_sink: Optional[EventSink],
    on_hook_error: Callable[[str, Any, Exception], None],
    logger: Optional[logging.Logger] = None,   # None이면 logging.getLogger(__name__)
) -> dict[str, Any]: ...
```

- 본문은 지금 `run_conversation`의 「사용자 메시지 추가와 원장 기록」부터 「`result.update(scope.reports)`」까지를 **줄 순서 그대로** 옮긴 것이다. 바뀌는 것은 참조 대상뿐이다: `self.session_db` → `store`, `self.dispatcher` → `tools`, `self.llm_client` → `llm`, `self.hooks` → `hooks`, `self.session_id` → `scope.session_id`, `self._last_input_tokens`·`self._last_message_count` → `estimate.input_tokens`·`estimate.message_count`, `self._on_hook_error` → `on_hook_error`, `self._emit(...)` → `emit_event(event_sink, ...)`(§1-4), `logger` → 주입된 `logger`.
- `TurnContext` 생성(`_live_messages=messages`, `_replace_fn`)과 매 바퀴의 `ctx.iteration`·`scope.iteration`·`ctx.tools_schema`·`ctx.last_input_tokens`·`ctx.last_message_count` 갱신 시점은 지금과 같다.
- `_execute_tool_calls(...)`와 `_replace_transcript(...)`는 이 모듈의 비공개 함수로 옮긴다(인자로 `store`·`tools`·`scope`·`estimate`·`event_sink`·`logger`를 받는다). 본문은 지금과 같고, 메시지 조립은 §1-2의 `assistant_message`·`tool_result_message`, 인자 해석은 `parse_tool_arguments`를 쓴다.
- 원장 호출의 형태(위치 인자와 키워드 인자의 구분, 넘기는 키워드)는 지금 코드와 같게 둔다. 예: 사용자 기록은 `store.append_message(session_id=..., role="user", content=...)`, 토큰 누적은 `store.update_token_counts(session_id, input_tokens=..., output_tokens=...)`.
- **추정값은 결과로 돌려주지 않고 `estimate` 객체를 제자리에서 고친다**(ROADMAP §2-5·§4 위험 2의 「결과에 돌려주고 파사드가 반영」을 바꾼 것. §6 참조). 갱신 시점은 지금과 같다: LLM 응답의 `input_tokens`가 참이면 즉시 `(input_tokens, 호출 직전 메시지 수)`, 대화 교체 성공 시 즉시 `(None, None)`.
- 잡는 예외는 지금처럼 `LLMError`(`kernel.ports`)뿐이다. 다른 예외(`KeyboardInterrupt` 포함)는 그대로 전파된다. `try/finally`를 새로 넣지 않는다.
- 경고 로그 세 가지의 형식 문자열은 바꾸지 않는다: `"Invalid JSON arguments for tool '%s': %s"`, `"LLM call failed with error: %s"`, `"Agent loop stopped at max_iterations=%d without a final response."`.
- import는 표준 라이브러리와 `hermes_core.kernel.*`뿐이다(R1).

### 1-4. `kernel/events.py` (변경) — 이벤트 안전 방출 한 곳

- 함수 `emit_event(sink: Optional[EventSink], kind: str, data: dict[str, Any], logger: logging.Logger) -> None`를 더한다. 동작은 지금 `HermesAgent._emit`과 같다: `sink`가 `None`이면 아무것도 안 하고, `sink(AgentEvent(kind=kind, data=data))`가 예외를 던지면 `logger.warning("EventSink failed for event '%s': %s", kind, e)` 후 삼킨다.
- 커널 루프의 `tool_call` 이벤트와 파사드의 `_emit`(확장 호스트의 `emit`, 확장 오류 이벤트, 훅 오류 이벤트가 쓰는 것)이 모두 이 함수를 거친다. 「sink 예외는 루프를 깨지 않는다」 규칙의 주인이 커널이 된다(ADR D-06 「이벤트 포트: 기존 `EventSink`와 같은 모양」).
- 기존 이름·값은 바꾸지 않는다.

### 1-5. `agent/agent.py` (변경) — 겉면만 남김

- `run_conversation`: `sys_prompt = self._build_system_prompt(system_message)` → 메시지 목록 준비(이어받은 대화가 있으면 그것, 없으면 시스템 메시지 하나) → `TurnScope(session_id=self.session_id, session_slots=self._session_slots, on_extension_error=self._on_extension_error)` 생성 → `run_turn(...)` 호출 결과를 그대로 반환. 부품은 **호출 시점의** `self.llm_client`·`self.dispatcher`·`self.session_db`·`self.hooks`·`self.event_sink`·`self.max_iterations`를 넘긴다(시험이 `agent.llm_client`를 실행 중 바꿔 끼우므로 생성자에서 붙잡지 않는다). `logger`는 이 모듈의 `logger`(`hermes_core.agent.agent`)를 넘긴다 — 020 §5 이월 관찰 2의 결정(§6).
- `_emit`: 본문을 `emit_event(self.event_sink, kind, data, logger)` 한 줄로.
- `_last_input_tokens`·`_last_message_count`: `self._token_estimate = TokenEstimate()`를 소유하고, 두 이름은 그 칸을 읽고 쓰는 **읽기·쓰기 프로퍼티**가 된다(시험의 대입 `agent._last_input_tokens = 999` 유지). `__init__`의 두 `None` 대입은 `TokenEstimate()` 생성으로 바꾼다.
- 지운다: `_execute_tool_calls`, `_replace_transcript`, `_parse_tool_arguments`, 쓰지 않게 된 import(`json`, `LLMError`, `ToolCall`, `TurnContext`, `BEFORE_LLM`, `AFTER_TOOL_CALLS`, `EVENT_TOOL_CALL`, `AgentEvent` 등 — 실제로 안 쓰게 된 것만).
- 바꾸지 않는다: 생성자 시그니처와 본문의 나머지(압축·`LoopGuard` 설치 포함, 040 몫), `MockLLMClient`·`MockLLMResponse`·`MockToolCall`, `_build_system_prompt`, `_resolve_skills_index_block`, `load_conversation_history`, `install_extension`, `extensions`, `_on_extension_error`, `_on_hook_error`, `_rejected_at_tokens`, `_compression_config`, `_ExtensionHost`, `AIAgent`. 모듈 docstring은 루프가 `kernel/loop.py`에 있다는 사실에 맞게 고친다.

### 1-6. `LLMError`의 자리와 루트 패키지

- [`llm_client.py`](../../../../src/hermes_core/llm_client.py): `LLMError` 정의를 지우고 `from hermes_core.kernel.ports import LLMError`로 가져다 쓴다(어댑터 → 커널 방향). `from hermes_core.llm_client import LLMError`는 같은 객체로 계속 동작한다.
- [`agent/compression.py`](../../../../src/hermes_core/agent/compression.py): `LLMError` import 한 줄만 `hermes_core.kernel.ports`로(020과 같은 원칙: `src`는 새 경로, 시험은 옛 경로).
- [`hermes_core/__init__.py`](../../../../src/hermes_core/__init__.py): 맨 위의 즉시 import 네 줄을 모듈 수준 `__getattr__(name: str) -> Any`(PEP 562)로 바꾼다. `__getattr__` 안에서 이름별로 `from hermes_core.agent import AIAgent, HermesAgent` 같은 **평범한 import 문**을 쓴다(의존 방향 스캐너가 함수 안 import도 읽으므로 import가 문자열 속으로 숨지 않는다). 모르는 이름은 `AttributeError`. `__version__`·`__all__`·docstring은 그대로.
  - 이유: 지금은 `import hermes_core.kernel.loop`만 해도 루트가 에이전트·상태 DB·도구 전부를 불러와서, 기능 모듈 하나가 import 단계에서 깨지면 커널 시험까지 함께 깨진다. 「메인루프 검증을 독립적으로」(PLAN §1)는 이 연결이 끊겨야 성립한다(020 §5 이월 관찰 1의 결정, §6).

## 5. 다음 지시서로 넘기는 관찰 (이 단계에서 처리하지 않음)

- **사용량 해석 두 갈래**: 루프는 `usage`의 `input_tokens`·`output_tokens`만, 대화 교체는 `prompt_tokens`·`completion_tokens`도 읽는다. `OpenRouterClient`는 응답을 `input_tokens`·`output_tokens`로 바꿔 주므로 지금은 문제가 드러나지 않는다. 050(LLM 호출 단일 입구)에서 사용량 누적을 미들웨어로 옮길 때 한 함수로 합칠지 정한다.
- **압축·`LoopGuard` 설치**: `agent.py` 생성자에 그대로 있다. 040에서 `assembly.py`로 옮긴다. 040 지시서에서 「`agent/agent.py`는 기능 확장 모듈을 import하지 않는다」 시험 규칙을 둘지 정한다(ROADMAP §6-4).
- **포트의 반환 모양**: `LLMReply`는 `content`·`tool_calls`만 약속한다. 050의 `LLMResponse`·미들웨어 체인을 설계할 때 `usage`를 포트에 올릴지 정한다.
