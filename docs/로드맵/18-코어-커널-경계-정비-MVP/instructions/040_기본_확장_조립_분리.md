## 1. 구현 내용 명세

기본 확장 목록(압축 → `LoopGuard`)을 만드는 일을 `agent.py`에서 조립 모듈 `assembly.py`로 **옮긴다**. 설치 순서, 확장 이름, 확장 기록(`agent.extensions`)의 내용, 압축 설정이 「부를 때의 에이전트 값」을 읽는 동작은 하나도 바꾸지 않는다. `HermesAgent`는 `extensions` 인자를 새로 받는다(ADR D-07).

### 1-1. `src/hermes_core/assembly.py` (신규) — 조립 지점

| 이름 | 내용 |
|---|---|
| `compression_config_of(agent: Any) -> CompressionConfig` | `CompressionConfig(enabled=agent.compression_enabled, context_window_tokens=agent.context_window_tokens, threshold_ratio=agent.compression_threshold_ratio, llm_client=agent.llm_client)`. 지금 `HermesAgent._compression_config`의 본문을 그대로 옮긴 것이다. 부를 때마다 새로 만든다 |
| `default_extensions(compression_config: Callable[[], CompressionConfig]) -> list[Extension]` | `[CompressionExtension(compression_config), LoopGuardExtension()]`. 부를 때마다 **새 인스턴스**로 만든 새 목록을 돌려준다(확장은 설치 뒤 호스트 등 상태를 가지므로 에이전트끼리 공유하면 안 된다) |

- import: 표준 라이브러리, `hermes_core.agent.compression_hook`(`CompressionConfig`, `CompressionExtension`), `hermes_core.agent.loop_guard`(`LoopGuardExtension`), `hermes_core.kernel.contract`(`Extension`). `hermes_core.agent.agent`는 import하지 않는다(에이전트 타입이 필요한 곳은 `Any`. 순환을 다시 만들지 않기 위해서다).
- 모듈 docstring에 「기본으로 끼울 기능의 목록과 순서는 이 파일 한 곳이 정한다. 기능을 더하거나 빼려면 `default_extensions`의 목록을 고친다」를 적는다.
- 050에서 이 모듈에 기본 LLM 미들웨어가 더해진다(ROADMAP §2-1). 이 단계에서는 위 두 함수만 둔다.

### 1-2. `agent/agent.py` (변경) — 기능 이름을 모르는 겉면

- import: `compression_hook`·`loop_guard` 두 줄을 지우고 `from hermes_core.assembly import compression_config_of, default_extensions`를 넣는다. 이 파일 어디에도 `CompressionConfig`·`CompressionExtension`·`LoopGuardExtension`이라는 이름이 남지 않는다.
- 생성자 시그니처: 맨 끝(`skills_index` 뒤)에 `extensions: Optional[Iterable[Extension]] = None`를 더한다(`Iterable`은 기존 `collections.abc` import 줄에 더한다). 기존 인자의 이름·순서·기본값은 바꾸지 않는다.
- 생성자 본문:
  1. **맨 처음**(어떤 부수 효과보다 먼저): `extensions`가 `None`이 아니면 `list(extensions)`로 한 번만 꺼내 지역 변수에 담고, 이름이 겹치면 `ValueError(f"Duplicate extension name '{name}' in extensions.")`를 던진다(처음 겹친 이름). 이유: 지금 순서대로면 설치 단계의 중복 오류가 원장 세션 생성·기억 파일 로드 **뒤에** 나서 반쯤 만들어진 세션 행이 남는다. 기본 목록은 겹치지 않으므로 기존 동작은 바뀌지 않는다.
  2. 마지막의 두 `install_extension` 줄을 「`extensions`가 `None`이면 `default_extensions(self._compression_config)`, 아니면 1에서 꺼낸 목록 → 차례대로 `self.install_extension(ext)`」로 바꾼다. 위치(훅 레지스트리·확장 관리 칸 초기화 직후)는 지금과 같다.
  3. 생성자 인자 `extensions`를 속성으로 저장하지 않는다(`agent.extensions`는 지금처럼 설치 기록을 돌려주는 읽기 전용 프로퍼티다).
- `_compression_config(self) -> Any`: 본문을 `return compression_config_of(self)` 한 줄로. 이름은 시험 호환을 위해 남긴다(§0-2, ADR D-07 「압축 설정 생성자 인자 3개는 호환을 위해 유지」). 반환 주석을 `Any`로 두는 이유: `CompressionConfig`를 주석에 쓰려면 기능 모듈을 import해야 하고, 문자열 주석은 010 주석 해석 시험이 실패한다.
- 클래스·모듈 docstring에 「기본 확장 목록은 `hermes_core.assembly`가 정한다」를 반영한다.
- 바꾸지 않는다: 그 밖의 생성자 본문, `install_extension`, `extensions` 프로퍼티, `_ExtensionHost`, `run_conversation`, `_build_system_prompt`, `MockLLMClient` 등.

### 1-3. `agent/__init__.py` (변경) — 패키지 지연 import

- 즉시 import 한 줄을 모듈 수준 `__getattr__(name: str) -> object`(PEP 562)로 바꾼다. `name`이 `__all__`에 있으면 함수 안에서 `from hermes_core.agent import agent as _agent_module`(평범한 import 문)을 한 뒤 `getattr(_agent_module, name)`을 돌려주고, 아니면 `AttributeError(f"module {__name__!r} has no attribute {name!r}")`. `__all__`과 docstring은 그대로.
- 이유: §0-3의 순환. 패키지를 import하는 것만으로 `agent.agent`가 불려 오면, `agent` 패키지 안의 기능 모듈(`compression_hook`·`loop_guard`)을 import하는 쪽(조립 모듈)과 겉면이 서로를 부르는 고리가 생긴다. 지연 import로 이 고리를 구조에서 없앤다. 030에서 루트 `hermes_core/__init__.py`에 적용한 것과 같은 방식이다. 겉면 쪽에서 함수 안 import로 고리를 숨기는 방법은 배척한다(고리는 남고 import 순서의 우연에 기대게 된다 — PLAN §2-2 #7).
- 덤으로 `import hermes_core.agent.compression_hook`만 해도 겉면·상태 DB·도구가 따라오던 연결이 끊긴다(시나리오 15).

### 1-4. 의존 방향 규칙 R5 (`tests/test_architecture/test_dependency_rules.py` 변경)

ROADMAP §6-4가 040에 맡긴 「`agent/agent.py`는 기능 확장 모듈을 import하지 않는다」를 **조립 지점 쪽에서 더 좁게** 정한다.

- 모듈 상수 `FEATURE_EXTENSION_MODULES: tuple[str, ...] = ("hermes_core.agent.compression_hook", "hermes_core.agent.loop_guard")`(주석: 「기본 기능 확장 모듈. 이 모듈을 import하는 `src` 모듈은 조립 지점 `hermes_core.assembly`뿐이다. 새 기능 확장을 만들면 여기에 더한다 — 시나리오 11이 빠뜨림을 잡는다」).
- `find_violations`에 R5: 대상이 `FEATURE_EXTENSION_MODULES`의 한 모듈과 같거나 `모듈 + "."`으로 시작하고, importer가 `hermes_core.assembly`가 아니면 `(importer, 대상, "R5")`.
- 이 파일에서 바꾸는 곳은 위 상수 추가, `find_violations`의 R5 블록과 docstring의 규칙 범위 표기(`R1~R4` → `R1~R5`), 시나리오 10의 실패 메시지 안 `(R1~R4)` → `(R1~R5)`, 새 시험 함수(시나리오 10·11)뿐이다. `KNOWN_DEBT`는 바꾸지 않는다(R5 위반은 이 단계가 끝나면 0건이어야 하므로 부채로 올리지 않는다).
- 대안으로 「`agent/agent.py`만 금지」를 검토했으나 배척했다: 그러면 다른 모듈(CLI·위임 도구 등)이 기능을 직접 설치하는 두 번째 조립 지점이 생겨도 시험이 모른다. 「조립 지점은 하나」가 D-07의 뜻이다.

## 5. 다음 지시서로 넘기는 관찰 (이 단계에서 처리하지 않음)

- **가정 D의 한계**: 이 단계 뒤에도 압축은 겉면을 거친다 — 압축 설정 생성자 인자 3개와 `_compression_config`가 `agent.py`에 남는다(ADR D-07의 호환 결정, 시험 소비자 §0-2). 따라서 「설정이 필요 없는 기능」의 추가·삭제는 `assembly.py` 목록 수정만으로 끝나지만, **겉면의 생성자 인자로 설정을 받는 기능**을 새로 기본에 넣으려면 지금 구조로는 겉면을 고쳐야 한다. 060 마감에서 가정 D를 「바뀌었다(조건부로 이뤘다)」로 대조할 근거로 남긴다. 해소(설정 묶음을 조립 지점이 받기)는 생성자 실물 기본값 제거와 함께 19번 후보다.
- **사용자 목록에서 압축만 다시 쓰기**: `extensions=`로 목록을 직접 줄 때 압축을 넣으려면 에이전트가 생기기 전에 설정 함수가 있어야 한다(지금은 겉면의 `_compression_config`가 그 역할). 쓰는 곳이 없어 이 단계에서 창구를 만들지 않는다.
- **050과의 연결**: 050의 기본 LLM 미들웨어도 `assembly.py`에 둔다(ROADMAP §2-1). LLM 호출 기록 콜백(`set_call_recorder`) 등록이 지금 겉면 생성자에 있으므로 050에서 함께 본다.
