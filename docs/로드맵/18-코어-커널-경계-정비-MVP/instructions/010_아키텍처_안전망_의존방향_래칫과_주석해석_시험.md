## 1. 구현 내용 명세

동작 코드는 import 두 줄만 바꾼다. 나머지는 시험이다. 시험은 「규칙을 시험이 강제한다」와 「이미 있는 위반은 줄어들기만 한다」를 실행 가능한 형태로 만든다.

### 1-1. 지원 버전 결함 수정
- `agent.py`: `from collections.abc import Collection` → `from collections.abc import Callable, Collection`.
- `cli.py`: 표준 라이브러리 import 묶음에 `from typing import Optional`을 넣는다.
- 다른 줄은 바꾸지 않는다.

### 1-2. 의존 방향 시험 (`tests/test_architecture/test_dependency_rules.py`, 신규)

**구성**: 시험 파일 안에 순수 함수 세 개를 두고, 그 함수를 합성 입력(시나리오 1~8)과 실제 소스 트리(시나리오 9~10)에 각각 적용한다. 합성 입력 시험이 있어야 「스캐너가 import를 하나도 못 찾아서 통과」하는 공허한 녹색을 막을 수 있다.

1. `collect_imports(module_name: str, source: str) -> set[str]`
   - `ast.walk`로 **파일 전체**(함수 안의 지연 import, `if TYPE_CHECKING:` 안 포함)의 `Import`·`ImportFrom`을 모은다.
   - `import a.b` → `"a.b"`. `from a.b import c` → `"a.b"`와 `"a.b.c"` 둘 다(이름 `c`가 모듈일 수 있으므로; `from hermes_core import cli`를 잡기 위함).
   - 상대 import(`level > 0`)는 `module_name` 기준 절대 이름으로 바꾼다. `module_name`이 패키지(`__init__`)인지는 인자 `is_package: bool = False`로 받는다.
2. `find_violations(imports: dict[str, set[str]]) -> set[tuple[str, str, str]]`
   - 입력: `{importer 모듈명: import 대상 집합}`. 출력: `{(importer, 대상, 규칙 ID)}`.
   - 대상 이름은 「`hermes_core`의 어느 모듈에 속하나」를 앞부분 일치(`대상 == X` 또는 `대상.startswith(X + ".")`)로 판정한다.
   - 규칙:
     - **R1**: importer가 `hermes_core.kernel` 또는 그 하위이면, 대상은 `hermes_core.kernel`(하위 포함)이거나 표준 라이브러리(`sys.stdlib_module_names`에 최상위 이름이 있음)여야 한다. 그 밖(`hermes_core`의 다른 모듈, 제3자 라이브러리)은 위반.
     - **R2**: 대상이 `hermes_core.cli` 또는 `hermes_core.cli_input`이면 importer는 `hermes_core.cli`여야 한다. 그 밖은 위반.
     - **R3**: importer가 `hermes_core.tools` 하위이면 대상이 `hermes_core.agent`(하위 포함)이면 위반.
     - **R4**: importer가 `hermes_core.extensions.contract`이면 대상은 표준 라이브러리이거나 `hermes_core.kernel`(하위 포함)이어야 한다. (지금 docstring에만 있는 「표준 라이브러리만」 규칙을 시험으로 옮긴다. `kernel` 허용은 020에서 이 모듈이 재수출만 남게 될 것을 미리 반영한 것이다.)
   - `"a.b"`와 `"a.b.c"`처럼 같은 import에서 나온 두 이름이 모두 위반이면 둘 다 기록한다(중복 제거는 하지 않는다. 결과가 결정론적이면 충분하다).
3. `compare_with_debt(actual: set, debt: set) -> tuple[set, set]`
   - `(actual - debt, debt - actual)`, 즉 `(새 위반, 사라졌는데 목록에 남은 부채)`를 돌려준다.

**실제 트리 스캔**: `src/hermes_core/**/*.py`를 읽어 경로에서 모듈명을 만든다(`src/hermes_core/agent/agent.py` → `hermes_core.agent.agent`, `__init__.py` → 패키지명, `is_package=True`). 파일을 import하지 않고 텍스트만 읽는다.

**부채 목록**: 시험 파일 상단의 상수.

```python
# 알려진 의존 방향 위반 (래칫). 줄어들기만 한다.
# 항목을 갚으면 시험이 「목록에서 지워라」로 실패한다. 새 항목 추가는 사용자 승인 사항이다.
KNOWN_DEBT: dict[tuple[str, str, str], tuple[str, str]] = {
    # (importer, 대상, 규칙): (사유, 해소 예정)
    ...
}
```

- 010 시점에 들어갈 항목은 착수 전 점검 1의 `delegate_tool.py` 두 줄에서 나오는 R3 위반이다(`from hermes_core.agent.agent import HermesAgent`가 만드는 `"hermes_core.agent.agent"`·`"hermes_core.agent.agent.HermesAgent"`, `prompt_builder` 줄이 만드는 두 이름 — 총 4개의 튜플). 사유는 「위임 도구가 자식 에이전트를 직접 생성」, 해소 예정은 「19번 이후: 자식 생성 팩토리 주입(16 대시보드 §6-2)」으로 쓴다.
- 실제 스캔 결과가 이 4개와 다르면 **부채 목록을 결과에 맞춰 늘리지 말고** 멈춰서 보고한다(목록 추가는 사용자 승인 사항).

### 1-3. 주석 해석 시험 (`tests/test_architecture/test_annotations_resolve.py`, 신규)

- 순수 함수 `unresolved_annotations(module) -> list[tuple[str, str]]`: 모듈 객체를 받아, 그 모듈에 **정의된**(`obj.__module__ == module.__name__`) 모든 함수와 클래스, 그리고 클래스 `__dict__`의 모든 함수(밑줄로 시작하는 것 포함)에 `typing.get_type_hints`를 적용해 실패한 `(qualname, 오류 문자열)` 목록을 돌려준다.
- 실제 패키지: `pkgutil.walk_packages(hermes_core.__path__, "hermes_core.")`로 모든 모듈을 import하고(import 실패도 시험 실패), 각 모듈에 함수를 적용한다.
- 허용 예외 목록 `ALLOWED_UNRESOLVED: dict[tuple[str, str], str]`(키 `(모듈명, qualname)`, 값 사유)을 둔다. 010 시점에는 **비어 있다**. 항목 추가는 사유와 함께 사용자 승인 사항이다.

### 1-4. Python 3.12 import 확인 (수동 명령, 결과는 대시보드 실행 기록)

레포의 `.venv`는 건드리지 않는다. 아래 명령을 레포 루트에서 실행한다(설치는 `uv` 캐시의 임시 환경에만 일어난다).

```bash
PYTHONPATH=src uv run --no-project --python 3.12 \
  --with httpx --with prompt_toolkit --with pydantic \
  python -c "import hermes_core.agent.agent, hermes_core.cli; print('ok')"
```

- 기대: `ok`. 네트워크 등으로 의존성을 받을 수 없으면 실패 사유를 그대로 기록하고 멈춰서 보고한다(대역 모듈로 대신하지 않는다).
