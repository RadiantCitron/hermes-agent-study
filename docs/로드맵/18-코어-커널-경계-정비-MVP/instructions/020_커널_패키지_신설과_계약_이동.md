## 1. 구현 내용 명세

네 모듈의 **본문을 옮기기만** 한다. 클래스·함수·상수의 이름·모양·동작·docstring의 의미는 바꾸지 않는다. 구 경로는 같은 객체를 다시 내보내는 얇은 모듈이 된다. 이 단계에서 루프(`run_conversation`)는 건드리지 않는다.

### 1-1. 커널 패키지 (`src/hermes_core/kernel/`, 신규)

| 새 파일 | 내용 | 출처 |
|---|---|---|
| `__init__.py` | 패키지 docstring만(「턴 루프·확장 계약·포트·대화 불변식. 표준 라이브러리와 `hermes_core.kernel`만 import한다(ADR-0018 D-02, 시험 R1)」). **이름을 다시 내보내지 않는다**(한 이름공간에 모든 것을 모으는 「신(god) 모듈」 방지) | 신규 |
| `contract.py` | `extensions/contract.py`의 본문 전부. 모듈 docstring의 「불변 원칙」 문장은 「이 모듈은 표준 라이브러리만 import한다」로 유지 | 이동 |
| `turn_hooks.py` | `agent/turn_hooks.py`의 본문 전부. `TurnScope` import만 `hermes_core.kernel.contract`로 | 이동 |
| `tool_call.py` | `ToolCall`·`ToolMiddleware` 정의. `TurnScope`는 `hermes_core.kernel.contract`에서 | `dispatcher.py`에서 이동 |
| `events.py` | `AgentEvent`·`EventSink`·`EVENT_TOOL_CALL`·`EVENT_HOOK_ERROR`·`EVENT_EXTENSION_ERROR` | `agent/events.py`에서 이동 |

- `EVENT_LOOP_GUARD`(기능의 이벤트 종류)와 `ConsoleEventSink`(화면 출력)는 커널로 옮기지 않는다(ADR-0018 D-05).

### 1-2. `src/` 쪽 import를 새 경로로

| 파일 | 바꿀 것 |
|---|---|
| `agent/agent.py` | events의 코어 이름 3개·`AgentEvent`·`EventSink`는 `kernel.events`에서, `ConsoleEventSink`는 `agent.events`에서. turn_hooks 이름은 `kernel.turn_hooks`, contract 이름은 `kernel.contract`, `ToolCall`은 `kernel.tool_call`에서. `ToolDispatcher`·`create_default_dispatcher`는 그대로 `tools.dispatcher` |
| `agent/compression_hook.py` | `BEFORE_LLM`·`TurnContext`는 `kernel.turn_hooks`, `ExtensionHost`는 `kernel.contract` |
| `agent/loop_guard.py` | `ExtensionHost`·`MiddlewarePhase`는 `kernel.contract`, `ToolCall`은 `kernel.tool_call`. `EVENT_LOOP_GUARD`는 그대로 `agent.events` |
| `tools/dispatcher.py` | `FailurePolicy`·`MiddlewarePhase`·`PHASE_FAILURE_POLICY`는 `kernel.contract`. `ToolCall`·`ToolMiddleware`는 정의를 지우고 `kernel.tool_call`에서 import(이 모듈의 공개 이름으로 계속 남는다 — 재수출). 쓰지 않게 된 import(`TurnScope`, `dataclass` 등)는 지운다 |

- 위 표 밖의 `src/` 파일은 바꾸지 않는다. `hermes_core/__init__.py`도 그대로다(§5 관찰 참조).

### 1-3. 구 경로는 재수출만 (호환 층)

- `extensions/contract.py`: 모듈 docstring(「호환 층: `hermes_core.kernel.contract`의 이름을 다시 내보낸다. ADR-0018 D-05」) + `from hermes_core.kernel.contract import (...)` + `__all__`. 다른 정의·로직 금지.
- `agent/turn_hooks.py`: 같은 방식으로 `hermes_core.kernel.turn_hooks`의 §0-2 이름 6개.
- `agent/events.py`: `hermes_core.kernel.events`의 이름 5개를 다시 내보내고, `EVENT_LOOP_GUARD`·`ConsoleEventSink`는 이 모듈에 그대로 정의한다(`ConsoleEventSink`는 `EVENT_TOOL_CALL`·`AgentEvent`를 커널에서 가져다 쓴다).
- `tools/dispatcher.py`: `ToolCall`·`ToolMiddleware`를 커널에서 import해 이름을 유지한다(§1-2).
- 재수출은 `from ... import 이름` 형태만 쓴다. 같은 이름을 다시 정의하거나 하위 클래스로 감싸지 않는다(위험 4: 복사본이 생기면 `isinstance`·`Enum` 비교가 깨진다).

### 1-4. 호환 층 시험 (`tests/test_architecture/test_compat_layers.py`, 신규)

010의 시험 파일은 고치지 않는다(검증된 시험 무수정). 호환 층은 별도 파일에서 관리한다.

```python
# 호환 층 재수출 목록. 줄어들기만 한다. 새 항목 추가는 사용자 승인 사항이다.
COMPAT_REEXPORTS: dict[tuple[str, str], str] = {
    # (구 모듈, 이름): 새 모듈
    ...
}
COMPAT_REASON = "기존 시험이 구 경로를 import한다(검증된 시험 무수정, ADR-0018 D-05)"
COMPAT_REMOVAL = "구 경로를 import하는 시험·코드가 0이 될 때(ADR-0018 D-10)"
# 재수출만 하는 모듈(정의 금지). agent/events.py와 tools/dispatcher.py는 자체 정의가 있으므로 넣지 않는다.
PURE_REEXPORT_MODULES = ("hermes_core.extensions.contract", "hermes_core.agent.turn_hooks")
```

- `COMPAT_REEXPORTS`는 §0-2의 구 경로 이름 중 커널로 옮긴 것 전부(contract 8, turn_hooks 6, events 5, dispatcher의 `ToolCall` 1 = 20개)다. `ToolMiddleware`는 시험이 구 경로로 import하지 않고 `dispatcher.py`가 내부(`add_middleware` 주석)에서 쓰려고 import할 뿐이므로 호환 층이 아니다.

## 5. 다음 지시서로 넘기는 관찰 (이 단계에서 처리하지 않음)

- **패키지 루트의 즉시 import**: [`hermes_core/__init__.py`](../../../../src/hermes_core/__init__.py)가 `agent`·`session_db`·`tools.dispatcher`·`tools.memory_tool`을 즉시 import한다. 그래서 `kernel/`이 R1을 지켜도 `import hermes_core.kernel`은 패키지 전체를 불러온다. 「커널 시험이 SQLite·파일을 **쓰지** 않는다」(ADR-0018 D-06)에는 영향이 없지만 「커널만 **불러온다**」는 성립하지 않는다. 030 지시서에서 커널 단독 시험의 판정 기준(import되는 모듈 범위를 볼지, 실행 중 부작용만 볼지)을 정하고, 루트 import를 바꿀지는 `from hermes_core import HermesAgent` 호환과 함께 판단한다.
- **로거 이름**: 시험 `test_agent_loop_signals.py`(`AGENT_LOGGER = "hermes_core.agent.agent"`)와 `test_dispatch_single_entry.py`가 `caplog`로 `hermes_core.agent.agent` 로거를 거른다(최대 횟수 경고, 깨진 JSON 경고). 030에서 루프를 옮기면 이 로그가 어느 로거로 나가야 기존 시험이 무수정 통과하는지 030 지시서에서 정한다.
