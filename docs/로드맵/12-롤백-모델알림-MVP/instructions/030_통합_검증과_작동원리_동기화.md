## 1. 구현 내용 명세

020은 가짜 클라이언트(`ScriptableClient`)로 「모델이 받은 글」을 확인했다. 이 단계는 남은 두 가지를 확인하고, 바뀐 동작을 작동원리 문서에 반영한다.

1. **실제 클라이언트 경로**: 실제 `OpenRouterClient`가 알림이 붙은 메시지를 HTTP 요청으로 직렬화하는지, 그리고 그 요청이 원장 `llm_calls.request_json`에 그대로(열쇠는 가린 채) 남는지(D-03).
2. **압축과의 공존**: 알림이 든 사람 메시지가 압축을 거쳐도 이전 요약으로 오인되지 않는지(D-07, 가정 D). 오래된 알림은 요약될 수 있다는 것도 이 확인 범위다(D-09, 가정 E).

### 1-1. 코드 대조로 확정한 사항

- `OpenRouterClient`는 `transport: Optional[httpx.BaseTransport]` 인자를 받는다(`llm_client.py` 86행). 요청 기록은 `"request": masked_request`로 넘어가 `SessionDB.record_llm_call`이 `request_json`에 저장한다(`llm_client.py` 243행, `session_db.py` 554행). 따라서 CLI 시험에서 `cli.OpenRouterClient`를 「실제 클래스에 `httpx.MockTransport`를 넣어 만드는 함수」로 바꿔 끼우면, 네트워크 없이 실제 직렬화·기록 경로를 지날 수 있다. 응답 JSON 모양은 `test_llm_client.py`의 기존 대본을 따른다.
- 이전 요약 탐지는 `compression.find_previous_summary`가 `SUMMARY_PREFIX`부터 `SUMMARY_END_MARKER`까지를 찾는 방식이다(`compression.py` 361행 부근). 알림 표지(010)는 이 둘을 포함하지 않는다.

### 1-2. 시험 파일

- **새 파일** `tests/test_hermes_core/test_cli_rollback_notice_e2e.py`. 이유: `test_agent_e2e.py`(4,000줄 넘음)의 구조 정리는 리팩토링으로 미뤘고, 실제 클라이언트 경로 시험은 픽스처가 다르다.
- 픽스처:
  - 임시 `HERMES_HOME`과 가짜 열쇠 환경변수.
  - 대본 응답 목록을 차례로 돌려주는 `MockTransport` handler. 받은 요청 본문을 목록에 모은다.
  - `monkeypatch.setattr(cli, "OpenRouterClient", factory)`.
  - 사람 입력은 `cli.read_user_input`을 대본 함수로 바꿔 넣는다(kwargs를 받아 버림).
- 새 pty 시험은 만들지 않는다(D-12).

### 1-3. 발견 수정 슬롯 (src 변경이 허용되는 유일한 범위)

시나리오가 결함을 드러내면 아래 순서로 처리한다.
1. 실패하는 시험을 먼저 확인한다.
2. 원인이 이 로드맵의 변경(010·020) 안에 있을 때만 그 파일(`tools/checkpoint.py`, `cli.py`, `constants.py`)을 고친다.
3. 수정마다 대시보드에 `F1`, `F2`…로 기록한다.

원인이 `agent/`·압축·`llm_client.py`처럼 이 로드맵 밖에 있으면 **고치지 않고 멈춰 보고한다.**

## 2. 문서 동기화 (문서작업)

### 2-1. 작동원리 01편 ([01-헤르메스코어-작동원리.md](../../../작동원리/01-헤르메스코어-작동원리.md))

- **Q11 6번** 「모델은 되돌림을 모름」을 다시 쓴다. 담을 내용:
  - 되돌리기는 여전히 모델을 부르지 않는다.
  - 1개 이상 되돌렸으면, 사람이 다음에 보내는 말 앞에 「사람이 일부러 되돌렸다, 무엇을 되돌렸고 무엇을 건너뛰었다, 요청 없으면 다시 하지 말라」는 알림이 붙어 함께 간다.
  - 그 알림은 장부에 그대로 남는다.
  - 왜 이렇게 하는가: 11번에서 모델이 되돌린 것을 「반영 지연」으로 오해하고 다시 고친 일이 있었다. 대화를 지우지 않는 이유도 적는다(대상 턴이 대화 중간일 수 있음, 앞부분 고정 규칙).
- **Q11 「지금은 없는 것 / 한계」**에 세 가지를 추가한다.
  - 되돌린 뒤 아무 말 없이 끝내면 알림은 가지 않는다.
  - 오래된 알림은 긴 대화 요약에서 흐려질 수 있다.
  - 되돌리기 도중 오류가 나면 알림이 가지 않는다(020 §1-4).
- **5부**:
  - ① 「잘못 고친 파일 되돌리기」 행에 「다음 사람 말 앞에 알림」을 추가한다.
  - ② 19번 항목에 `format_rollback_notice`, `_handle_rollback`의 반환, `main`의 보류 목록, 상수 `ROLLBACK_NOTICE_*`, 새 시험 파일을 추가한다.
  - ③ Q11 행의 미확인에 「실제 모델이 알림을 따르는지는 040에서 관찰」을 넣는다.
- **기준 커밋**: 이 단계 직전에 `src`·`tests`를 마지막으로 바꾼 커밋으로 옮긴다. 옮긴 이유를 ③ 검증 문단에 적는다(작동원리 README 규칙).
- 작동원리 문서에는 시험 개수를 적지 않는다(RULE-002).

### 2-2. 로드맵 문서

## 4. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 공통 진행 | `read it`에 대한 첫 HTTP 요청 본문(JSON)의 `messages` 마지막 user `content`가 `[Rollback notice - added by the CLI, not typed by the user]`로 시작하고, `  deleted: notes.txt`를 포함하며, `\n\nread it`으로 끝난다 |
| 2 | 공통 진행 | 원장 `llm_calls`를 `id` 순으로 읽어, `request_json`을 파싱한 마지막 user `content`가 `read it`으로 끝나는 첫 행을 고른다. 그 `content`가 1의 HTTP 본문 값과 **글자 그대로 같다** (D-03) |

| 4 | 공통 진행 | 원장 `messages`의 user 행은 `go`, (알림+`read it`) 두 개뿐이다. 즉 알림이 별도 행으로 생기지 않고 `read it` 행의 `content`가 1의 글과 같다 |
| 5 | `find_previous_summary`에 [system, user(알림+`\n\nread it`), assistant] 목록 | `None` (알림을 이전 요약으로 오인하지 않음, 가정 D) |

## 6. 위험·주의

- 시나리오 6·7에서 압축이 실제로 일어나도록 크기를 맞추기 어려울 수 있다. 그때는 압축 함수의 기존 시험(`test_compression_summary.py`) 준비 방식을 따른다. 그래도 결정적으로 만들 수 없으면 시나리오를 바꾸지 말고 멈춰 보고한다.
- 실제 키는 쓰지 않는다. 네트워크 호출이 생기면(`MockTransport` 누락) 시험이 실패해야 한다. handler 밖 요청이 없음을 대본 소진으로 확인한다.
