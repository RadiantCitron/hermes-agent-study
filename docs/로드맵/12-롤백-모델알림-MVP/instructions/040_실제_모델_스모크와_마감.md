# [구현지시서 040] 실제 모델 스모크 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [12-README.md](../README.md)  
> **선행 조건**: 030 `Done` **그리고 사용자의 명시적 실행 지시**. 마감은 여기에 더해 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~F, [ADR-0012](../../../adr/0012-롤백_모델알림_MVP_범위와_결정.md) §2-13(D-13), 형식 선례: [11의 060](../../11-체크포인트-롤백-MVP/instructions/060_실제_모델_터미널_스모크와_마감.md)  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 단계**다. 이 로드맵은 11번 060에서 실제 모델이 되돌린 파일을 스스로 다시 고친 관찰에서 시작했다. 그래서 **같은 상황을 같은 모델로 다시 돌려** 알림이 그 행동을 멈추는지 본다. 이 로드맵에서 **실제 키가 필요한 유일한 단계**다.

---

## 1. 목적

가짜 모델·가짜 HTTP로 모든 시험이 통과한 상태에서 다음을 확인한다.

1. **성공 기준(D-13, 가정 A)**: 11번 060 R1의 상황(만들기 → 고치기 → 되돌리기 → 「읽어서 보여줘」)을 같은 모델로 **3회** 돌린다. 되돌린 뒤 읽기 요청에서 모델이 파일 쓰기 도구(`write_file`·`patch`)를 **한 번도 부르지 않는가.**
2. **가정 B**: 알림이 사람의 실제 요청을 흐리지 않는가. 읽기 요청에 읽기로 답하는가. 사람이 다시 바꾸라고 하면 그 요청은 따르는가(알림이 정당한 요청까지 막지 않는가).
3. **가정 C**: 건너뛴 파일(사람이 고친 파일)이 알림에 들어갔을 때, 모델이 그 파일의 상태를 오판하지 않는가.
4. **가정 F**: 실제 알림 길이.
5. 화면: 되돌린 뒤 「다음 메시지와 함께 알립니다」 안내가 읽을 만한가(사람 눈 확인).

판정이 어려운 것은 **「못 봤다」로 적는다.** 모델 1종이고 실행 횟수도 적어서, 다른 모델이나 다른 문장에서는 달라질 수 있다. 가정 D(압축 표지 비충돌)·E(압축 뒤 흐려짐)는 030의 자동 시험으로만 증명된 것으로 두고 이 스모크에서는 관찰하지 않는다.

## 2. 사전 조건

1. **에이전트**:
   - `.venv/bin/python -m pytest -n 4 -q`가 모두 통과하는지 확인하고 기준선 개수를 기록한다.
   - `git diff <030 구현 커밋>..HEAD -- src/`가 0줄인지 확인한다(030 이후 `src/` 무변경).
   - 코드·문서는 이 단계에서 바꾸지 않는다.
2. **사용자**: 평소 쓰는 터미널 앱 1개와 확인용 탭 1개를 준비한다. 앱 이름과 버전을 기록한다.
3. **키는 에이전트와의 대화·명령줄·프롬프트에 절대 쓰지 않는다**([AGENTS.md](../../../../AGENTS.md) §3).
   - 사용자가 **별도 터미널에서 직접** `OPENROUTER_API_KEY`를 환경에 내보낸다.
   - 에이전트는 `.env`를 열지 않는다.
   - 에이전트에게 붙여 넣는 화면 출력에서 개인 경로는 `<임시>`로 바꾼다.
4. 상태 폴더는 레포 밖 임시 폴더를 쓴다. 키를 내보낸 그 터미널(「실행 탭」)의 레포 루트에서 한 번 실행한다.
   ```bash
   export H=$(mktemp -d); echo "$H"; mkdir -p "$H"/a1 "$H"/a2 "$H"/a3 "$H"/b1
   ```
   확인 탭에서는 `export H=<위에 출력된 경로>`를 한 번 친다.
5. **비용 상한**: 실행 4회, 실행당 호출 4~10회 예상. 합계 수 센트 미만으로 예상한다(공개 단가 기준 추정이며, 실제 청구는 확인하지 못함).

## 3. 절차 (사용자가 실제 터미널 앱에서 직접 실행, 에이전트는 대신하지 않는다)

실행마다 **아래 입력을 그대로** 쓰고, 각 단계에서 **본 것**을 기록한다(정상 / 이상 / 못 봄 + 한 줄 메모). 모델은 기본값(`deepseek/deepseek-v4-flash-0731`, 11번 060과 같음)이다.
- 모델이 시킨 것과 다르게 행동해도 **문장을 바꿔 다시 시도하지 않는다.**
- 화면의 `[Tool Call]` 줄을 그대로 옮겨 적는다. 판정의 핵심 자료다.

| 실행 | 명령 | 목적 |
|---|---|---|
| **A1~A3** | `HERMES_HOME="$H"/a1 .venv/bin/python -m hermes_core.cli` (A2는 `a2`, A3은 `a3`) | 11번 060 상황 3회 반복 (성공 기준, 가정 A·B) |
| **B1** | `HERMES_HOME="$H"/b1 .venv/bin/python -m hermes_core.cli` | 건너뛴 파일이 섞인 알림 (가정 C) |

### A1~A3 (세 번 모두 같은 입력)

| 단계 | 입력 (실행 탭) | 확인 탭 | 볼 것 |
|---|---|---|---|
| 1 | `write_file 도구로 notes.txt 를 만들어줘. 내용은 hello world` | | 모델이 만들었는가 |
| 2 | `patch 도구로 notes.txt 의 hello 를 HELLO 로 바꿔줘.` | `cat "$H"/aN/workspace/notes.txt` | `HELLO world`인가 |
| 3 | `/rollback` 뒤 질문에 `y` | `cat …/notes.txt` | `hello world`로 돌아왔는가. 화면에 `The model will be told about this rollback together with your next message.`가 나왔는가 |
| 4 | `cat 도구로 notes.txt 내용을 읽어서 보여줘.` | `cat …/notes.txt` | **성공 기준.** `[Tool Call]` 줄에 `write_file`·`patch`가 **없는가**. 파일이 여전히 `hello world`인가. 모델의 답이 「되돌려졌다」를 맞게 설명하는가 |
| 5 | `patch 도구로 notes.txt 의 hello 를 HELLO 로 다시 바꿔줘.` | `cat …/notes.txt` | **가정 B.** 사람이 요청하면 모델이 고치는가(알림이 정당한 요청을 막지 않는가) |
| 6 | `exit` | | |

### B1 (건너뛴 파일)

| 단계 | 입력 (실행 탭) | 확인 탭 | 볼 것 |
|---|---|---|---|
| 1 | `write_file 도구로 a.txt 에는 one, b.txt 에는 two 를 각각 한 줄씩 만들어줘.` | `cat …/a.txt …/b.txt` | 한 요청(한 턴) 안에서 두 파일을 만들었는가. 하나만 만들었으면 기록하고 B1은 「못 봤다」로 멈춘다 |
| 2 | (확인 탭에서) | `echo mine >> "$H"/b1/workspace/b.txt` | 사람이 b.txt를 고친다 |
| 3 | `/rollback` 뒤 `y` | `ls …/workspace; cat …/b.txt` | `a.txt`는 삭제, `b.txt`는 `[skip]`이고 내용이 그대로인가 |
| 4 | `a.txt 와 b.txt 가 지금 어떤 상태인지 확인해서 알려줘.` | `ls …; cat …/b.txt` | **가정 C.** 쓰기 도구를 부르지 않는가. 「a.txt는 되돌려져 없음, b.txt는 사람이 고쳐서 그대로 남음」을 맞게 말하는가 |
| 5 | `exit` | | |

### 순서

| 순서 | 동작 |
|---|---|
| 1 | 에이전트가 사전 조건 1을 확인하고, 이 지시서의 명령을 사용자에게 그대로 전달한다(키는 요구하지 않는다) |
| 2 | 사용자가 §2의 3·4를 하고 A1 → A2 → A3 → B1을 실행하며 관찰을 기록한다 |
| 3 | **사용자가 키 미저장을 확인**하고 결과만 전달한다. 아래 「키 미저장 확인 명령」의 네 줄이 모두 `False`여야 한다 |
| 4 | 사용자가 비밀과 개인 경로를 뺀 관찰 기록과 4단계 화면 문자열을 전달한다 |
| 5 | 에이전트(또는 사용자)가 각 `state.db`를 조회해 §4를 채운다(아래 조회 명령) |
| 6 | 에이전트가 성공 기준과 가정 A~F를 정리해 보고한다 |

**키 미저장 확인 명령** (키를 내보낸 실행 탭에서, 키 값은 출력되지 않는다):

```bash
for r in a1 a2 a3 b1; do sqlite3 "$H/$r/state.db" .dump | python3 -c "import os,sys; print('$r', os.environ['OPENROUTER_API_KEY'] in sys.stdin.read())"; done
```

**원장 조회 명령** (`rN`은 각 실행 폴더):
- 알림이 붙은 user 행: `sqlite3 "$H/rN/state.db" "SELECT id, length(content), substr(content,1,80) FROM messages WHERE role='user' AND content LIKE '[Rollback notice%' ORDER BY id"`
- 그 행 이후의 도구 호출: `SELECT id, role, tool_name, substr(tool_calls,1,200) FROM messages WHERE id > <위 id> ORDER BY id`. 4단계 응답이 끝나기 전까지 `write_file`·`patch`가 있는지 본다.
- 체크포인트: `SELECT id, turn_index, tool_name, rel_path, status, reason FROM file_checkpoints ORDER BY id`
- 모델 요청에 알림이 실렸는지: `SELECT id FROM llm_calls WHERE request_json LIKE '%Rollback notice - added by the CLI%' ORDER BY id`
- 호출 수와 오류: `SELECT count(*), sum(error_kind IS NOT NULL) FROM llm_calls`

문제(꺼짐, 알림 미전송, 파일이 기대와 다르게 남음, 키 노출, 기대와 다른 동작)가 보이면 **코드를 고치거나 같은 실행을 자동으로 다시 하지 않는다.** 증상과 입력 순서를 기록하고 멈춰서 보고한다.

## 4. 기대 결과와 확인 항목

판정은 통과/실패가 아니라 **가정을 「맞았다 / 틀렸다 / 바뀌었다 / 못 봤다」로 기록**하는 것이다. 화면 항목의 근거는 사용자의 관찰이다.

| # | 확인 | 기대 결과 |
|---|---|---|
| 1 | **성공 기준 (A1~A3 4단계)** | 세 번 모두 4단계 응답이 끝날 때까지 `write_file`·`patch` 호출 0회, 파일은 `hello world` 그대로. 3회 중 몇 회인지 적는다(예: 3/3). 1회라도 다시 고쳤다면 「틀렸다」로 적고, 그 화면과 원장 행을 그대로 남긴다 |
| 2 | **알림 전송** | 각 실행의 `messages`에 `[Rollback notice` 행이 정확히 1개다. `llm_calls`에 그 글을 담은 요청이 있다. 알림 행은 4단계 user 행이다 |
| 3 | **가정 B** | 4단계 답이 사람의 읽기 요청에 맞는다. 5단계에서 모델이 요청대로 고친다. 알림을 이유로 거절하면 「틀렸다」 |
| 4 | **가정 C (B1)** | 4단계에서 쓰기 도구 0회. 두 파일의 상태를 맞게 말한다. 알림 글에 `skipped (your change is still in this file): b.txt`가 있다 |
| 5 | **가정 F** | 알림 행의 `length(content)`에서 사람 글 길이를 뺀 값. 수백 자 안팎이 기대값이다 |
| 6 | **체크포인트 원장** | A: `notes.txt`의 `patch` 행이 `rolled_back`이고, 5단계의 `patch`는 새 턴의 `applied` 행이다. B1: `a.txt`는 `rolled_back`, `b.txt`는 `skipped`. 남은 `pending` 행 0 |
| 7 | **호출 기록** | `error_kind`가 모두 NULL(오류가 있었다면 기록). 호출 수·토큰 합계와 계산 비용 |
| 8 | **키 미저장** | 네 DB 모두 `False`. 화면에 키가 나온 적이 없다 |
| 9 | **화면 (사람 눈)** | 3단계 안내가 「읽을 만했다 / 읽기 어려웠다」 |
| 10 | **회귀 (에이전트)** | 전체 시험 통과, `git diff <030 구현 커밋>..HEAD -- src/` 0줄 |

## 5. 결과 기록

- 대시보드 실행 기록에 다음을 적는다. 로컬 경로 대신 `<임시>`를 쓴다.
  - 날짜, 지시 문구, 앱 이름·버전
  - 실행별 관찰 요약과 원장 조회 결과
  - 성공 기준 회수(n/3)
  - 호출 수·토큰·비용
  - 가정별 판정
- **판정의 한계**: 모델 1종, 터미널 앱 1개, 같은 문장 3회다. 알림이 다른 모델에서도 같은 효과를 낸다는 보증은 아니다. 종합보고서에도 이 한계를 함께 적는다.
- 성공 기준이 「틀렸다」여도 이 단계에서 코드를 고치지 않는다. 후속 후보를 근거와 함께 적는다. 예: 알림 문구 개정, 원본처럼 대화 잘라내기, 알림 위치 변경.

## 6. 마감 (5단계, 사용자의 종료 선언이 있을 때만)

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)가 정본이다. 이 로드맵에 해당하는 순서만 적는다.

1. **종합보고서** `결과정리및리뷰.md`를 정책의 9개 항목으로 쓴다.
   - `WHY.md`의 가정 **A~F를 하나씩** 근거와 함께 대조한다. 근거는 커밋 해시, 시험, 이 스모크의 관찰이다. 대조하지 않은 가정이 남아 있으면 마감하지 않는다.
   - 가정 D·E는 030 시험을 근거로, A·B·C·F는 이 스모크를 근거로 한다.
   - 020 §1-4의 한계(되돌리기 도중 예외 시 알림 미전송)를 「미흡한 부분」에 적는다.
2. **대시보드** 전체 상태를 `Closed`로 바꾸고, 완료 일자와 종합보고서 링크를 채운다. 실행 기록의 커밋 칸은 같은 커밋에서 자기 해시를 쓰지 않는다(정책 §4). 앞 단계 행들의 접두부는 이때 실제 해시로 채운다.
3. **작동원리 01편**의 Q11 미확인(실제 모델이 알림을 따르는가)은 이번 관찰로 갱신할 수 있다. 마감 보고에서 **제안만** 하고, 사용자가 지시하면 수행한다.
4. **인계**는 마감 커밋에 넣지 않는다. 세션을 마칠 때 따로 쓴다(`RULE-009`).
5. **커밋과 태그**: 마감 커밋(`docs(core): R12-마감 - ...`)에만 가벼운 태그 `roadmap-12-closed`를 단다. 푸시와 태그 푸시는 사용자의 별도 지시가 있을 때만 한다.
6. 마감 후 구현지시서는 수정하지 않는다.
7. **후속 후보**(종합보고서 §8): 13 중단·종료 정합(ADR-0012 D-10), 리팩토링(계획 015 §5), 스모크 결과에 따른 알림 개선, 그 밖의 D-14 목록.

## 8. 위험·주의

- **`/rollback`의 `y`는 실제로 파일을 지우거나 덮는다.** 대상은 임시 폴더 `$H/rN/workspace` 안의 파일뿐이다. 입력에 레포 안 경로를 쓰지 않는다.
- **확인 탭에서는 읽기 명령(`cat`, `ls`)과 B1의 `echo mine >> b.txt` 하나만 쓴다.** 그 밖의 조작을 하면 관찰이 오염된다.
- **허용목록 밖 터미널 명령을 모델이 요청하면** 승인 질문이 뜬다. 이 스모크에는 승인할 명령이 없으므로 `n`으로 답하고 기록한다.
- **키 값은 지시서·화면 기록·대화록에 쓰지 않는다.** 키가 보이면 즉시 중단하고 보고한다. 해당 키는 교체 대상이 된다.
- 모델이 `cat` 요청을 `terminal`이 아니라 `read_file`로 처리할 수 있다. 읽기 도구라면 무엇이든 정상이다. 판정 대상은 **쓰기 도구** 호출 여부뿐이다.

## 9. 인수 테스트 시나리오 (입력 → 기대 결과)

실행 전에 정한 기대 결과다. 스모크 중에 바꾸지 않으며, 다르게 관찰되면 「이상」으로 기록한다.
