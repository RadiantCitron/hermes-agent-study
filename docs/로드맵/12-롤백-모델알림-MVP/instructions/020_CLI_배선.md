## 1. 구현 내용 명세

`/rollback`이 실행한 결과를 CLI가 모아 둔다. 사람이 **모델에게 넘어가는 다음 메시지**를 보낼 때 010의 `format_rollback_notice`로 알림 글을 만들어 그 메시지 앞에 붙이고, 모아 둔 것을 비운다. `/rollback`은 계속 모델을 부르지 않는다.

### 1-1. `_handle_rollback`이 결과를 돌려준다 ([`cli.py`](../../../../src/hermes_core/cli.py))

- 반환형을 `None`에서 `Optional[RollbackResult]`로 바꾼다.
- `checkpointer.execute_rollback(plan)`이 정상적으로 끝났을 때만 그 `RollbackResult`를 돌려준다. 되돌린 개수가 0이어도 돌려준다. 알림을 만들지 말지는 010 함수가 정한다.
- 아래 경우는 모두 `None`을 돌려준다: 체크포인트 꺼짐, 인자 오류, 되돌릴 것 없음, 질문에서 취소·Ctrl+C·Ctrl+D, 예외(`CLI_ROLLBACK_ERROR_NOTICE` 경로).
- 화면 출력은 그대로다. 안내 문구 하나만 1-3대로 바꾼다.

### 1-2. 메인 루프 ([`cli.py`](../../../../src/hermes_core/cli.py) `main`)

- 루프 시작 전에 `pending_rollbacks: list[RollbackResult] = []`를 둔다.
- `/rollback` 분기: `result = _handle_rollback(...)`. `None`이 아니면 `pending_rollbacks`에 넣고 `continue`한다(D-06).
- **붙이는 자리**: 빈 줄, `exit`/`quit`, `/rollback` 판정을 모두 지나 **모델에게 넘기기 직전**이다. 즉 `begin_turn()` 뒤, `run_conversation` 앞이다.
  ```python
  notice = format_rollback_notice(pending_rollbacks)
  pending_rollbacks.clear()
  message = f"{notice}\n\n{user_input}" if notice else user_input
  # run_conversation(message, ...)
  ```
  - 비우기는 `run_conversation` **호출 전에** 한다. 호출이 실패하거나 중단돼도 같은 알림을 두 번 보내지 않는다(위험 4).
  - `exit` 판정은 붙이기 **전에**, 사람이 친 글(`user_input`)로 한다(위험 5).
- `exit`/`quit`, Ctrl+C·Ctrl+D 종료 때 남은 `pending_rollbacks`는 그냥 버린다(D-06). 되돌린 사실은 원장 `file_checkpoints`의 `rolled_back` 행에 남는다.
- 알림은 사람 메시지의 일부로 `run_conversation`에 넘어간다. 따라서 원장 `messages`의 user 행과 모델 요청에 같은 글이 들어간다(D-03). `agent.py`·`session_db.py`는 손대지 않는다.

### 1-3. 화면 안내 교체 ([`constants.py`](../../../../src/hermes_core/constants.py))

- 상수 이름 `CLI_ROLLBACK_MODEL_UNAWARE_NOTICE`를 `CLI_ROLLBACK_MODEL_WILL_BE_TOLD_NOTICE`로 바꾼다. 값은 `"The model will be told about this rollback together with your next message."`로 바꾼다(D-08). 옛 이름이 뜻과 달라지므로 이름도 바꾼다.
- 출력 조건은 지금과 같다(`result.rolled_back_count >= 1`). 그래서 이 안내가 나오는 경우와 010이 알림을 만드는 경우가 일치한다.

### 1-4. 알려진 한계 (이 단계에서 고치지 않음)

`execute_rollback` 도중 예외가 나면 일부 파일은 이미 복원됐을 수 있다. 그런데 결과 객체가 없으므로 알림은 가지 않는다. 화면에는 지금처럼 `CLI_ROLLBACK_ERROR_NOTICE`(「일부 파일이 이미 복원됐을 수 있다」)가 나온다. 드문 경로라 이번에는 기록만 하고, 마감 보고의 「미흡한 부분」에 적는다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 파일: `tests/test_hermes_core/test_cli_rollback.py`. 기존 픽스처를 그대로 쓴다: `cli_test_env`, `ScriptableClient`(모델이 받은 메시지를 `call_history`에 남김), `ScriptableInput`, `make_write_file_response`·`make_patch_response`. 015가 이 파일에 시험을 더하므로 번호가 겹치지 않도록 함수 이름은 `test_rollback_notice_NN_…`로 짓는다.

**사전 준비(공통)**: 첫 메시지 `go`에서 모델이 `new.txt`를 `write_file`로 만들고 끝난다. 이어서 `/rollback`에 `y`로 답한다. 알림 본문은 010 형식이다. 아래에서 「알림이 붙었다」는 것은 모델이 받은 마지막 user 메시지가 `[Rollback notice - added by the CLI, not typed by the user]`로 시작하고 `\n\n<사람 글>`로 끝난다는 뜻이다. 기대값은 실제 글자로 단언한다.

| # | 입력 (사람 입력 순서) | 기대 결과 |
|---|---|---|
| 1 | `go` → `/rollback`(y) → `read it` → `exit` | `read it`에 대한 첫 모델 호출의 마지막 user 메시지에 알림이 붙어 있고, `  deleted: new.txt` 줄을 포함하며, `\n\nread it`으로 끝난다 (D-01) |
| 2 | 1과 같음 | 원장 `messages`의 해당 user 행 `content`가 모델이 받은 글과 **글자 그대로 같다** (D-03) |
| 3 | `go` → `/rollback`(y) → `read it` → `again` → `exit` | `again` 호출의 마지막 user 메시지가 정확히 `again`이다(알림은 한 번만) |
| 4 | `go` → `/rollback`(n) → `read it` → `exit` | `read it`의 마지막 user 메시지가 정확히 `read it`이다(취소) |
| 5 | `/rollback`(되돌릴 것 없음) → `hello` → `exit` | `hello`의 마지막 user 메시지가 정확히 `hello`이다 |
| 6 | `go` → 사람이 `new.txt`를 직접 고침 → `/rollback`(y, 전부 건너뜀) → `read it` → `exit` | `read it`이 그대로 가고 알림이 없다. 화면에 `The model will be told about this rollback together with your next message.`가 없다 (D-05) |
| 7 | `go`(턴 1, `a.txt` 만들기) → `go2`(턴 2, `b.txt` 만들기) → `/rollback`(y) → `/rollback`(y) → `read it` → `exit` | 알림이 **한 번** 붙고, `Turn 2:`가 `Turn 1:`보다 앞에 있다 (D-06) |
| 8 | `go` → `/rollback`(y) → `exit` | `exit`으로 정상 종료한다(`user_exit`). 되돌린 뒤 모델 호출 횟수가 늘지 않는다. `file_checkpoints` 행은 `rolled_back` (D-06, 위험 5) |
| 9 | `go` → `/rollback`(y) → (빈 줄) → `/rollback`(되돌릴 것 없음) → `read it` → `exit` | 알림이 `read it`에만 한 번 붙는다(빈 줄과 「없음」은 알림을 소비하지 않는다) |
| 10 | 1과 같음 | 화면에 `The model will be told about this rollback together with your next message.`가 1번 나오고 `The model does not know about this rollback`은 없다 (D-08) |
| 11 | `--no-checkpoints`로 `/rollback` → `hello` → `exit` | `hello`가 그대로 간다 |
| 12 | `go` → `/rollback`(y) → 모델 호출이 `LLMError`로 실패하는 `read it` → `again` → `exit` | `read it` 요청에는 알림이 붙었다. `again` 요청의 마지막 user 메시지는 정확히 `again`이다(실패해도 두 번 보내지 않음, 위험 4) |
