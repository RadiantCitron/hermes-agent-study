## 1. 마감 개요

- **목표 달성**: `/rollback`이 파일을 1개 이상 되돌렸을 때, 그 사실(턴 번호, 복원·삭제·건너뛴 경로, 다시 적용 금지 지침)을 사람이 보내는 다음 메시지 앞에 고정 형식으로 결합하여 모델에게 알리고 원장(`messages`, `llm_calls.request_json`)에 일치되게 영구 보존하는 롤백 컨텍스트 동기화 MVP 구축 완료.
- **핵심 설계 및 원칙**:
  1. **다음 사람 메시지 앞 알림 주입 (Inject-Before-Next-User-Message)**:
     - `/rollback` 자체는 모델을 부르지 않는 순수 CLI 상호작용을 유지(ADR-0012 D-02).
     - 모델에게 메시지를 전달하기 직전(`begin_turn()` 뒤, `run_conversation()` 앞)에 알림을 결합(D-01).
     - 모델 호출 직전에 대기열을 즉시 비움으로써 실패 시 중복 발송을 방지(위험 4 방지).
  2. **원장 일치 원칙 (CQRS/Zero Hidden State)**:
     - 대화 기록을 임의로 잘라내거나 가짜 시스템 메시지를 만들지 않고, 실제 모델이 전송받은 알림이 포함된 사용자 메시지 그대로 SQLite 원장(`messages` 및 `llm_calls.request_json`)에 남김(D-03).
  3. **압축 표지 비간섭 및 위조 방지**:
     - 알림 표지(`[Rollback notice - ...]` / `[End of rollback notice]`)가 압축 요약 표지(`[대화 요약:`, `[대화 요약 끝]`)와 겹치지 않도록 설계(D-07).
     - 경로 및 건너뜀 사유 내 제어 문자(`\n`, ANSI escape 등)를 `_escape_control`로 이스케이프하여 표지 줄 위조를 원천 차단.
  4. **성공 기준 실증 달성 (Self-Healing Trap 무력화)**:
     - 11번 060에서 모델이 롤백 사실을 몰라 자발적으로 옛 변경을 재적용하던 자가 치유 함정(Self-Healing Trap)을, 알림 주입을 통해 완벽히 무력화(A1 스모크에서 읽기 요청 시 파일 쓰기 도구 호출 0회 달성).

## 3. 단계별 상세 (Why 중심)

### 010: 알림 글 만들기 (`format_rollback_notice` 순수 함수, `ROLLBACK_NOTICE_*` 상수)
- **무엇을**:
  - `src/hermes_core/constants.py`에 모델용 영어 안내 문구 및 표지 상수 10종 정의 (`ROLLBACK_NOTICE_*`, `ROLLBACK_NOTICE_MAX_PATHS = 20`).
  - `src/hermes_core/tools/checkpoint.py`에 `format_rollback_notice(results)` 순수 함수 및 `_escape_control` 함수 구현.
- **왜**:
  - 알림 조립 로직을 DB나 CLI 화면, I/O 부수 효과로부터 철저히 분리하여 100% 결정론적인 순수 함수로 검증하기 위함입니다.
  - 표지 위조 공격을 방지하기 위해 개행 및 제어 문자를 이스케이프하고, 같은 턴 내 동일 파일 변경의 중복을 제거하며, 과도한 토큰 소모를 막기 위해 경로 상한(20개)을 두었습니다.
- **결과**: 신규 17개 인수 테스트 전건 통과, 전체 793건 회귀 테스트 100% 통과 (커밋 `bd8502c`).

### 020: CLI 배선 (`pending_rollbacks`, 다음 메시지 결합, 화면 안내 교체)
- **무엇을**:
  - `cli._handle_rollback` 반환형을 `Optional[RollbackResult]`로 변경.
  - `cli.main` 루프에 `pending_rollbacks: list[RollbackResult]`를 두고 롤백 성공 결과를 누적(D-06).
  - 사람이 `exit`/`quit` 입력 시 모델 호출 없이 보류 알림을 안전 폐기.
  - 모델 호출 직전(`begin_turn()` 뒤)에 알림을 `f"{notice}\n\n{user_input}"`으로 조립하고 **호출 전 리스트를 비움**(호출 실패 시 재전송 방지).
  - 화면 안내 상수를 `CLI_ROLLBACK_MODEL_WILL_BE_TOLD_NOTICE`로 교체.
- **왜**:
  - 모델을 직접 부르지 않는 원칙을 사수하면서 사람이 다음에 보낼 질문과 함께 자연스럽게 컨텍스트를 동기화하기 위함입니다.
  - `run_conversation` 호출 전에 리스트를 비워 네트워크/모델 에러 발생 시 알림이 영구 누적되어 중복 전송되는 위험을 원천 차단했습니다.
- **결과**: 신규 12개 인수 테스트 전건 통과, 기존 시험 참조 5곳 갱신, 전체 805건 회귀 테스트 통과 (커밋 `6af6dc7`).

## 6. 미흡한 부분 및 알려진 한계

1. **세션 간 롤백 미지원**:
   - CLI를 종료(`exit`)하면 세션이 닫히며, 다음 CLI 실행 시에는 이전 세션의 파일 체크포인트를 되돌릴 수 없음 (`Nothing to roll back.` 출력).
2. **종료 시 알림 미전송**:
   - `/rollback` 후 사용자 발화 없이 바로 `exit`으로 세션을 종료하면 모델에게 알림이 전송되지 않음 (원장 `file_checkpoints`에만 `rolled_back`으로 남음).
3. **긴 대화 요약 시 경로 세부 흐려짐**:
   - 대화가 극도로 길어져 알림이 포함된 발화가 압축의 가운데 구간(중간 8칸)에 들어가면 요약문으로 대체되어 구체적인 되돌림 파일 경로 정보가 생략될 수 있음.
4. **롤백 도중 예외 발생 시 알림 미생성**:
   - 복원 도중 디스크 I/O 에러 등으로 예외가 터지면 결과 객체가 생성되지 않아 모델 알림이 가지 않음 (화면 경고만 출력).

## 7. 새로 발견한 부분과 교훈

1. **모델의 리다이렉션 미지원 인지 및 자율 우회 (b1_retry 관찰)**:
   - 사용자가 `terminal 도구로 echo mine >> b.txt 명령을 실행해줘`라고 요청했을 때, 모델은 터미널 도구가 셸 리다이렉션(`>>`)을 지원하지 못함을 스스로 판단하고 자발적으로 `patch` 도구를 호출하여 지시를 완수함. 모델의 프롬프트 및 시스템 제약 해석 능력이 매우 정교함을 확인.
2. **알림의 정확한 인지 및 설명**:
   - 모델은 `[Rollback notice ...]` 블록을 사람의 지시와 혼동하지 않고 시스템 메타데이터로 정확히 해석함.
   - 이후 응답에서 롤백된 사실을 능동적으로 언급하면서도, 사람이 다시 요청했을 때는 알림의 제약을 넘어 정상적으로 변경을 수행하여 이상적인 에이전트 상호작용을 보여줌.

## 8. 후속 인계 사항

- **로드맵 13 후보 (중단·종료 정합)**:
  - 처리 중 `Ctrl+C`, 비정상 종료 시 세션 상태 및 체크포인트 `pending` 행의 정합성 정리.
- **장기 개선 과제**:
  - 세션 종료 후에도 이전 세션의 마지막 턴을 되돌릴 수 있는 세션 간 롤백 체인 지원.
