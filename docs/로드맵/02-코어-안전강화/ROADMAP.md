## 1. 배경 및 목적 (Why)

로드맵 01은 에이전트가 돌아가는 코어를 만들었다. 마감 후 코드를 점검하자 「돌아간다」와 「안전하다」 사이에 공백이 있음이 확인되었다 ([01편 작동원리](../../작동원리/01-헤르메스코어-작동원리.md)의 「지금은 없는 방어선」).

이 로드맵의 목적은 **새 기능을 더하는 것이 아니라, 이미 있는 코어의 약속을 실제로 지키게 하는 것**이다. 대상은 다음 네 가지이며 범위와 방식은 ADR-0002에서 확정되었다.

| 공백 | 지금의 동작 (확인됨) | 이 로드맵 후 |
|---|---|---|
| 터미널 명령 | 모델이 낸 문자열을 셸로 그대로 실행 (시간·출력 제한만 있음) | 셸 없이, 허용된 프로그램만, 작업 폴더 안에서만 |
| 도구 인자 | 설명서를 모델에게 보여 줄 뿐 검증하지 않음 | 호출 전에 설명서 기준으로 검증 |
| 루프 신호 | 인자 읽기 실패는 조용히 빈 인자로, 상한 도달은 빈 응답으로 끝남 | 실패는 모델과 로그에 알리고, 상한 도달은 호출자가 구분 가능 |
| CLI | `--mock` 없이 실행해도 가짜 모델을 조용히 사용 | 안내 후 종료 |

## 4. 사전 점검 및 실패 위험 분석 (Pre-Mortem)

> *"만약 이 로드맵이 실패하거나 불안정해진다면 무엇 때문인가?"*

| 실패 위험 요소 | 잠재 원인 | 선제 방어책 (설계 반영) |
|---|---|---|
| **1. 도구 호출 파라미터 불일치·비정형 출력 파싱 실패** | 인자 검증이 너무 엄격해 정상 호출을 막거나, 스키마가 비어 있는 도구가 깨짐 | 010에서 기존 세 도구의 정상 호출을 회귀로 확인하고, 스키마가 비어 있으면 검증을 건너뜀. 020에서 인자 읽기 실패를 모델에게 돌려줘 스스로 고치게 함 |
| **2. 에이전트 루프 무한 반복·토큰 오버플로우** | 상한(50회) 도달이 구분되지 않아 호출자가 빈 응답을 정상으로 오해 | 020에서 종료 사유를 반환. 상한 값 자체는 바꾸지 않음 |
| **3. 비인가 도구 실행 부작용·샌드박스 오염** | 셸 확장, 허용 프로그램의 위험한 옵션, 상대경로·심볼릭 링크를 이용한 폴더 이탈 | 040에서 셸을 쓰지 않고 첫 토큰을 허용목록과 정확히 비교(경로 불가). 050에서 명령줄의 경로를 실제 경로로 풀어 작업 폴더 안인지 검사(인자로 준 경로의 심볼릭 링크 포함, 값이 붙은 짧은 옵션 `-f/etc/passwd`도 검사). `workspace` 인자 주입은 010의 정의되지 않은 인자 거부로 막고 050 시나리오 18로 고정. 위험한 인터프리터·`find`·`sed`·`awk`·`git`은 목록에서 제외. 한계: `grep -R`이 폴더 안 링크를 스스로 따라가는 것은 막지 못함(050 §1-3에 기록) |
| **4. 허용목록 프로그램이 입력을 기다리며 멈춤** | `cat`을 인자 없이 호출하면 표준입력을 기다림 | 040에서 표준입력을 닫아 실행(`DEVNULL`). 시간 제한은 유지 |
| **5. 보수적 판정으로 정상 사용을 막음** | 경로처럼 보이는 모든 인자를 검사하면 `grep / a.txt`의 패턴 `/`도 거부됨 | 알려진 한계로 050에 명시하고 시험으로 고정. 완화는 후속 로드맵 |
| **6. 문서와 코드의 불일치 재발** | 코드를 고치고 01편을 안 고침 | 각 단계 변경 파일에 01편을 포함하고, 060에서 「지금은 없다」 목록을 최종 대조 |
| **7. 모델이 시간 제한을 스스로 풀어 버림** | `timeout` 인자는 모델이 정하고 스키마에 상한이 없어, 큰 값을 넘기면 30초 제한이 무력화됨 | 040에서 `timeout`을 1~30초로 제한하고 범위 밖은 실행 없이 오류로 알림 (D-08) |

## 5. 4층위 검증 범위 설계 (Validation Grid)

```mermaid
flowchart LR
    L1["1층위: Mock 모델로 자동화"] --> L2["2층위: 단위 검증<br/>(010·020·030·040·050)"]
    L2 --> L3["3층위: 정합성 검증<br/>(도구 메시지와 원장 대응)"]
    L3 --> L4["4층위: 060 통합 E2E"]
```

1. **1층위**: 사람이 프롬프트를 입력하지 않는다. 모든 시나리오는 가짜 모델의 응답 시퀀스와 임시 폴더로 재생한다.
2. **2층위**: 각 지시서의 인수 시나리오를 테스트로 옮긴다. 외부 모델 호출은 없다.
3. **3층위**: 020에서 「모든 도구 요청에 대응하는 도구 메시지가 있다」를 검증한다 (인자 읽기 실패 때도 짝이 깨지지 않음).
4. **4층위**: 060에서 차단된 명령, 잘못된 인자, 정상 명령이 한 대화 안에서 섞여도 루프가 정상 종료함을 확인한다.

## 6. 설계 결정 상세

### 6-1. 터미널 허용목록 (D-03)

초기 목록: `echo`, `pwd`, `ls`, `cat`, `head`, `tail`, `wc`, `grep`

- **포함 기준**: 읽기·출력 중심이고 옵션만으로 다른 프로그램을 실행하거나 파일을 쓰는 기능이 없는 것.
- **제외한 것과 이유**:
  - `python`, `pytest`, `node`, `bash`, `sh`: 임의 코드를 실행하므로 가드가 무력해진다.
  - `find`: `-exec`로 임의 프로그램을 실행한다.
  - `sed`, `awk`: 스크립트 안에서 명령 실행·파일 쓰기가 가능하다.
  - `git`: 하위 명령과 설정 옵션으로 외부 프로그램을 부를 수 있어 하위 명령 단위 정책이 필요하다. 후속 로드맵 과제.
  - `rm`, `mv`, `cp`, `touch`, `mkdir` 등 쓰기 명령: 파일 변경 도구와 함께 후속 로드맵에서 다룬다.
- 허용목록은 상수 하나(`ALLOWED_COMMANDS`)로 모아 한 곳에서 보이게 한다.

### 6-2. 인자 검증 규칙 (D-04)

스키마(`function.parameters`)가 있을 때 아래를 검사한다. 위반이면 도구를 호출하지 않고 `{"success": false, "error": ...}`를 반환한다.

1. `required`에 있는 인자가 모두 있는가
2. 정의되지 않은 인자가 없는가 (`properties`에 없는 키)
3. 타입이 맞는가 (`string`, `integer`, `number`, `boolean`, `array`, `object`; `integer`와 `number`에는 `bool`을 허용하지 않는다)
4. `enum`이 있으면 값이 그 안에 있는가

알 수 없는 타입 이름은 타입 검사를 건너뛴다. 스키마가 없거나 비어 있으면 검증하지 않는다 (기존 호환).

### 6-3. 종료 사유 (D-05)

`run_conversation`의 반환 사전에 `stopped_reason`을 추가한다.
- `completed`: 도구 요청 없는 텍스트 응답으로 끝남
- `max_iterations`: 상한에 도달해 끝남 (이때 경고 로그를 남김)

기존 키(`final_response`, `messages`, `iterations`, `session_id`)는 이름과 의미를 바꾸지 않는다.

### 6-4. 인자 읽기 실패 처리 (020)

- JSON으로 읽지 못하거나 읽은 결과가 사전이 아니면, 도구를 호출하지 않고 실패 도구 메시지를 모델에게 돌려주고 경고 로그를 남긴다.
- 빈 문자열(공백 포함)과 `None`(`arguments: null`)은 「인자 없음」(`{}`)으로 본다. 인자 없는 도구를 빈 문자열이나 `null`로 부르는 공급자가 있기 때문이다 (D-09).

### 6-5. 터미널 `timeout` 범위 (D-08)

- `timeout`은 1 이상 30 이하의 정수만 허용한다 (상수 `TERMINAL_MAX_TIMEOUT = 30`). 기본값 30은 그대로다.
- 범위 밖이면 값을 조용히 깎지 않고 실행 없이 오류로 돌려준다. 모델이 자신의 요청이 무시된 것을 모른 채 넘어가지 않게 하기 위함이다.
- 더 긴 실행이 필요해지면 상한 상수를 올리는 별도 결정(ADR 또는 결정 표)으로 다룬다.

## 7. 문서 동기화 방식 (D-07)

[작동원리 README의 갱신 규칙](../../작동원리/README.md)에 따라 코드 변경과 같은 작업에서 01편을 고친다.

- 각 단계 커밋에서 01편의 **해당 서술**(Q&A, 방어선, 대조표, ③ 검증표, 「지금은 없는 방어선」)을 고친다.
- `기준 커밋`은 설명 대상 `src/`·`tests/`를 마지막으로 바꾼 커밋인데, 그 커밋 자신의 해시를 같은 커밋에 쓸 수 없다. 그래서 단계 커밋에서는 이전 값을 두고, **다음 커밋(다음 단계 또는 마감 커밋)에서 실제 해시로 채운다.** 대시보드 커밋 칸과 같은 방식이다.
- 마지막 단계(060)가 끝난 뒤의 `기준 커밋` 갱신은 마감(5단계) 커밋에서 한다.

## 8. 이 로드맵이 다루지 않는 것 (Non-Goals)

- 파일 읽기·쓰기·수정 도구 (이후 로드맵)
- `git`을 포함한 허용목록 확장, 쓰기 명령 허용
- 실제 LLM 클라이언트 연결
- 터미널 프로세스의 환경변수 정리, 자원(메모리·프로세스 수) 제한
- OS 수준 격리
