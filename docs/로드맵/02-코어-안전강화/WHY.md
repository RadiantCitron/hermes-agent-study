# [WHY] 02-코어-안전강화 — 왜 이 로드맵을, 왜 이 정도로만 하는가

> **성격**: 이 로드맵의 의도를 적은 문서다 ([ROADMAP_정책 §3-2](../ROADMAP_정책.md)).  
> **사후 작성 (2026-10-29)**: 02번은 `WHY.md`를 두는 규칙이 생기기 전에 마감되었다. 이 문서는 마감 후에 [ADR-0002](../../adr/0002-코어_안전_강화_범위와_터미널_가드_방식.md), [ROADMAP.md](ROADMAP.md), [대시보드](README.md), [결과정리및리뷰.md](결과정리및리뷰.md)에 **이미 적혀 있는 내용만** 모아 재구성했다. 착수 전에 쓴 의도의 원본이 아니며, 당시 기록에 없는 가정이나 판정은 새로 만들지 않았다.

---

## 1. 왜 지금 이 로드맵인가

01번으로 에이전트는 돌아갔고 시험도 통과했다. 그런데 마감 후 코드를 직접 점검하자 **「돌아간다」와 「안전하다」 사이에 이름만 있고 연결되지 않은 곳이 네 군데** 있었다 ([ADR-0002 §1](../../adr/0002-코어_안전_강화_범위와_터미널_가드_방식.md), 기준 커밋 `6884617`).

| 공백 | 그때의 동작 |
|---|---|
| 터미널 명령 | 모델이 낸 문장을 셸에 그대로 넘긴다. 시간(30초)과 출력(10,000자) 제한만 있다 |
| 도구 인자 | 도구의 「설명서」를 모델에게 보여 줄 뿐 검사하지 않는다 |
| 루프 신호 | 인자를 읽지 못하면 조용히 빈 인자로 진행하고, 반복 상한(50회)에 닿아도 호출자가 알 수 없다 |
| 명령줄 화면 | `--mock` 없이 실행해도 가짜 모델을 조용히 쓴다 |

시스템을 맡은 사람은 「모델이 엉뚱한 명령을 내면 그냥 실행되나?」「50번 돌다 멈췄는데 정상 종료인가?」 같은 질문을 하게 되는데, 네 질문의 답이 모두 「막는 장치가 없다」였다 ([결과문서 §2](결과정리및리뷰.md)). 이 상태에서 파일을 쓰는 도구까지 얹으면 위험이 커지므로, 기반의 약속부터 실제로 지키게 만든다. **새 기능을 더하는 로드맵이 아니라, 이미 있는 코어의 약속을 지키게 하는 로드맵이다** ([ROADMAP.md §1](ROADMAP.md)).

## 2. 왜 이 정도로만 하는가

[ROADMAP.md §8](ROADMAP.md)의 범위 밖 목록과 [ADR-0002](../../adr/0002-코어_안전_강화_범위와_터미널_가드_방식.md)에 적힌 이유다.

| 하지 않는 것 | 이유 (기록에 있는 것) | 이후 |
|---|---|---|
| 파일 읽기·쓰기·수정 도구 | 02의 가드 위에 얹는 순서가 자연스럽고, 한 로드맵에 합치면 범위가 커져 한 번에 한 단계 원칙으로 추적하기 어렵다 (ADR-0002 대안 C) | [03](../03-파일도구-추가/WHY.md) |
| `git`을 포함한 허용목록 확장, 쓰기 명령 허용 | `git`은 하위 명령과 설정 옵션으로 외부 프로그램을 부를 수 있어 하위 명령 단위의 정책이 필요하다 ([ROADMAP.md §6-1](ROADMAP.md)). 쓰기 명령은 파일 도구와 함께 다룬다 | 기록상 후속 과제(시기 미기재) |
| 실제 모델 연결 | 02는 안전 공백을 메우는 일이다 | [04](../04-실제모델-연결-MVP/WHY.md) |
| 터미널 프로세스의 환경변수 정리, 자원(메모리·프로세스 수) 제한 | 범위 밖으로 명시 | 기록 없음 |
| 운영체제 수준의 격리(컨테이너 등) | 가장 강하지만 OS에 의존해 순수 파이썬 코어 원칙과 맞지 않는다 (ADR-0002 대안 B) | 필요해지면 후속 ADR |

## 3. 왜 이 순서, 왜 이 단계 수인가

여섯 단계다 ([대시보드 §2](README.md)).

| 순서 | 단계 | 대응하는 공백 |
|---|---|---|
| 010 | 도구 인자 사전 검증 | 도구 인자 |
| 020 | 에이전트 루프 신호 개선 | 루프 신호 |
| 030 | CLI 가짜 모델 오표시 수정 | 명령줄 화면 |
| 040 | 터미널 허용목록 가드 (셸 미사용) | 터미널 명령 |
| 050 | 터미널 작업 폴더 경로 제한 | 터미널 명령 |
| 060 | 통합 E2E 검증, 문서 동기화 | 전체 |

- 네 공백 중 터미널이 가장 크기 때문에 두 단계(허용목록, 경로 제한)로 나눴다. 나머지는 공백 하나에 한 단계다.
- **이 순서를 정한 이유가 기록에 명시되어 있지는 않다**(미확인). 터미널 가드(040·050)가 인자 검증(010)이 만든 「정의되지 않은 인자 거부」에 기대는 부분이 있다는 점은 ROADMAP에서 확인된다(`workspace` 주입 방어, [ROADMAP.md §4](ROADMAP.md) 위험 3). 다만 그것이 순서의 이유였는지는 기록에 없다.

## 4. 왜 이 방식을 택하고 무엇을 배척했나

([ADR-0002 §2·§3](../../adr/0002-코어_안전_강화_범위와_터미널_가드_방식.md), [ROADMAP.md §6](ROADMAP.md), [결과문서 §6](결과정리및리뷰.md))

| 선택 | 배척한 대안 | 이유 |
|---|---|---|
| 허용된 프로그램만 실행하고 셸을 쓰지 않음 | 셸을 두고 위험한 패턴만 막는 차단목록 | 셸을 거치면 파이프·치환·인용으로 우회할 수 있어 막지 못한 명령이 남는다. 허용목록은 「허용한 것만 실행된다」를 코드와 시험으로 증명할 수 있다 |
| 코드로 증명되는 가드 | 운영체제 수준 격리 | OS 의존. 필요해지면 후속 ADR |
| 허용목록은 읽기·출력 위주 8개(`echo`, `pwd`, `ls`, `cat`, `head`, `tail`, `wc`, `grep`) | `python`, `find`, `sed`, `awk`, `git` 등 편의를 위한 포함 | 하나만 들어와도 임의 실행이 가능해져 가드 전체가 무력해진다 |
| 범위를 벗어난 `timeout`은 오류로 알림 | 조용히 30초로 깎기 | 모델이 자기 요청이 무시된 것을 모른 채 진행하게 된다 |
| 인자를 읽지 못하면 모델에게 실패로 알림 | 빈 인자로 계속 진행 | 도구가 엉뚱한 기본값으로 실행되고 원인이 남지 않는다 |
| 시험표를 구현 전에 요구사항에서 먼저 적음 | 구현자가 코드에서 시험을 도출 | 동어반복 시험 방지 |

**득과 실**: 득은 허용한 것만 실행된다는 증명이고, 실은 모델이 쓸 수 있는 명령이 8개로 줄고 보수적 경로 판정으로 정상 명령이 가끔 거부된다는 점이다 ([결과문서 §6](결과정리및리뷰.md)).

## 5. 성공 판단 기준과 당시의 위험 가정

02에는 `WHY.md의 가정 목록`이 없었다. 아래는 [ROADMAP.md §1·§4](ROADMAP.md)의 목표와 사전 점검(Pre-Mortem)을 옮긴 것이다. **이 문서에서 새로 판정하지 않으며**, 결과는 [결과문서](결과정리및리뷰.md)를 따른다.

**성공 기준 (ROADMAP §1·§3)**: 네 공백이 각각 닫힌다 — 터미널은 셸 없이 허용 프로그램만 작업 폴더에서, 인자는 호출 전에 검증, 상한 도달은 종료 사유로 구분, CLI는 안내 후 종료. 기존 테스트 19개는 그대로 통과한다.

| 번호 | 당시의 위험 가정 (ROADMAP §4) | 당시 방어책 |
|---|---|---|
| R1 | 인자 검증이 너무 엄격해 정상 호출을 막지 않는다 | 기존 세 도구의 정상 호출을 회귀로 확인, 설명서가 비어 있으면 검증 생략 |
| R2 | 반복 상한 도달을 호출자가 구분할 수 있다 | 종료 사유 반환 |
| R3 | 셸 확장, 허용 프로그램의 위험한 옵션, 상대경로·링크로 작업 폴더를 벗어날 수 없다 | 셸 미사용, 첫 토큰 정확 비교, 명령줄 경로를 실제 경로로 풀어 검사 |
| R4 | 허용 프로그램이 입력을 기다리며 멈추지 않는다 | 표준입력을 닫고 실행, 시간 제한 유지 |
| R5 | 보수적 판정이 정상 사용을 막는 정도가 받아들일 만하다 | 알려진 한계로 명시하고 시험으로 고정 |
| R6 | 코드를 고치고 문서를 안 고치는 일이 재발하지 않는다 | 각 단계 변경 파일에 01편 포함, 060에서 최종 대조 |
| R7 | 모델이 시간 제한을 스스로 풀지 못한다 | `timeout`을 1~30초로 제한 |

결과문서는 마감 시점에 코어 시험 87개 통과를 적는다 ([결과문서 §12](결과정리및리뷰.md)).

## 6. 알려진 위험과 아직 확인하지 못한 것

기록된 한계와 「미확인」을 그대로 옮긴다 ([ROADMAP.md §4](ROADMAP.md), [결과문서 §12](결과정리및리뷰.md)).

- **링크 따라가기 옵션**: `grep -S` 같은 옵션으로 작업 폴더 안의 링크를 통해 밖을 읽는 것은 막지 못한다.
- **보수적 판정**: 경로처럼 보이는 인자는 모두 검사하므로 `grep / a.txt`의 패턴 `/`도 거부된다.
- **미확인**: 실제 모델이 보내는 인자 형태(문자열·`null`·객체), 설명서에 `properties`가 없는 경우의 미정의 인자 검사, 시간 초과의 실제 대기 동작, 허용 프로그램별 옵션 위험, GNU `grep` 등 다른 구현과 macOS 외 환경, 터미널 직접 입력 경로.
- **이 문서 자체의 한계**: 사후 재구성이라서, 3절의 순서 이유처럼 당시 기록에 없는 것은 「미확인」으로 남겼다.
