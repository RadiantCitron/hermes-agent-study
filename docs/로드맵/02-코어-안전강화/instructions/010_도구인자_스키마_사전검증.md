## 1. 구현 내용 명세

1. **도구 통로에서 호출 전 검증** ([`dispatcher.py`](../../../../src/hermes_core/tools/dispatcher.py) `ToolDispatcher.handle_function_call`):
   - 없는 도구 확인 다음, 도구 본체를 부르기 **전에** 등록된 스키마(`function.parameters`)로 인자를 검증한다.
   - 검증 규칙은 [ROADMAP.md §6-2](../ROADMAP.md)를 따른다: 필수 인자, 정의되지 않은 인자, 타입(`string`·`integer`·`number`·`boolean`·`array`·`object`, `bool`은 `integer`/`number`로 불인정), `enum`.
   - 위반이면 도구를 호출하지 않고 `{"success": false, "error": "Invalid arguments for tool '<이름>': <사유>"}`를 반환한다. 사유에는 문제가 된 인자 이름이 들어간다.
   - 스키마가 없거나 `parameters`가 없으면 검증하지 않는다 (기존 호환).
2. **기존 예외 처리 유지**: 본체 호출 중의 `TypeError`와 일반 예외 처리, 반환 형식은 바꾸지 않는다.
3. **01편 갱신** ([01편](../../../작동원리/01-헤르메스코어-작동원리.md)): 도구 통로 관련 서술에서 「인자 사전 검증은 지금은 없다」를 고치고(Q3, 3부 방어선 3·「지금은 없는 방어선」, 5부 ① 첫 행), 5부 ③ 도구 통로 행의 미확인 사항을 갱신한다. `기준 커밋` 값은 건드리지 않는다 ([ROADMAP.md §7](../ROADMAP.md)).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험용 도구 `t`를 등록한다. 스키마: `action`(string, enum `add`/`remove`), `count`(integer), 필수는 `action`뿐. 본체는 호출 횟수를 센다.

| # | 입력 (`handle_function_call("t", ...)`) | 기대 결과 |
|---|---|---|
| 1 | `{}` | 실패(`success` false). 오류 문구에 `action` 포함. 본체 호출 0회 |
| 2 | `{"action": "zzz"}` | 실패. 오류 문구에 `action` 포함. 본체 호출 0회 |
| 3 | `{"action": "add", "count": "3"}` | 실패. 오류 문구에 `count` 포함. 본체 호출 0회 |
| 4 | `{"action": "add", "count": true}` | 실패. 오류 문구에 `count` 포함. 본체 호출 0회 |
| 5 | `{"action": "add", "extra": 1}` | 실패. 오류 문구에 `extra` 포함. 본체 호출 0회 |
| 6 | `{"action": "add", "count": 2}` | 본체 호출 1회. 반환값이 본체의 반환 문자열 그대로 |
| 7 | 스키마를 `{}`로 등록한 도구에 임의 인자 `{"a": 1}` | 검증 없이 본체 호출 |
| 8 | 없는 도구 이름 | 기존과 같은 `Unknown tool` 실패 (검증보다 먼저) |
| 9 | 기본 디스패처에서 기억 도구에 `{"action": "add", "target": "memory", "content": "x"}` | 검증을 통과해 본체가 실행됨 (회귀) |
| 10 | 위 1~5의 반환 문자열 | JSON으로 읽히고 키가 `success`, `error`만 있음 |

## 4. 검증 기준 (Done 조건)

1. 위 10개 시나리오를 옮긴 `test_dispatcher.py`가 통과한다.
2. 기존 19개 테스트가 모두 통과한다 (전체 `pytest tests/test_hermes_core/` 통과).
3. `grep -n "_validate" src/hermes_core/tools/dispatcher.py`로 검증 코드가 도구 통로 파일 안에만 있음을 확인한다 (흩뿌리지 않음).
