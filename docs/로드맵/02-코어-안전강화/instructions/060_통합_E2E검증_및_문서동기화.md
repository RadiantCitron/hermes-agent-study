## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

기본 디스패처의 터미널 도구는 현재 작업 폴더에서 실행되므로, 현재 작업 폴더를 임시 폴더로 바꾸고(`monkeypatch.chdir`) 그 안에 파일 `x`를 만든다. 가짜 모델의 응답 순서는 다음과 같다.

| 턴 | 가짜 모델의 응답 |
|---|---|
| 1 | 도구 `terminal`, 인자 `{"command": "rm -rf x"}` 요청 |
| 2 | 도구 `memory`, 인자 `{}` (필수 `action` 누락) 요청 |
| 3 | 도구 `terminal`, 인자 문자열 `"{bad"` 요청 |
| 4 | 도구 `terminal`, 인자 `{"command": "echo ok"}` 요청 |
| 5 | 텍스트 `"done"` |

| # | 기대 결과 |
|---|---|
| 1 | `final_response == "done"`, `stopped_reason == "completed"`, `iterations == 5` |
| 2 | 파일 `x`가 그대로 존재 |
| 3 | 도구 메시지 4개가 순서대로: 거부(`rm` 포함), 인자 오류(`action` 포함), 인자 읽기 실패(`JSON` 포함), 성공(`ok` 포함) |
| 4 | 세션 원장의 메시지 수 = 사용자 1 + 모델 5 + 도구 4 = 10 |
| 5 | 모델 요청마다 대응하는 도구 메시지가 있음 (`tool_call_id` 일치) |

## 4. 검증 기준 (Done 조건)

1. 위 5개 확인이 통과한다.
2. 전체 `pytest tests/test_hermes_core/`가 통과하고, 개수가 01편에 적힌 값과 같다.
3. 01편의 재확인 명령(grep 포함)을 모두 실행해 결과가 나옴을 확인한다.
4. 01편에서 「지금은 없다」로 적힌 항목마다 대응 코드가 정말 없는지(또는 생겼는지) 대조한 결과를 보고에 적는다.
