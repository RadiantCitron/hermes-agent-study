## 1. 구현 내용 명세

1. **인자 읽기 실패 처리** ([`agent.py`](../../../../src/hermes_core/agent/agent.py) `HermesAgent._execute_tool_calls`):
   - 인자 문자열이 JSON이 아니거나, 읽은 결과가 사전이 아니면 도구를 호출하지 않는다.
   - 대신 `{"success": false, "error": "Invalid JSON arguments for tool '<이름>': <사유>"}`를 도구 메시지(`role: tool`)로 모델에게 돌려주고, 세션 원장에도 같은 내용을 기록한다. 경고 로그를 남긴다.
   - 빈 문자열(공백 포함)과 `None`(`arguments`가 `null`)은 `{}`로 본다 ([ROADMAP.md §6-4](../ROADMAP.md), 결정 D-09).
2. **종료 사유 반환** (`HermesAgent.run_conversation`):
   - 반환 사전에 `stopped_reason`을 추가한다: 텍스트 응답으로 끝나면 `"completed"`, 반복 상한 도달이면 `"max_iterations"` (경고 로그).
   - 기존 키 `final_response`, `messages`, `iterations`, `session_id`는 바꾸지 않는다.
3. **독스트링 정정** (`agent.py`):
   - 상단 독스트링의 「엄격한 메시지 역할 교대를 철저히 유지」를 실제 동작(순서대로 쌓지만 검사하지는 않음)에 맞게 고친다.
   - `_build_system_prompt`의 「단 1회 조립」을 「`system_message`를 넘기면 다시 조립한다」는 실제 동작에 맞게 고친다. 동작 자체는 바꾸지 않는다.
4. **01편 갱신**: Q3의 「인자를 읽지 못하면 비어 있는 것으로 처리」, 3부 방어선 5와 「지금은 없는 방어선」, 5부 ① 반복 실행 행(「지금은 없는 것」), 5부 ③ 해당 행을 고친다. `기준 커밋`은 건드리지 않는다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

가짜 모델, 메모리 DB, 임시 기억 폴더를 쓴다. 시험용 도구 `t`(스키마 없음)를 디스패처에 등록해 본체 호출 횟수를 센다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 모델이 `t`를 인자 `"{bad json"`로 요청 후 텍스트로 마무리 | `t` 본체 호출 0회. 도구 메시지의 내용이 JSON이며 `success`가 false이고 `JSON` 포함. 경고 로그 1건 이상. 최종 응답은 마무리 텍스트 |
| 2 | 인자가 `"[1, 2]"` (유효한 JSON이지만 사전 아님) | 시나리오 1과 같은 실패 처리 |
| 3 | 인자가 `""` | `t` 본체 1회 호출(인자 없음) |
| 4 | 인자가 `"   "` (공백) | `t` 본체 1회 호출(인자 없음) |
| 5 | 시나리오 1~2에서 모델의 도구 요청 개수 | 도구 요청마다 `tool_call_id`가 같은 도구 메시지가 정확히 하나씩 있고, 세션 원장의 도구 메시지 수와 같음 |
| 6 | 모델이 매번 도구를 요청, `max_iterations=3` | `stopped_reason == "max_iterations"`, `iterations == 3`, `final_response == ""`, 경고 로그 1건 이상 |
| 7 | 모델이 바로 텍스트로 응답 | `stopped_reason == "completed"`, `iterations == 1` |
| 8 | 위 6, 7의 반환 사전 | `final_response`, `messages`, `iterations`, `session_id` 키가 모두 존재 |
| 9 | 인자가 `None` (`arguments: null`) | `t` 본체 1회 호출(인자 없음) |
