## 1. 목적

가짜 모델·가짜 입력·가상 터미널로 모든 시험이 통과한 상태(823건)에서 다음을 확인한다.

1. **가정 G**: 실제 터미널 앱(`prompt_toolkit` 경로)에서 `/rollback`의 목록·경고·`Roll back these changes? [y/N] ` 질문이 정상으로 뜨고, `y`/`n`/Enter/`Ctrl+C`/`Ctrl+D`가 전달되며, 그 뒤 REPL이 이어지는가.
2. **가정 C(실제 모델)**: 실제 모델이 만든 파일은 되돌리면 사라지고, 고친 파일은 바이트 단위로 원래 내용이 되는가. 다시 `/rollback`하면 그 앞 턴으로 넘어가는가.
3. **가정 H**: 되돌린 뒤 모델이 옛 내용을 전제로 고치려 하면 어떻게 되는가(「찾는 글이 없다」 실패 → 다시 읽고 바로잡는가, 사람에게 알리는가, 반복 실패하는가). 반복 실패가 보이면 구조는 되돌리지 않고 「모델에게 되돌림 알리기」를 후속 후보로 올린다.
4. **가정 D(실제 사람 손)**: 에이전트가 쓴 뒤 사람이 다른 창에서 고친 파일은 건너뛰고(`[skip]`), 같은 턴의 나머지는 되돌리는가.
5. **가정 B·E·F(실제 앱)**: 모델이 만든 모든 변경이 원장에 `pending`을 거쳐 남고, 보호 파일(`.env`) 쓰기는 기록 대상이 되지 않으며, 되돌린 행이 `rolled_back`/`skipped`로 확정되는가.
6. **R3 경고(실제 승인과의 공존)**: 같은 턴에 사람이 승인한 터미널 명령이 있으면 `/rollback` 질문 **앞에** 「섞인 상태」 경고가 보이는가.
7. **가정 A(실제 앱)**: `--no-checkpoints`에서 배너가 꺼짐을 알리고, 쓰기는 그대로 되며, `/rollback`은 모델로 가지 않고 안내만 하는가.
8. 화면: 목록 줄(`[restore]`/`[delete]`/`[skip]`)·경고·결과 줄·「모델은 모른다」 안내가 읽을 만한가(사람 눈 확인), 배너의 체크포인트 한 줄이 있는가.
9. **가정 J(실사용 저장량)**: 위 실행 뒤 `file_checkpoints`의 저장 바이트가 작은가.

판정이 어려운 것은 **「못 봤다」로 적는다.** 모델 1종·실행별 1회 관찰이며 다른 모델·다른 문장에서는 달라질 수 있다. 쓰기 거부 알림(`CLI_CHECKPOINT_REFUSED_NOTICE`)은 기록 실패·상한 초과를 실제 앱에서 일부러 만들 방법이 없어 자동 시험(030·040)으로만 증명된 것으로 두고 이 스모크에서는 **관찰 대상이 아니다**(「못 봤다」로 적는다).

## 2. 사전 조건

1. **에이전트**: `.venv/bin/python -m pytest -q`가 모두 통과함을 확인하고 기준선(050 마감 시 823건)을 기록한다. `git diff c25e633..HEAD -- src/`가 0줄임을 확인한다(050 구현 이후 `src/` 무변경). 작업 트리에 이 로드맵과 무관한 미커밋 파일(`pyproject.toml`, `tests/conftest.py` 등)이 있으면 건드리지 않는다. 코드·문서는 이 단계에서 바꾸지 않는다.
2. **사용자**: 평소 쓰는 터미널 앱 1개(예: Terminal.app, iTerm2, WezTerm). 앱 이름·버전을 기록한다. 같은 앱에서 **탭(창)을 하나 더** 열 수 있어야 한다(R1·R2에서 파일을 확인하고 고치는 용도, 이하 「확인 탭」).
3. **키는 에이전트와의 대화·명령줄·프롬프트에 절대 쓰지 않는다** ([AGENTS.md](../../../../AGENTS.md) §3). 사용자가 **별도 터미널에서 직접** `OPENROUTER_API_KEY`를 환경에 내보낸다(`export OPENROUTER_API_KEY=...` 또는 `set -a; source .env; set +a`). 에이전트는 `.env`를 열지 않는다. 에이전트에게 붙여 넣는 화면 출력에서 개인 경로(홈 폴더 이름)는 `<임시>`로 바꾼다.
4. 상태 폴더는 레포 밖 임시 폴더를 쓴다. 사용자가 **키를 내보낸 그 터미널(「실행 탭」)**에서 레포 루트에서 한 번 실행한다:
   ```bash
   export H=$(mktemp -d); echo "$H"; mkdir -p "$H"/r1 "$H"/r2 "$H"/r3 "$H"/r4 "$H"/r5
   echo "TERM_PROGRAM=$TERM_PROGRAM TERM=$TERM"; command -v python3 shasum sqlite3
   ```
   `python3`가 `PATH`에 없으면 R4는 의미가 없으니 알린다(R4의 프롬프트를 사용자가 가진 다른 비허용 프로그램으로 바꾼다. 허용목록은 `echo pwd ls cat head tail wc grep`뿐이다). 확인 탭에서도 같은 `$H`를 쓰려면 `export H=<위에 출력된 경로>`를 한 번 친다.
5. **비용 상한**: 실행 5회, 호출은 실행당 3~8회 예상, 출력 토큰 상한 4,096. 합계 1센트 미만으로 예상한다(공개 단가 기준 추정, 실제 청구는 확인하지 못함). `max_iterations`(50)가 폭주를 막는다.

## 3. 절차 (사용자가 실제 터미널 앱에서 직접 실행, 에이전트는 대신하지 않는다)

각 실행은 레포 루트의 실행 탭에서 한다. 실행마다 **아래 입력을 그대로** 쓰고, 각 단계에서 **본 것**을 기록한다(정상 / 이상 / 못 봄 + 한 줄 메모). 실제 모드(`--mock` 없음)이므로 작업 폴더는 `$H/rN/workspace`이고, 확인 탭에서는 `cd "$H/rN/workspace"`로 들어가 본다. 모델 이름은 기본값(`deepseek/deepseek-v4-flash-0731`)이다. 모델이 파일 이름·내용을 입력과 다르게 만들면 그 사실을 기록하고, **문장을 바꿔 자동으로 재시도하지 않는다.**

| 실행 | 명령 | 목적 |
|---|---|---|
| **R1** | `HERMES_HOME="$H"/r1 .venv/bin/python -m hermes_core.cli` | 만들기·고치기·되돌리기·연쇄 되돌리기, 되돌린 뒤 모델의 반응 (가정 C·G·H) |
| **R2** | `HERMES_HOME="$H"/r2 .venv/bin/python -m hermes_core.cli` | 사람이 고친 파일은 건너뜀 (가정 D) |
| **R3** | `HERMES_HOME="$H"/r3 .venv/bin/python -m hermes_core.cli` | 거절·빈 입력·Ctrl+C·Ctrl+D·인자 붙은 명령, 보호 파일 (가정 G·E·B) |
| **R4** | `HERMES_HOME="$H"/r4 .venv/bin/python -m hermes_core.cli` | 같은 턴의 승인된 터미널 명령 경고 (R3 위험, 10번과의 공존) |
| **R5** | `HERMES_HOME="$H"/r5 .venv/bin/python -m hermes_core.cli --no-checkpoints` | 체크포인트 끔 (가정 A) |

### R1 (만들기 → 고치기 → 되돌리기 → 모델의 반응)

「확인 탭」 열의 명령은 해당 턴이 끝난 뒤 확인 탭에서 친다. `S1`·`S2`는 사용자가 기록하는 해시 문자열이다.

| 단계 | 입력 (실행 탭) | 답 | 확인 탭 | 보아야 할 것 |
|---|---|---|---|---|
| 시작 | (배너) | | | `🚀 Running in REAL mode`, `File checkpoints enabled: write_file/patch changes can be undone with /rollback (terminal and delegated changes are not covered; disable with --no-checkpoints).` 한 줄이 `Type 'exit' or 'quit' to terminate.` **앞**에 있는가 |
| 1 | `write_file 도구로 notes.txt 를 만들어줘. 내용은 정확히 세 줄이야. 첫 줄 alpha, 둘째 줄 beta, 셋째 줄 gamma.` | | `cat -A notes.txt; shasum -a 256 notes.txt` → 출력 해시를 **S1**로 기록 | 모델이 파일을 만들었는가 |
| 2 | `patch 도구로 notes.txt 의 beta 를 BETA 로 바꿔줘.` | | `cat notes.txt; shasum -a 256 notes.txt` → **S2** (S1과 달라야 한다) | 모델이 `patch`로 고쳤는가 |
| 3 | `/rollback` | 목록 뒤 질문에서 `y` Enter | (아래 4에서 확인) | 머리말 `Rolling back turn 2: 1 to restore, 0 to skip (newest change first).`, 줄 `[restore] notes.txt (patch)`, 경고 줄 없음, 질문 `Roll back these changes? [y/N] ` 표시, `y` 전달, 결과 `restored  notes.txt`, `Rolled back 1 file(s), skipped 0.`, `The model does not know about this rollback. ...` 안내, 다음 `User >`가 정상으로 이어지는가 |
| 4 | | | `shasum -a 256 notes.txt` → **S1과 같아야 한다**. `cat notes.txt`에 `beta`(소문자) | 바이트 단위 복원 (가정 C) |
| 5 | `notes.txt 의 BETA 를 Beta 로 바꿔줘.` | | `cat notes.txt` | **가정 H 관찰.** 모델이 (a) `patch`를 시도해 「찾는 글 없음」을 받고 파일을 다시 읽어 바로잡는가 (b) 먼저 읽고 `beta`임을 알리는가 (c) 이미 `BETA`라고 믿고 같은 실패를 반복하는가 (d) 파일을 통째로 다시 만들려 하는가. 어느 쪽이든 **본 대로** 적는다. 실패 횟수를 센다 |
| 6 | `/rollback` | `y` Enter | `ls; cat notes.txt` | 5에서 파일이 바뀌었으면 그 턴(`turn 3`)이 먼저 되돌아온다. 5에서 변경이 없었으면 바로 `turn 1`의 `[delete] notes.txt (write_file)`가 나온다 |
| 7 | (필요하면) `/rollback` | `y` Enter | `ls` | **턴 1까지 이어지면** `[delete]  notes.txt (write_file)` 후 `deleted   notes.txt`, 확인 탭에서 `notes.txt`가 없다. 더 칠 때마다 한 턴씩 앞으로 넘어간다 |
| 8 | `/rollback` | (질문 없음) | | 되돌릴 것이 모두 끝나면 `Nothing to roll back.`만 나오고 질문이 뜨지 않는가. (6·7에서 이 문구가 먼저 나오면 그때부터 여기로 본다) |
| 끝 | `exit` | | | 종료 뒤 셸의 에코·커서가 정상인가 |

## 4. 기대 결과와 확인 항목

## 5. 결과 기록

- 대시보드 실행 기록에 날짜, 지시 문구, 앱 이름·버전, 실행별(R1~R5) 관찰 요약, 원장 조회 결과, 호출 수·토큰·계산 비용, 가정별 판정을 적는다. 로컬 경로 대신 `<임시>`를 쓴다.
- 확인 항목 1·4·13의 관찰은 **사용자가 본 대로** 종합보고서의 「목표와 결과」·「새로 발견한 부분」에 옮긴다. 관찰이 기대와 달라도 코드를 이 단계에서 고치지 않고 후속 제안만 근거와 함께 적는다.
- **판정의 한계**: 터미널 앱 1개, 모델 1종, 실행별 1회, 사용자의 눈이 근거다. 가정 H는 모델이 매번 같게 행동한다는 보증이 아니다. 파일 5개 안팎의 작은 작업이라 대량 변경·큰 파일·긴 대화의 저장량과 성능은 시험하지 않았다. 터미널 명령·위임 자식의 변경이 되돌려지지 않는 것은 기능의 범위이며 이 스모크는 경고 줄의 표시만 본다. 이 한계를 종합보고서에 함께 적는다.

## 6. 마감 (5단계, 사용자의 종료 선언이 있을 때만)

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)가 정본이다. 이 로드맵에 해당하는 순서만 적는다.

1. **종합보고서** `결과정리및리뷰.md`를 정책의 9개 항목으로 상세히 쓴다. `WHY.md`의 가정 **A~J를 하나씩** 「이뤘다 / 못 이뤘다 / 바뀌었다」로 근거(커밋 해시, 시험, 이 스모크의 사용자 관찰)와 함께 대조한다. 대조하지 않은 가정이 있으면 마감하지 않는다. 가정 A는 `--no-checkpoints`에서 `/rollback`을 가로채 안내하는 예외(040)가 있으므로 「바뀌었다」 여부를 근거와 함께 판단하고, 가정 F는 020에서 정한 `pending` 처리 규칙을, 가정 J는 020의 세션당 상한 50MB와 이 스모크의 저장량 관찰을, 가정 G·H는 스모크 관찰로 대조한다. 계획과 달라진 곳(대시보드 변경 기록과 WHY 변경 기록의 5건: `--no-checkpoints`의 `/rollback` 가로채기, 작업 폴더 일치 확인, 거부 호출의 상한 소모, F1 수정)은 「바뀌었다」로 기록한다.
2. **대시보드** `README.md`의 전체 상태를 `Closed`로, 완료 일자와 종합보고서 링크를 채우고 060 행·실행 기록을 갱신한다. 실행 기록의 커밋 칸은 같은 커밋에서 자기 해시를 쓰지 않는다(정책 §4). 이 시점에 앞 단계 행들의 접두부를 실제 해시로 채운다.
3. **인계**: 마감은 상태가 바뀌는 작업이지만, 인계는 단계마다 쓰지 않고 **세션을 마칠 때 `docs/인계/`에 새 파일 하나**로 쓴다([인계 README](../../../인계/README.md), `RULE-009`). 마감 커밋에는 인계 파일을 넣지 않고, 사용자가 「세션 저장해라」「인계해라」를 지시할 때 따로 만든다. 합의된 다음 순서는 대시보드·인계에서 확인한다(미확인: 11 다음 로드맵은 이 지시서 작성 시점에 정해지지 않았다).
4. **작동원리 01·02·03편**의 「미확인」(실제 터미널 앱에서의 `/rollback`, 되돌린 뒤 실제 모델의 행동)을 이번 관찰로 갱신할 수 있다. 이 갱신은 마감 보고에서 **제안만** 하고, 사용자가 지시하면 수행한다.
5. **커밋과 태그**: 스모크 기록과 마감이 같은 지시면 하나의 마감 커밋(`docs(core): R11-마감 - ...`), 스모크 기록이 먼저면 `R11-060` 기록 커밋 뒤 마감 커밋을 따로 만든다. 변경 파일을 경로로 지정해 스테이징한다. **마감 커밋에만** 가벼운 태그 `roadmap-11-closed`를 단다. 푸시와 태그 푸시는 하지 않으며 사용자의 별도 지시가 있을 때만 한다.
6. 마감 후 구현지시서(`instructions/`)는 수정하지 않는다.
7. **후속 인계**: 종합보고서 §8에 후속 후보를 적는다. 스모크 결과에 따라 「모델에게 되돌림 알리기」(가정 H), 터미널 명령 변경 되돌리기, 위임 자식 변경 되돌리기, 변경 목록·차이 보기, 오래된 기록 정리, 쓰기 거부가 상한 검사 전에 용량을 소모하는 한계 개선을 근거와 함께 올린다.

## 8. 위험·주의

- **승인한 명령은 실제로 실행된다.** 이 지시서의 승인 대상은 R4의 `python3 --version` 하나뿐이다. 모델이 다른 명령을 요청하면 **표시된 `argv`를 읽고 `n`으로 답한다.** 그 기록 자체가 관찰이다. `env`·`printenv`(인자 없음) 같은 환경 전체 출력 명령은 승인하지 않는다.
- **`/rollback`의 `y`는 실제로 파일을 지우거나 덮는다.** 대상은 임시 상태 폴더 `$H/rN/workspace` 안의 파일뿐이다. 실행 탭을 레포 루트에서 시작해도 실제 모드는 시작할 때 작업 폴더로 이동하므로 레포 파일은 대상이 아니다. 그래도 R1~R5의 입력에 레포 안 경로를 쓰지 않는다.
- **확인 탭에서 쓰는 명령은 읽기(`cat`, `ls`, `shasum`)와 R2의 `echo mine >> a.txt` 하나뿐이다.** 그 밖의 파일 조작을 하면 관찰이 오염된다.
- **키 값은 지시서·화면 기록·대화록에 쓰지 않는다.** 화면이나 파일에 키가 보이면 즉시 중단하고 보고하며 해당 키는 회전 대상이다(이 단계의 명령은 키를 출력하지 않는다).
- **모델이 시킨 대로 도구를 부르지 않을 수 있다.** 해당 가정은 「못 봤다」로 적고, 문장을 바꿔 자동으로 재시도하지 않는다. 문장 변경은 사용자의 새 지시로만 한다.
- **같은 이름 파일이 이미 있으면 `write_file`은 실패한다**(새 파일만 만든다). 각 실행이 별도 작업 폴더를 쓰므로 정상 순서에서는 생기지 않는다. 같은 실행 안에서 이름이 겹쳐 모델이 실패를 보고하면 그 사실을 기록한다.
- 이 단계에서 문제를 발견하면 **구조를 되돌리거나 땜질하지 않는다.** 근본 원인을 기록하고 후속 로드맵 후보로 올린다(AGENTS.md §1-4).
