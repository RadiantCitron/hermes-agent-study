## 1. 구현 내용 명세

이 단계는 세 가지를 한다. **`src/`는 원칙적으로 바꾸지 않되, 아래 2절의 「발견 수정 슬롯」이 허용하는 범위에서만 바꾼다.**

- **A. 대본형 가짜 모델 E2E**: 진짜 `HermesAgent` 루프 + 진짜 `SessionDB` + 진짜 `Checkpointer`·디스패처·파일 도구에 모델만 대본형으로 갈아 끼운다. 010~040이 단위 시험으로 증명한 「기록 → 쓰기 → 확정 → 계획 → 복원」이 층을 가로질러 이어 붙었을 때도 성립하는지 본다(턴 연속 되돌리기, 같은 파일 여러 번 수정, 충돌, 바이트 충실도, 경로 재판정, 승인·위임과의 공존, 끈 구성과의 쌍둥이 비교).
- **B. 가상 터미널(pty) `/rollback`**: 040의 시험은 `read_user_input`을 가짜로 바꿨으므로, 실제 `prompt_toolkit`/`input()` 경로에서 `/rollback` 목록·확인 질문이 뜨고 `y`/`n`/Enter/`Ctrl+C`/`Ctrl+D`가 전달되며 그 뒤 REPL이 이어지는지(WHY 가정 G)는 증명되지 않았다. 10번 050의 pty 방식(IUTF8를 끈 가상 터미널, `runpy` 런처)을 새 파일에 재현해 **프로세스 수준**에서 확인한다.
- **C. 문서 동기화**: 010~040이 「050에서 일괄 반영」으로 미룬 작동원리 01편(및 02·03편의 어긋난 서술)과 ROADMAP·WHY를 사실에 맞춘다.

실제 터미널 앱의 화면 모양, 실제 모델의 행동(가정 H), 실제 사용에서의 저장량(가정 J)은 이 단계가 확인하지 못한다. 060에서 사람이 본다.

### 1-2. 시험 파일

1. **`tests/test_hermes_core/test_agent_e2e.py` 끝에 추가만 한다**(삭제 0줄). 구분 주석 `# 로드맵 11: 구현지시서 050 통합 E2E 검증 시나리오 (시나리오 1 ~ 11)`, 시험 이름 `test_r11_050_scenario_NN_...`, 픽스처 `r11_e2e_env`.
   - 픽스처: 임시 `HERMES_HOME`, 작업 폴더 `HERMES_HOME/workspace`(`monkeypatch.chdir`), 가짜 키 `FAKE-NOT-A-REAL-KEY-0004`(`sk-or-` 꼴 **아님**), 파일 `SessionDB`, `session_id` 미리 생성. 조립 도우미 `build(checkpointer=True, approver=None, bytes_limit=None)`가 위 1-1의 조립을 한다.

2. **`tests/test_hermes_core/test_cli_rollback_pty.py` 신규.** 표준 라이브러리 `pty`·`termios`·`select`·`subprocess`·`sqlite3`만 쓴다. `pty`/`termios`/`termios.IUTF8`가 없으면 모듈 전체를 건너뛴다(10번과 같음).
   - 보조 도구 `RollbackPtySession(script, extra_args=(), fallback=False)`: IUTF8를 끈 pty, 자식은 `sys.executable -c <런처>`. 런처 = ① (`fallback`이면 `sys.modules["prompt_toolkit"] = None`) ② `hermes_core.llm_client.OpenRouterClient`를 대본형 클래스로 교체 ③ `sys.argv = ["hermes-core", *extra_args]` ④ `runpy.run_module(...)`. 환경: `PYTHONPATH=<레포>/src`, `HERMES_HOME=<임시>`, `OPENROUTER_API_KEY=FAKE-NOT-A-REAL-KEY-0004`, `TERM=xterm-256color`, `R11_PTY_SCRIPT_JSON=<대본 JSON>`, 작업 폴더 `<임시>`.
   - `wait_for(표지, 제한시간=15초)`·`read_available`·`write`·`close`·DB 읽기(`get_checkpoint_rows()`)는 10번 보조 도구와 같은 규칙: **표지가 나온 뒤에만 키를 보내고**, 고정 `sleep`에 기대지 않으며, 실패해도 자식을 정리한다.
   - 작업 폴더 `HERMES_HOME/workspace`에 `old.txt`(`before`)를 미리 만들어 둔다. 한 턴의 대본(`go1`): `write_file` `new.txt`=`hello` → `patch` `old.txt` `before`→`after`.
   - **통과 조건에 화면 모양은 넣지 않는다.** 출력 섞임·줄 위치·색은 060의 사람 관찰이다.
3. **`tests/test_hermes_core/test_r11_050_fixes.py` 신규**: 2절 발견 수정 슬롯의 시험만 둔다. 슬롯에서 아무것도 고치지 않으면 만들지 않는다.

### 1-3. 알려진 한계 (시험하지 않고 문서에 남긴다)

- pty는 실제 터미널 앱이 아니다. `prompt_toolkit`의 커서 위치 요청(CPR) 경고 등은 시험이 검사하지 않는다(실제 앱에서도 나오는지 **미확인**).
- E2E의 모델은 대본이다. 실제 모델이 파일 도구를 어떻게 부르는지, 되돌린 뒤 옛 내용을 전제로 헛도는지(가정 H)는 060에서만 본다.
- 도구가 거부한 호출도 세션 상한을 소모하는 030의 한계(가정 J)는 고치지 않고 마감 때 대조한다(2절 「고치지 않는 것」).
- `execute_rollback` 실행 중 `Ctrl+C`는 시험하지 않는다(040 1-4). 060에서 사람이 본다.

## 2. 발견 수정 슬롯 (src 변경이 허용되는 유일한 범위)

사용자 지시(2026-10-29): 통합 검증 중 드러나는 버그나 자잘한 수정을 **이 단계에서 함께 처리할 수 있게** 한다. 단 「동어반복 시험」과 「범위 팽창」을 막기 위해 아래 틀 안에서만 한다. 이 틀을 벗어나는 것은 [AGENTS.md §2](../../../../AGENTS.md)대로 **멈추고 보고한다.**

### 2-1. 사전 확인된 수정 F1 (지금 확정해 둔다)

**F1. 이전 턴을 되돌릴 때 터미널·위임 경고가 어긋난다** (040 1-4 기록, 020 동작).
- **증상**: `Checkpointer.plan_rollback`이 승인된 터미널 실행 수와 위임 자식 세션 수를 `turn_started_at`(가장 최근에 `begin_turn`한 턴의 시작 시각)부터 센다. 최신 턴을 되돌린 뒤 그 앞 턴을 `/rollback`하면 ① 앞 턴에서 일어난 터미널·위임은 세어지지 않고(경고 **누락**, 사람이 일부만 되돌아간 줄 모름: R3) ② 최신 턴에서 일어난 것이 세어진다(경고 **오탐**).
- **기대되는 동작** (ROADMAP R3 ②: 「그 **턴 시간 범위**의 승인된 터미널 실행 수와 위임 자식 세션 수」): 대상 턴의 `[시작, 끝)` 구간만 센다. 끝은 다음 턴의 시작 시각이고, 대상이 마지막 턴이면 끝 없음(현재까지).
- **수정 범위**: `src/hermes_core/tools/checkpoint.py`만. `Checkpointer`가 메모리에 `{turn_index: 시작 시각}`을 둔다(원장 열·표·`SessionDB` 메서드·`RollbackPlan` 필드 불변). `turn_started_at` 속성과 `plan_rollback(turn_index=None)` 시그니처는 유지한다(`test_checkpoint_module.py`가 `turn_started_at > 0`을 단언한다). `begin_turn(turn_index=N)`으로 번호를 직접 준 경우에도 같은 사전에 기록한다. 시작 시각을 모르는 턴(사전에 없음, 예: 프로세스를 다시 시작해 사전이 비었는데 `turn_index`를 지정해 부른 경우)은 **지금과 같은 방식**(`turn_started_at` 기준, 0이면 필터 없음)으로 센다.
- **기존 시험**: 020 시험이 지금 동작에 기대면 **멈추고 보고한다**(기존 시험을 임의로 고치지 않는다). 작성 시점에 `turn_started_at`을 쓰는 기존 단언은 `test_checkpoint_module.py:48` 하나임을 확인했다.

### 2-2. 발견 수정의 조건 (F1 외에 착수 중 발견한 것)

모두 만족할 때만 이 단계에서 고친다. 하나라도 어기면 **고치지 않고 멈춰서 보고한다.**

1. **버그이거나 사실 오류 수준이다**: 요구사항(ADR-0011·ROADMAP·이 로드맵 지시서 010~040의 명세)이 이미 정한 동작과 구현이 다르다. 새 동작을 정하는 일(설계 결정)이 아니다.
2. **파일 범위**: `tools/checkpoint.py`, `tools/dispatcher.py`, `cli.py`, `constants.py` 안이다. `file_tools.py`·`path_guard.py`·`session_db.py`(표·열·메서드)·`agent/`·`delegate_tool.py`·`approval.py`·`terminal_tool.py`에 닿으면 고치지 않고 보고한다.
3. **인터페이스 불변**: 공개 함수 시그니처·반환 모양·상태값·표·열·모델에게 가는 문구를 바꾸지 않는다. 사람에게 보이는 CLI 문구 상수 값을 바꾸는 것도 설계 결정이므로 제외한다(오탈자 수정은 예외, 그때 해당 상수를 쓰는 시험이 영향받는지 확인).
4. **시험이 먼저다**: 고치기 전에 **재현하는 시험을 `test_r11_050_fixes.py`에 쓰고 실패하는 것을 확인**한다. 시험의 기대값은 코드가 아니라 위 요구사항 문서에서 도출한다(구현 결과를 보고 쓰지 않음). 고친 뒤 통과시키고, 기존 시험은 무수정으로 통과해야 한다.
5. **기록한다**: 고친 항목마다 대시보드 실행 기록에 「F번호: 증상 · 원인 · 고친 곳 · 시험 이름」을 한 줄씩 남긴다. 번호는 F1 다음 F2, F3…
6. **한 커밋**: 수정·시험·문서가 이 단계 커밋 하나에 들어간다. 수정이 커서 단계의 검증을 흐릴 것 같으면(예: 3건 이상, 또는 한 건이 50줄 이상) 수정을 **이 단계에서 빼고** 별도 계획으로 제안한다.

### 2-3. 고치지 않는 것 (보고와 마감 대조만)

- **거부된 호출의 세션 상한 소모**(030 1-4, 가정 J): 설계 선택지(확정 때 바이트 반환 등)가 있는 설계 결정이다.
- **건너뜀 사유가 한국어**: 020 문구 정책이다.
- **되돌린 뒤 빈 폴더가 남음**(ROADMAP 위험 8), **`execute_rollback` 중 Ctrl+C**, **`--no-checkpoints`에서 `/rollback`을 가로채는 예외**: 설계된 한계 또는 사용자 확인 대기 사항이다.
- 발견한 이런 항목은 새 한계로 5부 ③·WHY 변경 기록·마감 보고(060)에 올린다.

### 5-1. 대본형 가짜 모델 E2E (`test_agent_e2e.py`)

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | **한 턴 전체 흐름**: 작업 폴더에 `old.txt`(`before`). 턴 1에서 모델이 `write_file` `new.txt`=`hello`, `patch` `old.txt` `before`→`after`를 요청한 뒤 최종 답. 이어서 되돌림 | 종료 사유 `completed`. 행 2개(id 오름차순 = 요청 순서) 모두 `applied`, `turn_index 1`. `messages`는 사용자 → assistant(도구 요청 2개) → tool → tool → assistant 순서이고 도구 메시지 `tool_call_id`가 요청 `id`와 순서대로 같다. 계획 항목은 최근 변경부터(`old.txt`, `new.txt`). 되돌림 뒤 `new.txt` 없음, `old.txt`는 `before`(바이트 동일), 행 두 개 `rolled_back`. **되돌림 전후 `messages` 개수가 같다**(되돌림은 대화 기록을 만들지 않는다) |

## 7. 위험·주의

- **시간 의존(불안정) 시험**: pty 시험은 기동·화면 갱신 시간에 흔들린다. 표지 기반 대기와 제한시간으로 막고, 질문 표지가 나온 **뒤에만** 답을 보낸다. 질문 전에 보낸 키는 `User >` 입력으로 새어 들어가 거짓 통과할 수 있다.
- **시험 쪽 DB 읽기**: 앱이 질문을 기다리는 동안 시험이 같은 `state.db`를 읽는다(시나리오 12). 읽기 전용으로 짧게 열고 닫는다. 앱이 막히면(잠김) 시나리오를 바꾸지 말고 멈춰서 보고한다.
- **가정 G가 깨질 수 있다.** pty에서 질문이 뜨지 않거나 `Ctrl+C`가 REPL을 죽이면 그것은 시험이 아니라 **발견**이다. 2-2의 조건(요구사항과 다름, 파일 범위, 인터페이스 불변)을 만족하는 작은 버그면 슬롯에서 고치고, 아니면 멈춰서 보고한다.
- **슬롯의 남용 금지**: 슬롯은 「구현 결과에 맞춰 시나리오를 바꾸는 길」이 아니다. 시나리오 1~21이 실패하면 시나리오가 아니라 구현이 틀린 것이며, 그것이 2-2를 만족하면 시험을 먼저 써 두고(이미 있음) 고친다. 만족하지 않으면 멈춘다.
- **F1의 기대값은 ROADMAP R3 ②의 문장(「그 턴 시간 범위」)에서 나왔다.** 020 구현을 보고 쓴 것이 아니다. 구현에서 시험을 통과시키려고 시나리오를 바꾸지 않는다.
- **시나리오 5(권한·바이트 충실도)가 플랫폼에 기댈 수 있다**: 개행 변환이 없는 POSIX(macOS·Linux)를 전제로 한다. 다른 결과가 나오면 그것이 발견이며 시나리오를 바꾸지 않는다.
- **런처 방식의 가정**: 시나리오 12~21은 「`runpy`가 새로 실행한 `cli`가 이미 바뀐 `hermes_core.llm_client.OpenRouterClient`를 가져온다」에 기댄다(사전 점검 ④). 어긋나면 시나리오가 아니라 런처 설계를 보고한다.
- **헛돌지 않는 시험**: 시나리오 18(`--no-checkpoints`)이 「대본형 모델이 정말 파일을 쓴다」의 대조군이다(쓰기가 일어나지 않았다면 `old.txt`가 `after`일 수 없다).
- **자식 프로세스 정리**: 실패해도 자식이 남지 않게 한다.
- **문서 정정의 범위**: 3절에 적은 문서만 고친다. ADR·로드맵 정책·다른 로드맵·작동원리 README는 건드리지 않고 필요해 보이면 제안으로 보고한다.
- **작동원리 서술은 시험으로 확인한 사실만**: pty 수준의 증거는 「가상 터미널에서 확인」으로 쓰고, 실제 터미널 앱·실제 모델 행동은 「미확인(060)」으로 남긴다. E2E의 모델은 대본이라는 한계를 5부 ③에 밝힌다.
- **미확인**: 실제 터미널 앱에서의 `/rollback` 표시와 출력 섞임(060), 실제 모델의 되돌림 뒤 행동(가정 H), 실사용 저장량(가정 J), `execute_rollback` 중 Ctrl+C.
