## 1. 구현 내용 명세

030까지는 `checkpointer`를 넘기는 앱이 없어서 사용자 경로가 이전과 같았다. 이 단계는 **CLI가 `Checkpointer`를 만들어 디스패처에 넘기고, 사용자 입력 한 번(턴)마다 경계를 알리고, REPL에서 `/rollback`을 가로채 되돌린다.** 켜짐이 기본이고 `--no-checkpoints`로 끈다. 확인 질문은 09의 `read_user_input`을 재사용하고 해석은 승인과 같은 함수(`is_approval_answer`)를 쓴다. **`HermesAgent`·`agent/`·`tools/`(`checkpoint.py`·`dispatcher.py` 포함)·`session_db.py`·`cli_input.py`·`delegate_tool.py`는 바꾸지 않는다**(바꾸는 파일은 `cli.py`와 `constants.py` 추가분뿐). 이 단계의 시험은 가짜 입력·대본형 가짜 모델로 도는 단위 시험이며, 실제 터미널(pty) 시험은 050, 사람이 하는 확인은 060이다.

### 1-2. 인자와 조립 ([`cli.py`](../../../../src/hermes_core/cli.py))

1. **새 인자** `--no-checkpoints` (`store_true`). 도움말: `Disable file checkpoints (write_file/patch changes cannot be rolled back with /rollback)`. `--mock`·`--delegate`·`--no-skills-index`·`--no-approval`과 함께 쓸 수 있다(충돌 없음).
2. **조립**: 실제 모드의 `HERMES_HOME` 고정·작업 폴더 이동 **뒤**(지금 `session_db = SessionDB()`가 있는 자리 근처)에서
   ```text
   checkpointer = Checkpointer(session_db, session_id, Path.cwd()) if not args.no_checkpoints else None
   dispatcher   = create_default_dispatcher(memory_store=…, session_db=…, approver=approver, checkpointer=checkpointer)
   ```
   `Checkpointer`는 `hermes_core.tools.checkpoint`에서, `Path`는 `pathlib`에서 가져온다. `approver`·`HermesAgent(...)` 조립·위임 도구 등록·`finally: agent.session_db.close()`는 **한 줄도 바꾸지 않는다**.
3. **배너**: 승인 안내 줄(`CLI_APPROVAL_*_NOTICE`) **뒤, `Type 'exit' or 'quit' to terminate.` 줄 앞.** 켜졌으면 `CLI_CHECKPOINT_ENABLED_NOTICE` 한 줄, `--no-checkpoints`가 주어졌으면 `CLI_CHECKPOINT_DISABLED_NOTICE` 한 줄(`--no-skills-index`와 같은 방식: 플래그가 주어졌을 때만 「꺼짐」 안내). 이 줄 앞뒤 순서는 기존 시험이 고정한다(`Type 'exit'…` 바로 다음 줄이 다중 행 안내).
4. **턴 경계**: 모의 단발 실행과 REPL의 `agent.run_conversation(...)` **바로 앞**에서 `if checkpointer is not None: checkpointer.begin_turn()`. 두 자리에 같은 한 줄이며 별도 함수로 빼지 않아도 된다(구현 재량. 시험은 호출 결과만 본다).
5. **`/rollback`** (REPL, 1-1의 자리): 가로채는 판정과 처리는 `cli.py` 안의 작은 함수로 둔다(구현 재량. 시험은 입출력만 본다). 처리 순서가 계약이다:
   1. `checkpointer is None` → `CLI_ROLLBACK_DISABLED_NOTICE` 출력 후 REPL로 돌아간다.
   2. 입력에 인자가 있다(토큰이 둘 이상) → `CLI_ROLLBACK_USAGE_NOTICE` 후 돌아간다.
   3. `plan = checkpointer.plan_rollback()`. `plan.items`가 비면 `CLI_ROLLBACK_NOTHING_NOTICE` 후 돌아간다.
   4. 머리말 `CLI_ROLLBACK_HEADER`(`turn_index`=`plan.turn_index`, `restore_count`=`will_skip`가 거짓인 항목 수, `skip_count`=참인 항목 수)와 항목 줄을 `plan.items` 순서대로 출력한다. 항목 줄: `will_skip`이면 `CLI_ROLLBACK_LINE_SKIP`(`reason`=`skip_reason`), 아니면 `before_exists`가 참이면 `CLI_ROLLBACK_LINE_RESTORE`, 거짓이면 `CLI_ROLLBACK_LINE_DELETE`.
   5. 경고: `plan.terminal_approvals_count > 0 or plan.subagent_count > 0`이면 `CLI_ROLLBACK_EXTERNAL_WARNING`. 항목 중 `status == "pending"`이 있으면 `CLI_ROLLBACK_PENDING_WARNING`. 둘 다 질문 앞.
   6. `answer = read_user_input(CLI_ROLLBACK_PROMPT)`. `EOFError`·`KeyboardInterrupt`는 취소로 본다. `is_approval_answer(answer)`가 거짓이면 `CLI_ROLLBACK_CANCELLED_NOTICE` 후 돌아간다(아무것도 바뀌지 않음).
   7. `result = checkpointer.execute_rollback(plan)`. 결과 줄을 `result.items` 순서대로 `action`에 따라 `CLI_ROLLBACK_RESULT_RESTORED`·`_DELETED`·`_SKIPPED`(`reason`=`reason`)로 출력하고, `CLI_ROLLBACK_RESULT_SUMMARY`(`rolled_back`, `skipped`)를 출력한다. `result.rolled_back_count >= 1`이면 마지막에 `CLI_ROLLBACK_MODEL_UNAWARE_NOTICE`(R4)를 출력한다(되돌린 파일이 없으면 모델이 믿을 내용이 바뀌지 않았으므로 출력하지 않는다).
   8. 3~7의 `Exception`은 `CLI_ROLLBACK_ERROR_NOTICE`(`reason`=`str(예외)`)로 처리하고 돌아간다.
6. **거부 알림**: REPL의 `run_conversation` 결과를 받은 직후(`history` 갱신과 `llm_error` 분기 처리 **뒤**), 아직 알리지 않았고 1-1의 판정이 참이면 `CLI_CHECKPOINT_REFUSED_NOTICE`를 출력하고 「알림 완료」를 기억한다. 켜짐이 아니면(`checkpointer is None`) 이 판정을 하지 않는다. 모의 단발 실행에는 넣지 않는다(모의 모델은 쓰지 않음).

### 1-4. 알려진 한계 (시험하지 않고 문서에 남긴다)

- **`prompt_toolkit` 경로에서 `/rollback` 확인 질문이 정상으로 뜨는지**(WHY 가정 G)는 가짜 입력 시험으로 증명되지 않는다. 050(pty)·060(사람)에서 본다(**미확인**).
- **`execute_rollback` 실행 중 Ctrl+C**는 잡지 않는다(`BaseException`). 이때 REPL이 어떻게 끝나는지, 일부만 복원된 상태가 원장에 어떻게 남는지는 **미확인**이며 050·060에서 본다. 복원은 파일마다 원자적이고 행마다 갱신되므로 중단돼도 이미 처리한 행은 `rolled_back`/`skipped`로 남는다(020 구조상의 추정, 실행 확인 전).
- **이전 턴을 되돌릴 때 경고 줄이 어긋날 수 있다(020 동작, 이 단계는 고치지 않는다)**: `plan_rollback`은 승인된 터미널 실행·위임 자식 수를 **가장 최근에 시작한 턴의 시작 시각**부터 센다(`turn_started_at`). 최신 턴을 되돌린 뒤 그 앞 턴을 `/rollback`하면, 앞 턴에서 일어난 터미널·위임은 세어지지 않고(경고 누락) 최신 턴에서 일어난 것이 세어질 수 있다(경고 오탐). 시나리오 17은 최신 턴만 본다. 후속 후보: `plan_rollback`이 대상 턴의 시작 시각을 별도로 보관하거나 턴 구간으로 센다.
- 거부 알림은 **세션당 한 번**이다. 이후 거부는 모델의 도구 결과로만 전달된다(모델이 사람에게 말하도록 `CHECKPOINT_REFUSED_HINT`가 이미 붙어 있음).
- 건너뜀 사유가 한국어라 영어 화면에 한국어가 섞인다(1-1). 020의 문구를 바꾸는 일은 이 단계의 범위가 아니다.
- 위임 자식의 쓰기·터미널 변경은 되돌려지지 않는다(ADR 대안 F). 배너 한 줄과 R3 경고가 알릴 뿐이다.
- 되돌리기 후 만든 파일의 빈 부모 폴더는 남는다(020, ROADMAP 위험 8).

### 1-5. 작동원리·ROADMAP 갱신

없음(050에서 일괄 반영. ROADMAP §4-1 R1 ① 서술 정정은 050).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험은 `tests/test_hermes_core/test_cli_rollback.py`에 둔다. 공통 준비는 `test_cli_approval.py`의 방식을 따른다(파일을 import하지 않고 같은 모양을 새로 둔다): `HERMES_HOME`을 임시 폴더로, `OPENROUTER_API_KEY`를 가짜 값(`sk-or-` 꼴이 **아닌** 문자열. 예: `FAKE-NOT-A-REAL-KEY-0003`)으로 `monkeypatch.setenv`, `cli.OpenRouterClient`를 대본형 가짜 클라이언트로 대체, `monkeypatch.setattr("sys.argv", […])`, 먼저 `monkeypatch.chdir(tmp_path)`로 복원 지점을 만든다. **작업 폴더**는 실제 모드가 `chdir`하는 `HERMES_HOME/workspace`(`get_default_workspace()`)이며, 시험은 `main()` 전에 `get_default_workspace()`를 불러 폴더를 만들고 미리 있어야 할 파일을 둔다. **입력**은 `cli.read_user_input`을 대체한 대본형 가짜: 호출마다 받은 `prompt`를 기록하고, `prompt == CLI_ROLLBACK_PROMPT`이면 준비된 되돌리기 답 목록에서, `prompt == APPROVAL_PROMPT`이면 준비된 승인 답 목록에서, 아니면 사용자 입력 목록(마지막은 `"exit"`)에서 순서대로 돌려준다(목록이 비면 시험 실패, 예외 값은 raise, **호출 가능한 값은 호출해 그 반환 문자열을 쓴다**: 파일을 몰래 고치는 「사람의 손」을 흉내 내는 데 쓴다). 되돌리기 질문이 뜨는 순간 그때까지의 출력(`capsys`)을 따로 저장해 둔다(「질문 앞에 보인 것」 확인용). 대본형 모델은 `write_file`·`patch` 도구 호출을 `MockLLMResponse(tool_calls=[…])`로 요청한 뒤 최종 답을 한다. 「원장 행」은 `main()` 종료 뒤 `HERMES_HOME/state.db`를 새로 열어 `get_file_checkpoints(session_id)`로 읽는다(세션은 `sessions` 표에서 읽음). 기대값은 ADR-0011 §2-5~2-8·§2-10, ROADMAP §2-4·§4·§6-4와 위 명세에서 나왔고 구현 결과를 보고 쓰지 않았다. `sk-or-v1-` 꼴 문자열을 시험 코드에 쓰지 않는다.

## 5. 위험·주의

- **사용자 경로가 처음으로 바뀌는 단계다.** CLI를 실행하면 기본으로 `write_file`·`patch`가 기록되고, 기록하지 못하면 쓰지 않는다(fail-closed). 사람이 보는 동작이 바뀌는 지점이므로 시나리오 9(끈 구성의 도구 결과가 같음)와 23(기존 시험 불변)이 지킨다.
- **작업 폴더 조립을 틀리면 모든 쓰기가 거부된다**: 030의 일치 확인이 막아 주지만 그 결과는 「파일 도구 전체 마비」다. 시나리오 6이 실제 모드의 `chdir` 뒤 조립을 직접 잡는다(첫 쓰기 성공 + 원장 `workspace` 값). 모의 모드는 `chdir`하지 않으므로 6과 달리 시험이 작업 폴더를 임의로 정해야 한다. 모의 모드의 쓰기는 시나리오에 넣지 않았다(모의 모델이 쓰기를 하지 않음, 8은 경계 호출만 본다).
- **턴 경계를 빠뜨리면 쓰기가 「Turn has not begun」으로 거부된다**: 시나리오 6·7·8이 세 자리(REPL, 빈 입력·`/rollback`이 소비하지 않음, 모의 단발)를 본다. 새 `run_conversation` 호출 자리를 나중에 더하면 같은 한 줄을 더해야 한다(후속 로드맵의 주의).
- **`--no-checkpoints`의 `/rollback` 가로채기는 「기능 없는 구성은 지금과 같다」의 예외다**(1-1). 가정 A(파일 도구 동작)는 영향이 없지만 마감 때 가정 A 대조에 이 예외를 적는다. 원치 않으면 구현 전에 알린다(그러면 `--no-checkpoints`에서는 `/rollback`이 모델 입력으로 간다).
- **`/rollback` 확인에서 취소는 하지 않음이다**(시나리오 12·13). 구현 중 결과가 다르면 시나리오를 바꾸지 말고 멈춰서 보고한다. 승인 흐름(10)과 같은 해석 함수를 쓰므로 어긋나면 입력 경로의 버그다.
- **거부 알림의 판정은 문자열 포함(꼬리 문구)에 기댄다**: 030이 거부 3종에 붙인 `CHECKPOINT_REFUSED_HINT`가 바뀌면 알림이 조용히 사라진다. 시나리오 21이 이 결합을 잡는다(문구를 바꾸는 쪽이 이 시험을 깨뜨리게 된다).
- **이전 턴을 되돌릴 때 R3 경고가 어긋날 수 있다**(1-4). 020의 동작이며 이 단계는 고치지 않는다. 마감 때 ROADMAP R3 해결책과 대조해 결과정리에 적는다.
- **키는 대화·명령줄에 쓰지 않는다**: 시나리오의 키는 가짜 값이며 실제 키가 필요한 단계는 060뿐이다.
- **미확인**: 실제 터미널(`prompt_toolkit`)에서 `/rollback` 질문이 정상으로 뜨고 y/n이 전달되는지(가정 G), `execute_rollback` 중 Ctrl+C 동작, 되돌린 뒤 실제 모델의 반응(가정 H). 이 단계 시험은 가짜 입력·대본형 모델만 쓴다.
