## 1. 구현 내용 명세

원장(010) 위에 **체크포인트 비즈니스 로직 모듈**([`src/hermes_core/tools/checkpoint.py`](../../../../src/hermes_core/tools/checkpoint.py))을 신설한다.
이 모듈은 CLI와 디스패처 사이에서 턴 경계를 관리하고, 파일 도구 실행 전후의 상태 기록·확정을 주관하며, `/rollback` 요청 시 안전한 되돌리기 계획을 수립하고 실행한다.

### 1-1. 상수 정의 ([`constants.py`](../../../../src/hermes_core/constants.py))

체크포인트 절에 상한 및 메시지 상수를 추가한다:
- `CHECKPOINT_SESSION_BYTES_LIMIT = 50_000_000` (세션당 `before_content` 누적 50MB 상한, 위험 R5 / 가정 J)
- `CHECKPOINT_LIMIT_ERROR_MESSAGE = "Checkpoint storage limit exceeded ({limit} bytes). The file was not modified."`
- `CHECKPOINT_PRE_RECORD_FAILED_MESSAGE = "Failed to record checkpoint before modification ({reason}). The file was not modified."`

### 1-2. 데이터 클래스 ([`src/hermes_core/tools/checkpoint.py`](../../../../src/hermes_core/tools/checkpoint.py))

```python
@dataclass(frozen=True)
class RollbackItem:
    """단일 파일의 되돌리기 계획 항목."""
    checkpoint_id: int
    tool_name: str
    workspace: str
    rel_path: str
    before_exists: bool
    before_content: Optional[str]
    after_sha256: Optional[str]
    status: str
    will_skip: bool
    skip_reason: Optional[str] = None

@dataclass(frozen=True)
class RollbackPlan:
    """되돌리기 계획 (실제 파일 복원 전 검토용)."""
    session_id: str
    turn_index: int
    items: tuple[RollbackItem, ...]
    terminal_approvals_count: int = 0
    subagent_count: int = 0
    has_warnings: bool = False

@dataclass(frozen=True)
class RollbackItemResult:
    """단일 파일 복원 실행 결과."""
    checkpoint_id: int
    rel_path: str
    action: str            # "restored" | "deleted" | "skipped"
    status: str            # "rolled_back" | "skipped"
    reason: Optional[str] = None

@dataclass(frozen=True)
class RollbackResult:
    """되돌리기 실행 종합 결과."""
    session_id: str
    turn_index: int
    rolled_back_count: int
    skipped_count: int
    items: tuple[RollbackItemResult, ...]
```

### 1-3. `Checkpointer` 클래스

```python
class Checkpointer:
    def __init__(
        self,
        db: SessionDB,
        session_id: str,
        workspace: Optional[Path] = None,
        *,
        bytes_limit: int = CHECKPOINT_SESSION_BYTES_LIMIT,
    ):
        ...
```

- **상태 관리**:
  - `self.db`, `self.session_id`, `self.workspace` (None이면 `get_default_workspace()`)
  - `self.bytes_limit`: 세션당 바이트 상한
  - `self.turn_index = 0`: 현재 턴 번호
  - `self.turn_started_at = 0.0`: 턴 시작 시각 (위험 R3)
  - `self._session_before_bytes = 0`: 세션 내 누적 기록 바이트 수

- **메서드 계약**:

1. `begin_turn(self, turn_index: Optional[int] = None) -> int`:
   - 턴 경계를 설정한다. `turn_index`가 지정되면 1 이상 정수 검증 후 설정, 생략 시 `self.turn_index + 1`.
   - `self.turn_started_at = time.time()`
   - 현재 턴 번호를 반환한다.

2. `record_before(self, tool_name: str, path: str) -> Optional[int]`:
   - 파일 도구(`write_file`, `patch`) 실행 전 상태를 읽고 원장에 선기록(`pending`)한다.
   - 턴 검사: `self.turn_index >= 1`이 아니면 `ValueError("Turn has not begun")`.
   - 도구명 검사: `CHECKPOINT_TOOL_NAMES`에 포함되지 않으면 `ValueError`.
   - **경로 판정 (위험 R1)**: `resolve_workspace(self.workspace)` 후 `check_write_path(path, resolved_ws)` 수행.
     - 판정 실패(`ok is False`)면 원장에 기록하지 않고 `None` 반환 (도구 본체가 동일 사유로 거부하도록 유도).
   - **바뀌기 전 상태 읽기**:
     - `resolved_path.exists()`:
       - 일반 파일이 아니면 `None` 반환.
       - 파일 크기 `FILE_MAX_BYTES` 초과 시 `None` 반환 (도구 본체 거부 대상).
       - 원시 바이트 읽은 후 UTF-8 디코드.
       - `before_exists = True`, `before_content = text`.
       - 바이트 수 `bytes_count = len(text.encode("utf-8"))`.
     - 부재 시:
       - `before_exists = False`, `before_content = None`, `bytes_count = 0`.
   - **세션 누적 상한 검사 (위험 R5 / 가정 J)**:
     - `self._session_before_bytes + bytes_count > self.bytes_limit`이면 `CheckpointLimitError` 예외 발생.
   - **원장 선기록**:
     - `rel_path = resolved_path.relative_to(resolved_ws).as_posix()`
     - `cid = self.db.record_file_checkpoint(...)` (pending, 즉시 커밋).
     - `self._session_before_bytes += bytes_count`
     - 생성된 `cid` 반환.

3. `finalize(self, checkpoint_id: Optional[int], tool_name: str, path: str, result_success: Optional[bool] = None, exception: Optional[Exception] = None) -> str`:
   - 도구 실행 후 **파일 상태를 직접 검사하여** 원장을 `applied` 또는 `failed`로 확정한다 (ROADMAP §6-3 / 위험 16).
   - `checkpoint_id is None`: (선기록 생략 건) 아무 작업 없이 `"none"` 반환.
   - 파일 재검사:
     - `resolved_ws = resolve_workspace(self.workspace)`
     - `ok, _, resolved_path = check_write_path(path, resolved_ws)`
     - 판정 실패 또는 접근 예외 시: `self.db.update_file_checkpoint(checkpoint_id, "skipped", reason="결과 확인 실패")` 후 `"skipped"` 반환 (위험 17).
   - 파일 상태 대조:
     - 원장에서 해당 행 조회 (`get_file_checkpoints`). 행이 없거나 `pending`이 아니면 `"invalid"`.
     - `resolved_path.exists()`:
       - 파일 원시 바이트 읽기 및 SHA-256 해시 계산.
       - If `before_exists == 0`: 없던 파일이 생김 → **`applied`** (`after_sha256=sha256`).
       - If `before_exists == 1`:
         - 파일 바이트와 `before_content.encode("utf-8")` 비교:
           - 다르면 내용 변경 성공 → **`applied`** (`after_sha256=sha256`).
           - 같으면 내용 변경 없음 (도구 실패) → **`failed`** (`reason="내용 미변경"`).
     - `not resolved_path.exists()`:
       - If `before_exists == 0`: 없던 파일이 여전히 없음 → **`failed`** (`reason="파일 미생성"`).
       - If `before_exists == 1`: 있던 파일이 사라짐 → **`failed`** (`reason="파일 소실"`).
     - 교차 확인: `result_success`가 제공되었는데 파일 상태 판정과 다르면 reason에 불일치 메모 추가.
     - `self.db.update_file_checkpoint(checkpoint_id, final_status, ...)` 수행.
     - 최종 상태 문자열 반환.

4. `plan_rollback(self, turn_index: Optional[int] = None) -> RollbackPlan`:
   - 되돌리기 계획 수립. 파일 시스템을 수정하지 않는다.
   - 대상 턴 결정: `turn_index` 미지정 시, 최근 턴 중 `applied` 또는 `pending` 행이 존재하는 가장 높은 턴 번호 선택. 대상 행이 없으면 `items`가 빈 계획 반환.
   - 대상 턴의 체크포인트 행을 조회하여 **`id` 내림차순(역순)** 정렬.
   - 각 행에 대해 충돌·경로 판정 (위험 R1, R2, 가정 C, D, E):
     - `resolved_ws = resolve_workspace(self.workspace)`
     - 작업 폴더 불일치: `row["workspace"] != str(resolved_ws)` → `will_skip=True`, `skip_reason="작업 폴더 불일치"`
     - 경로 재판정: `check_write_path(row["rel_path"], resolved_ws)` 실패 → `will_skip=True`, `skip_reason="경로 재판정 실패"`
     - `row["status"] == "pending"` (위험 R2): 절대 복원 불가 → `will_skip=True`, `skip_reason="결과 모름(pending)"`
     - `row["status"] == "applied"`:
       - `target_path = resolved_ws / row["rel_path"]`
       - 대상 파일 존재 시:
         - 현재 내용의 SHA-256 계산.
         - `current_sha256 == row["after_sha256"]`: 충돌 없음 → `will_skip=False`.
         - 다르면 외부 변경 충돌 → `will_skip=True`, `skip_reason="충돌(외부 변경)"`.
       - 대상 파일 부재 시:
         - `will_skip=True`, `skip_reason="충돌(파일 부재)"`.
     - 그 외 상태(`failed`, `rolled_back`, `skipped`): 대상 제외.
   - 부가 위험 정보 수집 (위험 R3):
     - 턴 시작 시각(`self.turn_started_at`) 이후 승인된 터미널 요청 수 조회 (`approval_requests`에서 `decision='approved' AND decided_at >= turn_started_at`).
     - 해당 세션의 서브에이전트 자식 세션 수 조회 (`sessions`에서 `parent_session_id = session_id AND started_at >= turn_started_at`).
     - 경고 여부: 터미널 승인 > 0 또는 자식 세션 > 0 또는 pending 행 존재 시 `has_warnings = True`.
   - `RollbackPlan` 반환.

5. `execute_rollback(self, plan: RollbackPlan) -> RollbackResult`:
   - 계획에 따라 실제 파일을 복원하고 원장 상태를 갱신한다.
   - `plan.items`를 순서대로(이미 `id` 역순):
     - `if item.will_skip`:
       - `self.db.update_file_checkpoint(item.checkpoint_id, "skipped", reason=item.skip_reason)`
       - skipped 카운트 증가.
     - `else`:
       - **복원 직전 재판정 (원자적 다층 방어)**:
         - 경로 재확인 및 현재 해시 대조 (계획과 실행 사이 변경 방어).
         - 불일치 시 `skipped` 처리.
       - **복원 쓰기/삭제**:
         - `resolved_path = Path(item.workspace) / item.rel_path`
         - `if item.before_exists`:
           - 기존 파일 권한 보존: `st_mode = resolved_path.stat().st_mode`
           - 임시 파일 작성 후 `os.replace` 원자적 교체, 권한 복원 (위험 9).
           - `action = "restored"`
         - `else`:
           - 파일 삭제: `resolved_path.unlink(missing_ok=True)` (위험 8: 부모 폴더 보존).
           - `action = "deleted"`
       - 원장 갱신: `self.db.update_file_checkpoint(item.checkpoint_id, "rolled_back", reason="되돌림")`.
       - rolled_back 카운트 증가.
   - `RollbackResult` 반환.
