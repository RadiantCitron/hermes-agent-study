## 1. 마감 개요

- **목표 달성**: 에이전트가 `write_file` 또는 `patch`로 작업 폴더 안의 파일을 생성·수정하기 직전의 파일 상태(내용 및 SHA-256 해시)를 SQLite 원장(`file_checkpoints`)에 선기록하고, 사용자가 REPL에서 `/rollback` 명령 한 번으로 직전 턴의 변경 사항을 바이트 단위로 정확히 되돌릴 수 있는 안전 롤백 MVP 구축 완료.
- **핵심 안전망**:
  1. **사전 선기록 원장 (Write-Before-Change)**: 파일이 수정되거나 생성되기 직전의 원본 상태를 `pending` 상태로 SQLite에 먼저 트랜잭션 기록하여, 기록 실패 시 쓰기 자체를 거부(`CLI_CHECKPOINT_REFUSED_NOTICE`).
  2. **외부 변경 충돌 보호 (External Edit Guard)**: 에이전트가 작업한 후 사람이 외부에서 파일을 고친 경우(`current_hash != after_hash`), 사용자의 작업을 덮어쓰지 않고 해당 파일만 건너뜀(`[skip]`, `skipped`) 처리.
  3. **보호 경로 및 바닥 가드 (Fail-Safe Scope)**: `.env*`, `.git` 등 보호 파일 및 작업 폴더 밖 경로(`is_protected_path`)는 체크포인트 원장 기록 자체를 거부하며 롤백 시에도 엄격히 차단.
  4. **승인·위임 공존 알림**: 롤백 대상이 순수 파일 도구로 제한됨에 따라, 같은 턴에 실행된 터미널 명령이나 위임 자식 에이전트가 있을 경우 질문 직전에 "혼합 상태(Mixed State)" 경고를 명확히 출력.
- **정량 성과**: 전체 823건 단위/통합 회귀 테스트 100% 통과 (기준선 708건 대비 +115건 신규 검증), pty 기반 가상 터미널 24개 시나리오 전수 통과, 실제 모델(`deepseek/deepseek-v4-flash-0731`) 터미널 실기 스모크 수행을 통한 파일 복원 및 모델의 독특한 보상 행동(Self-Healing Trap) 실증 관찰.

## 2. 목표와 결과 (`WHY.md` 가정 A~J 전수 대조)

[WHY.md](WHY.md)에서 수립한 10개 핵심 가정(A~J)을 단위 시험, pty 가상 터미널 통합 시험, 실제 모델 터미널 스모크 결과와 1:1로 대조했습니다.

| 가정 | 내용 | 판정 | 대조 결과 및 근거 |
|---|---|---|---|
| **가정 A** | 체크포인트 기능이 없는 구성(`--no-checkpoints`, 라이브러리 기본, 위임 자식)에서는 파일 도구가 지금과 똑같이 동작하고, 기존 시험이 깨지지 않는다 | **맞았다** | `Checkpointer(enabled=False)` 또는 `--no-checkpoints` 옵션 주입 시 시작 배너에 `File checkpoints: DISABLED` 알림 출력, 파일 도구는 기록 오버헤드 없이 원본 그대로 실행되며 `/rollback` 입력 시 모델 호출 없이 `File checkpoints are disabled...`로 안전 안내됨을 pty(시나리오 20) 및 회귀 테스트에서 입증. |
| **가정 B** | 파일 도구가 성공한 모든 변경은 바뀌기 **전에** 기록되고, 기록하지 못하면 파일이 바뀌지 않으며 모델에게 실패가 돌아간다 | **맞았다** | `record_before_change()`를 통해 파일 변경 직전 원본 스냅샷을 원장에 `pending`으로 선기록. DB 기록 실패 시 `ToolError`를 발생시켜 파일 쓰기 자체를 중단하고 `CLI_CHECKPOINT_REFUSED_NOTICE`를 모델에 전달(단위 테스트 `test_checkpointer_failure.py`, 시나리오 1~6). |
| **가정 C** | `/rollback` 한 번이 가장 최근 턴의 변경만 되돌린다. 만든 파일은 사라지고 고친 파일은 바이트 단위로 원래 내용이 된다. 다시 치면 그 앞 턴이 되돌려진다 | **맞았다** | **실제 모델 스모크 R1**: `notes.txt` 생성(`hello world`) 후 `patch`로 `HELLO` 변경한 뒤 `/rollback` 입력 시 `restored notes.txt`를 거쳐 바이트 단위 복원 확인. 단위/pty 시험(시나리오 12~14)에서 생성 파일의 `[delete]` 및 수정 파일의 `[restore]`, 다중 턴 순차 롤백(`turn 3` → `turn 2` → `turn 1`) 전수 확인. |
| **가정 D** | 에이전트가 쓴 뒤 사람이나 터미널 명령이 다시 고친 파일은 되돌리지 않고 「건너뜀」으로 보고하며, 같은 턴의 나머지 파일은 되돌린다 | **맞았다** | pty 시나리오 16: 에이전트가 생성한 `a.txt`와 `b.txt` 중 `a.txt`를 외부에서 수정한 경우, `a.txt`는 `[skip]` 및 `skipped (외부 변경 충돌)`로 보존하고 `b.txt`만 `deleted`로 정상 삭제됨을 검증. 충돌 행도 `skipped`로 원장에 확정되어 재롤백 방지. |
| **가정 E** | 되돌리기도 작업 폴더 밖, 보호 파일, 쓰기 금지 파일을 건드리지 않는다 | **맞았다** | pty 시나리오 18: `.env` 등 보호 파일 쓰기 요청은 파일 도구 계층에서 원천 거부되어 원장에 등록되지 않으며, `rollback_turn()` 시에도 `is_protected_path()`와 워크스페이스 경계 검사를 수행하여 안전 보장. |
| **가정 F** | 기록과 쓰기 사이에 실패나 중단이 있어도 원장과 실제 파일 상태가 되돌리기를 틀리게 만들지 않는다 | **맞았다** | 020에서 정립된 `confirm_applied()` 2단계 커밋 구조 채택. 도구 실행이 실패하거나 중단되어 `pending`으로 남은 행은 `plan_rollback()`에서 무시되므로, 불완전한 기록이 롤백 계획을 오염시키지 않음(시나리오 8). |
| **가정 G** | 실제 터미널에서 `/rollback`의 목록·확인 질문이 정상으로 뜨고 y/n이 전달되며, 그 뒤 REPL이 이어진다 | **맞았다** | 실제 터미널 및 pty 환경(시나리오 12~15)에서 `Rolling back turn N: ...`, `[restore] notes.txt`, `Roll back these changes? [y/N]` 프롬프트가 깨짐 없이 정상 출력되고, `y`/`n`/빈 엔터/`Ctrl+C`/`Ctrl+D` 취소 입력 후 다음 `User >` 프롬프트로 깔끔하게 복구됨을 확인. |
| **가정 H** | 되돌린 뒤 실제 모델이 옛 내용을 전제로 고치려 하면 어떻게 되는가 | **새로운 발견 (자가 치유 함정: Self-Healing Trap)** | **실제 모델 스모크 관찰**: 파일이 롤백되어 `hello world`로 복원된 상태에서 사용자가 `cat`을 요청하자, 모델은 이전 턴의 목표(HELLO로 변경)와 파일 내용의 불일치를 보고 *"앞선 패치 반영 지연"*으로 오판하여 **자발적으로 `patch`를 다시 실행해 다시 `HELLO`로 덮어씌움**! 롤백 사실이 모델 컨텍스트에 주입되지 않을 때 모델이 자가 치유(Self-Healing)를 시도하다 롤백을 무효화하는 현상을 최초 실증 발굴함. |
| **가정 I** | 새 부품이 파일 도구 외의 부분(에이전트 루프, 터미널과 승인, 압축, 위임, 입력)에 영향을 주지 않는다 | **맞았다** | `agent/agent.py`, `terminal_tool.py`, `skills_tool.py` 등 핵심 모듈 diff 0줄 유지. 기존 708건 테스트를 포함한 823건 회귀 테스트 전수 무수정 통과. |
| **가정 J** | 한 대화에서 쌓이는 기록의 양이 실사용에서 문제가 되지 않는다 (파일당 1MB 상한) | **맞았다** | `MAX_CHECKPOINT_FILE_SIZE_BYTES = 1,048,576` 상한 적용. 텍스트 파일 수정 위주의 세션에서 SQLite `file_checkpoints` 테이블 증가량은 수 KB~수십 KB 수준에 불과하여 대화 기록 대비 오버헤드가 극히 경미함. |

## 3. 단계별 구현 및 상세 (Why 중심)

### 010: 체크포인트 원장 (`file_checkpoints` 표, 스키마 v6, `SessionDB` 메서드)
- **무엇을**: SQLite 스키마 버전 6 상향, `file_checkpoints` 테이블 및 복합 인덱스(`(session_id, turn_index, id)`) 추가, `record_checkpoint_pending`, `confirm_checkpoint_applied`, `mark_checkpoint_resolved`, `get_checkpoints_for_turn` 메서드 구현.
- **왜**: 파일 변경 전 원본 상태를 상태 DB에 영구 기록하여 프로세스가 비정상 종료되더라도 원자성을 추적할 수 있어야 하며, `pending` → `applied` → `rolled_back`/`skipped`의 단방향 생명주기를 통해 데이터 무결성을 보장하기 위함입니다.
- **결과**: `SessionDB` 체크포인트 스토리지 엔진 완성. 단위 시험 12개 통과, 회귀 720건 통과.

### 020: 체크포인터 모듈 (`Checkpointer`, 복원 계획, 충돌 판정, 상한 가드)
- **무엇을**: `src/hermes_core/tools/checkpoint.py` 신규 모듈 작성, `Checkpointer` 클래스, `@dataclass(frozen=True)` 데이터 모델(`CheckpointPlan`, `CheckpointItem`, `RollbackResult`), 파일당 1MB 상한, SHA-256 해시 검증, 외부 변경 감지 충돌 로직 구현.
- **왜**: 도구 실행 계층이나 CLI 화면과 완전히 독립된 순수 도메인 모듈로 롤백 계획 및 복원 로직을 격리하여, 화면 표시 없이도 파일 복원 및 충돌 건너뛰기를 100% 독립 테스트할 수 있도록 설계했습니다.
- **결과**: 순수 체크포인터 도메인 완성. 단위 시험 22개 통과, 회귀 742건 통과.

### 030: 파일 도구 연동 (도구 래퍼, 선기록 가드, 거부 알림, 디스패처 팩토리)
- **무엇을**: `file_tools.py` 원본을 수정하지 않고 `checkpoint.py`의 `wrap_file_tools_with_checkpoints`를 통해 데코레이트, `write_file` 및 `patch` 실행 전 `record_before_change()` 호출 및 실패 시 쓰기 원천 거부(`CLI_CHECKPOINT_REFUSED_NOTICE`).
- **왜**: 기존 파일 도구의 코드 무결성을 유지하면서, "기록되지 않으면 쓰지 않는다(No Write Without Log)"는 대원칙을 엄격히 강제하고 위임 자식 에이전트 등 비대상 환경과의 선택적 결합을 투명하게 유지하기 위함입니다.
- **결과**: 파일 도구-체크포인터 무결성 결합 완성. 단위 시험 28개 통과, 회귀 770건 통과.

### 040: CLI 연동 (명령어 파싱, `--no-checkpoints`, `/rollback` 대화형 흐름, 배너, 상태 표시)

- **결과**: 823건 회귀 테스트 100% 통과 및 기술 문서 정본 동기화 완료.

## 4. 미흡한 부분 및 새로 발견한 사실

### 1. 자가 치유 함정 (Self-Healing Trap, 가정 H 실증)
- **현상**: 사용자가 `/rollback`을 통해 `notes.txt`를 이전 상태(`hello world`)로 복원한 뒤 단순히 `cat`으로 확인을 요청했을 뿐인데, 모델은 자신의 대화 기록(이전 턴에서 분명 HELLO로 고쳤다는 기억)과 실제 파일 내용 사이의 불일치를 "앞선 패치의 누락 또는 지연"으로 오판하고, **스스로 다시 `patch`를 호출하여 원복을 무력화**시켰습니다.
- **원인**: 본 로드맵은 MVP 범위(WHY.md §2)에 따라 "되돌렸다는 사실을 모델에게 알리지 않는 방식"을 택했습니다. 그러나 실제 고지능 LLM은 환경 상태의 불일치를 감지하면 스스로 바로잡으려는 적극적인 성향을 보입니다.
- **시사점**: 롤백이 진정한 의미의 안전망으로 완성되려면, 파일 시스템 롤백뿐만 아니라 **모델 컨텍스트 동기화(해당 턴의 어시스턴트 메시지 Pruning 또는 롤백 이벤트 시스템 메시지 주입)**가 반드시 동반되어야 함을 강력하게 입증했습니다.

### 2. 다중 턴 롤백 시 외부 이벤트 윈도우 분리의 중요성 (050 F1 수정)
- `Checkpointer`가 단일 `turn_started_at`만 들고 있을 경우, 턴 2에서 턴 1을 되돌릴 때 턴 1의 터미널 실행 경고가 누락되는 회귀 결함이 발견되었습니다. 턴별 시작 시각을 딕셔너리(`_turn_start_times[turn_index]`)로 구간 관리함으로써 다중 턴 롤백의 정밀도를 확보했습니다.

## 5. 차기 로드맵 제안 (Next Steps)

1. **모델 컨텍스트 롤백 동기화 (Context Pruning / Rollback Notice)**:
   - `/rollback` 성공 시 모델의 대화 메모리(메시지 리스트)에서 롤백된 턴의 어시스턴트 도구 호출 및 응답을 잘라내거나(Pruning), `[System] File rollback was executed. Previous changes were undone.` 시스템 알림을 주입하여 모델의 자발적 재패치(Self-Healing Trap)를 방지.
2. **선택적 롤백 및 차이 보기 (Diff & Selective Rollback)**:
   - 되돌리기 전 `unified diff` 형태로 변경 내용을 미리 보여주는 `/diff` 기능 및 특정 파일만 선택하여 되돌리는 옵션 제공.
3. **체크포인트 정리 주기 및 세션 관리 (Retention Policy)**:
   - 대화 세션 종료 시 오래된 체크포인트 스냅샷 정리 또는 영구 보관용 태그 기능.

## 6. 결론

로드맵 11은 에이전트의 파일 조작 위험에 대응하는 실질적인 "실행 취소(Undo)" 안전망을 구축했습니다.
SQLite 원장 선기록 기반의 2단계 확정 구조, 외부 수정 충돌 방지, 1MB 가드, fail-closed 설계를 통해 파일 도구의 안전성을 극대화했으며, 실제 모델 스모크를 통해 자가 치유 함정(Self-Healing Trap)이라는 귀중한 에이전트 행동학적 통찰을 획득하며 성공적으로 마감합니다.
