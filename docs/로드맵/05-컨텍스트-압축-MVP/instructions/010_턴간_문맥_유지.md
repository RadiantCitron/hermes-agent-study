## 1. 구현 내용 명세

1. **CLI 이력 전달** ([`cli.py`](../../../../src/hermes_core/cli.py)):
   - REPL 루프 밖에 `history = None`을 둔다.
   - 매 턴 `agent.run_conversation(user_input, conversation_history=history)`를 호출하고, 호출 뒤 `history = result["messages"]`로 갱신한다. 정상 종료·`llm_error`·`max_iterations` 어느 경우에도 갱신한다(DB와 일치 유지).
   - 입력·출력 형식, 종료 처리, Mock 단발 실행 경로는 바꾸지 않는다.
2. **에이전트는 바꾸지 않는다.** `conversation_history`가 있으면 system 메시지를 추가하지 않는 기존 분기를 그대로 쓴다(이력의 첫 요소가 system이다).
3. **작동원리 갱신**: 없음 (060에서 일괄 반영).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: 04의 `test_cli.py` 시나리오 08처럼 REPL 입력 두세 개를 주입하고 가짜 모델(`MockLLMClient` 또는 `LLMResponse`를 돌려주는 가짜)의 `call_history`를 관찰한다. 키·네트워크 없음.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | REPL 입력 `"내 이름은 철수야"` → `"내 이름이 뭐지?"` → `exit` | 두 번째 모델 호출의 `messages`에 첫 턴의 user 메시지 `"내 이름은 철수야"`와 첫 턴의 assistant 응답이 포함됨 |
| 2 | 위 시나리오의 두 번째 호출 `messages` | `role == "system"`인 메시지가 **정확히 1개**이고 첫 요소 |
| 3 | 세 턴 입력 | 세 번째 호출 `messages`에 앞선 두 턴이 모두 순서대로 있고 system은 여전히 1개 |
| 4 | 첫 턴에 도구 호출이 있는 응답(assistant tool_calls → tool 결과 → 최종 응답) 후 두 번째 턴 | 두 번째 호출 `messages`에 도구 호출 assistant 메시지와 대응하는 tool 메시지가 모두 있음(짝 유지) |
| 5 | 첫 턴이 `LLMError`로 끝난 뒤 두 번째 턴 | 프로세스가 죽지 않고, 두 번째 호출 `messages`에 첫 턴의 user 메시지가 있으며, 세션 DB의 user 행 수와 이력의 user 메시지 수가 일치 |
| 6 | 빈 입력(공백) 후 정상 입력 | 빈 입력은 이력에 영향 없음(기존 동작), 모델 호출 횟수 변화 없음 |
| 7 | Mock 비대화형 단발 실행(기존 경로) | 기존과 동일하게 1턴 실행 후 종료, 출력 문구 불변 |
| 8 | 기존 코어 테스트(04 마감 시점 전체) | **수정 없이** 통과 |
