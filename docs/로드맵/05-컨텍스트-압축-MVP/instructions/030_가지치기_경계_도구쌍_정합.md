## 1. 구현 내용 명세

모두 **LLM 없는 순수 함수**다. 입력 `messages`를 변경하지 않고 새 목록을 돌려준다.

1. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py)): `COMPRESSION_HEAD_MESSAGES = 3`, `COMPRESSION_MIN_TAIL_MESSAGES = 6`(`COMPRESSION_TAIL_TOKENS`는 020에서 정의), `TOOL_OUTPUT_CLEARED_FORMAT`(`"[Old tool output cleared: {tool}, {chars}자]"` 형태 표지).
2. **신규 모듈** `src/hermes_core/agent/compression.py` (이 단계는 아래 함수만):
   - `prune_old_tool_results(messages, keep_from: int) -> list`: 인덱스 `keep_from` **앞쪽**의 `tool` 메시지 본문을 표지로 치환. `tool_call_id`·`tool_name`·assistant의 호출 인자는 보존. 이미 표지인 메시지는 그대로(멱등). 빈 본문도 그대로.
   - `split_for_compression(messages, head_messages, tail_tokens, min_tail_messages) -> Optional[tuple[list, list, list]]`: `(head, middle, tail)` 반환. 헤드는 system(있으면) + 이어지는 `head_messages`개(**호출자가 0을 넘기면 system만**: 이전 요약이 이미 있으면 초기 턴이 영구히 남지 않도록 040이 0을 넘긴다). 테일은 뒤에서부터 `tail_tokens` 예산(020의 추정 사용)까지이되 최소 `min_tail_messages`개와 **가장 최근 user 메시지**를 포함. 경계 정렬: 헤드 끝이 tool_calls를 가진 assistant이고 그 결과 `tool` 메시지가 뒤에 이어지면 결과까지 헤드로 포함, 테일 시작이 `tool` 메시지이면 부모 assistant까지 테일에 포함. `middle`이 비어 있으면 `None`.
   - `sanitize_tool_pairs(messages) -> list`: 대응하는 assistant 호출 없는 `tool` 결과 제거, 결과 없는 assistant `tool_calls` 항목 제거(해당 assistant의 `tool_calls`가 모두 사라지고 `content`도 비면 `content = "(tool call removed)"`), 마지막 assistant의 진행 중 호출은 보존(뒤에 결과가 아직 없어도 마지막 메시지이면 유지).
3. **작동원리 갱신**: 없음.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

표기: `S`=system, `U`=user, `A`=assistant(텍스트), `A*`=assistant(tool_calls), `T`=tool 결과. 호출 id는 쌍마다 고유.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `keep_from` 앞쪽 `T` 3개(본문 각 1,000자), 뒤쪽 `T` 1개 | 앞쪽 3개 본문이 표지(도구명·글자 수 포함)로 바뀌고 `tool_call_id`·`tool_name` 유지, 뒤쪽 `T`는 원문 그대로 |
| 2 | 같은 입력에 `prune_old_tool_results`를 두 번 적용 | 두 번째 결과 == 첫 번째 결과 (멱등) |
| 3 | 입력 `messages` 리스트와 그 안의 dict | 함수 호출 전후로 변경 없음 |
| 4 | `[S,U,A,U,A,U,A,U,A,U,A,U]` + 헤드 3, 최소 테일 4, 예산 큼 | 헤드 = `S`+앞 3개, 테일 = 마지막 4개 이상(마지막 `U` 포함), 중간 = 나머지, `head+middle+tail == 원본`(순서·내용 동일) |
| 5 | 길이가 헤드+최소 테일 이하인 짧은 대화 | `None` (압축하지 않음) |
| 6 | 헤드 3번째가 `A*`이고 그 결과 `T`가 4번째 | 헤드가 `T`까지 포함하여 쌍이 쪼개지지 않음 |
| 7 | 테일 후보의 첫 메시지가 `T`(부모 `A*`는 중간에 있음) | 테일이 부모 `A*`부터 시작 |
| 8 | 가장 최근 `U` 뒤에 긴 `A*`/`T` 연속(토큰 예산 초과) | 테일에 가장 최근 `U`가 항상 포함됨 |
| 9 | 모든 분할 결과(시나리오 4·6·7·8)의 `head+middle+tail` 각각 | `sanitize_tool_pairs` 적용 없이도 `T`의 `tool_call_id`가 앞선 `A*` 호출 id와 대응(짝 불변식) |
| 10 | 중간을 제거한 `head+tail`을 `sanitize_tool_pairs`에 통과 | 짝 없는 `T`가 없고 결과 없는 호출 항목이 없음 |
| 11 | `A*` 두 호출 중 하나의 결과 `T`만 남은 경우 | 결과 없는 호출 항목만 제거되고 남은 호출·결과 짝은 유지 |
| 12 | `A*`의 모든 호출이 제거되고 `content`가 `None` | `content == "(tool call removed)"`, `tool_calls` 키 없음(또는 비어 있음) |
| 13 | 마지막 메시지가 결과 없는 `A*`(진행 중) | 그대로 보존 |
| 14 | `S`가 없는 입력(이력만) | 오류 없이 분할, 헤드는 앞 `head_messages`개 |
| 15 | 헤드의 `S` 메시지 내용 | 분할 전후 바이트 동일(시스템 프롬프트 불변) |
| 16 | `head_messages=0`으로 분할 | 헤드가 `S`뿐(또는 `S`가 없으면 빈 헤드), 나머지가 중간+테일 |
| 17 | `tail_tokens`를 매우 작게(예: 1) 하고 `min_tail_messages=4` | 테일은 토큰 예산과 무관하게 최소 4개 + 가장 최근 `U`를 포함 |
| 18 | 모든 메시지가 테일 예산 안에 들어가는 대화(중간 없음) | `None` |
| 19 | 기존 코어 테스트 | **수정 없이** 통과 |
