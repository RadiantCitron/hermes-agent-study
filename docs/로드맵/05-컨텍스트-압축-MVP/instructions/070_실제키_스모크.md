# [구현지시서 070] 실제 키 스모크 1회 (사용자 지시가 있을 때만 실행)

> **상위 대시보드**: [05-README.md](../README.md)  
> **선행 조건**: 060 단계 완료 (`Done`) **그리고 사용자의 명시적 실행 지시**  
> **근거**: [WHY.md](../WHY.md) 가정 B·C·D·E, [ADR-0005](../../../adr/0005-컨텍스트_압축_MVP_범위와_세션_연결_방식.md) §2-4  
> **성격**: 코드를 바꾸지 않는 **실행·검증 단계**다. 지시서는 절차와 기대 결과만 정한다. 실행 결과는 대시보드와 종합보고서에 기록한다.

---

## 1. 목적

가짜 통신으로 모든 시험이 통과한 상태에서, **실제 모델로 긴 대화가 낮춘 임계값에서 실제로 압축되고, 압축 뒤에도 모델이 요청을 거절하지 않으며 앞선 사실을 이어서 답하는지**, 그 기록이 남는지, 키가 어디에도 남지 않는지를 확인한다. 가정 B(짝 정리로 400 회피), C(요약 품질), D(요약 반영), E(추정 오차)는 이 단계에서만 검증할 수 있다.

## 2. 사전 조건 (사용자가 확인)

1. 키 변수 이름은 `OPENROUTER_API_KEY`다. 사용자의 셸에서 이 이름으로 내보냈는지만 확인한다. 에이전트는 `.env`를 열지 않는다.
2. **별도 터미널**(에이전트 세션이 아닌 사용자의 터미널)에서 직접 환경변수로 키를 내보낸다. **키는 에이전트와의 대화·명령줄·프롬프트에 절대 쓰지 않는다** ([AGENTS.md](../../../../AGENTS.md) §3).
3. `pytest tests -q`가 모두 통과한다.
4. **창 크기 선정**: 시스템 지시문과 도구 스키마(압축되지 않는 고정 부분)의 추정 토큰이 임계값(창×0.5)보다 크면 매 호출마다 압축을 시도하다 거부되므로, 020의 추정 함수로 고정 부분을 먼저 재서 임계값이 그 **위**가 되도록 창 크기를 정한다. 아래 `4000`은 예시일 뿐이며 착수 시 실측해 확정한다.
5. 비용 상한: 낮춘 창(예: `--context-window 4000`, 임계값 2,000토큰)에서 몇 턴만 진행하며 압축 호출이 추가되어도 총 입력은 수만 토큰 이내다(공개 단가로 1센트 미만 예상, 실제 청구는 확인하지 못함).

## 3. 절차

| 순서 | 동작 |
|---|---|
| 1 | **사용자가 별도 터미널에서 직접** 레포 루트에서 `python -m hermes_core.cli --context-window 4000` 실행. 에이전트는 이 실행을 대신하지 않는다 |
| 2 | 시작 안내에서 모드(실제), 모델, 작업 폴더를 확인 |
| 3 | 입력 1: `이 프로젝트의 코드명은 ORCA야. 기억해줘.` |
| 4 | 입력 2~4: 도구가 긴 출력을 내도록 요청(예: `workspace에 long1.txt를 만들고 1부터 300까지 한 줄에 숫자 하나씩 써줘. 그다음 읽어서 마지막 숫자만 알려줘.`를 파일 이름을 바꿔 2~3회) |
| 5 | 입력 5: `내가 처음에 말한 코드명이 뭐였지?` |
| 6 | 응답을 확인하고 `exit` |
| 7 | 사용자가 결과를 확인하고 비밀을 뺀 출력을 에이전트에게 전달. 에이전트는 원장 조회(읽기 전용)와 기록 정리를 한다 |

실패(오류 종료, 이상한 응답, 모델의 거절)하면 **자동으로 다시 시도하거나 코드를 고치지 않는다.** 원인을 기록하고 멈춰서 보고한다. 같은 스모크를 다시 하려면 사용자의 새 지시가 필요하다.

## 4. 기대 결과와 확인 항목

| # | 확인 | 기대 결과 |
|---|---|---|
| 1 | 압축 발동 | `llm_calls`에 요약 호출(도구 없음) 행이 1건 이상 있고, 같은 세션의 `messages`에 `compacted=1` 행이 있음 |
| 2 | **가정 B**: 거절 없음 | 압축 뒤 모든 호출이 `error_kind` NULL (`Model call failed` 미출력) |
| 3 | **가정 D**: 앞선 사실 | 마지막 응답이 `ORCA`를 정확히 말함 |
| 4 | **가정 C**: 요약 품질 | 보관되지 않은 활성 요약 메시지를 읽어 목표·완료한 작업·현재 상태 섹션이 쓸 만한지 사용자가 판단(주관적 관찰, 그대로 기록) |
| 5 | **가정 E**: 추정 오차 | 압축 직전 호출들의 실제 `input_tokens`와 거친 추정치를 `llm_calls` 요청 JSON으로 대조해 오차 비율을 기록 |
| 6 | **가정 G**: 헤드 불변 | `sessions.system_prompt`와 압축 후 호출의 첫 system 메시지가 동일 |
| 7 | **키 미저장** | 키가 원장 덤프에 없다. **사용자가 별도 터미널에서** 키 값을 출력하지 않고 확인하고 결과(`True`/`False`)만 전달한다 |
| 8 | 비용 | `llm_calls` 토큰으로 계산한 비용이 1센트 미만 |
| 9 | 출력·로그 | 키 값이 화면·로그에 없다 |

## 5. 결과 기록

- 대시보드 실행 기록에 날짜, 지시 문구, 통과/실패, 호출 수, 압축 횟수, 토큰, 계산한 비용을 적는다.
- 확인 항목 2~5의 관찰을 **그대로** 종합보고서의 「목표와 결과」·「새로 발견한 부분」에 옮긴다. 기대와 다르면 「틀렸다」로 적는다. 추정 오차가 크게 관찰되면 오버플로 복구를 후속 로드맵 후보로 기록한다.
