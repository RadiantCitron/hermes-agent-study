## 1. 구현 내용 명세

1. **상수** ([`constants.py`](../../../../src/hermes_core/constants.py)): `SKILLS_DIR_NAME = "skills"`, `SKILL_FILE_NAME = "SKILL.md"`, `SKILL_NAME_MAX_CHARS = 64`, `SKILL_DESCRIPTION_MAX_CHARS = 1024`. 이 단계에서 쓰지 않는 상수는 만들지 않는다(본문 상한 등은 030).
2. **`get_skills_dir()`** (같은 파일): `get_hermes_home() / SKILLS_DIR_NAME`을 **만들지 않고** 돌려준다.
3. **신규 모듈** `src/hermes_core/tools/skills_tool.py` (이 단계에서는 도구가 아닌 순수 부분만):
   - `parse_frontmatter(content: str) -> tuple[dict[str, Any], str]`: [ROADMAP §6-1](../ROADMAP.md)의 최소 파서. 외부 라이브러리를 쓰지 않는다. 구분선 줄은 끝의 공백·`\r`을 무시해 CRLF 파일도 읽는다. 파일은 `utf-8-sig`로 읽어 BOM이 있어도 첫 줄이 `---`로 인식된다.
   - 경로 판정은 [`path_guard.py`](../../../../src/hermes_core/tools/path_guard.py)의 `is_inside`·`is_protected_path`를 **수정 없이 재사용**한다(`skills_root`를 `resolve()`한 값을 두 번째 인자로).
   - `discover_skills(skills_root: Path) -> list[dict[str, str | None]]`: 각 항목은 `{name, description, category, path}`. 규칙·제외·정렬은 [ROADMAP §6-1](../ROADMAP.md). 폴더가 없으면 빈 목록이며 **어떤 폴더·파일도 만들지 않는다**. 한 스킬의 읽기·해석 실패는 그 스킬만 건너뛴다.
4. **작동원리 갱신**: 없음 (050에서 일괄 반영).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: `tmp_path`에 스킬 파일을 만들어 함수를 직접 호출한다. 모델·DB·네트워크 없음.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `parse_frontmatter("---\nname: deploy\ndescription: Deploy the app\n---\n# Body\ntext")` | `({"name": "deploy", "description": "Deploy the app"}, "# Body\ntext")` |
| 2 | 머리말이 없는 `"# Title\ntext"` | `({}, "# Title\ntext")` (본문 전체) |
| 3 | 닫는 `---`가 없는 `"---\nname: x\nbody"` | `({}, "---\nname: x\nbody")` (머리말 없음으로 취급, 본문 전체) |
| 4 | `name: "My Skill"`, `tags: [a, b]` | `name == "My Skill"`(따옴표 제거), `tags == ["a", "b"]` |
| 5 | 중첩: `"---\nname: x\nmetadata:\n  hermes:\n    name: wrong\n---\n"` | `name == "x"`. 들여쓴 `name: wrong`은 최상위 키로 읽히지 않음 |
| 6 | 값에 콜론: `description: Use: a thing` | `"Use: a thing"` (첫 콜론에서만 분리) |
| 7 | 주석 줄(`# c`)과 콜론 없는 줄(`junk`)이 섞인 머리말 | 무시되고 `name`은 정상 추출, 예외 없음 |
| 8 | `skills/hello/SKILL.md`, `skills/devops/deploy/SKILL.md` | 2개. hello: `category None`, `path "hello"`. deploy: `category "devops"`, `path "devops/deploy"`. 정렬은 분류 없음(hello)이 먼저 |
| 9 | 머리말에 `name`이 없는 스킬 / 머리말이 없고 본문이 `"# Title\n\nFirst line.\n"`인 스킬 | `name`은 폴더 이름, `description`은 `"First line."` |
| 10 | `name`이 리스트(`name: [a, b]`)인 스킬 / `description:`이 비었거나 리스트인 스킬(본문 첫 줄 `Body line.`) | 문자열이 아니거나 비면 `name`은 폴더 이름, `description`은 `"Body line."` |
| 11 | 65자 `name`, 1025자 `description` | `name` 길이 64, `description` 길이 1024이고 `...`로 끝남 |
| 12 | `skills/.git/x/SKILL.md`, `skills/.hub/x/SKILL.md`, `skills/.github/x/SKILL.md`, `skills/.envx/SKILL.md` | 모두 목록에 없음 |
| 13 | `skills/SKILL.md` (루트 바로 아래) | 목록에 없음 |
| 14 | 심볼릭 링크: ① `skills/fl/SKILL.md` 자체가 루트 밖 파일의 링크 ② `skills/evil` → 스킬 루트 밖 폴더(그 안에 `SKILL.md`) ③ `skills/alias/SKILL.md` → 루트 **안**의 `skills/real/SKILL.md` | ①②는 목록에 없음(링크 처리 방식과 무관하게 실제 경로가 루트 밖이면 제외), ③은 실제 경로가 루트 안이므로 포함. 참고: 이 환경(3.14.8)의 `rglob`은 폴더 링크를 따라가지 않아 ②는 검사 코드와 무관하게 통과한다 — 식별력 있는 시험은 ①이다 |
| 15 | UTF-8이 아닌 바이트(`b"\xff\xfe"`)로 된 `SKILL.md` + 정상 스킬 1개 | 깨진 스킬만 건너뛰고 정상 스킬은 반환, 예외 없음 |
| 16 | 스킬 루트 폴더가 없음 / 스킬 루트가 폴더가 아니라 파일 | 둘 다 `[]`, 예외 없음. 앞의 경우 호출 뒤에도 그 폴더가 **존재하지 않음** |
| 17 | 이름이 같은 스킬 둘(`a/dup`, `b/dup`) | 둘 다 목록에 있고 `path`가 다름 (중복 판단은 030) |
| 18 | `HERMES_HOME`을 임시 폴더로 지정하고 `get_skills_dir()` | `<임시>/skills`(경로 비교는 양쪽 모두 `resolve()` 후)를 돌려주고 그 폴더를 만들지 않음 |
| 18b | CRLF 줄바꿈(`---\r\nname: x\r\n---\r\nbody`) / 맨 앞 BOM이 붙은 `SKILL.md` | 둘 다 `name == "x"`로 읽히고 본문에 `\r`·BOM이 섞이지 않음(파서는 문자열 입력 기준, BOM은 `discover_skills`의 파일 읽기로 검증) |
| 18c | `skills/a/b/c/SKILL.md` (구성요소 4개) | `category == "a"`, `path == "a/b/c"` |
| 18d | 같은 스킬 집합을 서로 다른 순서로 생성 | 결과 목록이 같고 `(분류, 이름, path)` 순으로 정렬됨 (파일시스템 순서에 의존하지 않음) |
| 19 | 기존 코어 테스트(05 마감 시점 전체) | **수정 없이** 통과 |
