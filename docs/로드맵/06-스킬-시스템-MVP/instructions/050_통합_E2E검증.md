## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

공통 준비: 임시 `HERMES_HOME/skills/release-checklist/SKILL.md`(본문에 `STEP-7: tag the build`)와 `references/notes.md`(내용 `NOTE-ALPHA`), 스킬 루트 밖에 `state.db` 옆 비밀 마커 파일(`SECRET`). 가짜 모델의 `tool_calls` 인자는 시험이 직접 쓴다(요구사항의 호출 순서: 목록 → 본문).

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 가짜 모델 큐: `skills_list` 호출 → `skill_view(name="release-checklist")` 호출 → 최종 텍스트 | 결과 `stopped_reason == "completed"`, `iterations == 3`. 두 번째 모델 호출의 `messages`에 `skills_list` 결과 tool 메시지(스킬 이름 포함), 세 번째 호출의 `messages`에 `skill_view` 결과 tool 메시지(`STEP-7` 포함)가 순서대로 있고 각 `tool_call_id`가 짝을 이룸 |
| 2 | 위에 이어 `skill_view(name="release-checklist", file_path="references/notes.md")` 호출 | tool 메시지 `content`에 `NOTE-ALPHA` |
| 3 | 가짜 모델이 `skill_view(name="../state.db")`와 `skill_view(name="release-checklist", file_path="../../../state.db")`를 호출한 뒤 최종 텍스트 | 두 tool 메시지 모두 `success false`이고 `SECRET` 없음. 루프는 계속되어 `stopped_reason == "completed"` (에이전트가 죽지 않음) |
| 4 | 스킬 폴더 자체가 없는 상태에서 `skills_list` 호출 후 최종 텍스트 | 정상 종료, 빈 목록 결과가 tool 메시지로 전달됨, 대화 뒤에도 `skills/` 폴더가 **없음** |
| 5 | 시나리오 1~3 실행 전후 스킬 폴더(경로+내용 해시)와 `HERMES_HOME` 직하위 항목 | 동일 (읽기 전용) |
| 6 | 시스템 지시문 | 시나리오 1의 첫 모델 호출 `messages[0]`이 `SKILLS_GUIDANCE`를 포함하고, `sessions.system_prompt`와 같으며, 대화가 끝날 때까지 첫 시스템 메시지가 바이트 동일 |
| 7 | 낮춘 `context_window_tokens`로 압축이 발동하는 긴 대화에 `skill_view` 호출을 포함(큰 스킬 본문 약 19,000자) | 압축 뒤 모델 호출이 오류 없이 이어지고 `messages[0]`(시스템)이 바이트 동일, `skill_view` 호출이 `llm_calls`에 일반 도구 호출처럼 남음 |
| 8 | DB 전체(`messages`, `llm_calls`, `sessions`)를 직렬화해 가짜 키 문자열 검색 | 없음 (`OPENROUTER_API_KEY` 환경변수는 시험에서 제거되어 있음) |
| 9 | 작동원리 01편 | 위 영구 사실이 반영되고, 각 서술이 코드와 4축(동작·순서·소유자·시점)으로 대조됨. 확인하지 못한 것은 「미확인」 |
| 10 | 기존 코어 테스트(05 마감 시점 전체) | **수정 없이** 통과 |
