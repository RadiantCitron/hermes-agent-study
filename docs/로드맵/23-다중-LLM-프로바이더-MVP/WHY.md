# [의도와 가정] 23-다중-LLM-프로바이더-MVP

> **문서 성격**: 왜 이 로드맵을 지금 진행하며, 왜 이 정도로만 범위를 한정하는지, 그리고 마감 시 어떤 가정을 검증할 것인지를 선언하는 문서입니다 ([ROADMAP_정책.md §3-2](../ROADMAP_정책.md) 준수).

## 1. 왜 지금 이 로드맵인가

- 22번 로드맵까지 거쳐 에이전트의 코어 루프·도구·기억·제어판·포트 경계가 모두 완성되었지만, 실제 AI 모델을 부르는 문은 여전히 **OpenRouter 하나뿐**입니다.
- 사용자가 Google Gemini나 Anthropic Claude의 API 키를 직접 가지고 있더라도 지금은 쓸 수 없고, `.env` 파일에 키를 넣어 두어도 프로그램이 자동으로 읽지 못해 실행 전마다 터미널에서 수동으로 환경변수를 내보내야 합니다.
- 이 공백이 남으면 학습·실습 환경에서 OpenRouter 외의 직접 키를 실험할 수 없으며, 앞으로 여러 키를 함께 `.env`에 두고 쓸 때 어느 키가 어떤 규칙으로 선택되는지 예측할 수 없는 불안이 남습니다.

## 2. 왜 이 정도로만 하는가 (비목표)

| 하지 않는 것 | 이유 | 언제 하나 |
|---|---|---|
| Gemini 전용 네이티브 통신(`generateContent`) 어댑터 만들기 | Gemini가 공식 OpenAI 호환 엔드포인트를 이미 제공하므로 기존 OpenAI 호환 요청·응답 경로를 재사용하면 중복 코드 없이 바로 동작합니다 | 멀티모달 입력이나 Gemini 전용 컨텍스트 캐싱 등 호환 엔드포인트로 안 되는 기능이 필요할 때 |
| 대화 도중(턴 실행 중) `/ctl set provider`로 프로바이더 핫 스왑 | 실행 중 프로바이더를 바꾸면 대화 이력 형식과 프롬프트 캐시, 자식 위임 설정이 한 세션 안에서 섞여 예측이 어려워집니다 | 세션 단위가 아닌 턴 단위 멀티 모델 라우팅을 정식으로 설계할 때 |
| 호출 실패 시 다른 유료 프로바이더로 자동 우회(폴백) | 사용자가 지정한 키가 비었을 때 몰래 다른 회사 키로 넘어가면 의도치 않은 과금과 오작동을 낳습니다 | 사용자가 명시적으로 폴백 사슬 설정을 요구할 때 |
| 외부 라이브러리(`python-dotenv`, `anthropic`, `google-genai`) 추가 | 현재 코어는 `httpx`와 파이썬 표준 라이브러리만으로 동작하는 가벼운 학습용 에이전트입니다. 외부 SDK를 들이면 버전 결합과 크기만 커집니다 | 특정 SDK 고유 스트리밍·배치 기능이 꼭 필요해질 때 |
| OpenAI 직접 키(`OPENAI_API_KEY`)나 OAuth 로그인 사다리 추가 | 당장의 요구는 OpenRouter·Gemini·Claude 3종 지원입니다. 쓰지 않는 프로바이더까지 미리 넣으면 시험과 유지 대상만 늘어납니다 | 해당 프로바이더 사용 요구가 실제로 생길 때 |

## 3. 왜 이 순서, 왜 이 단계 수인가

총 5단계(구현 4단계 + 마감 1단계)로 나누며 순서는 **보안·바닥 → 어댑터 → 선택 규칙 → 진입점 연결 → 마감**입니다.

1. **010 (보안·상수·`.env` 로더 기반)**: 새 키를 환경에 읽어들이기 전에 터미널 자식 프로세스 차단, 마스킹, 깃 비밀 검사, 테스트 환경 격리를 먼저 잠가야 키 유출 위험 없이 다음 단계를 진행할 수 있습니다.
2. **020 (`AnthropicClient` 어댑터)**: Claude 직접 호출은 요청·응답·도구 형식이 달라 변환 어댑터가 독립적으로 검증되어야 합니다.
3. **030 (프로바이더 결정 사다리 및 설정 통합)**: 어댑터들이 준비된 뒤, `.env`/설정/CLI 입력을 조합해 "어떤 키와 모델을 쓸지" 결정하는 순수 규칙과 팩토리를 세웁니다.
4. **040 (CLI·위임 연동 및 아키텍처 잠금)**: 앞선 부품들을 CLI 진입점과 서브에이전트 위임(`delegate_task`)에 연결하고, 포트 적합성과 전체 회귀 테스트로 잠급니다.
5. **050 (마감 및 종합보고서)**: 아래 가정 목록을 실제 결과와 하나씩 대조해 마감합니다.

## 4. 왜 이 방식을 택하고 무엇을 배척했나

- **우선순위 사다리(`명시 지정 > 모델명 추론 > 키 우선순위 자동 감지`) + Fail-Closed**:
  - `.env`에 여러 키가 있을 때 항상 예측 가능한 결과를 내기 위해, 사용자가 `--provider`나 `--model`로 의도를 드러내면 그 프로바이더를 고정하고 키가 없을 때 즉시 오류로 멈추도록 정했습니다.
  - **배척한 대안**: "있는 키 아무거나 찾아서 조용히 호출하기" 또는 "키가 없으면 다음 키로 넘어가기"는 어느 회사 모델이 불렸는지 혼란과 오과금을 부르므로 배척했습니다.
- **표준 라이브러리 기반 `.env` 로더 (`setdefault`)**:
  - 이미 셸에서 `export`한 값을 덮어쓰지 않고, `.env`에 담긴 값만 보충하도록 해 운영·테스트 환경 제어를 유지합니다.
  - **배척한 대안**: 무조건 `.env`로 덮어쓰기는 테스트 격리와 CI/터미널 환경변수 우선 관례를 깨므로 배척했습니다.

## 5. 성공 판단 기준과 검증할 가정 목록 (A~H)

마감(050단계) 시 종합보고서(`결과정리및리뷰.md`)에서 하나씩 「이뤘다 / 못 이뤘다 / 바뀌었다」로 대조할 8개 가정입니다.

| 번호 | 검증할 가정 (Acceptance Hypotheses) |
|:---:|---|
| **A** | `.env` 로더는 주석·빈 줄·따옴표·`export` 접두사를 안전하게 읽되, 이미 설정된 셸 환경변수(`os.environ`)를 절대 덮어쓰지 않으며 CLI 작업 폴더 이동(`os.chdir`) 전에 동작한다 |
| **B** | `OpenRouter`와 `Gemini`는 기존 OpenAI 호환 클라이언트 경로를 공유해 정상 요청·응답·도구 호출·호출 원장 기록·키 마스킹이 동일하게 동작한다 |
| **C** | `AnthropicClient`는 `system` 메시지 분리, `tools` 스키마 변환, `tool_use`·`tool_result` 변환 및 연속 `tool` 메시지 병합을 통해 기존 코어의 턴 루프와 도구 호출·압축 요약에서 호환 동작한다 |
| **D** | 프로바이더 결정 사다리(`명시 지정 > 모델명 추론 > 키 우선순위`)가 모호함 없이 동작하며, 지정·추론된 프로바이더의 키가 없으면 다른 키로 우회하지 않고 종료 코드 `2`로 즉시 실패한다(Fail-Closed) |
| **E** | `delegate_task` 자식 서브에이전트도 CLI와 동일한 프로바이더·어댑터를 받아 별도 클라이언트 인스턴스로 원장을 격리해 실행된다 |
| **F** | 새로 추가된 `GEMINI_API_KEY`·`ANTHROPIC_API_KEY`는 터미널 도구 자식 프로세스 환경에서 제거되고, 스냅샷 마스킹·`.gitleaks.toml`·테스트 격리(`conftest.py`)에서도 빠짐없이 방어된다 |
| **G** | 코어 커널(`kernel/`) 변경 0줄, 의존 방향 규칙(`R1~R7`) 위반 0건, 전 소스 파일 `800줄` 상한 및 `LLMPort` 적합성 검사를 모두 통과한다 |
| **H** | 전체 자동 시험(`not pty` + `pty`)이 통과하고, 실제 `.env`를 이용한 Gemini·Claude 수동 스모크(사용자 별도 터미널 확인 또는 결과 확인)에서 정상 응답을 받는다 |

## 6. 알려진 위험과 아직 확인하지 못한 것

1. **Gemini OpenAI 호환 엔드포인트의 도구 호출 세부 응답 차이 (미확인)**: 실제 Google AI Studio API 서버가 `tool_calls`의 `id`나 `usage` 필드를 OpenRouter와 완전히 같은 형식으로 주는지, 빈 문자열/누락 필드가 있는지는 가짜 응답(`MockTransport`) 테스트로는 확인할 수 없으며 마감 전 실제 키 1회 스모크 실행으로 확인해야 합니다. (**현재 상태: 미확인**)
2. **Anthropic 실제 API의 오류 본문/응답 변형 (미확인)**: 공식 문서 규격에 맞춰 `AnthropicClient`를 구현하되, 실제 Anthropic 서버의 429·400 응답 세부 필드는 실제 키 스모크 실행 시 확인합니다. (**현재 상태: 미확인**)
3. **기존 `SETTING_SPECS` 12개 고정 단언 테스트**: `test_settings.py`와 `test_snapshot.py`가 설정 항목 수 `12`를 직접 비교하고 있어, `provider` 설정 추가 시 해당 테스트 단언을 `13`(또는 `len(SETTING_SPECS)`)으로 함께 맞춰야 합니다. (사전 점검으로 확인 완료)
