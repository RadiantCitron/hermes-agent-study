## 1. 목표 대비 결과 요약

23번 로드맵은 OpenRouter 단일 고정이던 `hermes_core`의 LLM 연결 구조를 확장해 **OpenRouter · Google Gemini · Anthropic Claude** 3종 프로바이더를 `LLMPort` 단일 규격으로 통일하고, `.env` 안전 로더·표준 우선순위 사다리(Fail-Closed)·다층 보안 방어까지 구현 및 자동 검증을 완료했다.

| 목표 항목 | 결과 | 근거 산출물 |
|---|---|---|
| **1. `.env` 안전 로딩** | 완료 | `src/hermes_core/env_loader.py` (`load_dotenv`, `setdefault` 보존, `cli.py` `os.chdir` 전 호출) |
| **2. 3종 프로바이더 지원** | 완료 | `src/hermes_core/llm_client.py` (OpenRouter/Gemini), `src/hermes_core/anthropic_client.py` (`AnthropicClient`) |
| **3. 표준 우선순위 사다리 + Fail-Closed** | 완료 | `src/hermes_core/provider.py` (`resolve_provider_config`, `build_llm_client`), `Settings.provider` |
| **4. 다층 보안·테스트 격리** | 완료 | `TERMINAL_STRIPPED_ENV_NAMES`, `mask_secrets()`, `.gitleaks.toml`, `tests/test_hermes_core/conftest.py` |
| **5. 아키텍처 불변식 사수** | 완료 | `kernel/` 무수정, `R1~R7` 0위반, 전 소스 파일 `800줄` 상한, `LLMPort` 적합성 잠금 |

## 2. `WHY.md` 가정 A~H 대조 결과

| 번호 | 검증할 가정 | 판정 | 근거 및 관찰 |
|:---:|---|:---:|---|
| **A** | `.env` 로더는 주석·빈 줄·따옴표·`export` 접두사를 안전하게 읽되, 기존 `os.environ`을 덮어쓰지 않으며 `os.chdir` 전에 동작한다 | **이뤘다** | `env_loader.py` 단위 시험 및 `test_cli_provider.py`에서 `os.chdir` 전 로딩 및 `setdefault` 보존 검증 완료 |
| **B** | `OpenRouter`와 `Gemini`는 기존 OpenAI 호환 클라이언트 경로를 공유해 요청·응답·도구 호출·원장 기록·키 마스킹이 동일하게 동작한다 | **이뤘다** | `OpenRouterClient` 기반 `base_url`·`api_key` 주입으로 공유. `mask_secrets()` 공용화로 키 마스킹 일원화 |
| **C** | `AnthropicClient`는 `system` 분리, `tools` 스키마 변환, `tool_use`·`tool_result` 변환, 연속 `tool` 병합으로 코어와 호환 동작한다 | **이뤘다** | `anthropic_client.py` 구현 및 `020` 7종 인수 시험, `test_ports_conformance.py` 적합성 검증 통과 |
| **D** | 프로바이더 결정 사다리(`명시 지정 > 모델명 추론 > 키 우선순위`)가 모호함 없이 동작하며 키 부재 시 종료 코드 `2`로 Fail-Closed 실패한다 | **이뤘다** | `provider.py` 결정 사다리 및 `test_provider.py` 7종·`test_cli_provider.py` 7종으로 검증 완료 |
| **E** | `delegate_task` 자식 서브에이전트도 CLI와 동일한 프로바이더·어댑터를 받아 별도 클라이언트 인스턴스로 원장을 격리해 실행된다 | **이뤘다** | `cli.py`에서 `llm_client_factory=lambda: build_llm_client(resolved_provider)` 주입 및 `test_cli_provider.py` 검증 완료 |
| **F** | `GEMINI_API_KEY`·`ANTHROPIC_API_KEY`는 터미널 자식 프로세스에서 제거되고 마스킹·`.gitleaks.toml`·`conftest.py`에서도 방어된다 | **이뤘다** | `constants.py`, `snapshot.py`, `.gitleaks.toml`, `conftest.py` 확장 및 `010`·`030` 시험 통과 |
| **G** | `kernel/` 변경 0줄, `R1~R7` 위반 0건, 전 소스 파일 `800줄` 상한 및 `LLMPort` 적합성 검사를 모두 통과한다 | **이뤘다** | `test_architecture.py` 및 `test_ports_conformance.py` 포함 전체 자동 시험 통과 |
| **H** | 전체 자동 시험(`not pty` + `pty`)이 통과하고, 실제 `.env`를 이용한 Gemini·Claude 수동 스모크에서 정상 응답을 받는다 | **부분 달성** | 전체 자동 시험(`MockTransport` 기반)은 100% 통과. 실제 키 수동 스모크는 사용자 별도 터미널 선택 작업으로 미실시(향후 필요 시 수행) |

## 4. 미흡한 부분 및 향후 과제

1. **실제 API 키 기반 E2E 스모크 미실시**: `WHY.md §6`에 명시된 Gemini OpenAI 호환 엔드포인트의 `tool_calls`/`usage` 세부 응답 및 Anthropic 실제 429/400 오류 본문 변형은 `MockTransport` 기반 자동 시험으로 대체되었으며, 실제 키 스모크는 사용자가 별도 터미널에서 `.env`에 키를 넣고 `python -m hermes_core.cli --provider gemini` / `--provider anthropic` 실행 시 최종 확인할 수 있다.
2. **비목표 유지**: Gemini 네이티브 API, 턴 중 프로바이더 핫 스왑, 자동 유료 폴백, 외부 SDK 도입, OpenAI 직접 키 지원은 `ADR-0023` 및 `WHY.md §2`에 따라 의도적으로 제외되었다.
