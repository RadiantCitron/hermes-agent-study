### 2.2 `src/hermes_core/env_loader.py` 신규 작성
외부 패키지 없이 파이썬 표준 라이브러리만 사용해 `.env` 파일을 읽는 경량 로더를 작성합니다 (`hermes-agent/hermes_cli/env_loader.py` 개념 매핑 독스트링 포함).

- `parse_dotenv_lines(text: str) -> dict[str, str]`:
  - 빈 줄, `#` 시작 주석 줄 무시.
  - 선택적 `export ` 접두사 제거 후 첫 `=` 기준으로 `key`, `raw_val` 분리 (`=` 없는 줄이나 유효하지 않은 빈 키 이름은 무시).
  - 양끝 큰따옴표(`"..."`) 또는 작은따옴표(`'...'`) 쌍 제거; 따옴표 없는 값만 인라인 주석(` #...`)과 앞뒤 공백 정리.
  - 큰따옴표 내부 `\n`, `\r`, `\t`, `\"`, `\\` 최소 이스케이프 해석.
- `load_dotenv_file(dotenv_path: Optional[Path] = None, *, environ: Optional[MutableMapping[str, str]] = None) -> list[str]`:
  - `target = Path(".env") if dotenv_path is None else Path(dotenv_path)`
  - 파일이 없거나 정규 파일이 아니면 빈 리스트 `[]` 반환 (오류 없이 무동작).
  - `encoding="utf-8"`로 읽기 (`UnicodeDecodeError` / `OSError` 시 예외 전파 없이 경고 로그 후 `[]` 반환 — 시작 실패 방지).
  - `target_env = os.environ if environ is None else environ`에 대해 **이미 존재하고 비어 있지 않은 키는 절대 덮어쓰지 않고**(`key not in target_env or not target_env[key].strip()`), 새 값이 비어 있지 않으면 반영한 뒤 반영된 키 이름 리스트 반환. (단, 이미 `target_env`에 비어 있지 않은 값이 있으면 그대로 유지.)

### 2.3 `src/hermes_core/control/snapshot.py` 비밀값 마스킹 보강

## 3. 선기술 인수 테스트 시나리오 (입력 → 기대 결과)

> 구현 전 확정된 시나리오입니다. 4단계 구현 시 아래 시나리오를 그대로 테스트 코드로 옮기며, 임의로 완화하거나 삭제하지 않습니다.

### 3.1 `.env` 로더 (`tests/test_hermes_core/test_env_loader.py`)
1. **시나리오 1 (기본 키·값 및 따옴표·`export` 파싱)**:
   - 입력: `# comment\n\nexport OPENROUTER_API_KEY="k1"\nGEMINI_API_KEY='k2'\nANTHROPIC_API_KEY=k3 # inline\n`
   - 기대 결과: 세 키 모두 각각 `"k1"`, `"k2"`, `"k3"`으로 `environ`에 적재되고 반환 리스트에 3개 키 포함.
2. **시나리오 2 (기존 셸 환경변수 우선 — `setdefault` 보존)**:
   - 입력: `environ={"GEMINI_API_KEY": "shell-key"}`, `.env` 파일에 `GEMINI_API_KEY=file-key\nANTHROPIC_API_KEY=file-ant`
   - 기대 결과: `environ["GEMINI_API_KEY"] == "shell-key"`로 유지되고, `environ["ANTHROPIC_API_KEY"] == "file-ant"`만 추가, 반환 리스트는 `["ANTHROPIC_API_KEY"]`.
3. **시나리오 3 (빈 셸 환경변수 보충 vs 빈 `.env` 값 무시)**:
   - 입력: `environ={"GEMINI_API_KEY": ""}`, `.env` 파일에 `GEMINI_API_KEY=from-file\nEMPTY_KEY=\n`
   - 기대 결과: `environ["GEMINI_API_KEY"] == "from-file"`로 채워지고 `EMPTY_KEY`는 반영되지 않음.
4. **시나리오 4 (`.env` 부재 및 손상된 UTF-8 안전 처리)**:
   - 입력: 존재하지 않는 경로, 또는 잘못된 바이트(`b"\xff\xfe"`)가 담긴 `.env` 파일
   - 기대 결과: 예외 없이 `[]` 반환 및 `environ` 무변경.
5. **시나리오 5 (잘못된 줄 무시)**:
   - 입력: `"NO_EQUALS_LINE\n=missing_key\nVALID=ok\n"`
   - 기대 결과: `"VALID": "ok"`만 반영되고 나머지 무시.

### 3.2 보안 · 마스킹 · 터미널 격리 · gitleaks
6. **시나리오 6 (터미널 자식 프로세스 3종 키 차단)**:
   - 입력: `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`가 모두 `os.environ`에 설정된 상태에서 `terminal_tool` 실행(`python3 -c ...`로 3개 환경변수 조회, 기존 `test_terminal_approval.py` 또는 `test_env_loader.py`에 검증)
   - 기대 결과: 세 환경변수 모두 자식 프로세스에서 미설정(`<unset>`), `TERMINAL_STRIPPED_ENV_NAMES`에 3종 키 이름 모두 포함.
7. **시나리오 7 (`snapshot.mask_secrets` Gemini/Anthropic 마스킹)**:
   - 입력: `"key=AIzaSyDummyTokenValue12345678901234"` 및 `"key=sk-ant-DummyToken1234567890"`
   - 기대 결과: 두 문자열 모두 마스킹되어 `"***"`로 치환(원본 토큰 문자열 미포함).
8. **시나리오 8 (`.gitleaks.toml` 3종 키 검출 및 자리표시자 비검출 — `test_gitleaks_config.py`)**:
   - 입력: 무작위 생성된 Anthropic 키 형태(`sk-ant-...` 길이 충족) 및 Gemini 키 형태(`AIzaSy...` 39자)가 문장/대입문에 포함된 커밋 vs 짧은 자리표시자(`sk-ant-...`, `AIzaSy...`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`)만 적은 커밋
   - 기대 결과: 실제 형태는 검출(exit 1), 자리표시자와 변수 이름 언급은 비검출(exit 0).
9. **시나리오 9 (`conftest.py` 3종 키 + `HERMES_PROVIDER` 격리)**:
   - 입력: 테스트 실행 전 `monkeypatch` 확인 또는 픽스처 동작 검증
   - 기대 결과: 테스트 시작 시 `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `HERMES_PROVIDER`가 모두 제거됨.
