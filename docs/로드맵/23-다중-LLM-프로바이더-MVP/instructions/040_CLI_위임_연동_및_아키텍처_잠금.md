## 1. 배경 및 목적

`010`~`030` 단계에서 구축한 `.env` 로더(`env_loader.py`), Anthropic Messages API 어댑터(`AnthropicClient`), 프로바이더 결정 사다리(`provider.py`), `Settings.provider` 계층을 실제 진입점인 [`cli.py`](../../../../src/hermes_core/cli.py)와 위임 도구(`delegate_task`)에 연결하고, 아키텍처 포트 적합성 시험(`test_ports_conformance.py`)으로 `AnthropicClient` 계약을 영구 잠금합니다.

## 2. 상세 구현 명세

### 2.1 `src/hermes_core/cli.py` 다중 프로바이더 연동
1. **`--provider` CLI 옵션 추가**:
   - `parser.add_argument("--provider", type=str, default=None, help="LLM provider (auto, openrouter, gemini, anthropic)")`
   - `args.provider is not None`이면 `cli_overrides["provider"] = args.provider`로 `load_settings()`에 전달한다. 잘못된 값이면 `SettingsError`를 잡아 `stderr` 출력 후 종료 코드 `2`로 중단한다.
2. **`.env` 안전 로딩 경계**:
   - 실제 모델 모드(`not args.mock`)에서만 `load_settings()`와 `os.chdir(workspace)` **이전**에 `load_dotenv_file()`을 호출한다.
   - `--mock` 모드에서는 `.env` 파일을 읽지 않는다.
3. **프로바이더 결정 및 클라이언트 생성 (`Fail-Closed`)**:
   - 실제 모델 모드에서 `resolve_provider_config(provider=settings.provider, model=model)`를 호출한다.
   - `ProviderResolutionError` 발생 시 `Error: <원인>`을 `stderr`에 출력하고 `HERMES_HOME`/DB 생성 전에 종료 코드 `2`로 종료한다.
   - `_build_cli_llm_client(resolved)` 헬퍼가 기본적으로 `create_llm_client(resolved)`를 호출해 `LLMPort` 구현체를 생성한다(단, 기존 단위 테스트의 `monkeypatch.setattr(cli, "OpenRouterClient", ...)` 등 모듈 심볼 교체 호환은 유지).
   - `resolved.model`을 에이전트 모델로 확정해 `create_agent(..., model=model, llm_client=llm_client)`에 전달한다.
4. **시작 배너 및 위임 도구(`delegate_task`) 연동**:
   - 실제 모드 시작 배너에 선택된 프로바이더와 모델을 함께 표시한다 (`🚀 Running in REAL mode (Provider: {provider}, Model: {agent.model}).`).
   - `register_delegate_if_enabled`의 `llm_client_factory`가 `lambda: _build_cli_llm_client(resolved)`를 사용하여 자식 서브에이전트도 부모와 동일한 프로바이더·모델·키·어댑터(`AnthropicClient` 또는 `OpenRouterClient`)로 동작하게 한다.

### 2.2 아키텍처 포트 적합성 잠금 (`tests/test_architecture/test_ports_conformance.py`)
- `AnthropicClient`가 `LLMPort` 및 `CallRecordable` 프로토콜을 만족함을 `issubclass`·`isinstance` 및 `inspect.signature().bind()`(`chat_completion`, `set_call_recorder`)로 검증한다.
- `OpenRouterClient`의 `CallRecordable` 적합성과 `create_llm_client()`가 3종 프로바이더(`openrouter`, `gemini`, `anthropic`) 모두에 대해 `LLMPort`·`CallRecordable` 구현체를 반환함을 함께 검증한다.

### 2.3 기존 CLI 테스트 격리 및 안내 동기화
- `tests/test_hermes_core/test_cli.py`의 `hermes_home` 픽스처와 `tests/test_hermes_core/test_cli_delegate.py`의 `cli_test_env`·키 부재 테스트에 `monkeypatch.chdir(tmp_path)`를 적용해 로컬 개발 환경의 `.env` 파일이 테스트로 유입되지 않도록 차단한다.
- `tests/test_hermes_core/test_cli_delegate.py` 시나리오 6의 키 부재 오류 검증을 다중 프로바이더 오류 메시지(`No LLM API key found`, `OPENROUTER_API_KEY`, `--mock`)에 맞게 갱신한다.

## 3. 선기술 인수 테스트 시나리오 (입력 → 기대 결과)

> 구현 전 확정된 시나리오입니다. 4단계 구현 시 아래 시나리오를 그대로 `tests/test_hermes_core/test_cli_provider.py`와 `tests/test_architecture/test_ports_conformance.py`로 옮기며, 임의로 완화하거나 삭제하지 않습니다.

1. **시나리오 1 (`.env` 로딩 및 `os.chdir` 이전 실행 검증)**:
   - 입력: 임시 시작 폴더에 `.env` (`GEMINI_API_KEY=...`, `HERMES_PROVIDER=gemini`) 배치 후 해당 폴더에서 `cli.main()` 실행(`stdin="hi\nexit\n"`), `MockTransport`로 요청 캡처.
   - 기대 결과: `os.chdir(workspace)`로 작업 폴더가 이동된 뒤에도 시작 폴더의 `.env`가 정상 로드되어 `GEMINI_OPENAI_CHAT_URL`로 요청이 전송되고, 배너에 `Provider: gemini, Model: gemini-2.5-flash`가 출력되며, 셸 `os.environ`에 이미 있던 값은 `.env`가 덮어쓰지 않는다.
2. **시나리오 2 (`--mock` 모드 `.env` 무간섭)**:
   - 입력: 임시 시작 폴더에 `.env` (`HERMES_PROVIDER=anthropic`, `ANTHROPIC_API_KEY=...`)를 두고 `hermes-core --mock` 실행.
   - 기대 결과: `.env`가 로드되지 않아 테스트 종료 시 `os.environ`에 `ANTHROPIC_API_KEY`/`HERMES_PROVIDER`가 추가되지 않고 Mock 모드가 정상 완료된다.
3. **시나리오 3 (`--provider gemini` CLI 실행 + `llm_calls` 원장 기록)**:
   - 입력: `GEMINI_API_KEY` 설정, `--provider gemini`로 1턴 대화 후 `exit`.
   - 기대 결과: `OpenRouterClient`가 `GEMINI_OPENAI_CHAT_URL` 및 `Authorization: Bearer <key>`로 요청하고, `SessionDB.sessions.model == "gemini-2.5-flash"`, `llm_calls` 테이블에 1건 기록되며 출력·DB에 키 원문이 노출되지 않는다.
4. **시나리오 4 (`--provider anthropic` CLI 실행 + `AnthropicClient` · `llm_calls` 원장 기록)**:
   - 입력: `ANTHROPIC_API_KEY` 설정, `--provider anthropic`로 1턴 대화 후 `exit`.
   - 기대 결과: `AnthropicClient`가 `ANTHROPIC_MESSAGES_URL`, `x-api-key`, `anthropic-version` 헤더로 요청하고, 배너에 `Provider: anthropic, Model: claude-sonnet-4-5`, `SessionDB.sessions.model == "claude-sonnet-4-5"`, `llm_calls`에 1건 기록되며 키 원문이 미노출된다.
5. **시나리오 5 (`--provider` 우선순위 · Fail-Closed 및 잘못된 `--provider` 거부)**:
   - 입력: (a) `OPENROUTER_API_KEY`만 있는 상태에서 `--provider gemini` 실행, (b) `--provider invalid` 실행.
   - 기대 결과: 둘 다 종료 코드 `2`로 즉시 종료되고 `state.db`가 생성되지 않으며, (a)는 `GEMINI_API_KEY` 누락 안내를 출력하고 `openrouter`로 우회하지 않는다.
6. **시나리오 6 (`HERMES_PROVIDER` / `config.toml` vs `--provider` CLI 계층 우선순위)**:
   - 입력: `config.toml`에 `provider = "gemini"`, `HERMES_PROVIDER=openrouter`, CLI `--provider anthropic` 조합 + `ANTHROPIC_API_KEY` 설정 후 실행.
   - 기대 결과: CLI `--provider`가 최우선으로 적용되어 `Provider: anthropic`으로 실행된다.
7. **시나리오 7 (`--delegate` 자식 서브에이전트 동일 프로바이더(Anthropic) 연동 및 Zero Leakage)**:
   - 입력: `ANTHROPIC_API_KEY` 설정, `--provider anthropic --delegate`로 부모가 `delegate_task` 1회 호출 후 최종 응답.
   - 기대 결과: 부모와 자식 모두 `AnthropicClient`로 `ANTHROPIC_MESSAGES_URL`을 호출하고, `sessions`에 부모(`cli`)·자식(`subagent`) 및 `llm_calls`에 각각 분리 기록되며 출력·DB 덤프에 키 원문이 없다.
8. **시나리오 8 (`AnthropicClient` 아키텍처 포트 적합성 잠금 — `test_ports_conformance.py`)**:
   - 입력: `AnthropicClient` 클래스/인스턴스 및 `create_llm_client` 3종 프로바이더 결과.
   - 기대 결과: `LLMPort`·`CallRecordable` `issubclass`/`isinstance` 및 `chat_completion`/`set_call_recorder` 시그니처 바인딩이 모두 통과한다.
