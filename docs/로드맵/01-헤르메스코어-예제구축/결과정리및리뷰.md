## 3. 아키텍처 개선 성과 (Architecture Achievements)

1. **God Object 해체 및 단일 책임 원칙 (SRP) 확립**:
   - 원본 `hermes-agent`의 거대 모듈(`run_agent.py`의 `AIAgent`)을 에이전트 루프([`HermesAgent`](../../src/hermes_core/agent/agent.py)), 도구 실행 레일([`ToolDispatcher`](../../src/hermes_core/tools/dispatcher.py)), 세션 원장([`SessionDB`](../../src/hermes_core/session_db.py))으로 명확히 분리하고 의존성 주입(DI) 구조를 완성했습니다.
2. **도구 실행 단일 진입로 (Tool Execution Rail)**:
   - 전역 함수 호출 방식 대신 `ToolDispatcher.handle_function_call()` 단일 관문을 통해 모든 도구 호출이 라우팅되도록 일원화하여, 향후 샌드박스 정책 및 보안 가드 확장이 용이해졌습니다.
3. **프롬프트 캐싱 불변 원칙 준수 (Prompt Caching Invariant)**:
   - 세션 시작 시 `_build_system_prompt()` 1회 호출로 시스템 프롬프트를 고정하고, 메모리 스냅샷을 불변(`Frozen Snapshot`)으로 묶어 턴 도중 프롬프트 캐시가 무효화되는 것을 원천 방어했습니다.
4. **개념 매핑(Concept Mapping) 및 독스트링 체계 구축**:
   - [`docs/코딩규약.md`](../코딩규약.md)에 원본 대응표를 작성하고, 모든 주요 클래스 및 함수 독스트링에 원본 위치(`hermes-agent/...`)를 명시하여 원본 학습 시 직관적인 나침반 역할을 제공합니다.

## 4. 트러블슈팅과 교훈 (Troubleshooting & Lessons Learned)

1. **파일 I/O 인코딩 명시 (`PLW1514`)**:
   - 크로스 플랫폼 환경에서 파일 저장 및 읽기 시 인코딩 불일치가 발생하지 않도록 모든 I/O에 `encoding="utf-8"`을 명시했습니다.
2. **메모리 파일 원자적 쓰기 (Atomic Write)**:
   - 에이전트 실행 도중 갑작스러운 인터럽트나 충돌로 인해 `MEMORY.md` 파일이 손상되는 것을 방지하기 위해 임시 파일 기록 후 `os.replace`로 치환하는 원자적 교체 메커니즘을 적용했습니다.
3. **FTS5 가상 테이블 정합성**:
   - SQLite FTS5 모듈을 활용하여 메시지 내용 전문 검색 시 트리거(`INSERT` 동기화)를 통해 메인 원장 테이블과 검색 인덱스 간의 데이터 불일치를 원천 차단했습니다.
4. **테스트 격리성의 중요성**:
   - 실제 LLM API 호출이나 외부 환경에 의존하지 않는 `MockLLMClient`와 In-Memory SQLite(`:memory:`)를 설계 초기부터 도입함으로써 0.07초 만에 19개 전체 테스트를 100% 검증할 수 있는 초고속 회귀 테스트망을 확보했습니다.

## 8. 미흡한 부분

- **안전 장치가 비어 있었다.** 마감 시점의 터미널 도구는 모델의 명령을 `shell=True`로 그대로 실행했고, 도구 인자는 검증하지 않았다. 이 때문에 마감 후 점검에서 안전 공백 네 건이 확인되어 02번이 만들어졌다 ([ADR-0002 §1](../../adr/0002-코어_안전_강화_범위와_터미널_가드_방식.md)).
- **실제 모델로는 한 번도 돌리지 않았다.** 가짜 모델만 썼다.
- **파일 도구가 없다.** 기억 도구(상한 있음)를 빼면 파일을 만들거나 고칠 수단이 없었다.

## 9. 새로 발견한 부분

- **「달성도 100%」는 기능의 달성이다.** §1의 100%는 계획한 기능이 동작한다는 뜻이고, 안전 공백은 그 평가 항목이 아니었다. 마감 직후 점검으로 드러났다.
- **의존성 선언과 실제 사용이 다르다.** 계획(ROADMAP §2)과 `pyproject.toml`(`6884617`)은 `httpx`, `pydantic`을 선언했지만 같은 시점 `src` 코드는 이 둘을 가져다 쓰지 않는다(`git grep`으로 확인). §2의 「외부 런타임 의존성 0개」는 코드 기준으로 맞고, 선언 기준으로는 맞지 않는다. 선언은 이후 모델 연결(04)을 염두에 둔 것으로 보이나 기록은 없다(미확인).
- **코드 규모 표기.** §2는 「약 1,300 라인」으로 적었는데, `6884617` 시점 `src/` 전체는 빈 줄과 독스트링을 포함해 1,615줄이다. 1,300의 산정 방식은 기록에 없다(미확인). 지표를 읽을 때 셈법을 확인해야 한다.
- **원래 기록의 차기 로드맵 서술이 실제와 달랐다.** §5 정정 참조.
