## 1. 구현 내용 명세

1. **통합 E2E 시험 추가** ([`test_agent_e2e.py`](../../../../tests/test_hermes_core/test_agent_e2e.py)): 한 대화 안에서 파일 생성·읽기·수정, 금지 경로 거부, 덮어쓰기 거부, 작업 폴더 밖 읽기 거부, 읽을 수 없는 인자가 섞여도 루프가 정상 종료함을 확인한다. 아래 3번 시나리오를 따른다.
2. **01·02편 최종 대조** ([01편](../../../작동원리/01-헤르메스코어-작동원리.md), 02편(이후 [로드맵 02 결과정리및리뷰.md](../../02-코어-안전강화/결과정리및리뷰.md)로 병합됨)):
   - 01편의 「지금은 없는 방어선」, 5부 ① 「지금은 없는 것」 열, 「파일 도구는 지금은 없다」류 서술이 실제 코드와 일치하는지 대조한다 (010~050에서 고친 부분 포함).
   - 5부 ③ 검증표를 갱신하고, 검증 방법 문단과 5부 ② 항목 10의 테스트 파일 수·개수를 최종 값으로 고친다.
   - 02편은 경로 판정 코드의 위치(`path_guard.py`)와 터미널 도구의 서술이 사실과 맞는지 대조한다.
   - 01편 「다시 확인하는 법」의 명령을 모두 실행해 결과가 나옴을 확인하고, 파일 도구용 명령(`grep`)을 추가한다.
3. **03편 작동원리 최종 대조** (작동원리 03편, 계획 단계부터 이미 존재. 이후 [결과정리및리뷰.md](../결과정리및리뷰.md)로 병합됨): 010~050에서 `[계획]` 서술을 사실로 고쳐 왔으므로, 060에서는 마지막 대조만 한다.
   - 문서 어디에도 `[계획]` 표시와 「구현 전 문서」 문구가 남아 있지 않다.
   - 머리의 설명(구현 완료·마감 전), 5부 ① 대조표의 「지금」 열, ② 색인(이미 만들어진 파일의 링크 활성화), ③ 검증표(시나리오 개수, 테스트 개수, 「미확인」)가 최종 코드와 맞는다.
   - 알려진 한계(쓰기 횟수 상한 없음, 링크 교체 경쟁, 하드링크, `patch`의 줄바꿈 민감성, 통째 교체 수단 없음)가 실제 구현과 일치하는지 확인한다.
   - 코드 용어는 5부 ②에만 쓴다. 확인하지 못한 것은 「미확인」으로 쓴다.
   - `기준 커밋` 값은 건드리지 않는다 (마감 커밋에서 채움).
4. **코드 변경 없음**: 이 단계는 테스트와 문서만 바꾼다. 시나리오가 실패하면 코드를 고치지 않고 멈춰서 보고한다.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

현재 작업 폴더를 임시 폴더 `W`로 바꾼다(`monkeypatch.chdir`). `W` 밖에 `outside.txt`(내용 `OUTSIDE-SECRET`)를 둔다. 기본 디스패처를 쓰고 `HERMES_HOME`은 `W` 밖 임시 폴더로 지정한다. 가짜 모델의 응답 순서는 다음과 같다.

| 턴 | 가짜 모델의 응답 |
|---|---|
| 1 | `write_file` `{"path": "notes.txt", "content": "hello\n"}` 요청 |
| 2 | `read_file` `{"path": "notes.txt"}` 요청 |
| 3 | `patch` `{"path": "notes.txt", "old_string": "hello", "new_string": "world"}` 요청 |
| 4 | `write_file` `{"path": "AGENTS.md", "content": "x"}` 요청 |
| 5 | `write_file` `{"path": "notes.txt", "content": "again"}` 요청 |
| 6 | `read_file` `{"path": "../outside.txt"}` 요청 |
| 7 | `patch`, 인자 문자열 `"{bad"` 요청 |
| 8 | `read_file` `{"path": "notes.txt"}` 요청 |
| 9 | 텍스트 `"done"` |

| # | 기대 결과 |
|---|---|
| 1 | `final_response == "done"`, `stopped_reason == "completed"`, `iterations == 9` |
| 2 | 파일 `W/notes.txt`의 내용이 `world\n` |
| 3 | `W/AGENTS.md`가 존재하지 않음, `outside.txt` 내용이 `OUTSIDE-SECRET` 그대로 |
| 4 | 도구 메시지 8개가 순서대로: 생성 성공(`notes.txt`), 읽기 성공(`1\|hello` 포함), 수정 성공(`replacements` 포함), 지시문 파일 거부(`instruction` 포함), 덮어쓰기 거부(`already exists` 포함), 폴더 밖 거부(`outside` 포함), 인자 읽기 실패(`JSON` 포함), 읽기 성공(`1\|world` 포함) |
| 5 | 세션 원장의 메시지 수 = 사용자 1 + 모델 9 + 도구 8 = 18 |
| 6 | 모델 요청마다 대응하는 도구 메시지가 있음 (`tool_call_id` 일치) |
| 7 | 어떤 도구 메시지에도 `OUTSIDE-SECRET`이 없음 |

## 4. 검증 기준 (Done 조건)

1. 위 7개 확인이 통과한다.
2. 전체 `pytest tests/test_hermes_core/`가 통과하고, 개수가 01편·03편에 적힌 값과 같다.
3. 01편의 재확인 명령(grep 포함)을 모두 실행해 결과가 나옴을 확인한다.
4. 01편에서 「지금은 없다」로 적힌 항목마다 대응 코드가 정말 없는지(또는 생겼는지) 대조한 결과를 보고에 적는다.
5. 03편의 링크가 모두 실제 파일을 가리키는지, 개인 경로·이메일이 없는지 확인한다.
