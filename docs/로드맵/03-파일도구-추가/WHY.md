# [WHY] 03-파일도구-추가 — 왜 이 로드맵을, 왜 이 정도로만 하는가

> **성격**: 이 로드맵의 의도를 적은 문서다 ([ROADMAP_정책 §3-2](../ROADMAP_정책.md)).  
> **사후 작성 (2026-10-29)**: 03번은 `WHY.md`를 두는 규칙이 생기기 전에 마감되었다. 이 문서는 마감 후에 [ADR-0003](../../adr/0003-파일_도구_범위와_쓰기_안전_정책.md), [계획 005](../../계획/005-03번로드맵_검토와_진행계획.md), [ROADMAP.md](ROADMAP.md), [대시보드](README.md), [결과정리및리뷰.md](결과정리및리뷰.md)에 **이미 적혀 있는 내용만** 모아 재구성했다. 착수 전에 쓴 의도의 원본이 아니며, 당시 기록에 없는 가정이나 판정은 새로 만들지 않았다.

---

## 1. 왜 지금 이 로드맵인가

02번으로 터미널 도구는 셸 없이 허용된 읽기·출력 프로그램만, 작업 폴더에서만 실행된다. 그 결과 **코어에는 파일을 만들거나 고칠 수단이 없다**(기억 도구는 크기 상한이 있는 별도 기능이다). 코드를 다루는 에이전트가 읽기만으로는 아무것도 완성하지 못하므로 파일 도구가 필요하다 ([ROADMAP.md §1](ROADMAP.md)).

그러나 쓰기는 에이전트가 처음 갖는 「바깥을 바꾸는 능력」이다. 이 레포의 구조에서는 쓰기 도구가 두 가지 새 위험을 만든다 ([ADR-0003 §1](../../adr/0003-파일_도구_범위와_쓰기_안전_정책.md)).

1. **상태 폴더**: 기억 파일과 대화 기록 데이터베이스(`state.db`)의 기본 위치가 레포 안 `.hermes/`다. 작업 폴더가 레포 루트이면 그 안에 있어서, 쓰기 도구가 직접 고치면 기억의 크기 상한과 대화 기록을 우회할 수 있다.
2. **지시문 파일**: 매 대화의 시스템 지시문에 `AGENTS.md`·`agents.md`·`SOUL.md`·`.cursorrules`가 자동으로 들어간다. 모델이 이를 고치면 다음 대화부터 사용자가 모르는 규칙으로 움직이는 지속적인 경로가 생긴다. 원본(`hermes-agent`)도 같은 이유로 지시문 파일 쓰기를 항상 사람 승인 대상으로 둔다.

따라서 이 로드맵은 「도구를 만드는 일」이 아니라, **쓰기 능력을 주면서 두 사고가 처음부터 일어나지 못하게 막는 일**이다.

## 2. 왜 이 정도로만 하는가

[ROADMAP.md §8](ROADMAP.md)의 범위 밖 목록과 [ADR-0003](../../adr/0003-파일_도구_범위와_쓰기_안전_정책.md)에 적힌 이유다.

| 하지 않는 것 | 이유 (기록에 있는 것) | 이후 |
|---|---|---|
| `search_files`(파일 순회·검색) | 파일을 훑는 범위와 링크 처리는 별도 설계 주제다 (ADR-0003 §2-1) | 당시 04 후보로 기록. 실제 04는 모델 연결이 되었다([04 WHY](../04-실제모델-연결-MVP/WHY.md)) |
| 기존 파일 전체 덮어쓰기, 퍼지(비슷한 문자열) 일치, 여러 파일을 한 번에 고치는 패치 | 원본은 이를 읽기 기록 상태로 통제하는데 구현이 매우 크다(원본 파일 도구가 수천 줄). 덮어쓰기는 새 파일 전용과 정확 일치 `patch`로 대신한다 | 기록 없음 |
| 읽기 기록 상태 관리(읽은 파일만 쓰기 허용) | 같은 이유 | 기록 없음 |
| 파일 삭제·이름 변경·폴더 생성 전용 도구 | 범위 밖으로 명시 | 기록 없음 |
| 쓰기 횟수·총량 상한, 동시성 잠금, 운영체제 수준 격리 | 범위 밖으로 명시. 크기 상한만 둔다 | 기록 없음 |
| 실제 모델 연결 | 범위 밖 | [04](../04-실제모델-연결-MVP/WHY.md) |
| 터미널의 링크 따라가기 옵션(`grep -S`) 완화 | 02에서 남은 문제로 03 범위가 아니다 | 기록 없음 |

## 3. 왜 이 순서, 왜 이 단계 수인가

여섯 단계다 ([대시보드 §2](README.md), [ROADMAP.md §6](ROADMAP.md)).

| 순서 | 단계 | 하는 일 |
|---|---|---|
| 010 | 경로 판정 공용 모듈 추출 | 터미널 도구 안의 작업 폴더 판정을 공용 모듈로 옮김. 동작은 그대로 |
| 020 | `read_file` | 읽기 도구. 줄 번호, 구간 읽기, 출력 상한 |
| 030 | 쓰기 금지 정책 | 상태 폴더와 지시문 파일 쓰기 거부 |
| 040 | `write_file` | 새 파일 전용, 원자적 쓰기 |
| 050 | `patch` | 정확히 일치하고 유일한 문자열만 교체 |
| 060 | 통합 E2E 검증, 문서 동기화 | 전체 |

- **쓰기 금지 정책(030)이 쓰기 도구(040·050)보다 앞에 있다.** 위험을 막는 장치를 먼저 만들고 그 위에 위험한 도구를 얹는 순서다. 이 순서의 이유는 단계표에서 확인되나, 순서를 정한 당시의 설명이 따로 적혀 있지는 않다(해석).
- 010을 별도 단계로 둔 이유는 ADR-0003 §2-3과 ROADMAP §3에서 확인된다. 터미널과 파일 도구가 같은 판정 코드를 쓰게 하되, 터미널 쪽은 가져다 쓰는 것으로만 바꾸어 기존 터미널 시험 38건이 수정 없이 통과하는지로 회귀를 막는다.
- 단계가 여섯 개인 이유는 기록에 없다(미확인). 도구 세 개, 공용 모듈, 정책, 통합 검증의 수와 같다.

## 4. 왜 이 방식을 택하고 무엇을 배척했나

([ADR-0003 §2](../../adr/0003-파일_도구_범위와_쓰기_안전_정책.md), [계획 005 §3](../../계획/005-03번로드맵_검토와_진행계획.md), [ROADMAP.md §4·§6](ROADMAP.md), [결과문서 §6](결과정리및리뷰.md))

| 선택 | 배척한 대안 | 이유 |
|---|---|---|
| `write_file`은 **새 파일만**, 수정은 `patch` (D2) | 기존 파일 전체 덮어쓰기 | 오래된 내용으로 통째로 교체하는 사고를 막는다. 포기하는 것은 통째로 갈아끼우는 편의 |
| `patch`는 정확히 일치하고 유일한 문자열만 교체 | 퍼지 일치 | 잘못된 곳이 바뀌는 사고를 막는다. 줄바꿈·들여쓰기가 다르면 못 찾고, 그때는 다시 읽어야 한다 |
| 작업 폴더 판정을 공용 모듈로 추출 (D3) | 파일 도구에 같은 코드를 따로 작성 | 터미널과 파일 도구의 판정이 어긋나지 않게 |
| 상태 폴더와 지시문 파일은 쓰기·수정 거부, 읽기는 허용 (D4) | 쓰기를 모두 허용 / 읽기까지 막음 | 위 두 위험을 닫으면서 읽기는 막지 않는다. 판정은 링크를 풀어 실제 경로로 하고, 이름 비교는 대소문자를 구분하지 않는다 |
| 지시문 파일 이름 목록을 상수 한 곳에 두고 지시문 조립과 쓰기 금지가 함께 사용 | 두 곳에 따로 적음 | 두 목록이 어긋나는 것을 막는다 |
| 임시 파일에 다 쓴 뒤 교체, 바이트 단위로 읽고 쓰기 | 직접 덮어쓰기, 텍스트 모드 | 쓰다가 멈춰도 반쯤 쓰인 파일이 남지 않게, 줄바꿈 변질을 막게 |
| 쓰기 도구의 `workspace` 매개변수를 설명서에 넣지 않음 | 모델에게 노출 | 모델이 넘기면 02에서 만든 도구 통로가 거부한다 |

## 5. 성공 판단 기준과 당시의 위험 가정

03에는 `WHY.md의 가정 목록`이 없었다. 아래는 [ROADMAP.md §1·§4](ROADMAP.md)의 목표와 사전 점검(Pre-Mortem)을 옮긴 것이다. **이 문서에서 새로 판정하지 않으며**, 결과는 [결과문서](결과정리및리뷰.md)를 따른다.

**성공 기준 (ROADMAP §1·§3)**: 세 도구가 02의 경로 가드 위에서 동작하고, 상태 폴더와 지시문 파일 쓰기가 거부되며, 기존 코어 시험 87건이 수정 없이 통과한다.

| 번호 | 당시의 위험 가정 (ROADMAP §4) | 당시 방어책 |
|---|---|---|
| R1 | 모델이 넘기는 값이 범위를 벗어나도 도구가 실패 메시지로 돌려준다 | 도구 본체가 범위(`offset`, `limit`)를 검사 |
| R2 | 큰 파일을 읽어도 모델 입력이 터지지 않는다 | 한 번에 2,000줄·100,000자, 1,000,000바이트 초과 거부 |
| R3 | 작업 폴더 밖에는 쓰이지 않는다 | 공용 경로 가드가 링크까지 풀어 판정 |
| R4 | 기억 상한·대화 기록을 쓰기 도구로 우회할 수 없다 | 상태 폴더 쓰기 거부 |
| R5 | 지시문 파일을 통한 지속적 주입이 일어나지 않는다 | 지시문 파일 이름과 링크 대상 쓰기 거부 |
| R6 | 오래된 내용으로 기존 파일이 덮어쓰이지 않는다 | 새 파일 전용 `write_file` |
| R7 | 쓰다가 중단되어도 파일이 손상되지 않는다 | 임시 파일 교체 |
| R8 | 줄바꿈·인코딩이 변질되지 않는다 | 바이트 읽기·쓰기, 비 UTF-8·NUL 파일 거부 |
| R9 | 지시문 파일 이름 목록이 두 곳에서 어긋나지 않는다 | 상수 한 곳 + 각 이름이 실제로 주입되는지 시험 |
| R10 | 코드를 고치고 문서를 안 고치는 일이 재발하지 않는다 | 각 단계에서 해당 서술을 고치고 060에서 최종 대조 |

결과문서는 마감 시점에 코어 시험 182개 통과를 적는다 ([결과문서 §12](결과정리및리뷰.md)).

## 6. 알려진 위험과 아직 확인하지 못한 것

[ROADMAP.md §4](ROADMAP.md)의 「알려진 한계」와 [결과문서 §7·§12](결과정리및리뷰.md)를 그대로 옮긴다.

- **쓰기 횟수 상한이 없다.** 작은 파일을 계속 만들어 디스크를 채울 수 있다.
- **검사와 실제 쓰기 사이에 링크가 바뀌는 경우(경쟁 상태)는 막지 않는다.** 프로그램이 한 줄로 순서대로 도는 것을 전제로 한다.
- **작업 폴더 안의 하드링크는 경로로 판정되지 않아** 읽기가 폴더 밖 파일의 내용을 드러낼 수 있다. 쓰기는 임시 파일 교체라 원본에 영향이 없다.
- **`patch`는 줄바꿈·들여쓰기가 다르면 찾지 못한다.** 파일을 통째로 교체하는 수단이 없는 것은 의도된 결과다.
- **미확인**: 대소문자를 구분하는 파일 시스템에서 `agents.md`와 `AGENTS.md`의 동작 차이, 환경변수로 상태 폴더를 지정했을 때의 동작, 쓰기 도중 전원이 꺼질 때의 동작, 실제 모델이 보내는 인자 형태, 원본의 읽기 중복 억제·문서 변환 세부와 Windows·원격 환경.
- **이 문서 자체의 한계**: 사후 재구성이라서, 3절의 순서·단계 수 이유처럼 당시 기록에 없는 것은 「미확인」이나 「해석」으로 남겼다.
