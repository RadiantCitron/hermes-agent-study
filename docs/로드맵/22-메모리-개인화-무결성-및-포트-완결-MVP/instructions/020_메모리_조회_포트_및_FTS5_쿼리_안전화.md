## 1. 배경 및 해결할 결함

ADR-0022([ADR-0022](../../../adr/0022-메모리_개인화_무결성_및_포트_완결_MVP_범위와_결정.md) D-05, D-06) 및 마스터 설계도([ROADMAP.md](../ROADMAP.md))에 정의된 잔여 구조 결함을 해결합니다:

1. **L-4 (`list` 액션 부재 및 `MemoryStorePort` 누락)**:
   - 세션 재개(`--resume`)나 컨텍스트 압축 이후 에이전트가 현재 기억된 항목들을 안전하게 확인하는 수단이 없어 불필요한 변경을 시도하거나 파일 시스템 직접 접근을 유발할 수 있습니다.
   - 도구 계층의 8종 포트 체계 중 `MemoryStorePort`만 누락되어, `dispatcher.py`의 `create_default_dispatcher`가 구체 클래스 `MemoryStore`에 직접 결합되어 있습니다.
2. **L-5 (에피소딕 검색 `session_search` FTS5 쿼리 구문 크래시)**:
   - `session_search` 도구에서 파일명(`config.toml`), 하이픈 모델명(`deepseek-v4`), 특수문자(`error: 404`, `"quotes"`), FTS5 예약어(`AND`, `OR`, `NOT`, `NEAR`)를 검색어로 입력하면 `messages_fts MATCH ?`에 날것의 문자열이 바인딩되어 `sqlite3.OperationalError` 구문 크래시가 발생합니다.
   - 단, 기존 단위 테스트 계약(`test_ledger_domain.py:159`의 `params == ["error log", ...]`)을 100% 보존하기 위해 일반 영숫자/공백/비예약어 평문은 원형을 유지해야 합니다 (Pre-Mortem 위험 1 방어).

## 2. 상세 구현 명세

### 2.1 `MEMORY_SCHEMA` 및 `memory_tool.py` 확장
1. `MEMORY_SCHEMA`:
   - `action` enum에 `"list"` 추가:
     ```python
     "action": {
         "type": "string",
         "enum": ["add", "replace", "remove", "list"],
         "description": "Action to perform on memory: 'add', 'replace', 'remove', or 'list'.",
     }
     ```
   - 도구 설명문 갱신:
     `"description": "Manage persistent bounded memory (add, replace, remove, or list durable facts)."`
2. `MemoryStore.list_entries(self, target: str = "memory") -> dict[str, Any]`:
   - `target`이 `"memory"` 또는 `"user"`가 아니면 에러 반환.
   - `self._sync_from_disk_if_modified(target)`을 호출하여 세션 중 디스크 파일이 외부에서 변경되었으면 최신 항목으로 동기화.
   - `self._success_response(target)` 반환:
     `{"success": True, "target": target, "entries": entries, "usage": ..., "entry_count": len(entries)}`
   - 디스크 쓰기나 시스템 프롬프트 스냅샷 갱신을 발생시키지 않는 순수 조회(Read-Only) 멱등성을 보장.
3. `memory_tool` 진입로 함수:
   - `elif action == "list":` 분기 추가:
     `result = store.list_entries(target)`
   - 미지원 액션 에러 메시지에 `"list"` 안내 추가:
     `"Unknown action '{action}'. Use: add, replace, remove, list"`

### 2.2 `src/hermes_core/tools/ports.py` 내 `MemoryStorePort` 신설
도구 포트 모듈에 9번째 프로토콜로 추가:
```python
@runtime_checkable
class MemoryStorePort(Protocol):
    """Memory 도구 및 ToolDispatcher가 의존하는 바운디드 메모리 저장소 포트 (ADR-0022 D-05)."""

    def load_from_disk(self) -> None: ...

    def add(self, target: str, content: str) -> dict[str, Any]: ...

    def replace(self, target: str, old_text: str, new_content: str) -> dict[str, Any]: ...

    def remove(self, target: str, old_text: str) -> dict[str, Any]: ...

    def list_entries(self, target: str = "memory") -> dict[str, Any]: ...

    def format_for_system_prompt(self, target: str = "memory") -> Optional[str]: ...
```

### 2.3 `src/hermes_core/tools/dispatcher.py` 결합도 해소
1. `from hermes_core.tools.ports import ApproverPort, CommandExecutorPort, MemoryStorePort, SessionSearchPort`로 `MemoryStorePort` 임포트.
2. `from hermes_core.tools.memory_tool import MEMORY_SCHEMA, memory_tool` (`MemoryStore` 구체 클래스 임포트 제거).
3. `create_default_dispatcher`의 타입 힌트를 구체 클래스에서 포트로 전환:
   ```python
   def create_default_dispatcher(

       include: Optional[Collection[str]] = None,
       approver: Optional[ApproverPort] = None,
       checkpointer: Optional[Checkpointer] = None,
       command_executor: Optional[CommandExecutorPort] = None,
   ) -> ToolDispatcher:
   ```

### 2.4 `src/hermes_core/ledger_domain.py` 내 FTS5 안전화
1. `sanitize_fts_query(query: str) -> str` 순수 도메인 함수 신설:
   - 빈 문자열이거나 공백뿐이면 `""` 반환.
   - 공백(`\s+`) 기준으로 개별 토큰 분리.
   - 토큰별 정규화 규칙:
     - FTS5 대문자 예약어(`{"AND", "OR", "NOT", "NEAR"}`): 대소문자 무관하게 예약어이면 큰따옴표로 감쌈 (`f'"{token}"'`).
     - 특수문자 검사: 영숫자, 언더스코어, 유니코드 문자/숫자(`\w`) 외의 문자가 포함된 토큰(예: `-`, `.`, `:`, `"`, `*`, `^`, `(`, `)`, `{`, `}`, `+`, `/`, `\`)은 내부의 `"`를 `""`로 치환(이스케이프)한 뒤 양끝을 큰따옴표로 감쌈 (`f'"{escaped}"'`).
     - 순수 단어/문장 토큰은 그대로 유지하여 평문 원형 보존.
   - 정규화된 토큰들을 공백(`" "`)으로 결합하여 반환.
2. `build_fts_search_query` 연동:
   - 입력받은 `query`를 먼저 `sanitized = sanitize_fts_query(query)`로 정규화.
   - `if not sanitized: return ("", [])`
   - `params: list[Any] = [sanitized]`로 바인딩하여 특수문자나 예약어 검색 시 SQLite 구문 크래시 원천 차단.

## 3. 선기술 인수 테스트 시나리오 (6종)

`tests/test_hermes_core/test_memory_port_and_fts.py` 신설:

1. **시나리오 1 (`test_scenario_r22_020_memory_list_action_returns_entries_and_usage`)**:
   - 상황: `store.add("memory", "Fact 1")`, `store.add("memory", "Fact 2")`가 등록됨.
   - 행동: `memory_tool(action="list", target="memory", store=store)` 호출.
   - 기대 결과: `success: True`, `entries: ["Fact 1", "Fact 2"]`, `entry_count: 2`, `usage` 문자열 반환. 디스크 파일 및 동결 스냅샷 변경 없음.
2. **시나리오 2 (`test_scenario_r22_020_memory_list_reflects_external_disk_edits`)**:
   - 상황: `store.load_from_disk()` 완료 후 외부에서 `MEMORY.md` 파일에 `"§ External list fact"`를 직접 추가.
   - 행동: `memory_tool(action="list", target="memory", store=store)` 호출.
   - 기대 결과: `_sync_from_disk_if_modified`를 통해 외부 변경이 감지되어 반환된 `entries`에 `"External list fact"`가 포함됨.
3. **시나리오 3 (`test_scenario_r22_020_memory_store_conforms_to_memorystore_port`)**:
   - 상황: `MemoryStore` 인스턴스 생성.
   - 행동: `isinstance(store, MemoryStorePort)` 검증 및 `create_default_dispatcher(memory_store=store)` 주입.
   - 기대 결과: 런타임 프로토콜 적합성 단언 통과 및 디스패처의 `"memory"` 도구 정상 실행.
4. **시나리오 4 (`test_scenario_r22_020_sanitize_fts_query_preserves_plain_text_contract`)**:
   - 상황: `query="error log"`, `query="한글 검색 쿼리 123"`.
   - 행동: `sanitize_fts_query` 및 `build_fts_search_query` 호출.
   - 기대 결과: 따옴표 없이 원형 `"error log"`, `"한글 검색 쿼리 123"`을 반환하며, 기존 단위 테스트 단언 `params == ["error log", ...]`가 100% 통과됨.
5. **시나리오 5 (`test_scenario_r22_020_sanitize_fts_query_escapes_special_characters_and_reserved_keywords`)**:
   - 상황: `query="config.toml deepseek-v4 AND NOT error:404 \"quoted\""`.
   - 행동: `sanitize_fts_query(query)` 호출.
   - 기대 결과: 특수문자 및 예약어가 포함된 토큰만 안전하게 큰따옴표로 감싸지고 내부 큰따옴표가 `""`로 이스케이프된 정규화 문자열 반환.
6. **시나리오 6 (`test_scenario_r22_020_fts5_crash_prevention_end_to_end_with_session_db`)**:
   - 상황: 실제 `:memory:` `SessionDB` 인스턴스에 메시지(`"deepseek-v4 released with config.toml"`) 저장.
   - 행동: `db.search_messages(query="deepseek-v4")`, `db.search_messages(query="config.toml")`, `db.search_messages(query="AND")`, `db.search_messages(query='invalid"syntax(')` 호출.
   - 기대 결과: SQLite FTS5 구문 에러(`sqlite3.OperationalError`) 크래시 없이 정상 검색 결과를 반환 (안전한 결과 목록 반환).
