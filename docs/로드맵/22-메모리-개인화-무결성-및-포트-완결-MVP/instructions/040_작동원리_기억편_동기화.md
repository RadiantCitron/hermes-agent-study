## 1. 배경 및 동기화 목적

22번 로드맵([`22-메모리-개인화-무결성-및-포트-완결-MVP`](../README.md)) 010~030단계를 통해 기억 장치의 5대 구조적 결함(L-1~L-5)이 코드와 시험 스위트 전반에서 완전히 해결되었습니다:
1. **L-1 (부분 문자열 가림 함정 해소)**: `_resolve_entry_index`를 도입하여 완전 일치 항목(`e == old_text`)을 최우선 매칭함으로써 짧은 메모의 영구 수정/삭제 불능 문제를 해결하고 `replace` 시 중복 항목 생성을 방어했습니다 (R22-010).
2. **L-2 (인메모리 선변경 및 파일 증발 차단)**: `_commit_entries` 단일 관문을 도입하여 디스크 쓰기 성공 후에만 인메모리를 갱신(Write-First)하며, 읽기 오류 시 Fail-Closed 잠금(`_unreadable_targets`)으로 기존 기억 덮어쓰기 증발을 차단하고, 외부 수정 감지(`_sync_from_disk_if_modified`)를 구축했습니다 (R22-010).
3. **L-3 (구분자 및 헤더 위조 관문)**: `_validate_entry_content`를 통해 `"§"` 구분자 입력 분할 오염, 제어문자(C0/DEL), 시스템 프롬프트 헤더 구분선(`══════`) 위조 시도를 쓰기 시점에 원천 거절했습니다 (R22-010).
4. **L-4 (메모리 조회 및 도구 포트 추상화 종결)**: `MEMORY_SCHEMA`에 `action="list"`를 추가하여 세션 재개 후에도 Prefix Cache를 보존한 채 기억을 조회할 수 있게 하고, `src/hermes_core/tools/ports.py`에 `MemoryStorePort` 프로토콜을 신설하여 디스패처와의 결합을 완화했습니다 (R22-020, R22-030).
5. **L-5 (에피소딕 검색 FTS5 쿼리 안전화)**: `ledger_domain.py`에 `sanitize_fts_query` 순수 함수를 도입하여 하이픈·특수문자 검색 크래시를 방어하되 기존 평문 바인딩 계약을 100% 보존했습니다 (R22-020).

그러나 현재 [`docs/작동원리/04-기억-작동원리.md`](../../작동원리/04-기억-작동원리.md)는 2026-10-31 기준 커밋(`a972b78`) 시점의 상태로 머물러 있어, Q6(허술한 곳)에 이미 해결된 결함들이 여전히 잔존하는 문제로 서술되어 있고, `list` 액션 및 `MemoryStorePort`, 단일 관문 무결성 메커니즘이 누락되어 있습니다.

본 040 단계는 [작동원리 README](../../작동원리/README.md)의 작성 규약(쉬운 개념·설계·Why 중심, 이름의 3층 원칙, 귀띔 괄호 표기, Mermaid 규격)과 `AGENTS.md` §4를 엄격히 준수하여 `04-기억-작동원리.md`를 현재 실제 구현에 맞추어 완전 동기화합니다.

### 2.3 2부: 핵심 질문과 답변 (Q&A) 동기화
- **Q1 (기억의 형태와 입력 검증)**:
  - 칸막이(`§`)와 헤더 구분선 구조 설명 유지.
  - 신규 무결성 관문(`_validate_entry_content`) 해설: AI가 임의로 `"§"`를 넣어 다음 읽기 시 칸막이가 쪼개지는 파싱 오염(L-3), 제어문자(C0/DEL), 시스템 프롬프트 헤더 구분선(`══════`) 위조 시도를 쓰기 시점에 원천 거절함을 명시.
  - (구현: `memory_tool.py` · `_validate_entry_content`, 5부 ② 1번)
- **Q2 (읽기와 사본 및 Fail-Closed 잠금)**:
  - 대화 시작 시 한 번 읽어 사본을 고정하는 Prefix Cache 최적화 원리 유지.
  - Fail-Closed 읽기 잠금 메커니즘(`_unreadable_targets`): 디스크 읽기 시 권한이나 인코딩 오류(`UnicodeDecodeError`, `OSError`)가 발생했을 때, 기존 As-Is처럼 빈 목록으로 폴백하여 다음 쓰기 시 기존 파일을 덮어써 증발시키던 위험(L-2)을 차단. 읽기 실패한 파일은 잠금 상태로 격리하여 쓰기 시도시 즉시 안전하게 거절(`RuntimeError`)함을 해설.
  - (구현: `memory_tool.py` · `_unreadable_targets`, `load_from_disk`, 5부 ② 1번)
- **Q3 (갱신 판단과 도구 설명서)**:
  - 도구 설명서(`MEMORY_SCHEMA`)에 4대 액션(추가 `add`, 바꾸기 `replace`, 지우기 `remove`, 조회 `list`) 명시.
  - 시스템 프롬프트 `MEMORY_GUIDANCE`에 세션 재개 후 기억 상태 확인을 위한 `list` 액션 안내가 포함됨을 설명.
  - 도구 계층 추상화(`MemoryStorePort`): `ToolDispatcher`가 구체 구현인 `MemoryStore`에 결합되지 않고 포트 규약을 통해 의존함으로써 가상 메모리 저장소(`FakeMemoryStore`)로도 완결 구동될 수 있음을 귀띔.
  - (구현: `prompt_builder.py` · `MEMORY_GUIDANCE`, `ports.py` · `MemoryStorePort`, 5부 ② 1, 3, 4번)
- **Q4 (갱신 후 처리 - 4대 액션 순서 및 단일 매칭 관문)**:
  - 공통 준비:
    1. 외부 변경 선동기화(`_sync_from_disk_if_modified` via SHA-256): 사람이 메모장을 외부 편집기로 수정한 경우 도구 호출 직전 디스크 내용을 자동 선반영.
    2. 동작 이름 검증 (`add`, `replace`, `remove`, `list`).
  - 추가(`add`):
    - 공백 정리, 내용 무결성 검증(`_validate_entry_content`), 중복 확인, 글자 한도 체크 후 `_commit_entries` 호출.
  - 바꾸기(`replace`):
    - 새 내용 검증, 동일 내용 중복 치환 거부.
    - **단일 매칭 관문 (`_resolve_entry_index`)**: 찾을 글을 포함하는 항목이 여러 개일 때, 찾을 글과 완전히 일치하는 항목(`e == old_text`)이 존재하면 이를 최우선 매칭하여 Substring Shadowing(L-1) 문제를 완벽히 해결! 서로 다른 항목 다중 일치 시에만 모호성 거절.
    - 글자 한도 체크 후 `_commit_entries` 호출.
  - 지우기(`remove`):
    - `_resolve_entry_index`를 통한 완전 일치 우선 탐색 후 `_commit_entries` 호출.
  - **조회(`list`)**:
    - 파일 수정 없이 현재 인메모리 목록 전체와 사용량(% 및 글자 수)을 Prefix Cache 변경 없이 도구 결과로 반환.
  - (구현: `memory_tool.py` · `_resolve_entry_index`, `list_entries`, `_sync_from_disk_if_modified`, 5부 ② 1번)
- **Q5 (저장 과정 - Write-First 원자적 트랜잭션)**:
  - 기존 As-Is의 Split-Brain 결함(인메모리를 먼저 바꾸고 디스크 저장 실패 시 상태 불일치)을 설명.
  - **To-Be: Write-First 원자적 커밋 (`_commit_entries`)**:
    1. 임시 파일 생성(`tempfile.mkstemp`) 후 전체 내용 작성.
    2. `os.fsync`로 디스크 물리 플러시 보증.
    3. `os.replace`로 원자적 파일 교체.
    4. 디스크 쓰기가 100% 성공한 직후에만 인메모리 `entries` 및 SHA-256 해시 갱신!
    5. 디스크 쓰기 실패 시 예외가 전파되며 인메모리 원본 목록 100% 보존.
  - (구현: `memory_tool.py` · `_commit_entries`, `_write_file`, 5부 ② 1번)
- **Q6 (허술한 곳 점검 - 해결 내역과 잔여 한계)**:
  - **해결된 허술한 곳 (L-1 ~ L-5)**:
    1. [해결됨] 읽기 실패가 빈 메모장으로 처리되어 증발하던 문제 ➔ Fail-Closed 잠금(`_unreadable_targets`)으로 쓰기 원천 차단.
    2. [해결됨] 저장 실패 시 인메모리와 디스크 어긋남 ➔ Write-First 트랜잭션(`_commit_entries`)으로 원자적 동기화.
    3. [해결됨] 외부 편집 및 동시 변경 시 덮어쓰기 ➔ SHA-256 해시 대조(`_sync_from_disk_if_modified`)로 외부 편집 선동기화.
    4. [해결됨] 내용에 `"§"` 포함 시 파싱 분할 오염 ➔ `_validate_entry_content` 관문으로 거절.
    5. [해결됨] 과거 대화 검색(FTS5) 특수문자 문법 에러 ➔ `ledger_domain.py`의 `sanitize_fts_query` 순수 함수로 안전화.
  - **잔여 자연적 한계**:
    - 전원 강제 차단 하드웨어 시험 미실시(운영체제의 원자적 교체 성질에 의존).
    - 다중 프로세스 분산 락 부재(로컬 단일 인스턴스 전제).
    - AI의 기억 선별 판단 품질(프로그램은 글자 수와 일치성만 검증).
- **Q7 (틀린 기억 수정 및 외부 동기화)**:
  - AI에게 요청(`remove`/`replace`)하거나 파일 직접 수정.
  - 외부 수정 시 SHA-256 해시 비교로 다음 도구 호출 때 자동 반영됨을 기술.
