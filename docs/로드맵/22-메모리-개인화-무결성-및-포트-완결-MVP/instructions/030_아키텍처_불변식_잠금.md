## 1. 배경 및 해결할 결함

22번 로드맵 020 단계에서 `src/hermes_core/tools/ports.py`에 `MemoryStorePort` 프로토콜을 신설하고, `dispatcher.py`의 `create_default_dispatcher`가 의존하는 메모리 저장소 타입을 구체 클래스 `MemoryStore`에서 `Optional[MemoryStorePort]`로 완화하여 도구 계층의 9대 포트 체계를 완결했습니다.

그러나 현재 `tests/test_architecture/test_ports_conformance.py`에는 `MemoryStorePort`에 대한 아키텍처 수준의 프로토콜 적합성 및 시그니처 바인딩 검증이 빠져 있습니다. 또한 디스패처가 실제 파일시스템 I/O나 `tmp_path` 없이 순수 인메모리 `FakeMemoryStore`만으로도 완결 구동될 수 있음을 아키텍처 단위에서 보증해야 합니다 (시나리오 R7의 `FakeApprovalStore`, `FakeSearchStore`와 동일한 원칙).

본 030 단계는 다음과 같은 아키텍처 불변식을 영구 잠금합니다:
1. **`MemoryStorePort` 프로토콜 적합성 및 시그니처 검증**:
   - `MemoryStore` 구체 클래스가 `MemoryStorePort`를 완전 충족(`issubclass`, `isinstance`)함을 증명.
   - 6대 공개 메서드(`load_from_disk`, `add`, `replace`, `remove`, `list_entries`, `format_for_system_prompt`)의 `inspect.signature().bind()` 호출 정합성 검증.
2. **순수 인메모리 `FakeMemoryStore` 독립 완결 구동**:
   - `MemoryStorePort`를 구현한 순수 Fake 객체로 `ToolDispatcher` 주입 및 4대 액션(`add`, `list`, `replace`, `remove`)의 완결 실행 검증.
3. **아키텍처 불변식 스위트 전수 통과 보증**:
   - 의존 방향 규칙(R1~R7) 및 잔여 부채 0건(`KNOWN_DEBT == {}`).
   - `src/hermes_core/` 내 신규 소스 파일 0개 유지 및 전 파일 800줄 상한 준수.
   - `kernel/` 디렉터리 0줄 무수정 및 격리 불변식.
   - `ledger_domain.py`의 `sanitize_fts_query`를 포함한 6대 순수 도메인 모듈의 인프라(DB/네트워크) 무의존성.
   - 전 모듈 타입 주석 100% 런타임 해석.

## 2. 상세 구현 명세

### 2.1 `tests/test_architecture/test_ports_conformance.py` 확장
`test_ports_conformance.py`에 `test_scenario_r22_memory_store_port_conformance` 및 `test_scenario_r22_fake_memory_store_standalone_in_dispatcher` 테스트 함수 추가:

1. **`test_scenario_r22_memory_store_port_conformance()`**:
   - `from hermes_core.tools.memory_tool import MemoryStore`
   - `from hermes_core.tools.ports import MemoryStorePort`
   - `issubclass(MemoryStore, MemoryStorePort)` 단언.
   - 임의의 경로 인자로 생성한 `MemoryStore(Path("/virtual/memory"))`에 대해 `isinstance(store, MemoryStorePort)` 단언.
   - 6대 메서드 시그니처 바인딩 검증:
     ```python
     # load_from_disk
     sig_load = inspect.signature(MemoryStore.load_from_disk)
     sig_load.bind(None)

     # add
     sig_add = inspect.signature(MemoryStore.add)
     sig_add.bind(None, "memory", "fact")

     # replace
     sig_replace = inspect.signature(MemoryStore.replace)
     sig_replace.bind(None, "memory", "old", "new")

     # remove
     sig_remove = inspect.signature(MemoryStore.remove)
     sig_remove.bind(None, "memory", "old")

     # list_entries
     sig_list = inspect.signature(MemoryStore.list_entries)
     sig_list.bind(None)
     sig_list.bind(None, target="user")

     # format_for_system_prompt
     sig_format = inspect.signature(MemoryStore.format_for_system_prompt)
     sig_format.bind(None)
     sig_format.bind(None, target="memory")
     ```

2. **`test_scenario_r22_fake_memory_store_standalone_in_dispatcher()`**:
   - `MemoryStorePort`를 구현하는 순수 인메모리 `FakeMemoryStore` 클래스 정의 (디스크 I/O 0회):
     ```python
     class FakeMemoryStore:
         def __init__(self) -> None:
             self.storage: dict[str, list[str]] = {"memory": [], "user": []}

         def load_from_disk(self) -> None:
             pass

         def add(self, target: str, content: str) -> dict[str, Any]:
             self.storage.setdefault(target, []).append(content)
             return {"success": True, "target": target, "action": "add"}

         def replace(self, target: str, old_text: str, new_content: str) -> dict[str, Any]:
             entries = self.storage.get(target, [])
             for i, e in enumerate(entries):
                 if old_text in e:
                     entries[i] = new_content
                     return {"success": True, "target": target, "action": "replace"}
             return {"success": False, "error": f"No entry matched '{old_text}'."}

         def remove(self, target: str, old_text: str) -> dict[str, Any]:
             entries = self.storage.get(target, [])
             for i, e in enumerate(entries):
                 if old_text in e:
                     entries.pop(i)
                     return {"success": True, "target": target, "action": "remove"}
             return {"success": False, "error": f"No entry matched '{old_text}'."}

         def list_entries(self, target: str = "memory") -> dict[str, Any]:
             entries = list(self.storage.get(target, []))
             return {"success": True, "target": target, "entries": entries, "entry_count": len(entries), "usage": "fake 100/1000 chars"}

         def format_for_system_prompt(self, target: str = "memory") -> Optional[str]:
             entries = self.storage.get(target, [])
             return "\n".join(entries) if entries else None
     ```
   - `assert issubclass(FakeMemoryStore, MemoryStorePort)`
   - `fake = FakeMemoryStore()`
   - `assert isinstance(fake, MemoryStorePort)`
   - `dispatcher = create_default_dispatcher(memory_store=fake)` 주입.
   - `dispatcher.handle_function_call("memory", {"action": "add", "target": "memory", "content": "Fake item 1"})` 실행 및 검증.
   - `dispatcher.handle_function_call("memory", {"action": "list", "target": "memory"})` 실행 및 검증 (`entries == ["Fake item 1"]`).
   - `dispatcher.handle_function_call("memory", {"action": "replace", "target": "memory", "old_text": "item 1", "content": "Fake item 2"})` 실행 및 검증.
   - `dispatcher.handle_function_call("memory", {"action": "remove", "target": "memory", "old_text": "item 2"})` 실행 및 검증 (`storage["memory"] == []`).

## 3. 선기술 인수 테스트 시나리오 (4종)

1. **시나리오 1 (`test_scenario_r22_030_memory_store_port_conformance_and_signature_binding`)**:
   - 상황: `MemoryStore` 클래스와 `MemoryStorePort` 프로토콜을 대조.
   - 행동: `issubclass`, `isinstance` 확인 및 6대 공개 메서드 시그니처 바인딩 수행.
   - 기대 결과: 모든 바인딩이 예외 없이 성공하며 런타임 서브타입 단언 통과.
2. **시나리오 2 (`test_scenario_r22_030_fake_memory_store_standalone_in_dispatcher`)**:
   - 상황: 파일시스템이나 세션 DB가 없는 순수 가상 환경에서 `FakeMemoryStore` 생성.
   - 행동: `create_default_dispatcher(memory_store=fake)`에 주입 후 `memory` 도구 4대 액션(`add`, `list`, `replace`, `remove`) 호출.
   - 기대 결과: `ToolDispatcher`가 구체 구현 없이 포트 인터페이스만으로 정상 동작하며 응답 JSON 반환.
3. **시나리오 3 (`test_scenario_r22_030_source_files_size_and_purity_suite`)**:
   - 상황: `tests/test_architecture/test_dependency_rules.py` 실행.
   - 행동: 6대 순수 도메인 모듈(인프라 무의존성), 800줄 상한선, R1~R7 의존 방향 규칙 검증.
   - 기대 결과: `sanitize_fts_query`가 추가된 `ledger_domain.py`를 포함하여 모든 순수 도메인 및 소스 파일이 아키텍처 규칙을 100% 준수.
4. **시나리오 4 (`test_scenario_r22_030_kernel_isolation_and_annotations_suite`)**:
   - 상황: `test_kernel_isolation.py` 및 `test_annotations_resolve.py` 실행.
   - 행동: 커널 모듈 격리 및 전 모듈 타입 주석 get_type_hints 런타임 해석 수행.
   - 기대 결과: 커널 0줄 무수정 및 전 모듈 타입 주석 해석 100% 통과 (실패 0건).
