# [구현지시서 040] 실제 모델 스모크 및 마감

> **상위 대시보드**: [15-README.md](../README.md)  
> **선행 조건**: 030 `Done` **그리고 사용자의 명시적 실행/마감 지시**.  
> **근거**: [WHY.md](../WHY.md) 성공 기준과 가정 A~F, [ADR-0015](../../../adr/0015-코드_탐색_및_루프_정체_감지_MVP_범위와_결정.md) §2-8  
> **성격**: 코드·문구를 바꾸지 않는 **실행·검증 및 5단계 마감 단계**다.

---

## 1. 목적

010~030의 단위·통합·실제 클라이언트(`OpenRouterClient` + `MockTransport`) E2E 검증이 모두 통과한 상태에서, 실제 모델 스모크(또는 사용자 지시에 따른 030 E2E 갈음 확인)를 거친 뒤 [ROADMAP_정책.md §5](../../ROADMAP_정책.md)에 따라 종합보고서(`결과정리및리뷰.md`)를 작성하고 로드맵 15를 `Closed`로 마감한다.

---

## 2. 사전 조건 및 스모크 절차

### 2-1. 에이전트 사전 점검
1. `.venv/bin/pytest -n 4 -q` 및 `.venv/bin/pytest -m pty -q` 전체 통과 확인.
2. `git diff <030 구현 커밋>..HEAD -- src/`가 0줄인지 확인.

### 2-2. 실제 모델 터미널 스모크 (사용자 별도 터미널 실행 시, Zero Leakage 준수)
- 키(`OPENROUTER_API_KEY`)는 대화창에 절대 입력하지 않고 별도 터미널에서 실행한다([AGENTS.md](../../../../AGENTS.md) §3).
- 확인 항목:
  1. 작업 폴더 안에 하위 파일(`sub/calc.py`)을 만들어 두고 파일 이름을 알려주지 않은 채 *"작업 폴더에서 `multiply` 함수가 들어 있는 파일을 찾아 그 안의 상수를 고쳐줘"*라고 요청했을 때, 에이전트가 `terminal`(`find`) 승인 질문 없이 `search_files` → `read_file` → `patch` 순서로 완주하는가 (**가정 A·B**).
  2. `state.db`에 API 키가 기록되지 않았는가 (`key_leaked: False`).
- *(참고: 사용자가 030의 `OpenRouterClient` + `MockTransport` E2E 검증으로 스모크를 갈음하고 즉시 마감을 지시한 경우에는 14번 로드맵 050 선례와 동일하게 030 E2E 결과를 근거로 마감을 수행한다.)*

## 3. 마감 (5단계) 수행 내역

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)에 따라 다음을 수행한다:

1. **종합보고서 ([`결과정리및리뷰.md`](../결과정리및리뷰.md)) 작성** — 필수 9개 항목 포함:
   1. 목표와 결과 (`WHY.md` 가정 A~F 전수 대조표 포함)
   2. 단계별 상세 (010~040, Why 중심 서술)
   3. 정량 검증 지표 (층위별 테스트 수, 코드 규모)
   4. 아키텍처 성과와 작동원리 반영 목록 (01·02·03편 반영 내역)
   5. 미흡한 부분 및 알려진 한계
   6. 새로 발견한 부분 (인사이트)
   7. 트러블슈팅과 교훈
   8. 후속 인계 사항 (다음 로드맵 후보)
   9. 사실 검증 4축 결과와 「미확인」
2. **대시보드 ([`README.md`](../README.md)) 갱신**:
   - 전체 상태를 `Closed`로 전환, 완료 일자·마감 태그(`roadmap-15-closed`)·종합보고서 링크 기록, 030 커밋 해시 및 040 실행 기록 채움.
3. **커밋 및 마감 태그 부착**:
   - 커밋 제목: `docs(core): R15-마감 - 15번 코드 탐색(search_files) 및 루프 정체 감지(LoopGuard) MVP 마감 및 종합보고서 작성`
   - 태그: `git tag roadmap-15-closed` (푸시는 별도 지시 시에만 수행).
