## 1. 왜 지금 이 로드맵인가

14번까지로 에이전트의 기억, 안전, 되돌리기, 멈추고 다시 이어 달리기까지 모든 기본 뼈대가 갖춰졌다. 그런데 막상 에이전트에게 실제 코딩 일을 시켜 보면 **가장 시급한 두 가지 빈자리** 때문에 손발이 묶이거나 헛바퀴를 돈다.

### 첫째 (가장 급선무): 눈(파일 읽기)과 손(파일 쓰기·고치기)은 있는데 더듬이(파일·내용 찾기)가 없다

> 에이전트에게 "프로젝트 안에서 로그인 처리하는 부분을 찾아 고쳐 줘"라고 시켰다. 어느 파일 몇째 줄에 있는지 찾으려면 검색 도구가 있어야 하는데, 03번 로드맵에서 읽기·쓰기·고치기만 먼저 만들고 찾기 도구는 뒤로 미뤄 둔 채 14번까지 왔다.
> 그래서 지금 에이전트는 어쩔 수 없이 터미널 명령으로 파일 찾기 프로그램을 부르는데, 그 프로그램은 기본 허용 목록에 없어서 매번 사람에게 "실행할까요? [예/아니오]" 승인을 물어보며 멈추거나, 숨김 폴더까지 다 뒤져 너무 많은 글자를 한꺼번에 쏟아낸다.

사람의 승인 질문에 가로막히지 않고, 비밀 파일이나 상태 폴더는 알아서 피해 가며 필요한 파일과 줄 번호만 깔끔하게 찾아 주는 **전용 찾기 도구**가 들어가야 비로소 **「찾기 → 읽기 → 고치기」**라는 코딩 에이전트의 기본 3박자가 완성된다.

### 둘째 (루프 안전망): 같은 실수를 되풀이할 때 옆구리를 찔러 멈추게 하는 장치가 없다

> 에이전트가 고칠 위치를 잘못 짚어 수정이 실패했는데도, 파일을 다시 찾아보지 않고 똑같은 틀린 요청을 세 번, 다섯 번, 열 번씩 되풀이하며 최대 횟수(50번)까지 비용과 시간을 태운다.

사람이 매번 화면을 지켜보며 멈춤 키를 누르지 않아도, 에이전트 스스로 **「똑같은 도구 호출이 3번 연속이면 경고를 주어 다른 방법(다시 찾기나 읽기)을 쓰게 유도하고, 그래도 5번 연속이면 즉시 멈춘다」**는 안전망이 있으면 찾기 도구와 완벽하게 맞물려 돌아간다.

## 2. 왜 이 정도로만 하는가

이 로드맵이 **일부러 하지 않는 것**과 그 이유다.

| 하지 않는 것 | 이유 | 언제 하는가 |
|---|---|---|
| 외부 고속 검색 프로그램이나 데이터베이스 설치 | 파이썬에 기본으로 들어 있는 파일 순회와 문자열 비교만으로도 작업 폴더 안의 코드 검색은 충분히 빠르고, 외부 프로그램 설치 문제도 생기지 않는다 | 수십만 개 파일을 다루는 대규모 저장소를 지원할 때 |
| 비밀 파일(`.env`), 깃 폴더(`.git`), 에이전트 상태 폴더(`.hermes`), 바로가기 링크 따라가며 검색하기 | 검색 도구가 비밀 파일 안의 한 줄이라도 결과로 돌려주면 곧바로 비밀 유출이 되고, 바로가기 링크를 따라가면 작업 폴더 밖으로 나가거나 끝없는 순환에 빠질 수 있다 | 해당 없음 (영구 금지) |
| 헛바퀴인지 판단하려고 별도의 인공지능 모델을 한 번 더 부르기 | 도구 이름과 넘긴 값들을 일정한 순서로 정렬해 직전 호출과 같은지만 비교하면 비용 0, 시간 0으로 정확하게 잡아낼 수 있다 | 단순 비교로 잡히지 않는 복잡한 반복이 실제로 문제 될 때 |
| 이전 질문에서 했던 호출 횟수까지 다음 질문으로 이어서 세기 | 사람이 새 질문을 했다는 것은 맥락이 바뀌었다는 뜻이다. 한 질문(한 턴) 안에서만 연속 반복을 세는 것이 자연스럽고 억울한 차단을 막는다 | 해당 없음 |
| 장부의 표 구조 바꾸기나 실제 터미널 창을 띄우는 새 시험 만들기 | 찾기는 읽기 전용 도구이고 반복 감지는 한 턴 안의 동작이므로 장부 표를 바꿀 필요가 없고, 가짜 통신 시험으로 정확하게 검증할 수 있다(계획 015 기준) | 해당 없음 |

**한마디로**: 작업 폴더 안에서 비밀 경로를 피해 파일과 내용을 안전하게 찾고, 한 질문 안에서 똑같은 도구 호출을 되풀이하면 3번째에 경고하고 5번째에 장부 짝을 맞춘 채 깔끔하게 멈춘다.

|---|---|---|
| 010 | 안전한 파일·내용 찾기 도구 만들고 에이전트와 하위 에이전트에 연결하기 | 에이전트가 헛바퀴를 돌지 않으려면 먼저 정당하게 파일과 내용을 찾을 수 있는 수단(`찾기 → 읽기 → 고치기`)이 있어야 한다. 도구 쪽 파일만 건드리므로 독립적으로 먼저 검증한다 |
| 020 | 반복 호출 감지기 만들고 에이전트 루프와 화면 안내에 연결하기 | 010과 겹치지 않는 에이전트 루프 쪽에 감지기를 달아, 3번 반복 시 경고하고 5번 반복 시 장부의 질문-대답 짝을 맞춘 뒤 멈추게 한다 |

| 040 | 실제 모델 확인과 마감 | 실제 모델에서도 찾기 도구를 잘 쓰고 마감 기준을 모두 채웠는지 확인한 뒤 종합보고서를 쓰고 마감한다 |

## 4. 왜 이 방식을 택하고 무엇을 배척했나

| 선택 | 배척한 대안 | 이유 |
|---|---|---|
| 전용 찾기 도구를 새로 만든다 | 터미널 허용 목록에 파일 찾기 명령(`find`)을 추가한다 | 터미널의 `find` 명령은 파일을 지우거나 다른 프로그램을 실행하는 위험한 옵션을 가지고 있어 허용 목록에 넣으면 안전장치가 무너진다 |
| 찾기 도구의 기본 검색을 글자 그대로 찾기(단순 문자열 포함)로 두고, 정규식은 선택 옵션으로 둔다 | 무조건 정규식으로만 검색하게 한다 | 코드에는 괄호나 대괄호가 자주 나오는데, 기본이 정규식이면 모델이 기호를 잘못 써서 검색에 실패하기 쉽다 |
| 찾기 도구가 순회 도중 비밀 파일이나 상태 폴더를 만나면 에러로 멈추지 않고 조용히 건너뛴다 | 비밀 파일이 하나라도 있으면 전체 검색을 에러로 실패시킨다 | 작업 폴더에는 늘 `.env`나 `.git`, `.hermes`가 있기 마련인데, 그때마다 검색 전체가 멈추면 찾기 도구를 쓸 수 없다. 그 파일들만 빼고 나머지 결과를 돌려주는 것이 맞다 |
| 3번째 반복 경고는 도구 결과 묶음(JSON) 안의 한 항목으로 넣는다 | 도구 결과 글자 뒤에 일반 문장으로 덧붙인다 | 결과 뒤에 그냥 글자를 덧붙이면 결과 묶음의 형식이 깨져 이를 읽는 다른 부품에서 오류가 난다 |
| 5번째 반복으로 멈출 때도 도구를 실행하지만 않을 뿐, 장부에는 「반복으로 차단됨」이라는 대답을 짝맞춰 적어 둔다 | 대답을 적지 않고 그 자리에서 바로 루프를 끝낸다 | 이미 에이전트가 「이 도구를 부르겠다」고 장부에 적은 뒤라서, 대답 없이 끝내 버리면 짝 잃은 호출이 장부에 남아 다음 대화나 이어받기(`--resume`)가 고장 난다 |

## 5. 성공 판단 기준과 검증할 가정

**성공 기준**: (1) 에이전트가 사람의 터미널 승인 없이 전용 찾기 도구로 파일 이름과 파일 속 내용을 찾아 읽고 고칠 수 있으며, (2) 작업 폴더 안에 비밀 파일(`.env`), 깃 폴더(`.git`), 에이전트 상태 폴더(`.hermes`), 외부 바로가기 링크가 있어도 검색 결과에 절대 새어 나오지 않고 결과 개수가 상한(50건)을 넘지 않으며, (3) 한 턴 안에서 똑같은 도구와 인자를 연속 3번 부르면 경고가 전달되고 5번 부르면 실제 실행 없이 장부 짝을 맞춘 채 루프가 즉시 멈춘다.

| 번호 | 가정 | 틀렸다면 |
|---|---|---|
| **A** | 찾기 도구(`search_files`)가 있으면 에이전트가 터미널 승인 질문 없이 파일 위치와 코드 줄 번호를 찾아 읽기·고치기로 이어 갈 수 있다 | 찾기 도구의 입력 항목이나 설명 문구를 점검한다 |
| **B** | 작업 폴더 안에 `.env`, `.git`, `.hermes` 상태 폴더, 작업 폴더 밖을 가리키는 바로가기 링크, 바이너리 파일이 섞여 있어도 찾기 결과에는 단 한 줄도 노출되지 않고 정상 파일만 검색된다 | 순회 중 건너뛰기 조건과 상태 폴더 판정 함수를 고친다 |
| **C** | 일치하는 파일이나 줄이 아무리 많아도 최대 50건·한 줄 200자·스캔 파일 5,000개 상한에서 잘리고 잘렸다는 표시(`truncated`)가 함께 반환된다 | 상한 절단 조건을 고친다 |
| **D** | 인자의 키 순서나 공백만 다르게 쓴 똑같은 호출(또는 똑같이 깨진 인자)이 연속 3번 들어오면 3번째 실행 결과 안에 반복 경고가 담겨 모델에게 전달된다 | 호출 지문 정규화 방식과 경고 부착 방식을 고친다 |
| **E** | 똑같은 호출이 연속 5번에 이르면 5번째 호출은 실제 도구를 실행하지 않고 차단하여 최대 횟수(50번)까지 비용을 태우지 않는다 | 차단 임계값 판정과 핸들러 우회 분기를 고친다 |
| **F** | 5번째 반복으로 루프가 조기 차단된 뒤에도 장부와 메모리의 질문-대답 짝이 온전히 맞아, 곧바로 다음 질문을 하거나 세션을 껐다 다시 이어받아도(`--resume`) 오류가 나지 않는다 | 차단 시 도구 대답 메시지 기록 경로를 점검한다 |

## 6. 알려진 위험과 아직 확인하지 못한 것

- **두 도구를 번갈아 부르는 반복**: 똑같은 도구 하나를 연달아 부르는 것은 즉시 잡아내지만, A 도구와 B 도구를 번갈아 부르는 패턴은 이 감지기가 잡지 않으며 기존의 최대 반복 횟수(50번) 상한이 막아 준다.
- **작업 폴더 안을 가리키는 바로가기 링크**: 순환과 외부 탈출을 원천 차단하기 위해 찾기 도구는 모든 바로가기 링크를 건너뛴다. 바로가기 링크 자체는 파일 읽기 도구로 이름을 직접 지정할 때만 읽을 수 있다.
- 실제 모델이 3번째 반복 경고를 받았을 때 얼마나 잘 다른 방법(찾기·읽기)으로 돌아서는지는 **미확인**이다(030 E2E 및 040에서 확인).
