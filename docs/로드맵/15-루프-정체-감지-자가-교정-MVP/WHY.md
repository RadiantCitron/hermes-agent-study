## 1. 왜 지금 이 두 가지(`search_files` + `LoopGuard`)인가

14번까지로 에이전트의 기억·안전·복원·재개 뼈대는 모두 갖춰졌다. 이제 에이전트가 실제로 일을 잘하고 헛돌지 않게 만드는 **가장 시급한 두 가지 빈자리**가 남았다.

### 첫째 (가장 급선무): 눈(`read_file`)과 손(`write_file`·`patch`)은 있는데 더듬이(`search_files`)가 없다
> 에이전트에게 "프로젝트에서 로그인 처리하는 함수를 찾아 고쳐줘"라고 시켰다. 어느 파일에 있는지 찾으려면 검색 도구가 있어야 하는데, 지금은 검색 도구가 없어서 에이전트가 터미널 명령(`find`)을 부른다. 그런데 `find`는 허용목록에 없어서 매번 사람에게 "실행할까요? [y/N]" 승인을 물어보며 멈추거나, `grep`이 숨김 폴더(`.git`)까지 다 뒤져 거대한 출력을 쏟아낸다.

03번 로드맵([ADR-0003](../../../adr/0003-파일_도구_범위와_쓰기_안전_정책.md))에서 `read_file`·`write_file`·`patch`만 먼저 만들고 다음으로 미뤄 두었던 **`search_files`(안전한 파일·내용 찾기)**를 넣어야 비로소 **「찾기(Search) → 읽기(Read) → 고치기(Edit)」**라는 코딩 에이전트의 기본 3박자가 완성된다.

### 둘째 (루프 안전망): 같은 실수를 되풀이할 때 옆구리를 찔러 멈추게 하는 장치(`LoopGuard`)가 없다
> 에이전트가 고칠 위치를 잘못 짚어 `patch`가 실패했는데도, 파일을 다시 찾아보지 않고 똑같은 틀린 요청을 세 번, 다섯 번, 열 번씩 되풀이하며 최대 횟수(50번)까지 비용을 태운다.

사람이 매번 화면을 지켜보며 `Ctrl+C`를 누르지 않아도, 에이전트 루프 스스로 **「똑같은 호출 3번이면 경고(Nudge)하여 다시 찾아보게 유도하고, 5번이면 즉시 멈춘다(Circuit Break)」**는 안전망이 있으면 두 기능이 완벽히 맞물린다.

## 2. 왜 이 정도로만 하는가 (비목표 초안)

| 하지 않는 것 | 이유 |
|---|---|
| 외부 검색 엔진(ripgrep 바이너리, 벡터 DB, AST 파서) 설치 | 파이썬 표준 라이브러리(`Path.rglob`, 문자열·정규식 매칭)와 기존 `path_guard`만으로도 작업 폴더 내 텍스트 검색은 충분히 빠르고 외부 의존성이 0이다 |
| 보호 파일(`.env*`, `.git`, `.hermes`)이나 작업 폴더 밖 검색 허용 | 검색 도구가 비밀 파일 안의 한 줄이라도 결과로 돌려주면 곧바로 비밀 유출이 된다. 보호 경로는 검색 대상에서 아예 제외한다 |
| 루프 감지를 위해 별도 판정용 LLM 호출하기 | 정규화된 호출 지문(`이름 + 인자`) 비교만으로 비용 0, 지연 0으로 100% 결정론적 감지가 가능하다 |
| DB 스키마 변경 | 검색은 순수 읽기 도구이고 루프 감지는 한 턴 안의 메모리 상태이므로 새 테이블이나 컬럼이 필요 없다 |

## 3. 검증할 핵심 가정 (초안, 14번 완료 후 확정)

| 번호 | 가정 |
|---|---|
| **A** | `search_files`가 추가되면 모델이 파일 위치나 문자열을 찾을 때 `terminal`(`find`/`grep`) 승인 질문 없이 `search_files` → `read_file` → `patch` 순서로 일을 마친다 |
| **B** | 작업 폴더 안에 `.env`나 `.git` 파일이 있어도 `search_files` 결과에는 절대 노출되지 않으며, 매치 수가 많아도 상한(예: 50건)에서 안전하게 잘린다 |
| **C** | 똑같은 도구·인자 호출이 연속 $K$회(예: 3회) 반복될 때 경고(Nudge)를 주입하면 모델이 반복을 멈추고 다른 방법을 택한다 |
| **D** | 경고를 무시하고 연속 $M$회(예: 5회) 반복하면 50회까지 가지 않고 즉시 `stuck_loop`으로 루프가 중단된다 |
