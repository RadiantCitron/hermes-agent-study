## 1. 왜 이 로드맵인가

01~14번까지로 에이전트는 도구를 안전하게 부르고, 기억을 압축하고, 잘못 고친 파일을 되돌리고, 멈췄다가 다시 이어 달릴 줄 안다. 그러나 **에이전트가 스스로 판단의 늪에 빠졌을 때**를 제어하는 장치는 아직 없다.

> 에이전트가 파일에서 어떤 줄을 고치려다 찾을 문자열을 조금 틀려 `patch`가 실패했다. 보통 사람이라면 파일을 다시 읽어 보겠지만, 모델은 가끔 똑같은 틀린 인자로 `patch`를 세 번, 네 번, 열 번씩 계속 부른다. 지금은 최대 횟수(50번)를 다 채울 때까지 에이전트가 같은 벽에 머리를 부딪히며 시간과 비용을 다 써 버린다.

에이전트 프로그래밍에서 이 문제를 푸는 핵심 원리는 **「일하는 고리(Loop) 바깥에서 반복을 감지해 개입하기」**다.
1. 처음 몇 번 같은 호출이 반복되면 **"지금 똑같은 요청을 계속 반복하고 있으니 다른 방법을 쓰거나 사람에게 물어보라"고 옆구리를 찔러 주고(자가 교정 유도, Nudge)**,
2. 그런데도 계속 같은 호출을 고집하면 **50번까지 기다리지 않고 그 자리에서 고리를 끊어(회로 차단, Circuit Breaker)** 사람에게 제어권을 돌려준다.

## 2. 왜 이 정도로만 하는가 (비목표 초안)

| 하지 않는 것 | 이유 |
|---|---|
| 다른 모델을 따로 불러 「지금 루프에 빠졌는지」 판정하게 하기 | 감지기를 돌리느라 매번 추가 모델 비용과 지연이 든다. 똑같은 도구와 똑같은 인자를 거듭 부르는지는 단순한 글자 비교만으로도 100% 정확하고 즉시 알 수 있다 |
| 여러 턴이나 여러 세션에 걸친 반복까지 추적하기 | 정체 현상은 사람의 한 번의 요청 안에서 에이전트가 혼자 도구를 연달아 부를 때 일어난다. 한 요청 안에서만 세면 구조가 가장 단순하고 장부를 건드릴 필요가 없다 |
| 장부(DB) 표 구조 바꾸기 | 요청 하나가 도는 동안에만 필요한 계산이므로 장부에 새 표를 만들지 않는다 |

## 3. 검증할 핵심 가정 (초안, 14번 완료 후 확정)

| 번호 | 가정 |
|---|---|
| **A** | 똑같은 도구·인자 호출이 지정한 횟수(예: 3회) 반복되었을 때 결과에 경고 안내(Nudge)를 붙여 주면, 모델이 같은 호출을 멈추고 파일을 다시 읽거나 사람에게 답한다 |
| **B** | 경고를 받고도 모델이 같은 호출을 계속 반복하면, 최대 횟수(50회)까지 가지 않고 차단 횟수(예: 5회)에서 즉시 멈춰(`stuck_loop`) 추가 모델 호출을 막는다 |
| **C** | 인자 안의 띄어쓰기나 항목 순서만 다르고 내용이 같은 호출도 같은 호출로 정확히 잡아내고, 내용이 다른 정상적인 연속 호출(예: 파일 5개를 차례로 읽기)은 절대 막지 않는다 |
