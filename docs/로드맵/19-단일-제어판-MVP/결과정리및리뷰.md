## 1. 목표와 결과

### 1-1. 목표 달성 요약
본 로드맵의 목표는 흩어져 있던 에이전트의 런타임 설정과 수명주기, 확장(미들웨어·턴 훅) 상태를 단일한 제어 창구로 모으고, 자동 회로 차단과 선감사 원장, 턴 경계 반영 규약을 통해 메인루프의 안정성을 보장하는 것이었다:
1. **[목표 1 — 계층 설정과 출처 추적]**: 기본값 < TOML 설정 파일 < 환경변수 < CLI 인자의 4계층 설정을 단일한 불변 스냅샷([`Settings`](../../../src/hermes_core/control/settings.py))으로 합성하고, 각 설정 항목이 어떤 계층에서 왔는지 명확히 기록.
2. **[목표 2 — 상태 스냅샷과 비밀값 보호]**: 에이전트 내부 상태(설정, 확장의 켜짐과 실패 통계, 세션, 토큰 사용량)를 동결된 읽기 전용 모델([`ControlSnapshot`](../../../src/hermes_core/control/snapshot.py))로 추출하고, 터미널 출력 시 API 키 등 비밀값을 자동 마스킹.
3. **[목표 3 — 확장 게이트와 자동 회로 차단]**: 연속으로 실패하는 불안정한 확장을 메인루프 앞단 게이트([`_ExtensionHost`](../../../src/hermes_core/agent/agent.py))에서 감지하여 자동으로 차단(회로 차단기)함으로써 동일 오류의 무한 반복을 방지.
4. **[목표 4 — 쓰기 명령 검증, 선감사, 턴 경계 반영]**: 런타임 설정 변경 및 확장 온/오프를 엄격히 검증된 명령 객체로 제한하고, 장부(DB v7 [`control_audit`](../../../src/hermes_core/session_db.py))에 먼저 기록한 뒤 턴이 시작되는 경계에서만 안전하게 일괄 반영. 보안 잠금 설정은 런타임 완화 차단.

### 1-4. 실제 모델 스모크를 하지 않는 이유

19번 로드맵은 에이전트의 런타임 제어 인터페이스(`control/`), 불변 설정 계층 로더, 확장 회로 차단기, 감사 원장을 추가하는 내부 제어 구조 정비다.

- **What**:
  - [`hermes_core.control.settings`](../../../src/hermes_core/control/settings.py) 모듈 신설: `@dataclass(frozen=True)` 기반 `Settings`, `SettingOrigin`, `LoadedSettings`, 4계층 설정 로더(`load_settings_from_sources`, `load_settings`).
  - [`assembly.create_agent`](../../../src/hermes_core/assembly.py) 및 [`cli.py`](../../../src/hermes_core/cli.py)에 설정 로더 배선.
  - `tests/test_architecture/test_dependency_rules.py`에 R6 양방향 격리 규칙 추가.
  - 신규 시험 12개(`tests/test_control/test_settings.py`) 구축.
- **결과 및 다른 점**: 기본 설정 합성 및 4계층 우선순위 검증 완료. 회귀 시험 1,106개(not pty) + 10개(pty) 통과.

### 020단계: 상태 스냅샷(읽기 모델)과 비밀값 마스킹 (`00aafc3`)
- **Why**: 에이전트의 런타임 상태(설정, 확장 상태, 세션 정보, 토큰 사용량)를 외부에서 관찰할 때 에이전트 내부 상태를 오염시키지 않는 순수 읽기 모델이 필요했고, 상태 출력 시 API 키 등 비밀값의 유출을 원천 차단해야 했다.
- **What**:
  - [`hermes_core.control.snapshot`](../../../src/hermes_core/control/snapshot.py) 모듈 신설: 동결 dataclass 기반 `ControlSnapshot`, `ExtensionView`, `SessionView`, `UsageView`.
  - 비밀값 정규식 패턴 마스킹(`mask_secrets`) 및 ANSI 터미널 렌더러(`render_snapshot`) 구현.
  - `HermesAgent.get_snapshot()` 메서드 제공 및 `hermes_core.control` 공개 API 재수출.
  - 신규 시험 6개(`tests/test_control/test_snapshot.py`) 구축.
- **결과 및 다른 점**: `test_dependency_rules.py`의 래칫 허용 목록에 `snapshot` 추가(사용자 사전 승인). 1,112개(not pty) + 10개(pty) 통과.

### 030단계: 확장 게이트와 차단기 (`2948da4`)

## 5. 미흡한 부분 (한계와 약점)

1. **런타임 모델 변경 불가**: 대화 진행 도중 LLM 모델을 교체하는 것은 시스템 프롬프트 재구성, 컨텍스트 윈도우 크기 불일치, 제공자별 도구 규약 차이, 프롬프트 캐시 무효화 등 심각한 부작용을 유발하므로 startup 전용(`startup_only`)으로 제한됨. 모델을 변경하려면 세션을 재시작해야 함.
2. **위임 자식 에이전트 생성 시 제어판 전달 미지원 (`KNOWN_DEBT` 4건 유지)**: 위임 도구(`delegate_tool`)가 자식 에이전트를 생성할 때 `cli` 및 `agent`를 역방향으로 참조하는 구조가 잔류하여, 부모 에이전트의 제어판 설정이나 차단기 상태가 자식 에이전트에 완전히 전파되지 않음 (차기 로드맵 과제).
3. **체크포인트 및 승인 로직의 미들웨어 완전 분리 미완**: 제어판을 통해 `approval_enabled`나 `checkpoints_enabled` 설정을 읽을 수는 있으나, 실제 승인 프롬프트와 롤백 처리 로직은 여전히 `cli.py`와 에이전트 본체에 강결합되어 있음.
4. **원격 관리(HTTP/WebSocket) 어댑터 미구현**: 이번 로드맵의 범위는 단일 머신 터미널 제어판(MVP)에 집중하였으므로, 외부 백오피스 웹 UI나 원격 모니터링 데몬 연동을 위한 네트워크 어댑터는 구현하지 않음 (비목표 명시).

## 6. 새로 발견한 부분

1. **Python 3.11+ 표준 `tomllib`의 뛰어난 안정성**: 별도의 서드파티 라이브러리(`toml`, `tomli` 등) 설치 없이도 표준 라이브러리 `tomllib`만으로 TOML 설정 파일을 완벽하게 파싱할 수 있었으며, Python 3.12 환경에서도 추가 의존성 없이 무결하게 작동함을 확인.
2. **스키마 버전 단언의 유연성 확보 필요성**: 040 단계에서 DB 스키마가 v7로 확장될 때, 구형 테스트 코드(`test_checkpoint_ledger.py`)에서 `schema_version == 6`처럼 엄격한 등호 단언을 사용하고 있어 테스트가 실패함을 발견. 11-010의 선례에 따라 `>= 6`으로 교체함으로써 향후 스키마 확장에 유연하게 대처할 수 있도록 개선함.
3. **도구 관문의 예외 동일성 보존 메커니즘**: `tools/dispatcher.py`에 내장된 `mw_exc is inner_exc` 식별 로직 덕분에, 확장 게이트(`_ExtensionHost`)가 도구 내부에서 정상적으로 발생한 예외(예: 사용자 도구 오류)와 미들웨어 자체의 버그로 인한 결함을 정확하게 구별하여, 내부 핸들러 예외를 중립적으로 통과시킬 수 있음을 입증.
4. **CLI REPL 2단계 제어 생명주기의 우수성**: `/ctl` 명령 입력 시에는 대기열에 안전하게 보관하고 다음 턴이 시작되는 경계에서 `apply_pending()`을 실행하는 구조가, 사용자 대화 흐름의 원자성과 턴 무결성을 보장하는 데 대단히 효과적임을 확인.

   - 이를 임의로 수정하여 덮어쓰지 않고, 사용자에게 정밀 보고 후 승인을 받아 허용 목록에 `snapshot`을 등록함으로써 시스템 안전망의 신뢰도를 유지함.
2. **콜백 주입을 통한 R6 유출 의존성 원천 차단**:
   - 040 단계에서 `ControlPanel`이 런타임 설정을 에이전트에 반영해야 했으나, R6 유출 규칙으로 인해 `control/`은 `agent`나 `assembly`를 import할 수 없었음.
   - 이를 해결하기 위해 `ControlPanel` 생성 시 설정 반영 콜백(`apply_settings_fn: Callable[[Settings], None]`)을 외부(`assembly` 또는 `cli`)에서 주입받아 실행하는 방식을 채택하여, 완벽한 단방향 의존성과 모듈 간 결합도 제로를 달성함.

## 9. 사실 검증 4축(동작·순서·소유자·시점) 결과와 「미확인」 해소 보고

### 9-1. 사실 검증 4축 매트릭스
- **동작 (Action)**:
  - 제어판 명령 접수(`panel.submit`), 명령 유효성 검증(`validate_command`), 선감사 장부 기록(`record_control_audit`), 턴 직전 일괄 반영(`apply_pending`), 확장 게이트 래핑 및 자동 차단(`set_extension_enabled(False)`).
- **순서 (Sequence)**:
  - 1. CLI에서 `/ctl set/enable/disable` 입력
  - 2. `panel.submit()` 호출 및 `validate_command()` 검증
  - 3. 장부에 `accepted`(또는 `rejected`) 선감사 기록
  - 4. 대기열(`_pending`) 적재
  - 5. 사용자 메시지 입력 후 REPL이 다음 턴 시작 직전 `panel.apply_pending()` 호출
  - 6. `apply_settings_fn` 및 `set_extension_enabled` 실행
  - 7. 장부에 `applied` 사후 감사 기록
  - 8. 메인루프(`run_conversation`) 진입
- **소유자 (Owner)**:
  - 명령 접수·대기열: 제어판([`ControlPanel`](../../../src/hermes_core/control/panel.py))
  - 감사 기록: SQLite 세션 원장([`session_db.py`](../../../src/hermes_core/session_db.py))
  - 런타임 반영 실행자: 조립 모듈([`assembly.py`](../../../src/hermes_core/assembly.py))
  - 확장 게이트 및 차단 상태 관리자: 에이전트([`_ExtensionHost`](../../../src/hermes_core/agent/agent.py))
- **시점 (Timing)**:
  - `startup`: 기동 시 4계층 설정 로딩 및 에이전트 인스턴스 생성
  - `runtime`: 턴 경계(`apply_pending`)에서만 안전하게 일괄 적용
  - `locked`: 실행 중 완화/변경이 영구 금지된 보안 설정

### 9-2. WHY §6 「미확인」 항목 5건 전수 해소 보고
1. **[도구 관문 실패 정책과의 정합성]**: `dispatcher.py`의 `mw_exc is inner_exc` 판정 로직과 완벽히 정합함을 확인. 게이트가 내부 핸들러 예외를 변조 없이 그대로 전달하므로 사용자 도구 오류가 확장 실패로 오인되어 차단되는 현상 없음 (해소 완료).
2. **[기능 단위 연속 실패 집계 기준]**: 확장 단위의 단일 실패 카운터 정책을 확정하고, 성공 턴 진입 시 카운터를 리셋하며 3회 연속 실패 시 즉시 차단되도록 구현 및 검증 완료 (해소 완료).
3. **[DB v6 → v7 이전 안전성]**: 기존 v6 데이터베이스를 보유한 환경에서 `init_session_db()` 기동 시 `control_audit` 테이블이 자동으로 증설되고 기존 데이터가 무결하게 보존됨을 `test_commands_and_panel.py` 시나리오 2에서 검증 완료 (해소 완료).
4. **[CLI 문자열 분기 충돌 방지]**: `/ctl` 토큰 기반 파싱 로직을 격리하여 기존 `/rollback` 분기 및 일반 대화 프롬프트와의 간섭이 전혀 없음을 단위 및 가상 터미널(`pty`) 시험으로 검증 완료 (해소 완료).
5. **[Python 3.12 TOML 읽기]**: 표준 라이브러리 `tomllib`이 3.12 환경에서 추가 설치 없이 완벽하게 작동함을 확인 완료 (해소 완료).
