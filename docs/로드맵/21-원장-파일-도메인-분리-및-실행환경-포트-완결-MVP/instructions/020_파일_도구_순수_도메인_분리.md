## 0. 착수 전 점검 (지시서 작성 시점에 완료된 사실)

`ROADMAP.md §6 (020)` 및 `§4` 사전 점검 항목을 실제 코드와 대조한 결과는 다음과 같다.

1. **`file_tools.py` 실측 규모**:
   - `wc -l src/hermes_core/tools/file_tools.py` 결과: **640줄**.
   - 레포지토리 소스 트리 내에서 `session_db.py`에 이어 두 번째로 큰 비대 파일임.
2. **`file_tools.py` 내 순수 도메인 알고리즘과 디스크 I/O 혼재 현황**:
   - `read_file_tool` (139~260행, 122줄): 디스크 읽기 및 UTF-8 검증 외에 줄바꿈 분할/CRLF 정규화, 줄 번호 포맷팅(`line_num|content`), 글자 수 누적 상한(`FILE_READ_MAX_CHARS`) 계산, `truncated` 및 `next_offset` 산출 순수 로직이 약 75줄 차지.
   - `patch_tool` (330~436행, 107줄): 디스크 읽기/원자적 쓰기 교체 외에 `old_string` 공백 검사, 동일 문자열 검사, 일치 건수 검사(0건, 다중 일치), 단일/전체 치환, UTF-8 인코딩 크기 검증(`FILE_MAX_BYTES`) 순수 로직이 약 40줄 차지.
   - `search_files_tool` (479~640행, 162줄): 디렉터리 순회 및 경로 가드 외에 내용 검색 모드에서 파일별 줄바꿈 분할, 리터럴/정규식 줄 단위 매칭, 최대 줄 길이 절단(`SEARCH_MAX_LINE_CHARS`) 및 `...` 붙이기 순수 로직이 약 30줄 차지.
3. **불변식 및 테스트 계약 제약 조건 확인**:
   - **디스크 I/O 0건 제약**: `file_domain.py`는 순수 인메모리 텍스트 가공 모듈이어야 하며, `open`, `Path.read_bytes`, `os.replace`, `tempfile` 등 디스크 I/O 함수를 일체 포함하지 않는다.
   - **인프라 무의존 제약**: `sqlite3`, `httpx`, `session_db` 등 인프라 모듈 임포트를 철저히 차단한다 (040 단계에서 `PURE_DOMAIN_MODULES`에 추가될 예정).
   - **기존 테스트 monkeypatch 계약 보존**: `tests/test_hermes_core/test_file_tools.py` 등에서 사용하는 `monkeypatch.setattr("os.replace", ...)` 및 파일 권한 검사 흐름을 100% 무수정 보존하기 위해, 파일 I/O 및 원자적 교체(`tempfile.mkstemp`, `os.replace`)는 `file_tools.py`에 그대로 유지한다.
   - **커널 무수정 원칙**: `src/hermes_core/kernel/` 디렉터리는 완전 무수정 (diff 0줄)을 사수한다.

## 1. 구현 내용 명세

### 1.1 `src/hermes_core/tools/file_domain.py` 신설

디스크 I/O나 외부 라이브러리 없이 순수 인메모리 텍스트 분할, 줄 번호 포맷팅, 글자 수 절단, 패치 문자열 치환, 정규식/리터럴 라인 매칭을 담당하는 순수 도메인 모듈을 신설한다. 표준 라이브러리(`typing`, `re`, `dataclasses` 등)와 `hermes_core.constants`만 임포트한다.

#### 1. 결과 데이터 클래스
- `@dataclass(frozen=True) class SliceLinesResult`:
  - `content: str`: 번호가 붙은 줄들의 결합 문자열 (`\n` 구분).
  - `total_lines: int`: 전체 라인 수.
  - `offset: int`: 요청된 시작 오프셋.
  - `lines_returned: int`: 실제로 반환된 라인 수.
  - `truncated: bool`: 글자 수 상한 또는 limit/남은 라인으로 인한 절단 여부.
  - `next_offset: Optional[int]`: 다음 번 읽기를 위한 오프셋 (더 읽을 줄이 없으면 `None`).
  - `to_dict() -> dict[str, Any]`: 도구 반환 JSON 딕셔너리로 변환하는 헬퍼 메서드.
- `@dataclass(frozen=True) class PatchResult`:
  - `new_text: str`: 치환이 완료된 전체 텍스트.
  - `replacements: int`: 치환된 횟수 (단일 치환 시 1, `replace_all` 시 일치 총 건수).
  - `chars_before: int`: 치환 전 문자 수.
  - `chars_after: int`: 치환 후 문자 수.
  - `encoded_bytes: bytes`: 원자적 쓰기용 UTF-8 인코딩 바이트 열.

#### 2. 순수 도메인 함수
- `split_text_to_lines(text: str) -> list[str]`:
  - `text`가 빈 문자열이면 `[]` 반환.
  - `text.split("\n")` 수행 후 마지막 줄이 빈 문자열이면 제거 (`pop()`).
  - 각 줄의 끝에 `\r`이 있으면 제거 (`line[:-1] if line.endswith("\r") else line`).
  - 정규화된 줄 목록 반환.
- `slice_lines_with_numbers(text: str, offset: int = 1, limit: int = FILE_READ_MAX_LINES, max_chars: int = FILE_READ_MAX_CHARS) -> SliceLinesResult`:
  - `split_text_to_lines(text)`로 정규화된 줄 목록 생성 및 `total_lines = len(lines)` 계산.
  - `total_lines == 0`일 때:
    - `offset > 1`이면 `ValueError(f"offset {offset} is beyond end of file (0 lines).")` 발생.
    - `offset == 1`이면 빈 `SliceLinesResult(content="", total_lines=0, offset=offset, lines_returned=0, truncated=False, next_offset=None)` 반환.
  - `offset > total_lines`이면 `ValueError(f"offset {offset} is beyond end of file ({total_lines} lines).")` 발생.
  - `target_lines = lines[offset - 1 : offset - 1 + limit]` 슬라이싱.
  - 각 줄을 `{line_num}|{raw_line}`으로 포맷팅하며 `max_chars` 상한까지 누적.
  - 누적 한계 초과 시 `truncated = True` 처리 및 `next_offset` 계산 (첫 줄부터 초과 시 해당 줄을 `max_chars`만큼 절단 채택).
  - 전체 라인 끝까지 도달하지 못했을 때도 `truncated = True`, `next_offset = last_read_line_num + 1` 설정.
- `apply_text_patch(text: str, old_string: str, new_string: str, replace_all: bool = False, max_bytes: int = FILE_MAX_BYTES, file_path: Optional[str] = None) -> PatchResult`:
  - `path_suffix = f": '{file_path}'"` if `file_path` else `""`.
  - `not old_string` -> `ValueError("old_string must not be empty.")`.
  - `old_string == new_string` -> `ValueError("old_string and new_string must differ.")`.
  - `count = text.count(old_string)`.
  - `count == 0` -> `ValueError(f"old_string not found in file{path_suffix}")`.
  - `count > 1 and not replace_all` -> `ValueError(f"old_string found {count} times; make it unique or set replace_all=True{path_suffix}")`.
  - 치환 수행:
    - `replace_all == True`: `new_text = text.replace(old_string, new_string)`, `replacements = count`.
    - `replace_all == False`: `new_text = text.replace(old_string, new_string, 1)`, `replacements = 1`.
  - `encoded_new = new_text.encode("utf-8")`.
  - `len(encoded_new) > max_bytes`이면 `ValueError(f"Patch result too large ({len(encoded_new)} bytes > {max_bytes} bytes limit){path_suffix}")` 발생.
  - `PatchResult(new_text, replacements, len(text), len(new_text), encoded_new)` 반환.
- `match_text_lines(text: str, pattern: str, compiled_re: Optional[re.Pattern] = None, max_line_chars: int = SEARCH_MAX_LINE_CHARS) -> list[tuple[int, str]]`:
  - 텍스트를 `\r` 제거된 줄들로 분할 (`[ln.rstrip("\r") for ln in text.split("\n")]`).
  - 1부터 시작하는 `line_num`을 매겨 `(compiled_re.search(line) is not None) if compiled_re else (pattern in line)` 일치 검사.
  - 일치하는 줄에 대해 `preview = line[:max_line_chars] + "..."` (길이 초과 시) 처리.
  - 일치된 `[(line_num, preview), ...]` 리스트 반환.

### 1.2 `src/hermes_core/tools/file_tools.py` 변경 (슬림화)

1. `hermes_core.tools.file_domain`에서 순수 도메인 함수를 임포트한다:
   - `slice_lines_with_numbers`, `apply_text_patch`, `match_text_lines`.
2. `read_file_tool`:
   - 파일 경로 가드, 파라미터 검증, 디스크 읽기 및 UTF-8 검증 완료 후, 텍스트 슬라이싱을 `slice_lines_with_numbers(text, offset, limit)` 호출로 대체.
   - `ValueError` 발생 시 `_failure(str(e))` 반환.
   - 성공 시 `{"success": True, **result.to_dict()}` JSON 직렬화 반환.
3. `patch_tool`:
   - 파일 경로 가드, 디스크 읽기 및 UTF-8 검증 완료 후, 패치 문자열 검증 및 치환을 `apply_text_patch(text, old_string, new_string, replace_all, file_path=path)` 호출로 대체.
   - `ValueError` 발생 시 `_failure(str(e))` 반환.
   - 임시 파일에 `patch_result.encoded_bytes`를 기록하고 원자적 `os.replace` 수행.
   - 성공 시 기존 포맷과 동일한 통계 JSON 반환.
4. `search_files_tool`:
   - 내용 검색 모드에서 파일 읽기 후 줄 단위 매칭을 `match_text_lines(text_content, pattern, compiled_re)` 호출로 대체.
   - `SEARCH_MAX_MATCHES` 초과 시 조기 중단(`truncated = True`) 및 `matches` 리스트 추가.
5. 리팩토링 후 `file_tools.py` 줄 수를 **420줄 내외로 슬림화**한다 (목표: < 450줄, 필수: < 800줄).
6. 모든 도구 함수의 공개 시그니처 및 스키마 상수(`READ_FILE_SCHEMA` 등)를 100% 불변 유지한다.

## 2. 인수 테스트 시나리오 (동어반복 방지 선기술)

구현 전에 요구사항과 명세에서 독립적으로 도출한 8대 인수 테스트 시나리오는 다음과 같다:

1. **시나리오 1 (`test_scenario_r21_file_domain_slice_empty_and_normal`)**:
   - 빈 문자열 `text = ""`, `offset = 1` -> `content = ""`, `total_lines = 0`, `lines_returned = 0`, `truncated = False`, `next_offset = None` 반환.
   - 빈 문자열 `text = ""`, `offset = 2` -> `ValueError("offset 2 is beyond end of file (0 lines).")` 발생.
   - 일반 텍스트 `text = "line1\nline2\nline3"`, `offset = 1, limit = 2` -> `content = "1|line1\n2|line2"`, `total_lines = 3`, `lines_returned = 2`, `truncated = True`, `next_offset = 3`.
   - `offset = 2, limit = 5` -> `content = "2|line2\n3|line3"`, `total_lines = 3`, `lines_returned = 2`, `truncated = False`, `next_offset = None`.
2. **시나리오 2 (`test_scenario_r21_file_domain_slice_crlf_and_trailing_newline`)**:
   - CRLF 개행 및 마지막 개행 정규화 검증:
     `text = "hello\r\nworld\r\n"` -> 줄 목록 `["hello", "world"]` (마지막 빈 줄 제거 및 `\r` 제거).
     `offset = 1, limit = 2` -> `content = "1|hello\n2|world"`, `total_lines = 2`.
3. **시나리오 3 (`test_scenario_r21_file_domain_slice_truncation_max_chars`)**:
   - `max_chars` 상한선 누적 및 절단 검증:
     `text = "a" * 50 + "\n" + "b" * 50`, `max_chars = 60` 호출 시 첫 줄(52자) 채택 후 두 번째 줄에서 60 초과로 절단되어 `truncated = True`, `next_offset = 2`, `lines_returned = 1`.
   - 단일 줄이 `max_chars`를 초과하는 경우:
     `text = "x" * 100`, `max_chars = 30` 호출 시 첫 줄이 30자로 잘려 채택(`"1|" + "x" * 28`), `truncated = True`, `next_offset = 2`.
4. **시나리오 4 (`test_scenario_r21_file_domain_apply_patch_success`)**:
   - 단일 치환 (`replace_all = False`):
     `text = "hello world\nhello universe"`, `old_string = "world"`, `new_string = "earth"`
     결과: `new_text = "hello earth\nhello universe"`, `replacements = 1`, `chars_before = 26`, `chars_after = 26`, `encoded_bytes` 일치.
   - 전체 치환 (`replace_all = True`):
     `text = "foo bar foo baz"`, `old_string = "foo"`, `new_string = "qux"`, `replace_all = True`
     결과: `new_text = "qux bar qux baz"`, `replacements = 2`.
5. **시나리오 5 (`test_scenario_r21_file_domain_apply_patch_validation_errors`)**:
   - 빈 `old_string`: `ValueError("old_string must not be empty.")`
   - 동일 문자열 `old_string == new_string`: `ValueError("old_string and new_string must differ.")`
   - 미발견 문자열 (`file_path="test.py"`): `ValueError("old_string not found in file: 'test.py'")`
   - 다중 일치인데 `replace_all = False` (`file_path="test.py"`):
     `text = "a b a c"`, `old_string = "a"`
     `ValueError("old_string found 2 times; make it unique or set replace_all=True: 'test.py'")`
   - 크기 상한 초과: 결과 바이트 수가 `max_bytes` 초과 시 `ValueError("Patch result too large ...")`
6. **시나리오 6 (`test_scenario_r21_file_domain_match_text_lines_literal_and_regex`)**:
   - 리터럴 매칭:
     `text = "alpha\nbeta gamma\nalpha delta"`, `pattern = "alpha"`
     결과: `[(1, "alpha"), (3, "alpha delta")]`
   - 정규식 매칭:
     `pattern = r"b\w+"`, `compiled_re = re.compile(r"b\w+")`
     결과: `[(2, "beta gamma")]`
   - 긴 라인 프리뷰 절단:
     `text = "short\n" + "x" * 500`, `pattern = "x"`, `max_line_chars = 100`
     결과 2행의 내용이 `"x" * 100 + "..."`로 103자 프리뷰가 되는지 확인.
7. **시나리오 7 (`test_scenario_r21_file_tools_regression_and_line_count`)**:
   - `file_tools.py` 줄 수가 800줄 미만(목표: 400~450줄)인지 확인.
   - 기존 파일 도구 테스트(`tests/test_hermes_core/test_file_tools.py`, `test_search_files.py`, `test_file_tools_checkpoint.py` 총 102개)가 단 1개의 수정 없이 100% 통과하는지 회귀 검증.
8. **시나리오 8 (`test_scenario_r21_pure_file_domain_no_io_or_infra`)**:
   - AST 분석을 통해 `file_domain.py` 내에 `open`, `read`, `write`, `os.replace`, `tempfile` 등 I/O 호출 및 `sqlite3`, `httpx` 등 인프라 모듈 임포트가 0건인지 확증.

## 3. 파급 범위 및 하위 호환성 검증
