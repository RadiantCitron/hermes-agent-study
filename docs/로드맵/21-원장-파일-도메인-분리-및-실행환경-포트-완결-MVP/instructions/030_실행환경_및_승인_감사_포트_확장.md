## 0. 착수 전 점검 (지시서 작성 시점에 완료된 사실)

`ROADMAP.md §6 (030)` 및 `§4` 사전 점검 항목을 실제 코드와 대조한 결과는 다음과 같다.

1. **현재 테스트 기준선 실측**:
   - `.venv/bin/pytest -q` 결과: **총 1,189개 테스트 전수 통과** (`not pty` 1,178개 + `pty` 11개).
   - 010 단계(`ledger_domain.py`) 8개 시험 및 020 단계(`file_domain.py`) 8개 순수 단위 시험이 모두 포함되어 녹색 통과 상태임.
2. **`terminal_tool.py` (167줄) 및 `dispatcher.py` (433줄)의 현재 결합 실측**:
   - `terminal_tool.py` 21행: `from hermes_core.tools.approval import Approver`로 구체 클래스에 직접 결합되어 있음.
   - `terminal_tool.py` 77~119행 `_execute`: 호스트의 `subprocess.run`을 고정 호출하며 외부 격리 환경(Docker 컨테이너, Firecracker 마이크로VM, 원격 실행기 등)을 주입받을 수 있는 인터페이스가 없음.
   - `dispatcher.py` 339~345행 `create_default_dispatcher`: `approver: Optional[Approver] = None`만 수용하고 있으며, `command_executor` 주입 인자가 없음.
3. **`ports.py` (109줄)의 현재 정의 현황**:
   - 20번 로드맵에서 정의된 5종 프로토콜(`ApprovalStorePort`, `CheckpointStorePort`, `DelegateStorePort`, `SessionSearchPort`, `ChildRunnerPort`)이 안정적으로 운용 중.
   - 여기에 `ApproverPort`, `CommandExecutorPort`, `ControlAuditPort` 3종을 신설하여 총 8종의 포트 체계를 완결해야 함.
4. **불변식 및 테스트 계약 제약 조건 확인**:
   - **기존 `subprocess.run` monkeypatch 테스트 계약 보존**: `tests/test_hermes_core/test_terminal_tool.py` 및 `test_terminal_approval.py`의 20여 개 시험은 `monkeypatch.setattr(terminal_module.subprocess, "run", ...)`을 수행한다. 따라서 `command_executor` 기본값은 반드시 `None`이어야 하며, `None`일 때는 기존의 `terminal_tool._execute` 경로를 그대로 타야 한다.
   - **`ApproverPort` 호환성**: `Approver.request(self, argv: list[str]) -> ApprovalOutcome` 시그니처와 100% 부합하여 기존 `Approver` 인스턴스가 `isinstance(approver, ApproverPort)`를 무수정으로 통과해야 한다.
   - **`ControlAuditPort` 호환성**: `SessionDB.record_control_audit(...)` 및 `list_control_audit(...)` 시그니처와 100% 부합하여 기존 `SessionDB` 인스턴스가 `isinstance(session_db, ControlAuditPort)`를 무수정으로 통과해야 한다.
   - **다층 보안 방어선 불변**: `command_executor`가 주입되더라도 `ALLOWED_COMMANDS` 판정, `path_guard`의 작업 디렉터리 내 경로 검사(`is_inside`), 보호 파일 접근 차단(`is_protected_path`), 승인기 검사(`approver.request`)는 실행기 호출 전에 먼저 수행되어야 한다.
   - **`create_child_dispatcher()` 불변**: 자식 에이전트는 무승인·기본 실행기 격리 상태를 유지해야 하므로 `create_child_dispatcher`의 인자 없는 시그니처는 그대로 보존한다.
   - **커널 무수정 원칙**: `src/hermes_core/kernel/` 디렉터리는 완전 무수정 (diff 0줄)을 사수한다.

## 1. 구현 내용 명세

### 1.1 `src/hermes_core/tools/ports.py` 확장 (포트 3종 추가)

표준 라이브러리 `typing`(`Protocol`, `runtime_checkable`, `TYPE_CHECKING`) 및 `pathlib.Path`를 활용하여 다음 3종의 프로토콜을 추가한다.

1. **`ApproverPort`**:
   ```python
   @runtime_checkable
   class ApproverPort(Protocol):
       """터미널 도구가 사용자나 외부 정책 엔진에 명령 승인을 요청하는 포트 (ADR-0021 D-04)."""

       def request(self, argv: list[str]) -> ApprovalOutcome: ...
   ```
   - 순환 참조 방지를 위해 `ApprovalOutcome`은 `if TYPE_CHECKING:` 블록에서 `from hermes_core.tools.approval import ApprovalOutcome`으로 임포트하고, 모듈 상단의 `from __future__ import annotations`를 활용한다.
2. **`CommandExecutorPort`**:
   ```python
   @runtime_checkable
   class CommandExecutorPort(Protocol):
       """작업 디렉터리 내에서 서브프로세스 또는 샌드박스 명령을 실행하는 포트 (ADR-0021 D-04).

       서브프로세스 격리(Docker 컨테이너, Firecracker 마이크로VM, 원격 gRPC 실행기 등)
       구현체가 이 프로토콜을 구현하여 terminal_tool에 주입된다.
       """

       def __call__(self, args: list[str], cwd: Path, timeout: int) -> str: ...
   ```
   - 반환값은 `terminal_tool` 규격의 JSON 문자열(`{"success": bool, "exit_code": int, "stdout": str, "stderr": str}` 또는 실패 JSON)이다.
3. **`ControlAuditPort`**:
   ```python
   @runtime_checkable
   class ControlAuditPort(Protocol):
       """제어 명령 검증·반영 및 차단기 동작 감사 기록 저장소 포트 (ADR-0021 D-04)."""

       def record_control_audit(
           self,
           session_id: str,
           *,
           source: str,
           command: str,
           target: str,
           old_value: Optional[str] = None,
           new_value: Optional[str] = None,
           result: str,
           reason: Optional[str] = None,
       ) -> int: ...

       def list_control_audit(self, session_id: str) -> list[dict[str, Any]]: ...
   ```

### 1.2 `src/hermes_core/tools/terminal_tool.py` 포트 주입 수용

1. `from hermes_core.tools.ports import ApproverPort, CommandExecutorPort` 임포트. (구체 클래스 `from hermes_core.tools.approval import Approver` 임포트 제거).
2. `terminal_tool` 함수 시그니처 확장:
   ```python
   def terminal_tool(
       command: str,
       timeout: int = TERMINAL_MAX_TIMEOUT,
       workspace: Optional[Path] = None,
       approver: Optional[ApproverPort] = None,
       command_executor: Optional[CommandExecutorPort] = None,
   ) -> str:
   ```
3. 실행 위임 헬퍼 `_run_command` 도입 또는 실행 분기 정돈:
   ```python
   def _run_command(
       args: list[str],
       cwd: Path,
       timeout: int,
       command_executor: Optional[CommandExecutorPort] = None,
   ) -> str:
       if command_executor is not None:
           try:
               return command_executor(args, cwd, timeout)
           except Exception as e:
               return json.dumps(
                   {
                       "success": False,
                       "error": f"Execution error: {str(e)}",
                       "exit_code": -1,
                   },
                   ensure_ascii=False,
               )
       return _execute(args, cwd, timeout)
   ```
4. `ALLOWED_COMMANDS` 및 승인 통과 후 실행 지점에서 `_run_command(args, base, timeout, command_executor)` 호출.
   - 경로 가드(`is_inside`, `is_protected_path`)와 승인기(`approver.request`) 검사는 실행기 호출 전에 100% 동일하게 선행.

## 2. 인수 테스트 시나리오 명세 (`tests/test_hermes_core/test_sandbox_and_approver_ports.py`)

신규 작성할 테스트 모듈 `tests/test_hermes_core/test_sandbox_and_approver_ports.py`에 다음 10개 독립 시나리오를 작성한다.

| 시나리오 | 대상 | 입력 / 조건 | 기대 결과 |
|:---:|---|---|---|
| **01** | `ApproverPort` 런타임 검사 | `Approver` 인스턴스 및 `request(argv)`를 갖춘 가짜 객체 | `isinstance(obj, ApproverPort) is True`. `request`가 없거나 호출 불가능한 객체는 `False` |
| **02** | `CommandExecutorPort` 런타임 검사 | 일반 함수 `fake_exec(args, cwd, timeout)` 및 `__call__`을 가진 클래스 인스턴스 | `isinstance(fn, CommandExecutorPort) is True`. `__call__`이 없는 일반 객체는 `False` |
| **03** | `ControlAuditPort` 런타임 검사 | `SessionDB` 인스턴스 및 `record_control_audit`/`list_control_audit` 메서드를 갖춘 객체 | `isinstance(session_db, ControlAuditPort) is True`. 하나라도 누락된 객체는 `False` |
| **04** | `terminal_tool` 허용 명령 실행기 위임 | `command="ls"`, `command_executor=fake_executor` 주입. `subprocess.run` 모의 호출 기록 감시 | `fake_executor`가 인자 `(["ls"], workspace, 30)`으로 호출되고 그 결과 JSON이 반환됨. `subprocess.run`은 전혀 호출되지 않음 |
| **05** | `terminal_tool` 미허용 명령 승인 후 실행기 위임 | `command="pytest"`, `approver` (승인 응답), `command_executor` 주입 | `approver.request`가 먼저 호출되어 `approved=True` 확인 후 `fake_executor`가 실행되어 결과 반환 |
| **06** | `terminal_tool` 미허용 명령 승인 거부 시 차단 | `command="pytest"`, `approver` (거부 응답), `command_executor` 주입 | `approver.request` 호출 후 거부 메시지 JSON 반환. `fake_executor`는 전혀 호출되지 않음 (`called == False`) |
| **07** | `terminal_tool` 보호 경로 차단 선행 | `command="ls .env"`, `command_executor` 주입 | 실행기 호출 전 `Path '.env' refers to a protected file` 실패 JSON 반환. 실행기는 전혀 호출되지 않음 |
| **08** | `terminal_tool` 실행기 예외 방어 | `command_executor`가 `RuntimeError("Docker daemon socket error")` 발생 | 프로세스가 비정상 종료되지 않고 `{"success": False, "error": "Execution error: Docker daemon socket error", "exit_code": -1}` 반환 |
| **09** | `terminal_tool` 기본 실행기(`None`) 로컬 폴백 | `command="echo hello"`, `command_executor=None` 기본값. `monkeypatch.setattr(terminal_module.subprocess, "run", ...)` 적용 | 기존 monkeypatched `subprocess.run`이 정상 호출되어 결과 반환 (하위 호환성 100%) |
| **10** | Lv 4 Docker 샌드박스 통합 E2E 시뮬레이션 | `MockDockerSandboxExecutor` (가상 컨테이너 격리 실행기)를 `create_default_dispatcher`에 주입 후 `dispatcher.dispatch("terminal", {"command": "cat test.txt"})` 호출 | 컨테이너 격리 환경 문자열이 디스패처를 통해 투명하게 반환되고, 에이전트 코어 변경 없이 Lv 4 샌드박스 주입 성공 |
