## 2. 단계별 상세 (010~060, Why 중심 서술)

### 010단계: 원장 순수 도메인 분리와 `SessionDB` 슬림화 (`aa761f4`)
- **Why**: 시스템 내 유일한 1,000줄 초과 모듈이었던 `SessionDB`(1,001줄) 안에 실제 SQLite 연결/쿼리 실행과 순수 입력 유효성 검증, 메시지 역할 변환, 압축 메타데이터 가공, FTS5 MATCH 검색 쿼리 문자열 조립이 뒤섞여 있어 가독성이 떨어지고 단위 테스트 작성이 어려웠다.
- **What**:
  - [`hermes_core.ledger_domain`](../../../src/hermes_core/ledger_domain.py) 모듈 신설 (352줄).
  - 유효성 검증 함수 6종(`validate_session_id`, `validate_message_role`, `validate_message_content`, `validate_session_status`, `validate_tool_call_payload`, `validate_checkpoint_id`), 상태 변환 4종(`build_message_record`, `build_session_summary`, `format_tool_result_content`, `parse_compression_meta`), 전문 검색 쿼리 빌더(`build_fts5_match_query`), 스키마 상수 분리.
  - [`session_db.py`](../../../src/hermes_core/session_db.py)를 1,001줄에서 779줄로 슬림화하고, SQLite 연결선(`_conn`) 핸들은 오직 `SessionDB` 내부에만 보존.
  - [`test_ledger_domain.py`](../../../tests/test_hermes_core/test_ledger_domain.py) 신설 (8개 순수 단위 시험).
- **결과 및 다른 점**: 순수 단위 시험 8종 통과, 기존 시험 1,170개 전수 통과, 커널 diff 0줄 유지.

### 020단계: 파일 도구 순수 도메인 분리 (`aa2b5fc`)
- **Why**: 파일 도구 모듈(`file_tools.py`, 640줄) 안에 실제 디스크 파일 I/O 및 백업 원자적 교체 로직과 순수한 텍스트 줄 슬라이싱, 패치 치환, 라인 매칭 알고리즘이 혼재되어 있어 단위 검증에 디스크 I/O가 강제되었다.
- **What**:

## 6. 새로 발견한 부분

1. **기본값 `None` 폴백 패턴의 하위 호환성 위력**: `CommandExecutorPort`의 기본값을 `None`으로 두고, 주입되지 않았을 때 모듈 내부의 `_execute`로 자연스럽게 폴백되도록 설계함으로써, 기존 20여 개 터미널 테스트의 `monkeypatch.setattr(subprocess, "run", ...)` 계약을 단 한 줄도 손대지 않고 통과시킬 수 있음을 입증하였다.
