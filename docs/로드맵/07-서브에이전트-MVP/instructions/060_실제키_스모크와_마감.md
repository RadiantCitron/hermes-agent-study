# [구현지시서 060] 실제 키 스모크 1회 (사용자 지시가 있을 때만 실행) 및 마감

> **상위 대시보드**: [07-README.md](../README.md)  
> **선행 조건**: 050 단계 완료 (`Done`) **그리고 사용자의 명시적 실행 지시**. 마감은 추가로 사용자의 종료 선언이 있을 때만 한다.  
> **근거**: [WHY.md](../WHY.md) 가정 A·B·D·E·F·G, [ADR-0007](../../../adr/0007-서브에이전트_MVP_범위와_격리_방식.md), 형식 선례: [06의 060](../../06-스킬-시스템-MVP/instructions/060_실제키_스모크.md)  
> **성격**: 코드를 바꾸지 않는 **실행·검증 단계**다. 지시서는 절차와 기대 결과만 정한다. 실행 결과는 대시보드와 종합보고서에 기록한다.

---

## 1. 목적

가짜 통신으로 모든 시험이 통과한 상태에서 다음을 실제 모델·실제 클라이언트로 한 번 확인한다.

1. **가정 G**: 안내문만으로 실제 모델이 필요할 때 `delegate_task`를 부르고, 자식이 `goal`만으로 일을 끝내는가. 가짜 모델로는 판정할 수 없다.
2. **가정 B**: 실제 `OpenRouterClient`를 자식마다 새로 만들었을 때 자식 호출이 자식 세션 원장에만 쌓이는가.
3. **가정 A·E**: 자식 통로의 도구 집합과 프롬프트가 실제 요청에 그대로 실리는가.
4. **가정 F**: 실제 자식 응답이 요약 상한(8,000자) 안에 드는가.
5. 키가 어디에도 남지 않는가. 비용이 얼마나 곱해지는가(위험 8).

## 2. 사전 조건 (사용자가 확인)

1. 키 변수 이름은 `OPENROUTER_API_KEY`다. 사용자의 셸에서 이 이름으로 내보냈는지만 확인한다. 에이전트는 `.env`를 열지 않는다.
2. **별도 터미널**(에이전트 세션이 아닌 사용자의 터미널)에서 직접 환경변수로 키를 내보낸다. **키는 에이전트와의 대화·명령줄·프롬프트에 절대 쓰지 않는다** ([AGENTS.md](../../../../AGENTS.md) §3).
3. `pytest tests -q`가 모두 통과한다.
4. **임시 상태 폴더**: 실제 `.hermes`를 쓰지 않고 레포 밖 임시 폴더(세션 scratchpad 등)를 `HERMES_HOME`으로 쓴다. 에이전트가 그 경로를 사용자에게 알려 주며, 레포의 문서·대시보드에는 로컬 경로 대신 `<임시>`로 적는다. 에이전트는 키가 없는 **가짜 자료 파일만** `<임시>/workspace/data/`에 만든다: `a.txt`, `b.txt`, `c.txt`, `d.txt`, `e.txt` 다섯 개. 각 파일은 여러 줄의 잡다한 문장 사이에 모델이 사전 지식으로 알 수 없는 **고유 줄** `CODE: <단어>-<숫자>`를 정확히 하나 가진다(예: `CODE: PELICAN-7`, `CODE: QUOKKA-3`, `CODE: WOMBAT-9`, `CODE: TAPIR-2`, `CODE: IBEX-5`). 이 코드들이 응답에 나오면 모델이 파일을 실제로 읽은 것이다.
5. 비용 상한: 질문 1턴. 호출 수는 위임이 일어나면 부모 2~3회 + 자식 수 회~25회 이내로 예상한다. 공개 단가 기준 몇 센트 미만으로 예상하나 실제 청구는 확인하지 못한다. 예상보다 호출이 많아 보이면 사용자가 `Ctrl-C`로 멈춘다(자동 중단은 없다).

## 3. 절차

| 순서 | 동작 |
|---|---|
| 1 | 에이전트가 임시 `HERMES_HOME`에 위 가짜 자료를 만들고, 만든 직후 `data/`의 파일 해시와 `HERMES_HOME` 직하위 항목 이름을 기록 |
| 2 | **사용자가 별도 터미널에서 직접** 레포 루트에서 `HERMES_HOME=<임시 폴더> python -m hermes_core.cli --delegate` 실행. 에이전트는 이 실행을 대신하지 않는다 |
| 3 | 시작 안내에서 모드(실제), 모델, 작업 폴더, `Delegation enabled (delegate_task).` 줄을 확인 |
| 4 | 입력 1: `data 폴더에 있는 모든 텍스트 파일에서 CODE: 로 시작하는 줄을 찾아서 파일 이름 순서로 정리해 알려줘.` (**「위임」「서브에이전트」「자식」이라는 단어를 쓰지 않는다** — 안내문만으로 부르는지 보려는 것이다) |
| 5 | 응답을 확인하고 `exit` |
| 6 | 사용자가 결과를 확인하고 비밀을 뺀 출력을 에이전트에게 전달. 에이전트는 원장 조회(읽기 전용)와 기록 정리를 한다 |

실패(오류 종료, 위임하지 않음, 이상한 응답)하면 **자동으로 다시 시도하거나 코드·안내문을 고치지 않는다.** 원인을 기록하고 멈춰서 보고한다. 같은 스모크를 다시 하려면 사용자의 새 지시가 필요하다. 모델이 위임 없이 직접 `terminal`·`read_file`로 풀어도 오류가 아니다. 그 사실이 가정 G의 관찰 결과다.

## 4. 기대 결과와 확인 항목

원장 조회는 에이전트가 읽기 전용으로 한다(`messages`, `llm_calls`, `sessions`).

| # | 확인 | 기대 결과 |
|---|---|---|
| 1 | **가정 G**: 위임 호출 | 부모 세션의 assistant 행 `tool_calls`에 `delegate_task`가 있다. **없으면 관찰 결과로 기록**(통과/실패가 아니라 가정 G를 「이번 1회 관찰에서는 틀렸다」로 판정) |
| 2 | **가정 G**: `goal`·`context` 품질 | 위임이 일어났다면 `goal`과 `context`의 실제 문장을 그대로 기록한다. `goal`만으로 자식이 폴더 위치와 찾을 대상(`data`, `CODE:`)을 알 수 있었는지 판정한다 |
| 3 | 결과 반영 | 최종 응답에 다섯 코드가 파일 이름 순서로 나온다 |
| 4 | **가정 B**: 원장 분리 | 위임이 일어났다면 `sessions`에 `source == "subagent"`이고 `parent_session_id`가 부모인 행이 있고, `llm_calls`가 부모 세션 id와 자식 세션 id로 각각 쌓이며 자식 호출이 부모 세션에 섞이지 않는다. 자식 `llm_calls` 행 수가 결과 JSON의 `iterations`와 맞는다 |
| 5 | **가정 A**: 자식 도구 | 자식 첫 호출 `llm_calls.request_json`의 도구 이름 집합이 정확히 `{terminal, read_file, write_file, patch, skills_list, skill_view}`이고, 자식 세션의 tool 행에 `delegate_task`·`memory`·`session_search`가 없다 |
| 6 | **가정 E**: 프롬프트 | 부모 `sessions.system_prompt`에 위임 안내문(`delegate_task` 언급)이 있고 부모 첫 호출과 마지막 호출의 첫 system 메시지가 동일. 자식 첫 호출의 system 메시지에는 `focused subagent`가 있고 `Known Fact`류 기억 마커·`delegate_task`·`memory` 안내문이 없으며, 마지막 `user` 메시지가 `goal`이고 사용자의 원래 문장이 어디에도 없다 |
| 7 | **가정 F**: 요약 길이 | 결과 JSON의 `summary` 길이와 `truncated`를 기록한다. 잘렸으면 가정 F를 「이번 1회 관찰에서는 틀렸다」로 적는다 |
| 8 | 모든 호출 정상 | 부모·자식 `llm_calls`의 모든 행 `error_kind` NULL (아니면 어느 세션의 몇 번째 호출인지 기록) |
| 9 | 세션 종료 | 부모 `end_reason == "user_exit"`, 자식 `end_reason == "completed"` (실패면 `llm_error` 등 실제 값을 기록) |
| 10 | 읽기 전용 확인 | `data/`의 파일 해시와 `HERMES_HOME` 직하위 항목이 실행 전과 같다. 새로 생긴 파일이 있으면 이름을 기록 |
| 11 | **키 미저장** | 키가 원장 덤프(부모·자식 모든 세션)에 없다. **사용자가 별도 터미널에서** 키 값을 출력하지 않고 확인하고 결과(`True`/`False`)만 전달한다 |
| 12 | 비용·호출 수 (위험 8) | 부모·자식 `llm_calls`의 호출 수 합계와 토큰으로 계산한 비용을 기록한다. 위임이 비용을 얼마나 곱했는지(부모 호출 대비 자식 호출 비)를 적는다. 1센트를 넘으면 이상 징후가 아니라 기록 사항이다 |
| 13 | 출력·로그 | 키 값이 화면·로그에 없다 |

## 5. 결과 기록

- 대시보드 실행 기록에 날짜, 지시 문구, 통과/실패, 호출 수(부모·자식), 도구 호출 순서, 토큰, 계산한 비용을 적는다.
- 확인 항목 1·2·7의 관찰을 **그대로** 종합보고서의 「목표와 결과」·「새로 발견한 부분」에 옮긴다. 모델이 위임하지 않았다면 가정 G는 「이번 1회 관찰에서는 틀렸다」로 적고, 안내문 보강 또는 도구 설명 보강을 근거와 함께 후속 제안한다. 코드·안내문은 이 단계에서 고치지 않는다.
- **판정의 한계**: 표본이 1회이고 모델 응답은 매번 다를 수 있다. 성공해도 「안내문만으로 위임한다」가 이 1회에서 확인된 것이지 보장이 아니며, 실패해도 우연일 수 있다. 프롬프트가 위임에 얼마나 유리하게 쓰였는지(자료가 다섯 파일로 적은 점)도 한계로 적는다. 종합보고서에 함께 적는다.

## 6. 마감 (5단계, 사용자의 종료 선언이 있을 때만)

[ROADMAP_정책.md §5](../../ROADMAP_정책.md)가 정본이다. 이 로드맵에 해당하는 순서만 적는다.

1. **종합보고서** `결과정리및리뷰.md`를 정책의 9개 항목으로 상세히 쓴다. `WHY.md`의 가정 A~H를 **하나씩** 「이뤘다 / 못 이뤘다 / 바뀌었다」로 근거(커밋 해시·시험·이 스모크의 관찰)와 함께 대조한다. 대조하지 않은 가정이 있으면 마감하지 않는다. 가정 B의 「미확인」(클라이언트 복제 방법)은 030 지시서에서 팩토리 주입으로 바뀌었음을 「바뀌었다」로 기록한다.
2. **대시보드** `README.md`의 전체 상태를 `Closed`로, 시작·완료 일자와 종합보고서 링크를 채운다. 060 행과 실행 기록을 갱신한다. 실행 기록의 커밋 칸은 같은 커밋에서 자기 해시를 쓰지 않는다(정책 §4).
3. **`docs/인계.md`** 를 갱신한다(상태가 바뀌는 작업의 완료 보고).
4. **작동원리 01편 ③의 「미확인」 줄**(실제 모델의 위임 호출)은 이번 1회 관찰과 그 한계로 갱신할 수 있다. 이 갱신은 마감 보고에서 **제안만** 하고, 사용자가 지시하면 수행한다.
5. **커밋과 태그**: 스모크 결과 기록과 마감이 같은 지시로 요청되면 하나의 마감 커밋(`docs(core): R07-마감 - ...`), 스모크 기록이 먼저면 `R07-060` 기록 커밋 뒤 마감 커밋을 따로 만든다. 변경 파일을 경로로 지정해 스테이징한다. **마감 커밋에만** 가벼운 태그 `roadmap-07-closed`를 단다. 푸시와 태그 푸시는 하지 않으며 사용자의 별도 지시가 있을 때만 한다.
6. 마감 후 구현지시서(`instructions/`)는 수정하지 않는다.
