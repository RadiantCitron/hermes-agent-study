## 1. 구현 내용 명세

[`HermesAgent.__init__`](../../../../src/hermes_core/agent/agent.py)에 키워드 인자 네 개를 **맨 끝에** 추가한다. 기본값은 모두 현재 동작과 같다.

1. **`parent_session_id: Optional[str] = None`**: `session_db.create_session(..., parent_session_id=...)`로 그대로 전달한다. `SessionDB`는 이미 이 인자와 외래키(`PRAGMA foreign_keys=ON`)를 갖고 있다. 존재하지 않는 부모 id를 주면 `sqlite3.IntegrityError`가 생성자에서 그대로 올라온다(조용히 끊어진 연결을 만들지 않는다). 이 단계는 그 예외를 잡거나 바꾸지 않는다.
2. **`source: str = "cli"`**: `create_session(source=...)`에 전달한다. 값 검증은 하지 않는다. 자식 값(`"subagent"`)은 이후 단계(030)의 상수로 쓴다. 이 단계에서 상수를 만들지 않는다.
3. **`skip_memory: bool = False`**: 참이면
   - `_build_system_prompt`가 `memory_store.format_for_system_prompt`를 **부르지 않고** 메모리 블록을 넣지 않는다.
   - 생성자가 `self.memory_store.load_from_disk()`를 **부르지 않는다**. 디스크를 읽지 않고, 폴더도 만들지 않으며, **같은 `MemoryStore` 객체를 부모와 공유하더라도 부모의 동결 스냅샷을 다시 찍지 않는다**(`load_from_disk`는 스냅샷을 새로 동결한다. 자식 생성이 부모의 시스템 프롬프트 기반을 바꾸는 사고를 막는다).
   - `self.memory_store` 속성 자체와 기본 디스패처 조립은 현재 그대로다(자식에게는 030에서 자식 전용 디스패처를 주입하므로 영향 없다).
4. **`skip_context_files: bool = False`**: 참이면 `build_context_files_prompt()`를 부르지 않고 지시문 파일 블록(AGENTS.md 등)을 넣지 않는다. `skip_memory`와 서로 독립이다.
5. **프롬프트 조립 구조는 바꾸지 않는다**: `build_system_prompt(...)`에는 `memory_block=None` 또는 `context_files_block=None`을 넘길 뿐이다(`prompt_builder.py` 무변경). `tools_guidance`(메모리·세션검색·스킬 안내문)는 이 단계에서 건드리지 않는다.
6. **이월(040)**: 자식 통로에는 `memory`·`session_search` 도구가 없는데 시스템 프롬프트에는 두 안내문이 그대로 남는다. 자식이 없는 도구를 부르려다 `Unknown tool`을 받을 수 있다. 안내문 정리는 자식 프롬프트를 만드는 040의 몫이며, 020은 확인한 사실만 남긴다.
7. **작동원리 갱신**: 없음 (050에서 일괄 반영).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: `MockLLMClient`와 임시 `SessionDB(tmp_path/...)`, 임시 `MemoryStore(memory_dir=tmp_path/...)`를 쓴다. 모델·네트워크 없음. 시스템 프롬프트는 `run_conversation`을 한 번 돌린 뒤 `MockLLMClient.call_history[0]["messages"][0]["content"]`로 읽는다(비공개 속성을 보지 않는다). 지시문 파일 시나리오는 `tmp_path`에 `AGENTS.md`(마커 문자열 `CTXMARK`)를 만들고 `monkeypatch.chdir`한다. 메모리 마커는 `MEMORY.md`에 `MEMMARK`, `USER.md`에 `USRMARK`를 쓴다. 마커는 시험 안에 문자열로 직접 적는다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 새 인자 없이 `HermesAgent(...)` 생성 후 `get_session` | `source == "cli"`, `parent_session_id`는 `None`. 시스템 프롬프트에 `MEMMARK`, `USRMARK`, `CTXMARK`가 모두 있음 (기본 동작 회귀) |
| 2 | 부모 에이전트 `P` 생성 후 `HermesAgent(parent_session_id=P.session_id, source="subagent", ...)` 생성 | 자식 `get_session`의 `parent_session_id == P.session_id`, `source == "subagent"`. 부모 행은 그대로 `source == "cli"`, `parent_session_id` 없음 |
| 3 | 존재하지 않는 id로 `parent_session_id="nope"` 생성 | `sqlite3.IntegrityError`. 이후 `get_session`에 해당 자식 세션이 없음 |
| 4 | `skip_memory=True` | 시스템 프롬프트에 `MEMMARK`·`USRMARK`가 없고 `CTXMARK`는 있음 |
| 5 | `skip_memory=True`, 존재하지 않는 `memory_dir`를 가진 `MemoryStore` | 생성 후 그 폴더가 **만들어지지 않았고** `store.memory_entries == []` (디스크를 읽지도, 만들지도 않음) |
| 6 | 부모가 쓰는 같은 `MemoryStore`로 부모 생성(스냅샷에 `MEMMARK`) → 디스크의 `MEMORY.md`를 `MEMMARK2`로 바꿈 → 같은 store로 `skip_memory=True` 자식 생성 | `store.format_for_system_prompt("memory")`가 여전히 `MEMMARK`를 담고 `MEMMARK2`를 담지 않음 (자식 생성이 부모 스냅샷을 다시 동결하지 않음) |
| 7 | `skip_context_files=True` | 시스템 프롬프트에 `CTXMARK`가 없고 `MEMMARK`·`USRMARK`는 있음 (두 인자는 독립) |
| 8 | `skip_memory=True, skip_context_files=True` | 시스템 프롬프트에 세 마커 모두 없음. 여전히 에이전트 정체성 문장과 도구 안내가 포함됨 (빈 프롬프트가 되지 않음) |
| 9 | 부모 DB와 같은 DB에 `source="subagent"` 자식 세션을 만들고 자식 대화에 고유어 `ZEBRA` 기록 후, 부모 디스패처의 `session_search(query="ZEBRA")` | `success: true`이고 결과 목록이 비어 있음 (기본 `source_filter`에 `subagent`가 없어 자식 대화가 부모 검색에 섞이지 않음) |
| 10 | 기존 코어 테스트(010 완료 시점 전체) | **수정 없이** 통과 |

## 4. 검증 기준 (Done 조건)

1. 시나리오 1~9가 통과한다 (`test_agent_child_args.py`).
2. 기존 테스트가 모두 통과한다 (사전 점검에서 기록한 기준선 + 신규). 기존 시험 파일의 변경이 0건이다 (`git diff <단계 시작 커밋>..HEAD --stat -- tests/`가 신규 파일뿐).
3. `git diff <단계 시작 커밋>..HEAD --stat`의 `src/` 변경이 `agent/agent.py`뿐이다 (`session_db.py`, `memory_tool.py`, `prompt_builder.py` 무변경).
4. `grep -rn "delegate" src/`가 비어 있다 (이 단계도 위임 도구를 만들지 않는다).
