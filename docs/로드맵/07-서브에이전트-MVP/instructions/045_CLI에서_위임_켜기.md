## 1. 구현 내용 명세

### 1-0. 확정된 결정

| 결정 | 내용 | 근거 |
|---|---|---|
| 켜는 방식 | `--delegate` **플래그를 줬을 때만** 켠다. 기본은 꺼짐 | 위임은 모델 호출 수를 곱한다(위험 8: 자식 25회 × 부모 50회). 기본 동작과 비용이 바뀌지 않아야 한다. 사용자 승인 사항 |
| 모의 모드 | `--delegate`와 `--mock`을 같이 주면 **오류로 종료**한다(종료 코드 2). 조용히 무시하지 않는다 | 모의 응답에 위임 시나리오가 없다. 02의 「가짜 모델을 조용히 쓰지 않는다」와 같은 원칙. 사용자 승인 사항 |
| 자식 모델 | 부모와 **같은 모델·같은 키**의 새 `OpenRouterClient` | 자식 모델 별도 지정은 범위 밖(ADR-0007 §2-1) |
| 등록 시점 | 에이전트 생성 직후, 첫 `run_conversation` **전** | 시스템 프롬프트는 첫 호출에서 한 번 조립되므로(040) 이때 등록해야 위임 안내문이 들어간다 |

### 1-1. [`cli.py`](../../../../src/hermes_core/cli.py)

1. **인자**: `--delegate`(`store_true`). 도움말에 「실제 모델 모드에서 `delegate_task`(순차 단일 자식)를 켠다」 취지를 쓴다.
2. **검증**: `args.context_window` 검증과 같은 위치(모의 모드 준비 전)에서 `args.delegate and args.mock`이면 표준 오류에 `Error: --delegate cannot be used with --mock (delegation needs a real model).`를 출력하고 `sys.exit(2)`. 이 경우 세션 DB도 작업 폴더 이동도 일어나지 않는다.
3. **등록**: 실제 모델 모드에서 `HermesAgent`를 만든 직후, `args.delegate`이면
   ```
   register_delegate_tool(
       agent.dispatcher,
       session_db=agent.session_db,
       parent_session_id=agent.session_id,
       llm_client_factory=lambda: OpenRouterClient(api_key=api_key, model=model),
   )
   ```
   `OpenRouterClient`는 호출 시점에 `cli` 모듈 전역에서 찾는다(기존 시험이 `cli.OpenRouterClient`를 바꿔치는 방식과 같다). `model`은 기본값 보정(`DEFAULT_REAL_MODEL`)이 끝난 값이다. 키 값은 어떤 출력에도 쓰지 않는다.
4. **안내 출력**: 켜졌을 때만 시작 배너에 한 줄 `Delegation enabled (delegate_task).`를 출력한다. 꺼져 있으면 출력이 이전과 같다.
5. **그 밖의 동작은 그대로다**: 플래그가 없으면 클라이언트 생성 횟수, 도구 8종, 시스템 프롬프트, 출력이 모두 이전과 같다.

### 1-2. 하지 않는 것

자식 모델 별도 지정 플래그, 환경변수로 켜기, 모의 모드 위임 시나리오, 반복 상한·요약 상한을 CLI 인자로 열기, 작동원리 갱신(050).

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: 기존 `test_cli.py`와 같이 `monkeypatch`로 `sys.argv`, `sys.stdin`(`io.StringIO`), 환경변수 `HERMES_HOME`(임시 폴더)과 `OPENROUTER_API_KEY`(가짜 값 `test-key-safe-delegate`)를 설정하고 `cli.OpenRouterClient`를 **대본 클라이언트**로 바꿔치는 방식. 대본 클라이언트는 생성될 때마다 순번을 받아(0번 = 부모, 1번 = 자식) 순번별 응답 목록을 재생하고, 받은 `messages`·`tools`·`api_key`·`model`을 기록한다. 네트워크 없음. 도구 이름·핵심 구절·종료 코드는 시험 안에 직접 적는다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 플래그 없이 실제 모드, 입력 `hi` → `exit`, 부모 응답 1회 | 생성된 클라이언트 정확히 1개. 첫 호출이 받은 도구 이름 집합이 정확히 `{"memory","session_search","terminal","read_file","write_file","patch","skills_list","skill_view"}`. 시스템 메시지에 `delegate_task` 없음. 출력에 `Delegation enabled` 없음 |
| 2 | `--delegate`, 같은 입력 | 첫 호출 도구 이름 집합이 위 8종 + `delegate_task` 정확히 9종. 시스템 메시지에 `delegate_task` 포함(위임 안내문 반영). 출력에 `Delegation enabled (delegate_task).` 한 번 |
| 3 | `--delegate`, 입력 `go` → `exit`. 부모 0번: 1회차 `delegate_task(goal="G1")` 호출, 2회차 최종 `parent done`. 자식 1번: 최종 `child summary` | 종료 코드 0(예외 없음). 출력에 `parent done`. 생성된 클라이언트 정확히 2개이고 둘의 `model`이 `DEFAULT_REAL_MODEL`과 같음. DB의 세션 2개: 자식은 `source == "subagent"`, `parent_session_id`가 부모 세션 id, `ended_at`이 비어 있지 않음. 부모는 `exit`로 `end_reason == "user_exit"` |
| 4 | 시나리오 3에 `--model custom/model-x` 추가 | 부모·자식 클라이언트 둘 다 `model == "custom/model-x"` |
| 5 | `--delegate --mock` | 종료 코드 2. 표준 오류에 `--delegate`와 `--mock`을 모두 포함한 오류 메시지. `state.db`가 만들어지지 않음. 클라이언트가 만들어지지 않음 |
| 6 | `--delegate`, 키 환경변수 없음(실제 모드) | 기존과 같이 종료 코드 2, 키 안내 메시지(`--mock` 안내 포함). `state.db` 없음 |
| 7 | 시나리오 3 실행 후 | 자식 클라이언트의 `api_key`가 부모와 같고, 가짜 키 문자열이 표준 출력·표준 오류에 없고, DB 전체 덤프(세션·메시지·`llm_calls`)에도 없음 (Zero Leakage) |
| 8 | 시나리오 3에서 자식 클라이언트가 `LLMError("server", "boom")`를 던짐 | 종료 코드 0. 부모는 도구 결과(실패)를 받고 최종 응답 `parent done`을 출력. 자식 세션 `end_reason == "llm_error"` |
| 9 | `--help` | 종료 코드 0, 출력에 `--delegate` 포함 |
| 10 | 기존 코어 테스트(040 완료 시점 전체, `test_cli.py` 포함) | **수정 없이** 통과 |

## 4. 검증 기준 (Done 조건)

1. 시나리오 1~9가 통과한다 (`test_cli_delegate.py`).
2. 기존 테스트가 모두 통과한다 (사전 점검 기준선 + 신규). 기존 시험 파일의 변경이 0건이다.
3. `git diff <단계 시작 커밋>..HEAD --stat`의 `src/` 변경이 `cli.py`뿐이다.
4. 플래그 없이 실행한 결과(시나리오 1)가 이전과 같다는 것이 시험으로 확인된다.
