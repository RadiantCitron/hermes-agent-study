## 1. 구현 내용 명세

### 1-0. 이 지시서에서 확정한 열린 항목 (코드 대조 결과)

| 열린 항목 | 확정 | 근거 |
|---|---|---|
| 안내문을 언제 넣는가 | **실제로 등록된 도구에 대한 안내문만** 넣는다. 도구 이름 집합으로 고르는 순수 함수 `select_tools_guidance(tool_names)`를 둔다 | 지금은 `agent.py`가 세 안내문을 도구 유무와 무관하게 고정 목록으로 넣는다([agent.py:210](../../../../src/hermes_core/agent/agent.py)). 자식 통로에는 `memory`·`session_search`가 없는데 안내문이 남는 문제(020 이월)와 위임 안내문의 조건부 삽입이 **같은 규칙** 하나로 풀린다. 에이전트에 `delegate`라는 이름을 하드코딩하지 않아도 된다 |
| 기본 에이전트(8종)의 프롬프트 | **바이트 단위로 이전과 같다** | 8종이 모두 있으면 선택 결과가 `[MEMORY, SESSION_SEARCH, SKILLS]`(기존과 같은 순서)이고 위임 도구가 없으면 위임 안내문은 빠진다 |
| 위임 안내문의 반영 시점 | **첫 `run_conversation` 전에 등록한 경우만** 들어간다 | 시스템 프롬프트는 세션 시작 시 1회 조립해 캐시한다(Prompt Caching 보존). 이후 등록은 프롬프트를 바꾸지 않는다. 이 한계를 시험(시나리오 5)으로 고정한다 |
| 자식 프롬프트 | `context`를 그대로 시스템 칸에 싣던 030의 최소형을 **「집중된 하위 작업자」 프롬프트 + context 블록**으로 바꾼다. `goal`은 계속 첫 사용자 메시지 한 곳에만 있다 | ADR-0007 §2-2 |
| `cli.py`에서 위임을 켜는 연결 | **이 지시서에 넣지 않는다.** 별도 단계(사이번호 `045`)로 제안한다 | 대시보드의 어느 단계에도 없다. 켤지 말지(기본 켬 vs 플래그), 모의 모드 처리는 비용(위험 8)과 직결되는 판단이라 사용자 확인이 필요하다. 제안은 작업 보고에 적는다 |

### 1-1. [`prompt_builder.py`](../../../../src/hermes_core/agent/prompt_builder.py)

1. **`SUBAGENT_GUIDANCE`** (영어, 600자 이하): `delegate_task`를 언급하고 다음 네 가지를 담는다. ① 위임이 맞는 경우: 중간 단계가 대화를 어지럽힐 독립적인 하위 작업(탐색, 반복 수정). ② 위임하지 않는 경우: 도구 한 번이면 끝나는 일. ③ 자식은 대화를 모르므로 `goal`·`context`에 필요한 것을 모두 담을 것. ④ 돌아오는 것은 요약뿐이므로 중요한 결과는 직접 확인할 것.
2. **`CHILD_AGENT_PROMPT`** (영어): 자식이 「하나의 위임된 작업에 집중하는 하위 작업자」이고, 부모의 대화를 볼 수 없으며, 도구로 일한 뒤 **짧은 요약**(한 일, 발견한 것, 건드린 파일, 남은 문제)으로 응답한다고 알린다. 부모에게 되묻거나 추가 위임을 할 수 없다는 사실도 쓴다.
3. **`select_tools_guidance(tool_names: Collection[str]) -> list[str]`**: 순서대로 다음 조건을 만족하는 안내문만 돌려준다.

   | 안내문 | 들어가는 조건 (이름이 모두 있을 때) |
   |---|---|
   | `MEMORY_GUIDANCE` | `memory` |
   | `SESSION_SEARCH_GUIDANCE` | `session_search` |
   | `SKILLS_GUIDANCE` | `skills_list`, `skill_view` |
   | `SUBAGENT_GUIDANCE` | `delegate_task` |

   빈 집합이면 빈 목록이다. 입력을 바꾸지 않는다.
4. **`build_child_system_message(context: Optional[str]) -> str`**: `CHILD_AGENT_PROMPT`를 돌려준다. `context.strip()`이 비어 있지 않으면 `\n\n## Context from the parent agent\n\n` + `context.strip()`을 뒤에 붙인다. `None`·빈 문자열·공백뿐인 값은 블록을 만들지 않는다(문자열 `None`이 새지 않는다).

### 1-2. [`agent.py`](../../../../src/hermes_core/agent/agent.py)

`_build_system_prompt`의 `tools_guidance`를 고정 목록 대신 `select_tools_guidance(<self.dispatcher.get_tools_schema()의 function.name들>)`로 바꾼다. 이 외 조립 순서·캐시·DB 저장 동작은 그대로다. 더 이상 쓰지 않는 안내문 import는 정리한다. 에이전트 코드에 `delegate_task`라는 문자열을 넣지 않는다.

### 1-3. [`delegate_tool.py`](../../../../src/hermes_core/tools/delegate_tool.py) (030 산출물)

자식 생성 인자 `system_message=context`를 `system_message=build_child_system_message(context)`로 바꾼다. 한 줄 외 변경은 없다.

### 1-4. 하지 않는 것

`cli.py` 연결(제안만), 작동원리 갱신(050), 안내문에 도구 목록·스킬 이름을 나열하는 일, 위임 사용을 강제하는 문구.

## 3. 인수 테스트 시나리오 (구현 전 작성, 임의 변경 금지)

시험 방식: 모델·네트워크 없음. 에이전트는 `MockLLMClient`, 임시 `SessionDB`·`MemoryStore`, `monkeypatch.chdir(tmp_path)`. 시스템 프롬프트는 `MockLLMClient.call_history[0]["messages"][0]["content"]`로 읽는다. 기대 도구 이름·핵심 구절은 시험 안에 문자열로 직접 적는다. 본문 문구 자체가 아니라 **구성 요소 포함 여부**를 단언한다(안내문 상수는 비교 오라클로 쓸 수 있으나 위임 도구 이름 `delegate_task`와 아래 핵심 구절은 직접 적는다).

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | `SUBAGENT_GUIDANCE` | 비어 있지 않고 `delegate_task`·`goal`·`context` 포함, 길이 600자 이하, 줄바꿈으로 시작·끝나지 않음 |
| 2 | `select_tools_guidance`에 (a) 기본 8종 이름 (b) 8종 + `delegate_task` (c) 자식 6종 `terminal,read_file,write_file,patch,skills_list,skill_view` (d) `skills_list`만 (e) `memory`만 (f) 빈 집합 | (a) 정확히 `[MEMORY, SESSION_SEARCH, SKILLS]` 순서 (b) 위에 `SUBAGENT_GUIDANCE`가 마지막으로 하나 더 (c) `[SKILLS]`만 (d) `[]` (`skill_view` 없음) (e) `[MEMORY]` (f) `[]` |
| 3 | 위임 도구를 등록하지 않은 기본 부모 에이전트의 시스템 프롬프트 | `build_system_prompt(tools_guidance=[MEMORY_GUIDANCE, SESSION_SEARCH_GUIDANCE, SKILLS_GUIDANCE], ...)`로 따로 조립한 프롬프트와 **바이트 단위로 같고**(시작 시각은 같은 `start_time`을 고정해 비교하거나, 두 문자열에서 시각 줄을 제외하고 비교) `delegate_task` 문자열이 없음 |
| 4 | `register_delegate_tool` 등록 후 **첫** `run_conversation` | 시스템 프롬프트에 `SUBAGENT_GUIDANCE`가 있고 `SKILLS_GUIDANCE`보다 뒤에 있음. DB에 저장된 시스템 프롬프트가 첫 LLM 호출의 시스템 메시지와 같음 |
| 5 | 첫 `run_conversation` **이후** `register_delegate_tool`, 그다음 두 번째 `run_conversation` | 두 번째 호출의 시스템 메시지가 첫 번째와 바이트 단위로 같고 `delegate_task`가 없음 (세션 중 프롬프트 불변) |
| 6 | 부모가 `delegate_task(goal="G1", context="C1")` 호출, 자식이 받은 첫 호출의 시스템 메시지 | `CHILD_AGENT_PROMPT`의 핵심 구절 `focused subagent` 포함. `## Context from the parent agent` 아래에 `C1`. `SKILLS_GUIDANCE` 포함. `MEMORY_GUIDANCE`·`SESSION_SEARCH_GUIDANCE`·`SUBAGENT_GUIDANCE`·`delegate_task`는 **없음**. `G1`은 시스템 메시지에 없고 마지막 `user` 메시지가 정확히 `G1` |
| 7 | `build_child_system_message`에 `None`, `""`, `"   \n"` | 셋 모두 `CHILD_AGENT_PROMPT`와 같고 `Context from the parent agent`와 `None`이라는 글자가 없음 |
| 8 | `build_child_system_message("  C2\n")` | `C2`가 정확히 한 번, `## Context from the parent agent` 뒤에 나오고 앞뒤 공백이 제거됨 |
| 9 | 도구가 없는 `ToolDispatcher()`로 만든 에이전트의 시스템 프롬프트 | 예외 없이 생성되고 세 안내문(`MEMORY_GUIDANCE`, `SESSION_SEARCH_GUIDANCE`, `SKILLS_GUIDANCE`)이 없음 (선택 규칙의 파급을 고정) |
| 10 | 기존 코어 테스트(030 완료 시점 전체, 030 시험 포함) | **수정 없이** 통과 (특히 030의 「시스템 메시지에 `C1` 포함」) |

## 4. 검증 기준 (Done 조건)

1. 시나리오 1~9가 통과한다 (`test_subagent_guidance.py`).
2. 기존 테스트가 모두 통과한다 (사전 점검 기준선 + 신규). 기존 시험 파일의 변경이 0건이다. 기존 시험이 깨지면 시험을 고치지 않고 멈춰서 보고한다.
3. `git diff <단계 시작 커밋>..HEAD --stat`의 `src/` 변경이 `agent/prompt_builder.py`, `agent/agent.py`, `tools/delegate_tool.py`뿐이다.
4. `grep -rn "delegate_task" src/hermes_core/agent/agent.py`가 비어 있다 (에이전트가 위임 도구 이름을 모른다).
